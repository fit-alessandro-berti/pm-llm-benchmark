# Description of the Visualization

This image illustrates a **Proclet-based workflow model** for a laboratory testing process, divided into three parts:

## (a) Two Proclet Classes Connected Through Two Channels
This is the main diagram showing two parallel workflows connected by communication channels:

- **"Lab visit" proclet** (left side): Shows the patient-facing process including:
  - Order entry (by doctor)
  - Take blood sample (by lab assistant)
  - Judge results
  - Decision point ("Everything fine" or "Do tests again")
  - Send report

- **"Lab test" proclet** (right side): Shows the laboratory process including:
  - Perform test (by chemical analyst)
  - Make report
  - Perform test again (if needed)
  - Provide updated report
  - Finish lab test

- **Two connecting channels**:
  - **"Order system"** channel (top) - handles initial communication with cardinality markers (*,1) and (1,1)
  - **"HIS"** (Hospital Information System) channel (bottom) - handles result/report communication with cardinality markers (*,1) and (1,?)

The gray-shaded boxes (Receive result, Do tests again, Receive updated result, Finish lab test) represent synchronization/communication points between the two proclets.

## (b) Class Diagram
A simple UML-style class diagram showing the relationship:
- **Lab visit** "requires" **Lab test** with cardinality **1..1** to **1..***

This indicates one lab visit can require multiple lab tests.

## (c) Example of a Performative
A table demonstrating a concrete message instance passed through the channel, showing:
- **Time**: 11:00
- **Channel**: Order system
- **Sender**: Lab visit - John
- **Receiver**: Lab test – HGB John
- **Action**: Create
- **Content**: "Can you perform a HGB test for John?"
- **Scope**: Private
- **Direction**: OUT

## Overall Purpose
This diagram demonstrates how **proclets** (a modeling technique for inter-organizational or multi-perspective processes) can model two related but independent processes that communicate asynchronously through defined channels, useful for healthcare/laboratory information systems where visit management and test execution are separate but coordinated processes.
