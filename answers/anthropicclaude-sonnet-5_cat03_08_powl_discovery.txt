# POWL Model for Manufacturing & Distribution Process

## Analysis of the Event Log

From the traces, I can identify the following control-flow patterns:

1. **OR  MS  QS**: Always executed in this fixed sequence at the start.
2. **AS/IQC loop**: Assembly (AS) is performed, and optionally followed by an In-line Quality Check (IQC) leading to another Assembly round. This repeats 0+ times (Case 4 has just one AS with no IQC; Case 3 has three AS/IQC repetitions).
3. **TST/RT loop**: Testing (TST) occurs, and optionally a Re-Test (RT) leads to another TST. This repeats 0+ times (Case 4 has just one TST; Case 5 has three TST/RT repetitions).
4. **PK** always follows the testing loop.
5. **LB (Labeling)** is optional — it may be skipped (Case 2) or executed (Cases 1, 3, 4, 5).
6. **DP  D**: Always executed at the end, in this order.

The overall structure is a strict sequence of these blocks (no concurrency observed between the phases).

## POWL Model Construction

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# Basic activities
OR = Transition(label="OR")
MS = Transition(label="MS")
QS = Transition(label="QS")
AS = Transition(label="AS")
IQC = Transition(label="IQC")
TST = Transition(label="TST")
RT = Transition(label="RT")
PK = Transition(label="PK")
LB = Transition(label="LB")
DP = Transition(label="DP")
D = Transition(label="D")

# Silent transition for skipping labeling
skip_LB = SilentTransition()

# Loop: perform AS, then either exit the loop or perform IQC and repeat AS
assembly_loop = OperatorPOWL(operator=Operator.LOOP, children=[AS, IQC])

# Loop: perform TST, then either exit the loop or perform RT and repeat TST
testing_loop = OperatorPOWL(operator=Operator.LOOP, children=[TST, RT])

# Choice: Labeling is either performed or skipped
labeling_choice = OperatorPOWL(operator=Operator.XOR, children=[LB, skip_LB])

# Build the overall strict partial order (sequence) of the process
root = StrictPartialOrder(nodes=[
    OR, MS, QS, assembly_loop, testing_loop, PK, labeling_choice, DP, D
])

# Define sequential order (each step must complete before the next starts)
root.order.add_edge(OR, MS)
root.order.add_edge(MS, QS)
root.order.add_edge(QS, assembly_loop)
root.order.add_edge(assembly_loop, testing_loop)
root.order.add_edge(testing_loop, PK)
root.order.add_edge(PK, labeling_choice)
root.order.add_edge(labeling_choice, DP)
root.order.add_edge(DP, D)
```

## Explanation of the Structure

- **`assembly_loop = * ( AS, IQC )`**: Encodes that Assembly (AS) is always executed first; the loop can exit immediately (as in Case 4, single AS) or repeat via IQC  AS as many times as needed (as in Case 3, three iterations).

- **`testing_loop = * ( TST, RT )`**: Encodes that Testing (TST) is always executed first; the loop can exit (single TST, as in Case 4) or repeat via RT  TST (as in Cases 1, 3, and especially Case 5 with two repetitions).

- **`labeling_choice = X ( LB, tau )`**: Models the optional nature of the Labeling activity — either it is performed (Cases 1, 3, 4, 5) or skipped entirely via a silent transition (Case 2).

- **Root `StrictPartialOrder`**: All major phases (Order Receipt, Material Sourcing, Quality Screening, Assembly loop, Testing loop, Packaging, Labeling choice, Distribution Planning, Dispatch) are strictly sequenced, since the log shows no concurrency between these phases — each phase completes fully before the next begins.

This POWL model faithfully captures:
- The fixed opening sequence (OR  MS  QS),
- The variable-length assembly/quality-check cycle,
- The variable-length testing/re-testing cycle,
- The optional labeling step,
- The fixed closing sequence (DP  D).
