In an insurance claim process the baseline is visible in cases **2001 and 2004**.

| Case | Lead Time | #Activities | Path |
| :--- | :--- | :--- | :--- |
| **2001** | **1h 30m** - 09:00 to 10:30 same day | 5 | Submit > Evaluate > Approve > Pay > Close |
| **2004** | **1h 25m** - 09:20 to 10:45 same day | 5 | Submit > Evaluate > Approve > Pay > Close |
| **2002** | **25h 55m** - 1d 01h 55m | 6 | Submit > Evaluate > **1x Request Docs** > Approve > Pay > Close |
| **2003** | **48h 20m** - 2d 00h 20m | 7 | Submit > Evaluate > **2x Request Docs** > Approve > Pay > Close |
| **2005** | **77h 05m** - 3d 05h 05m | 8 | Submit > Evaluate > **3x Request Docs** > Approve > Pay > Close |

**Performance issue:** Cases with `Request Additional Documents` are outliers. The expected happy path is 1.5h. Any case >24h is a performance issue. **2005 is critical, 2003 is major, 2002 is moderate.**

Lead time increases almost linearly with the number of Request loops.

### 2. Root Cause Analysis by Attribute

#### A. Complexity = Main Driver
This is the strongest correlation.

* **Low Complexity - 2001, 2004:** No Request step. Avg duration = 1h 27m.
* **Medium Complexity - 2002:** 1x Request. Duration = 25h 55m
* **High Complexity - 2003, 2005:** 2x and 3x Requests. Avg duration = 62h 42m.

Breakdown of waiting time:

* 2002: Evaluate > Request = 4h15m, Request > Approve = 20h
* 2003: Request > Request = 6h, Request > Approve = 23h, Approve > Pay = 17h
* 2005: Request > Request = 29h30m + 22h, Request > Approve = 19h

Pattern: High complexity claims trigger **rework loops**. The process doesn't collect all needed documents at once, so the adjuster has to ask again. Each loop incurs customer response time + internal queue time.

#### B. Resource = Secondary Bottleneck

* **Adjuster_Mike [A]**: 2001 fast [0 requests], 2003 slow [2 requests]. Not inherently slow, but caught in high complexity loop.
* **Adjuster_Lisa [B]**: 2004 fast [0 requests], 2002 [1 request], 2005 [3 requests]. She handles 60% of all cases in log, including the most complex. Potential overload in Region B.
* **Manager_Bill**: Appears **ONLY** in High Complexity cases 2003 & 2005 for `Approve Claim`. His approve step takes 19-23h after the last document. 
* **Manager_Ann**: Approves Low/Medium cases 2001, 2002, 2004 within 0.5h to 20h - much faster.
* **Finance_Carl vs Finance_Alan**: No clear difference, both pay in 15m-4h once approved.

> **Deduction:** Bill is the designated senior manager for High Complexity. He is a bottleneck. The loop itself happens at adjuster level.

#### C. Region = Weak Correlation / Confounder

* **Region A:** 1 fast + 1 slow -> Avg 24h 55m
* **Region B:** 1 fast + 1 medium + 1 slowest -> Avg 34h 55m

Region B is on average 40% slower, but that's because it has 2 out of 3 cases that required requests and the only case with Adjuster_Lisa's 3x loop. Region is not root cause by itself, it reflects workload distribution and complexity assignment.

### 3. Why and How to Mitigate

**Why high complexity causes long lead times:**

1.  No upfront completeness check - Submit is accepted even if documentation will be insufficient for High claims.
2.  Sequential requesting - Instead of one comprehensive list, adjusters ask piecemeal, forcing customer to respond multiple times.
3.  Expert approval queue - High complexity requires Manager_Bill, creating a single point of failure.

**Suggestions:**

**1. Prevent the loop - Front-load for Complexity=High:**
Create a mandatory checklist / dynamic form for High complexity. If `Complexity = High`, trigger `Request Additional Documents` automatically right after `Submit Claim` with a complete list, before evaluation.

**2. Fix the Rework:**
Implement a rule: `Request Additional Documents` may only happen once. Train Adjuster_Mike and Adjuster_Lisa to request all missing documents in one go. Use a document portal with automated reminders to the customer instead of waiting 22-29h passively.

**3. Fix the Resource Bottleneck:**
* Cross-train Manager_Ann to approve High complexity or add a second senior approver. Set SLA for Approve: e.g., 4h after documents received.
* Load balance: Reassign some Region B / Medium-High claims from Adjuster_Lisa to other adjusters. 2004 proves Lisa can be fast on Low claims, she is overloaded on High.

**4. Process Mining Monitoring:**
Create a KPI: Cases with count[Request Additional Documents] > 1. Alert if case duration > 1.5x median. Track `Time between Request > Approve` as a customer wait + manager queue metric.

If you implement 1+2, you would convert cases 2003/2005 from 48-77h path to the 2002 path ~26h, and with parallel approval down to < 8h.
