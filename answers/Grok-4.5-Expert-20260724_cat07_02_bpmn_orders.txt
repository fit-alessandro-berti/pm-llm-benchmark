**This is a BPMN 2.0 collaboration diagram** that models an end-to-end order fulfillment process across four organizational lanes (pools): **Sales**, **Production**, **Procurement**, and **Warehouse**. It shows both the happy path and exception/compensation handling for materials.

### Sales lane
- The process is triggered by a **timer start event** (“Monday morning”).
- A start event leads into two sequential tasks:
  1. **Check order for completeness**
  2. **Check if customer is already in the database**
- An exclusive gateway then decides:
  - If the customer is **not** in the database → **Add customer to the database** (connected to a data store).
  - If the customer **is** already in the database → continue.
- After the customer check, the process **sends order details** (message throw) to the other departments.
- It then waits for a **“Product sent”** message intermediate catch event.
- Finally it performs **Draft invoice** and ends.

A collapsed group labeled “Check customer’s order” visually groups the customer-related activities.

### Production lane
- Starts with a **message start event** (“Order details arrive”).
- A **parallel (AND) gateway** splits the flow:
  - One path executes **Plan production**.
  - The other path waits for a **“Material not faulty”** message intermediate catch event.
- The two paths join again at a second parallel gateway.
- Then **Manufacture product** is performed and a **“Product complete”** message is thrown to the Warehouse.
- A dashed message flow links the material-status event back to Procurement.

### Procurement lane
- Also starts with a **message start event** (“Order details arrive”).
- Contains a **compensation subprocess** titled “Material Compensation Subprocess”:
  - Main activity: **Order materials**.
  - Compensation handler: **Return material** (the double-bordered activity with the compensation marker).
- After the subprocess, **Check materials** is executed (shown with an error/escalation marker).
- From the check there is a path to an intermediate timer event and an **“Order cancelation”** end event (exception path).
- Successful material checks enable the “Material not faulty” signal that Production is waiting for.

### Warehouse lane
- Starts with a **message start event** (“Product complete”).
- Performs **Send product**.
- Throws a **“Product sent”** message that Sales is waiting for, then ends.

### Key message flows & interactions
- **Order details** (dashed lines) travel from Sales to both Production and Procurement.
- **Material not faulty** signal travels from Procurement to Production.
- **Product complete** travels from Production to Warehouse.
- **Product sent** travels from Warehouse back to Sales.

### Notable BPMN constructs
- Parallel gateways in Production (plan + wait for material confirmation).
- Compensation subprocess in Procurement (ensures materials can be returned if the order is later cancelled).
- Error/escalation handling and an explicit order-cancellation path in Procurement.
- Data store association for the customer database in Sales.
- Multiple intermediate message catch/throw events that synchronize the four lanes.

In short, the diagram describes a coordinated order-to-delivery process that starts in Sales every Monday, triggers parallel planning and material ordering, manufactures only after materials are confirmed good, ships the product from the Warehouse, and finally creates the invoice once the product has been sent. Compensation and cancellation paths handle the cases where materials must be returned or the order is aborted.
