SWITCH events act as attention-transfer signals: the destination application/window begins (or resumes) a case segment, while the source case is implicitly suspended. Two cases (CASE-01, CASE-05) are non-contiguous — the user interleaves them with other work — which process mining tools handle naturally as gaps within a trace. The initial 08:59:50 FOCUS on Quarterly_Report.docx is interpreted as the user glancing at the report first, then pivoting to other tasks before returning to finish it.

**Activity naming.** Raw low-level verbs were mapped to a standardized, analyst-friendly vocabulary following an *Open  Work  Save/Close* pattern per artifact type: documents (Open / Draft Text / Save / Close), email (Open / Read / Compose / Send), PDF (Open / Review / Annotate), and spreadsheets (Open / Update / Save). Returning to a suspended case is labeled "Resume Document Editing." The raw payload (typed text, clicked action, highlighted text) is preserved in the **Details** attribute, and the **Original Action** column retains full traceability to the source log.

**Case termination.** Only the two Word documents have explicit CLOSE events. The email, PDF, and spreadsheet cases end implicitly when the user switches away — a common pattern in desktop interaction logs that analysts may optionally treat as "abandoned" or "completed without formal closure."

**The narrative.** The log tells the story of a focused morning work session: the user drafts a new document, pauses to confirm Annual Meeting details by email, reviews and annotates a report draft, updates Q1/Q2 budget figures, then returns to the draft to insert a budget reference before closing it, and finally completes the executive summary of the quarterly report — a realistic, multitasking knowledge-work routine.
