## 2. Analyzing Constraint Interactions

Understanding interactions is critical because optimizing one constraint in isolation often **amplifies** others. The key interactions in your environment are:

**Express + Cold-Packing = Double Bottleneck with Preemption Risk**

**Batching + Hazardous Limits = Cascading Region Bottlenecks**

If your scheduling system does not cross-check both constraints (express urgency AND regulatory cap), it will attempt to seize a resource illegally or create a blocking queue inside the regulated zone.

**Interaction Importance:** These dependencies mean your optimization strategies must be **coordinated** through an integrated scheduling layer rather than local rules (e.g., “express always wins” or “batch at 5 orders”). **Specific Changes:**
- Implement a **digital pre-queue** for orders upon `Item Picking COMPLETE`, not upon physical arrival at packing.
- Use process mining-derived distributions (inter-arrival times, processing durations by order type) to build a **predictive arrival model** per 30–60 minute horizon.
- Replace pure FIFO/preemptive rules with a **priority-weighted aging queue**: Express orders receive high priority but can only preempt a standard order if the standard order has not already waited longer than a dynamic threshold (e.g., > 15 min). Additionally, reserve 1 cold station via predictive scheduling if an express cold order is forecasted to arrive within 10 minutes.
- Physically assign orders to stations remotely to minimize idle time.

**Leveraging Data:** Analyze historical peaks (peak-season logs) to predict when express cold orders cluster. Use the resource log (C1–C5) to identify which stations have highest contention and rotate assignments dynamically.

**Expected Outcomes:** 
- Reduced average queue length at cold stations.
- Controlled inter-instance delay for standard orders (starvation is prevented).
- Faster express fulfillment *without* the cascading batch delay, because standard cold orders are not arbitrarily interrupted.

### Strategy 2: Dynamic Hybrid Batching with Decoupled Shipping Label Generation
*Constraints Addressed:* Shipping Batch Delays (+ interaction with upstream cold/regulatory delays).

**Specific Changes:**
- **Redesign the batch trigger:** Replace static “wait for full batch” with a **hybrid time/size trigger** per region: a batch releases to the label stage when either (a) target size is reached (e.g., 4 orders for high-volume regions like North), or (b) a maximum wait time is exceeded (e.g., 20 minutes), preventing indefinite blocking.
- **Decouple label generation from batch synchronization:** Generate shipping labels asynchronously using pre-validated address/route data immediately upon `Quality Check COMPLETE`. Hold orders in a **route-staging buffer** physically near dispatch, grouped by region. The “batch” now becomes a logical grouping for route optimization (truck loading) rather than a synchronous process bottleneck at `Shipping Label Gen.`

**Leveraging Data:** Use historical inter-arrival times per `Destination Region` from the event log to calibrate regional triggers (e.g., West has low volume, so trigger at 2 orders / 15 min).

**Expected Outcomes:** 
- Orders spend near-zero time at `Shipping Label Gen.` because labels are ready; they only wait in a brief dispatch staging window.
- Upstream delays (cold-packing, hazardous limits) no longer cascade into batch formation failure because the critical path is decoupled.

### Strategy 3: Regulatory-Compliant Concurrent Capacity Management with Staggered Release Scheduling
*Constraints Addressed:* Hazardous Material Limits (+ interactions with Express and Cold-Packing).

**Specific Changes:**
- Implement a **global token/semaphore** for hazardous orders across both `Packing` and `Quality Check`. Before a hazardous order can start either activity, it must acquire a token; if the concurrent count is 10, it waits in a **pre-regulatory buffer** (before the activity, not inside it, to keep workspaces clear).
- **Staggered scheduling:** Learn from process mining interval analysis that hazardous orders often arrive in clusters (e.g., after a supplier delivery window). Introduce a dynamic **release throttle**: once 8 concurrent hazardous orders are in process, delay new releases into Packing/QC by 3–5 minutes to smooth the peak, preventing a “thundering herd” that blocks the entire facility.
- **Cross-constraint integration:** The scheduling engine must check both the token count (hazardous limit) *and* station availability (cold station) *and* express status before assigning a resource, preventing partial starts.

**Leveraging Data:** Build concurrency time-series from the 3-month log to identify high-risk hours. Use average duration in Packing/QC for hazardous orders to estimate token release rates.

**Expected Outcomes:** 
- Zero regulatory violations; reduced average regulatory queue time.
- Smoother flow through the constrained activities, preventing a scenario where 10 hazardous orders block all downstream batch formation.

## 4. Simulation and Validation

Before implementation, use **Discrete Event Simulation (DES)** (e.g., SimPy, AnyLogic, or Simio) parameterized directly by your process mining results.

### Building the Baseline & Strategy Models

**Model Inputs from Process Mining:**
- **Activity durations:** Fit distributions (exponential, gamma, or empirical) per `Activity`, `Resource`, and `Order Type` using the event log.
- **Arrival process:** Model case arrival rates with seasonal/peak patterns discovered in the log.
- **Resource logic:** Model exactly 5 cold stations, standard stations, staff counts for Picking/Quality Check, and the batch-assembly logic at `Shipping Label Gen.`
- **Priority rules:** Model express orders as having high priority with preemption logic at shared resources.
- **Regulatory constraint:** Implement a global semaphore (capacity = 10) shared across the `Packing` and `Quality Check` activity servers specifically for `Hazardous = TRUE` instances.

### Critical Simulation Focus Areas

To accurately capture instance-spanning dynamics, your simulation must include:

1. **Resource Contention with Preemption:** The cold-station model must allow an express order to seize a station from a standard order (with a finish/resume mechanism), and you must track the resulting delay injected into the standard order’s timeline.

2. **Batch Formation Module:** Do not model `Shipping Label Gen.` as a simple server. Build an **assembly queue** by `Destination Region`. Orders enter the module upon `Quality Check COMPLETE`. The module releases orders only when the batch rule (time/size) is met, explicitly recording the synchronization delay.

3. **Regulatory Semaphore:** Model the 10-token limit as a shared resource pool accessible to both `Packing` and `Quality Check`. Hazardous orders must seize one token to enter either activity. This will reveal whether your current “first-come, first-served” release pattern creates artificial peaks.

4. **Cross-Constraint Scheduling:** In your strategy scenarios, implement a master scheduling logic that queries *both* the cold-station queue state and the hazardous-token state before assigning a case to a resource.

**Validation Approach:**
- **Baseline Simulation:** Run with current rules (FIFO/preemptive, fixed batch windows, no token management) and calibrate so that average cycle times and resource utilization match your log.
- **Scenario Comparison:** Run Strategy 1 (predictive cold scheduling), Strategy 2 (hybrid batching), and Strategy 3 (token management). Measure:
  - End-to-end cycle time (mean / 95th percentile).
  - Average wait at cold stations / batch stage / regulatory queue.
  - Throughput (orders/day) and resource utilization (preventing over-utilization that causes starvation).
- **Sensitivity:** Test under peak-season arrival rates to ensure your dynamic rules remain robust.

## 5. Monitoring Post-Implementation

To continuously manage these inter-order dependencies, establish **constraint-specific process mining dashboards** alongside standard KPIs.

### Key Metrics & Dashboards

**Dashboard 1: Cold-Packing & Priority Impact**
- Real-time queue length per station (C1–C5).
- Average waiting time for `Requires Cold Packing = TRUE` orders entering `Packing`.
- Preemption events/hour: number of times an express order interrupted a standard order at shared resources.
- **Starvation Alert:** If average wait for standard cold orders exceeds a threshold, trigger predictive reserve logic.

**Dashboard 2: Batching & Regional Flow**
- Average `Shipping Label Gen.` synchronization delay by `Destination Region`.
- Batch formation time (first member ready to batch release).
- Percentage of orders meeting delivery windows vs. delayed specifically at labeling/dispatch.

**Dashboard 3: Hazardous Compliance & Flow**
- **Real-time concurrent count:** A live “semaphore” display of hazardous orders currently in `Packing` + `Quality Check` (must stay  10).
- Regulatory queue length (orders waiting for a token before entering Packing/QC).
- Average duration of regulatory wait versus total hazardous order flow time; target: reduce ratio.

**Dashboard 4: Overall Process Mining & Conformance**
- **Process Discovery (DFG):** Updated continuously to detect if new bottleneck variants emerge.
- **Conformance Checking:** Monitor adherence to new scheduling rules (e.g., preemption limits, batch triggers, token acquisitions).

### Tracking Constraint Management Effectiveness

| Constraint | Health Metric | Tracking Method |
|---|---|---|
| **Cold-Packing** | Queue length / station; standard order delay due to preemption | Compare actual start times to predicted start times in digital queue |
| **Batching** | Batch synchronization time; % batches formed within window | Correlate `Quality Check COMPLETE` with `Shipping Label Gen. START` by region |
| **Priority** | Average extension of standard intervals when express present | Resource-level interval overlap analysis; compare to historical baseline |
| **Hazardous** | Regulatory queue time; concurrent count trends; zero violations | Token-semaphore log; interval count analysis at 15-minute windows |

**Continuous Improvement Loop:** Use weekly process mining analyses (e.g., variant analysis, bottleneck detection) to adjust the predictive scheduling thresholds (Strategy 1), batch triggers (Strategy 2), and throttle levels (Strategy 3). The goal is to maintain a state where instance-spanning constraints are not eliminated (they are structural) but are **smoother**, **predictable**, and **non-blocking** to the overall fulfillment flow.
