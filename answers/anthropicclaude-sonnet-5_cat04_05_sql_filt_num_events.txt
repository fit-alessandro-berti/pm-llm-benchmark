Here's a DuckDB SQL query that accomplishes this task:

```sql
SELECT *
FROM event_log
WHERE case_id IN (
    SELECT case_id
    FROM event_log
    GROUP BY case_id
    HAVING COUNT(*) <= 6
);
```

### How it works:

1. **Subquery (inner query):**
   - Groups all events by `case_id`.
   - Uses `COUNT(*)` to determine the number of events in each case.
   - Filters (`HAVING COUNT(*) <= 6`) to keep only those `case_id`s whose total event count is six or fewer.

2. **Outer query:**
   - Selects all columns (`*`) from `event_log`.
   - Filters rows to include only those whose `case_id` appears in the list of qualifying case IDs produced by the subquery.

### Alternative using a window function (often more efficient in DuckDB):

```sql
SELECT *
FROM (
    SELECT *,
           COUNT(*) OVER (PARTITION BY case_id) AS event_count
    FROM event_log
)
WHERE event_count <= 6;
```

### How this alternative works:

1. **Window function (`COUNT(*) OVER (PARTITION BY case_id)`):**
   - Computes the number of events per `case_id` without collapsing rows (unlike `GROUP BY`), so each event still has its own row along with the count of events in its case.

2. **Outer filter:**
   - Keeps only rows where the case-level event count (`event_count`) is six or fewer.

3. Note: If you don't want the additional `event_count` column in the final result, you can explicitly list the desired columns instead of using `SELECT *` in the outer query, e.g.:

```sql
SELECT case_id, activity, timestamp
FROM (
    SELECT case_id, activity, timestamp,
           COUNT(*) OVER (PARTITION BY case_id) AS event_count
    FROM event_log
)
WHERE event_count <= 6;
```

Both approaches correctly filter out cases with more than six events while preserving all events belonging to cases with six or fewer events. The window function approach can be more performant on larger datasets since it avoids a separate subquery scan, but both are valid and idiomatic DuckDB SQL solutions.
