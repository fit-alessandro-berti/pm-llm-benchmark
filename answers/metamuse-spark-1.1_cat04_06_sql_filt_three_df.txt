In DuckDB you can solve this with `LEAD()` to check direct succession and a date difference for the timing.

The cases to exclude are those where *at least one* occurrence of the triple exists with `Confirm - Create > 5 days`.

```sql
-- 1. Find the case_ids to exclude
WITH ordered_log AS (
  SELECT
    case_id,
    activity,
    timestamp,
    LEAD(activity, 1)  OVER (PARTITION BY case_id ORDER BY timestamp) AS next1_activity,
    LEAD(activity, 2)  OVER (PARTITION BY case_id ORDER BY timestamp) AS next2_activity,
    LEAD(timestamp, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS next1_ts,
    LEAD(timestamp, 2) OVER (PARTITION BY case_id ORDER BY timestamp) AS next2_ts
  FROM event_log
),
bad_cases AS (
  SELECT DISTINCT case_id
  FROM ordered_log
  WHERE activity = 'Approve Purchase Requisition'
    AND next1_activity = 'Create Order'
    AND next2_activity = 'Confirm Order'
    -- time elapsed between Create and Confirm > 5 days
    AND next2_ts - next1_ts > INTERVAL '5 days'
)
-- 2. Return all events whose case_id is NOT in that set
SELECT e.*
FROM event_log e
WHERE e.case_id NOT IN (SELECT case_id FROM bad_cases)
-- null-safe alternative:
-- WHERE NOT EXISTS (SELECT 1 FROM bad_cases b WHERE b.case_id = e.case_id)
ORDER BY e.case_id, e.timestamp;
```

Explanation:

* `PARTITION BY case_id ORDER BY timestamp` enforces per-case ordering, so `LEAD(...,1)` and `LEAD(...,2)` are the direct successors.
* The condition `activity = 'Approve Purchase Requisition' AND next1_activity = 'Create Order' AND next2_activity = 'Confirm Order'` enforces direct succession with no other event in between.
* `next2_ts - next1_ts > INTERVAL '5 days'` enforces the >5 days rule on that specific occurrence.
* `DISTINCT case_id` means if *any* occurrence in a case matches both conditions, the whole case is excluded.
* Final `NOT IN / NOT EXISTS` returns all events from the remaining cases.
