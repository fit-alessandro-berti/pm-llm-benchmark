**Event Log for Process Mining**

**Assumptions and notes:**
- Case ID = `order_id` for the full order-to-cash process instance.
- One event per meaningful activity instance (separate Item Picked events per order line; separate Dispatched/Arrived per delivery; separate Invoice Issued and Payment Received per invoice/payment).
- Activity names are derived logically from the source tables and typical order lifecycle.
- Resource = the primary actor/system entity ID responsible (sales person, picker, carrier, billing person). Resource names are enriched from the Resources table where available.
- Timestamps are used as-is (ISO 8601). Chronological order is preserved within each case.
- Order 1004 has only creation + picking (no delivery/invoice/payment records); it is included as an incomplete case.
- Payments are linked via `invoice_id` → `order_id`.
- Additional attributes (item, quantity, delivery_id, carrier, invoice details, payment method/reference, customer info, priority, notes) are retained where relevant and left blank otherwise.
- Products table descriptions/categories are available for enrichment but omitted from the event log for brevity (can be joined later if needed).
