Based on consolidation of the 5 interviews, below is a visualizable BPMN-like textual model for the **Invoice Approval Process**.

### 1. Participants / Lanes
One Pool: **Company Internal Process**, with Lanes:
* **L1: Accounts Payable Clerk** - Mary
* **L2: Purchasing Officer** - Dan
* **L3: Department Manager** - Carlos
* **L4: Accounts Payable Supervisor** - Rita - Exception Handler
* **L5: Supplier Relationship Manager** - Karen - Exception Support
* **System:** Accounting System - automated tasks
* **External Pool:** Supplier - black box

### 2. Artifacts / Data Objects
* **D1: Incoming Invoice** - via Email
* **D2: Purchase Order [PO]** - Reference data
* **D3: Invoice Record** - in Accounting System
* **D4: Goods Receipt Confirmation**
* **D5: Contract / Supplier Terms**
* **D6: Approval Notification / Request**

### 3. Process Model - Activities and Flow

**START EVENT:** E1 - Invoice Received by Accounts Payable Clerk [D1]

**Task T1 - L1:** Check for valid Purchase Order number on invoice

**Gateway G1 - Exclusive [L1]:** PO present and valid?
* **Condition G1-NO:** PO missing / invalid
* **Condition G1-YES:** PO present

**Sequence for G1-NO:**
* **Task T2 - L1 + L5:** Request missing PO / corrected invoice from Supplier.
    * Mary: "send it back to supplier requesting more details"
    * Dan: "tell Mary she needs to get that information"
    * Karen involvement: contacts Supplier to provide PO or send revised invoice.
* **Intermediate Throw Message Event:** Send request to Supplier
* **End Event E2a:** Awaiting Revised Invoice. *Process loops back to E1 when new invoice arrives. [Uncertainty Note U1]*

**Sequence for G1-YES - Main Flow:**

* **Task T3 - L1 / System:** Log Invoice into Accounting System. Creates D3.
* **Task T4 - L1:** Forward Invoice to Purchasing Dept for Goods Receipt & PO verification. *System email.*

* **Task T5 - L2:** Verify Invoice Details vs. PO & Goods Receipt.
    Input: D1, D2
    Actions: Compare quantities, prices, delivery charges. Confirm goods/services actually received.

**Gateway G2 - Exclusive [L2]:** Does invoice match PO and receipt? Confirmation possible?

* **G2-NO - Discrepancy Found:**
    * **Task T6 - L2 + L1 + L5:** Clarify discrepancy.
        * Option A: Purchasing contacts Supplier directly
        * Option B: Purchasing asks AP Clerk to hold invoice until corrected version
        * Option C: Involve Supplier Relationship Manager - Karen checks Contract D5 for correct price and advises AP/Purchasing
    * **Gateway G3 - Exclusive [L1/L2]:** Can discrepancy be resolved quickly?
        * G3-YES: Supplier sends corrected invoice -> Loops back to T5
        * G3-NO: **Task T7 - L1 -> L4:** Escalate to Accounts Payable Supervisor. *Trigger for Exception Sub-process.*

* **G2-YES - Match Confirmed:**
    * **Task T8 - L2:** Send Confirmation Email back to Accounts Payable. Creates D4.

* **Task T9 - L1 / System:** System-level Match of Invoice line items against PO.
    * *Note: Mary describes this after confirmation, Dan describes it as part of T5. Consolidated as sequential check by AP Clerk after purchasing confirmation.*
    Input: D3, D2, D4

**Gateway G4 - Exclusive [L1]:** System match successful?

* **G4-NO:**
    * **Task T10 - L1 -> L2:** Email Purchasing team to clarify
    * Loops to G3 - If not resolvable -> T7 Escalation

* **G4-YES:**
    * **Task T11 - System:** Automatic - Send approval request email to Department Manager with D1, D2, D4. Creates D6.

* **Task T12 - L3:** Manager Review and Approve/Reject.
    Input: D6
    Actions: Review invoice details, PO, confirmation for budget alignment, suspicious amounts, unexpected items.

**Gateway G5 - Exclusive [L3]:** Manager Decision?

* **G5-REJECT/HOLD:** 
    * **Task T13 - L3 -> L1:** Reject or Request Hold for further investigation.
    * Leads to T7 Escalation. Frequency: approx. 1x every 2 months.

* **G5-APPROVE:**
    * **Task T14 - L3 / System:** Approve in Accounting System.

* **Task T15 - L1:** Schedule Invoice for Payment in next payment cycle/run.

**END EVENT E3:** Invoice Scheduled for Payment - Happy Path End.

### 4. Exception Sub-Process - Handled by Supervisor

Triggered by T7.

**Lane L4 - Rita:**

* **Task E1 - L4:** Triage escalated/problematic invoice - contact supplier, coordinate between depts.

**Gateway G6 - Exclusive [L4]:** Invoice type?

* **G6-A:** Standard invoice with resolvable issue - resolve via supplier/departments
* **G6-B:** No PO because informal/service contract - special case mentioned by Rita

**For G6-B:**
* **Task E2 - L4 + L3:** Work with department heads to decide outcome.
    * **Gateway G7 - Exclusive:** Decision?
        * Create Retrospective PO -> loop back to Main Flow to T4
        * Reject Invoice -> **End Event E4:** Invoice Rejected

**For G6-A after resolution:**
* Return flow to main process: Return to T5 or T9 for re-verification. Then continue to T11-T15.

**Role of Lane L5 - Karen:** Does not execute system approvals. Acts as intermediate message handler in T2 and T6 to expedite supplier communication.

### 5. Consolidated Sequence Flow Summary - Happy Path

`E1 -> T1 -> G1[YES] -> T3 -> T4 -> T5 -> G2[YES] -> T8 -> T9 -> G4[YES] -> T11 -> T12 -> G5[APPROVE] -> T14 -> T15 -> E3`

### 6. Uncertainty and Conflicting Accounts - To be validated

> **U1 - PO Missing Loop:** It is unclear if process terminates and restarts as new instance when revised invoice is requested, or if original invoice is kept in "Hold" status in system. Model assumes wait-loop with new start event linking to old case.

> **U2 - Order of Matching:** Mary describes two matching stages: Purchasing confirms receipt [T5], then AP matches line items [T9]. Dan describes his check as the matching itself. Model preserves both as sequential checks but they may be a single joint verification task.

> **U3 - Who contacts Supplier on discrepancy:** Mary says AP emails purchasing to clarify. Dan says Purchasing contacts supplier directly OR asks AP to hold. Karen says she is looped in to contact supplier. Model consolidates this as collaborative Task T6 with three possible actors.

> **U4 - Approval Trigger:** Mary states approval is triggered after *both* receipt confirmation AND PO match. Model implements this via G2 + G4 being passed before T11.

This description can be directly converted to BPMN with: Start -> Exclusive Gateway -> Tasks per lane -> Intermediate Message Throw to Supplier Pool -> Exclusive Gateways for discrepancy, manager decision, and escalation -> End Events.
