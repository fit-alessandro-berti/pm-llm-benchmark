**This is a process map (process mining visualization) of an order-to-cash / procure-to-pay style workflow.** It shows how different business document/item types flow through shared process steps, along with case volumes (“Overall”) and average transition times (in ms).

### Source item types (top and left)
These are the case/object types entering the process, with their total volumes:

| Item type              | Volume   | Color coding |
|------------------------|----------|--------------|
| PurchaseRequisitionItem | 2.0M    | Purple      |
| SalesOrderItem         | 3.5M    | Blue / Orange |
| PurchaseOrderItem      | 5.0M    | Blue / Orange |
| VendorInvoiceItem      | 1.2M    | Green       |
| ReturnOrderItem        | 0.8M    | Red         |

Colored dots on activity boxes indicate which source types pass through that step.

### Main process steps and volumes
Activities are shared across item types. Key nodes and their overall case counts:

- **Create Requisition** — 3.0M (mainly from PurchaseRequisitionItem)
- **Create Order** — 8.5M (mainly from SalesOrderItem + PurchaseOrderItem)
- **Approve Requisition** — 5.7M (central hub; receives flows from multiple sources)
- **Send Order** — 5.2M
- **Check Stock** — 1.0M
- **Process Return** — 0.8M
- **Pack Goods** — 2.0M
- **Ship Goods** — 1.8M
- **Confirm Delivery** — 1.7M
- **Approve Payment** — 1.5M
- **Create Invoice** — 2.0M
- **Close Order** — 1.7M

### Typical flows (high-level)
- **Requisition path (purple)**: Start → Create Requisition → Approve Requisition → (Send Order / Check Stock / Process Return) → further downstream steps or End.
- **Sales / Purchase Order path (blue/orange)**: Start → Create Order → Pack Goods → Ship Goods → Confirm Delivery → Close Order (or branches into Approve Payment / Create Invoice).
- **Invoice / Return paths (green/red)**: Enter via Approve Requisition or Process Return and feed into Create Invoice, Approve Payment, or Close Order.
- Multiple cross-links exist (e.g., from Approve Requisition into packing/shipping, from Check Stock / Process Return into payment/invoice creation). Several “Start” and “End” nodes exist because different item types have independent entry and exit points.

### Performance annotations
Arrows are labeled with average durations (e.g., 300 ms, 450 ms, 650 ms, 10 ms). These represent mean waiting/processing time between consecutive activities for the cases that take that path. Very short times (10–100 ms) usually indicate nearly instantaneous hand-offs; longer ones (400–800 ms) indicate more significant delays or processing.

In short, the diagram is a frequency- and performance-annotated process map that reveals:
- how five different document types converge on a common set of activities,
- the relative volume of each step,
- the main process variants, and
- where time is spent between steps.
