## Explanation of Logic

**Case Identification:**
Each case corresponds to a distinct document or task-object the user is working on (`Document1.docx`, `Quarterly_Report.docx`, the Annual Meeting email thread, `Report_Draft.pdf`, `Budget_2024.xlsx`). This follows the "document-centric" case notion common in office-work process mining, since the window title reliably identifies the object of work. Even though the user interleaves tasks (multitasking), events are reattached to their correct case based on the window/document identified in each log line — this reflects how the same case (e.g., CASE-001) can have activity gaps and be resumed later (as seen at 09:06:00 when the user returns to `Document1.docx` after working in Excel).

**Activity Standardization:**
Raw actions were mapped to higher-level, tool-agnostic process steps:
- `FOCUS` (first occurrence for a case)  **Open Document/Spreadsheet**
- `FOCUS` (later occurrence, same case)  **Resume Editing**
- `TYPING`  **Edit Content** (or **Edit Spreadsheet** / **Compose Reply** depending on context)
- `SAVE`  **Save Document/Spreadsheet**
- `CLOSE`  **Close Document**
- `SCROLL`  **Review Content**
- `HIGHLIGHT`  **Annotate PDF**
- `CLICK` (email actions)  **Open Email Message**, **Reply to Email**, **Send Email**
- `SWITCH`  repurposed as the **opening/resuming activity** for the destination case, since it marks the start of a new work context in that case rather than being a standalone meaningless navigation event.

**Narrative:**
The resulting log tells a coherent multitasking story: the user starts drafting the Quarterly Report, pivots to a new Document1 draft, handles an email reply, briefly reviews a PDF report, updates a budget spreadsheet, returns to finish edits in Document1 (referencing the budget), then finally returns to and completes the Quarterly Report — illustrating realistic context-switching behavior in a knowledge-work environment.
