**Assumptions made:**
- Case ID = `order_id`.
- Separate “Item Picked” event created for every row in Order Lines (different timestamps/resources).

- “Invoice Issued” for every invoice; “Payment Received” for every payment (linked to the order via the invoice).
- Resource names resolved via the Resources table (shown as “Name (Role)” where possible). Payments have no resource, so left blank.
- Extra attributes stored as a compact key-value string for readability while preserving all useful data (customer, item description/category from Products, amounts, notes, IDs, etc.).
- Events sorted first by Case ID, then by Timestamp (preserving real process order). Incomplete cases (e.g., 1004) are kept as-is.
