## Overview

This is a **BPMN 2.0 collaboration diagram** (a business process model) showing an **ordertodelivery / order fulfilment process** distributed across four organisational units. Each unit is drawn as a horizontal pool/lane, stacked vertically:

1. **Sales**
2. **Production**
3. **Procurement**
4. **Warehouse**

Solid arrows inside each lane are **sequence flows**; the long **dashed arrows** running vertically between lanes are **message flows** (labelled "Order details", "Product complete", "Product sent", "Material not faulty", etc.).

---

## Sales lane (top)

- Starts with a **timer start event** labelled **"Monday morning"**.
- Leads into an **expanded subprocess "Check customer's order"**, which contains:
  - a start event  task **"Check order for completeness"**  task **"Check if customer is already in the database"**
  - an **exclusive (XOR) gateway** that splits into two labelled branches:
    - *"Customer not in the database"*  task **"Add customer to the database"**, which is linked by a dotted **data association** to a **data store "database"**
    - *"Customer in the database"*  straight to the merge
  - both branches rejoin at a second XOR gateway  end event.
- After the subprocess: task **"Send order details"**. Two message flows leave this task downward, feeding Production and Procurement.
- Then an **intermediate message catch event "Product sent"** (receives the message from the Warehouse)  task **"Draft invoice"**  **end event**.

---

## Production lane

- **Message start event "Order details arrive"** (triggered by Sales).
- A **parallel (AND) gateway** splits the flow:
  - one branch  task **"Plan production"**
  - the other branch  **intermediate message catch event "Material not faulty"** (message from Procurement)
- Both branches synchronise at a second **AND gateway**  task **"Manufacture product"**  **message end event "Product complete"**, which sends a message down to the Warehouse.

---

## Procurement lane

- **Message start event "Order details arrive"**.
- An expanded subprocess **"Material Compensation Subprocess"** (drawn with a doubled/rounded border) containing:
  - start event  task **"Order materials"** with a **compensation boundary event** attached, connected by a dotted line to the **compensation activity "Return material"** (marked with the rewind/compensation symbol)  end event.
- Afterwards, task **"Check materials"** with a **boundary event** attached (error/escalation type). Its outputs:
  - a **message throw event** sending *"Material not faulty"* up to Production
  - a **compensation throw event "Order cancelation"**  end event (this triggers the "Return material" compensation).

---

## Warehouse lane (bottom)

- **Message start event "Product complete"** (from Production)  task **"Send product"**  **message end event "Product sent"**, whose message flow travels back up to the Sales lane so the invoice can be drafted.

---

## Process logic in words

Every Monday morning Sales validates the incoming order and registers the customer if necessary, then forwards the order details simultaneously to Production and Procurement. Procurement orders the required materials and inspects them; if they are fine it notifies Production, otherwise the order is cancelled and the material purchase is compensated (materials returned). Production plans and, once the material confirmation arrives, manufactures the product. The Warehouse then ships it and confirms dispatch to Sales, which finally drafts the invoice.
