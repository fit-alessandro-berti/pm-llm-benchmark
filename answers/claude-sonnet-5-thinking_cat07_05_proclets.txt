# Visualization Description

This image illustrates a **proclet-based process modeling notation** (used in process choreography/interaction modeling), showing how two related process fragments ("proclets") communicate. It contains three parts:

## (a) Two Proclet Classes Connected Through Two Channels
This is the main diagram showing two parallel workflows:

- **Lab visit** (left): A process flow involving a doctor and lab assistant, including steps like *Order entry*, *Take blood sample*, *Judge results*, *Do tests again*, and *Send report*. It uses gateways (circles) and decision points.
- **Lab test** (right): A parallel process flow performed by chemical analysts, including *Perform test*, *Make report*, *Perform test again*, *Provide updated report*, and *Finish lab test*.

These two proclets are connected via **two channels** (shown as dashed boxes):
- **Order system** channel (top) — carries messages like "Receive result"
- **HIS** (Hospital Information System) channel (middle) — carries messages like "Receive updated result"

Cardinality labels (e.g., *1,1*, ***,1*, *1,?*) indicate the multiplicity of message exchanges between the two proclets at each interaction point. Gray-shaded boxes represent **communication/receive actions**, while white boxes represent internal **process activities**.

A simplified UML-style class diagram summarizing the relationship between the two proclet classes:

This shows the cardinality constraint: one lab visit requires one or more lab tests.
