## 1. Identifying Instance-Spanning Constraints and Their Impact

Traditional case-centric process mining treats each order as an independent case. That is insufficient here because important delays are caused by relationships across orders: competing for the same station, waiting for a shipping cohort, being displaced by express work, or being blocked by a facility-wide hazardous-material limit.

The analysis should therefore combine case-level process mining with resource-, batch-, and facility-state analysis. An object-centric event log or an enriched event log is particularly suitable: events should be linked not only to an order but also to resources, station types, shipping batches, destination regions, and facility-wide regulatory capacity states.

### 1.1 Prepare and enrich the event log

Before analysis, reconstruct activity intervals and relevant system states.

For each order, derive:

- `Activity start`, `activity completion`, and `service duration`.
- `Ready time`: when the preceding activity completed and the order became eligible for the next activity.
- `Queue/waiting time`: time from eligibility to actual start.
- `End-to-end lead time`: Order Received to Shipping Label Generation completion.
- Order class: Standard versus Express.
- Required resource type: standard packing versus cold-packing.
- Hazardous-material status.
- Destination region and shipping batch identifier.
- SLA/deadline, if available.

For shared constraints, construct time-varying state histories:

- Number of occupied cold-packing stations over time.
- Number of orders waiting for cold-packing.
- Number of hazardous orders active in Packing or Quality Check.
- Batch membership and batch release time.
- Resource assignment, interruptions, and reassignment events.
- Queue composition by Express/Standard, cold/non-cold, hazardous/non-hazardous, and destination.

Data-quality checks are important. For example:

- Ensure START and COMPLETE events are paired correctly.
- Detect missing lifecycle events.
- Standardize time zones and clock sources.
- Verify whether “preemption” is actually captured as a pause/resume event, reassignment event, or only inferred from gaps.
- Confirm which stations are genuinely cold-capable and whether a cold order can ever be processed at a standard station.

### 1.2 Shared Cold-Packing Stations

#### Formal representation

Let \( C(t) \) be the number of cold-packing stations occupied at time \(t\). The capacity constraint is:

\[
C(t) \leq 5
\]

For each order requiring cold packing, calculate:

\[
\text{Cold-packing queue time} =
\text{Packing Start} - \text{Ready for Packing}
\]

An order is “ready for packing” when Item Picking is complete and any prerequisite internal checks are completed.

A likely cold-resource contention delay occurs when:

1. A cold-required order is ready for packing;
2. No cold station is available;
3. One or more other cold-required orders are occupying the five cold stations.

#### Process mining analyses

Useful techniques include:

- Resource-centric process mining to visualize station utilization and workload.
- Queue and work-in-progress analysis by station type.
- Bottleneck analysis segmented by cold-packing requirement.
- Performance spectrum charts showing start and completion timing for cold-packing orders.
- Time-series analysis of cold-station occupancy and queue length.
- Process comparison between cold and non-cold orders, controlling for order type and order complexity.

#### Key metrics

- Mean, median, P90, and P95 waiting time before cold packing.
- Percentage of cold orders waiting more than a threshold, such as 10 or 20 minutes.
- Cold-packing station utilization:
  \[
  \frac{\text{Busy time of cold stations}}{\text{Available cold-station time}}
  \]
- Queue length distribution for cold packing.
- Maximum and average concurrent cold orders.
- Fraction of time all five cold stations are occupied.
- Missed delivery SLA rate for cold orders versus non-cold orders.
- Throughput of cold orders per hour/shift.
- Queue composition: Express cold orders versus Standard cold orders.

High utilization alone does not prove a bottleneck. However, sustained utilization near 100%, accompanied by growing queues and long readiness-to-start times, is strong evidence that the capacity constraint is causing delay.

### 1.3 Shipping Batch Dependencies

#### Formal representation

Shipping Label Generation is not immediately triggered by completion of Quality Check. Instead, an order may wait until a batch for the same destination region is formed or released.

For each order:

\[
\text{Batch waiting time} =
\text{Shipping Label Generation Complete} -
\text{Ready for Shipping Label Generation}
\]

If labels are generated as a batch, a more precise measure is:

\[
\text{Batch formation wait} =
\text{Batch Release Time} -
\text{Order QC Completion Time}
\]

The analysis requires a reliable batch identifier, such as `Batch B1`, or a reconstructed batch relationship based on region, label-generation timestamp, shipping route, and system release event.

#### Process mining analyses

- Discover the normal order flow and measure the delay between Quality Check completion and Shipping Label Generation.
- Group orders by destination region and batch ID.
- Analyze batch size, batch formation time, batch release frequency, and batch composition.
- Compare waiting times across regions, shifts, weekdays, peak periods, and shipment types.
- Use event correlation to identify cases that wait for the same batch event.
- Build an interaction graph in which orders are linked when they belong to the same shipping batch.

#### Key metrics

- Average and percentile waiting time from QC completion to label generation.
- Batch formation time:
  \[
  \text{Batch release time} - \text{first eligible order time}
  \]
- Waiting time of the first, median, and last order entering a batch.
- Batch size distribution by destination region.
- Number of batches per hour/day/shift.
- Percentage of orders held longer than a maximum allowed batch-wait threshold.
- On-time shipping performance by batch and region.
- Number of partially filled or underfilled batches.
- Cost/service trade-off: transportation efficiency gained versus customer lead-time added.
- Express orders delayed by batch rules.

A common problem is that a fixed “wait until batch is full” policy optimizes transportation utilization but worsens end-to-end delivery performance, especially for low-volume regions and for express orders.

### 1.4 Priority Handling for Express Orders

#### Formal representation

Express priority creates dependencies because an express order may receive a resource before a standard order that was already waiting or may interrupt a standard order currently in service.

There are two possible operating policies:

1. **Non-preemptive priority:** express orders move ahead of standard orders waiting in the queue, but do not interrupt work already in progress.
2. **Preemptive priority:** express orders can interrupt standard work in progress, requiring the standard order to pause, resume later, or restart.

The event log should determine which occurs in practice. Useful evidence includes:

- A standard order’s Packing START event followed by a pause, resource reassignment, or delayed COMPLETE event.
- An express order starting on the same station immediately after the standard order is paused.
- A standard order resuming after the express order completes.
- Resource-level temporal overlap or work interruption patterns.

#### Key metrics

For express orders:

- Express queue time before Picking, Packing, QC, and Label Generation.
- Express end-to-end lead time and SLA adherence.
- Percentage of express orders meeting promised dispatch time.
- Time saved by priority treatment compared with equivalent standard orders.

For standard orders affected by priority:

- Incremental queue time attributable to express arrivals.
- Number and duration of standard-order interruptions.
- Number of standard orders overtaken by an express order.
- Standard-order SLA breach rate during high express demand.
- Additional processing time caused by interruption, setup repetition, rework, or resource switching.
- Fairness/aging measures, such as longest waiting standard order.

A useful estimate is the “priority displacement delay”:

\[
\text{Displacement delay} =
\text{Actual wait of Standard order} -
\text{Expected wait without Express interference}
\]

The expected wait can be estimated using comparable periods with low express volume, regression models, queueing models, or simulation-based counterfactuals.

### 1.5 Hazardous-Material Capacity Limit

#### Formal representation

The regulatory rule is facility-wide:

\[
H_{Packing}(t) + H_{QC}(t) \leq 10
\]

where:

- \(H_{Packing}(t)\) is the number of hazardous orders active in Packing at time \(t\);
- \(H_{QC}(t)\) is the number of hazardous orders active in Quality Check at time \(t\).

This must be measured from START and COMPLETE timestamps, not merely from the number of hazardous orders currently in the overall process.

For each hazardous order, identify whether it was eligible to enter Packing or QC but could not start because the hazardous-work-in-process limit had already been reached.

#### Process mining analyses

- Reconstruct the hazardous WIP state minute-by-minute or event-by-event.
- Perform conformance checking against the “maximum 10 active hazardous orders” rule.
- Identify peak hazardous demand periods and the duration spent at the capacity threshold.
- Analyze the queue before Packing and QC for hazardous orders.
- Compare hazardous and non-hazardous order flow times.
- Identify whether Packing or QC is the dominant contributor to hazardous WIP saturation.
- Examine whether hazardous orders cluster by shift, destination, product family, or inbound arrival pattern.

#### Key metrics

- Percentage of time hazardous WIP is at 10.
- Number and duration of hazardous-capacity saturation episodes.
- Hazardous-order waiting time due to capacity gating.
- Throughput of hazardous orders per hour/shift.
- Number of attempted capacity violations, if admission attempts are logged.
- Confirmed regulatory violations:
  \[
  \max_t(H_{Packing}(t)+H_{QC}(t)) > 10
  \]
- Lead time and SLA breach rate for hazardous orders.
- Non-hazardous orders delayed because shared Packing/QC capacity was effectively reserved for hazardous work.
- Estimated throughput loss attributable to the hazardous cap, obtained through simulation or queueing counterfactuals.

### 1.6 Separating Within-Instance Delays from Between-Instance Delays

A critical analytical distinction is between:

- **Within-instance delay:** delay caused by the order’s own work, such as unusually long Packing duration, rework, failed quality checks, missing inventory, or complex packaging.
- **Between-instance delay:** delay caused by other orders, shared capacity, batching policies, or facility-wide limits.

For an activity \(A\):

\[
\text{Total elapsed time from prior step to activity completion}
=
\text{Queue time} + \text{Service time}
\]

where:

\[
\text{Queue time} =
\text{Activity Start} -
\text{Previous Activity Completion}
\]

and:

\[
\text{Service time} =
\text{Activity Complete} -
\text{Activity Start}
\]

The queue time should then be attributed using the reconstructed facility state.

Examples:

| Situation when an order is ready | Likely delay attribution |
|---|---|
| Cold order is ready, all cold stations busy | Cold-resource contention |
| Order finishes QC, but labels wait for regional batch release | Batch formation delay |
| Standard order is waiting while an express order is admitted first | Priority displacement |
| Hazardous order is ready but hazardous WIP is already 10 | Regulatory capacity gate |
| Order is being processed but Packing duration is unusually long | Within-instance service-time issue |
| Order waits while no resource is occupied and no batch rule applies | Staffing, scheduling, missing data, or other local cause |

Delays can overlap. For example, a hazardous express cold order may be blocked simultaneously by cold-station scarcity and the hazardous WIP limit. Therefore, delay attribution should not simply double count time. The company should use one of the following approaches:

- A defined precedence rule, such as compliance constraint first, then resource availability, then priority.
- Multi-label attribution, showing all constraints active during the waiting period.
- Weighted attribution using simulation or causal models to estimate each constraint’s marginal contribution.
- Shapley-style attribution for shared waiting intervals where several constraints jointly explain the delay.

This approach avoids incorrectly blaming a single activity or employee for delays that were actually created by cross-order dependencies.

## 2. Analyzing Constraint Interactions

The constraints should not be optimized independently. Local optimization can worsen overall flow if it ignores interactions.

### 2.1 Express Priority and Cold-Packing Contention

An express order requiring cold packing competes for one of only five cold stations. If priority is strict, it may:

- Move ahead of standard cold orders already waiting.
- Interrupt a standard cold-packing job, if preemption is allowed.
- Increase standard-order queue time substantially during express peaks.
- Create idle downstream capacity if standard orders become unevenly delayed.
- Cause a cycle in which standard cold orders accumulate and later create a surge at Quality Check.

A strict priority rule may improve express SLA performance while degrading total throughput, workforce stability, and standard-order SLA compliance.

The analysis should therefore examine the trade-off between:

- Express on-time delivery rate.
- Standard order delay.
- Total orders shipped per hour.
- Cold-station utilization.
- Number and cost of interruptions.
- Overall customer-service performance.

### 2.2 Batching and Hazardous-Material Limits

Suppose multiple hazardous orders are destined for the same region. If the operation attempts to accelerate them to form a batch, this may create a hazardous WIP surge in Packing and QC.

Potential effects include:

- The hazardous cap of 10 becomes saturated.
- Hazardous orders may queue before Packing or QC.
- Non-hazardous orders may compete for the same general Packing/QC resources.
- A batch may still be delayed because some hazardous orders are blocked by compliance capacity.
- The first completed hazardous orders in a regional batch may wait a long time for the remaining batch members.

Thus, a regional batch policy can unintentionally amplify the effect of the hazardous capacity limit.

### 2.3 Cold-Packing and Hazardous Limits

Some orders may be both cold-required and hazardous. These are particularly constrained because they require:

- A scarce cold station.
- Admission under the hazardous WIP cap.
- Potentially priority treatment if they are express.
- Subsequent QC capacity.

If the company starts too many hazardous cold orders simply because cold capacity becomes available, it can overload hazardous QC later. Conversely, limiting hazardous admissions without coordinating cold-station allocation can leave cold stations idle while waiting for compliance capacity.

The correct decision is therefore not simply “assign the next available cold station.” It is “assign the station to the order that improves end-to-end flow while preserving downstream hazardous capacity and SLA commitments.”

### 2.4 Batching and Priority Policies

Express orders should generally not wait for a conventional regional batch to become full. However, releasing every express order individually may increase transportation cost and reduce route efficiency.

Potential alternatives include:

- Express-specific mini-batches.
- Earlier release thresholds for express orders.
- Scheduled “express release windows.”
- Shipment consolidation only if it does not risk the express SLA.
- Pre-generated labels and late route assignment.

The process mining analysis should quantify how many express orders are delayed solely by batch rules and how much delivery-cost benefit is actually obtained from holding them.

### 2.5 Why Interaction Analysis Matters

A strategy that improves one local metric may harm the end-to-end process:

- Adding cold capacity can move the bottleneck to QC or hazardous admission.
- Increasing batch size can reduce transportation cost but worsen lead time.
- Aggressive express priority can reduce express delays but create excessive standard-order aging.
- Releasing hazardous orders quickly may saturate the regulatory WIP limit and block downstream flow.

The company should therefore model the fulfillment center as a connected system of queues, resources, rules, and shared constraints rather than as a sequence of independent activities.

## 3. Constraint-Aware Optimization Strategies

The following strategies should be treated as candidate policies, tested in simulation, and implemented through controlled pilots.

### Strategy 1: Dynamic Cold-Packing Allocation and Reservation Policy

#### Primary constraints addressed

- Limited cold-packing station capacity.
- Express-priority impact on standard orders.
- Interaction between cold-packing demand and downstream QC/hazardous capacity.

#### Proposed changes

Implement a dynamic dispatching policy for the five cold-packing stations. Rather than using a simple first-in-first-out or strict express-first rule, prioritize orders based on:

- Shipping deadline slack:
  \[
  \text{Slack} = \text{Promised dispatch time} - \text{Predicted remaining processing time}
  \]
- Express versus Standard classification.
- Cold-packing requirement.
- Hazardous-material status and available hazardous capacity.
- Destination batch cutoff or expected batch release time.
- Predicted QC availability after Packing.
- Age of the order in queue, to avoid starvation.

Examples of policy controls:

- Reserve one cold station during forecasted express peaks, rather than allowing all stations to be consumed by standard work.
- Use a limited priority quota, such as reserving a maximum number of consecutive express admissions before serving the oldest at-risk standard order.
- Use non-preemptive priority where safety, product integrity, or rework makes interruption expensive.
- Allow preemption only before a defined point in Packing, such as before sealing or temperature-control preparation begins.
- Cross-train selected standard-pack staff for cold-packing tasks during peak periods, where feasible.
- Establish a temporary overflow cold-packing capability if operationally and regulatorily practical.

#### Use of data and process mining

Historical logs can be used to predict:

- Cold-order arrivals by hour, day, season, and promotion period.
- Express cold-order demand patterns.
- Average service time by order type and product profile.
- Probability that an order will miss its shipping cutoff if delayed.
- Downstream QC congestion for cold and hazardous work.

A machine-learning or statistical model can estimate remaining processing time and SLA risk, while a rules-based dispatcher uses those predictions.

#### Expected outcomes

- Reduced queue time for cold orders.
- Better express-SLA adherence without excessive degradation of standard orders.
- Lower P90/P95 cold-packing waiting time.
- Reduced unnecessary work interruption and rework.
- More stable cold-station utilization.
- Improved end-to-end flow because decisions consider downstream QC and hazardous capacity.

---

### Strategy 2: Adaptive Shipping Batching with SLA-Based Release Triggers

#### Primary constraints addressed

- Delays caused by regional shipping batch formation.
- Express orders waiting for batches.
- Interaction between batching and hazardous-material flow.

#### Proposed changes

Replace a fixed “wait until the batch reaches a target size” rule with adaptive batching rules.

Possible release triggers include:

1. **Maximum waiting-time trigger**  
   Release a batch when the oldest eligible order has waited longer than a defined threshold.

2. **SLA-risk trigger**  
   Release the batch when any order in it is predicted to miss its dispatch or delivery commitment if held longer.

3. **Minimum-size plus time-cap rule**  
   Release when either:
   - the batch reaches target size; or
   - a maximum hold time is reached.

4. **Dynamic regional thresholds**  
   Use different batch sizes and waiting thresholds by destination volume. High-volume regions can batch more frequently; low-volume regions should use smaller batches or shorter hold limits.

5. **Express mini-batches or direct release**  
   Allow express orders to bypass standard batch formation when their SLA risk exceeds a threshold.

6. **Pre-labeling and late consolidation**  
   Generate labels earlier, once the order passes QC, while retaining the option to consolidate route or dispatch documentation later. This partially decouples label generation from full batch completion.

7. **Hazard-aware batch coordination**  
   Avoid pushing many hazardous orders through Packing/QC merely to complete a regional batch if doing so will saturate the hazardous cap.

#### Use of data and process mining

Use historical data to estimate:

- Batch size versus waiting time by region.
- Transportation benefit of larger batches.
- Delay patterns for low-volume destinations.
- Seasonal and hourly demand patterns by region.
- Number of SLA breaches caused by batching.
- Probability that a batch will reach its target size within a defined time window.

A predictive model can estimate whether waiting an additional 10 or 20 minutes is likely to produce meaningful consolidation benefit or simply create avoidable delay.

#### Expected outcomes

- Reduced QC-to-label waiting time.
- Improved end-to-end lead time, especially for low-volume regions.
- Fewer express orders delayed by conventional batching.
- Better balance between delivery-route efficiency and customer service.
- Reduced batch-induced order aging.
- Improved transparency into the transportation-cost versus service-level trade-off.

---

### Strategy 3: Integrated Hazardous-Work Admission Control and Downstream Scheduling

#### Primary constraints addressed

- Regulatory cap of 10 concurrent hazardous orders in Packing and QC.
- Congestion in hazardous Packing/QC flow.
- Interaction with cold stations, express handling, and regional batches.

#### Proposed changes

Implement a “hazardous WIP controller” that regulates admission of hazardous orders into Packing based on both current and predicted downstream load.

Rather than admitting hazardous work whenever a Packing resource is free, the system should consider:

- Current hazardous WIP in Packing and QC.
- Expected completion time of currently active hazardous orders.
- Available QC staff and QC queue length.
- Whether the order needs cold packing.
- Whether the order is express.
- Whether the order is close to a shipping batch cutoff.
- Expected arrival of future express hazardous orders.

Specific policy options:

- Set a target hazardous WIP below the legal maximum, such as 8 or 9, to avoid operating constantly at the hard limit of 10.
- Reserve one or two hazardous capacity slots for late-arriving express hazardous orders during peak windows.
- Sequence hazardous orders to avoid downstream bunching at QC.
- Apply pull-based release: start a hazardous Packing task only when sufficient future QC capacity is available.
- Use a separate visible hazardous queue with SLA-based priority and aging.
- Coordinate hazardous and cold resource allocation for orders requiring both conditions.
- Stagger release of hazardous orders across regions rather than pushing all same-region hazardous orders through at once for a batch.

#### Use of data and process mining

The historical event log supports estimation of:

- Hazardous order arrival patterns.
- Service-time distributions in Packing and QC.
- Frequency and duration of hazardous-cap saturation.
- Downstream queue buildup caused by Packing releases.
- Whether hazardous work is disproportionately delayed at Packing or QC.
- SLA risk for hazardous orders.
- Correlation between hazardous orders, regions, cold requirements, and express classification.

#### Expected outcomes

- Continued regulatory compliance with fewer near-violation situations.
- Reduced waiting time for hazardous orders.
- Smoother flow from Packing into QC.
- Less stop-start behavior caused by repeatedly reaching the cap.
- Better ability to protect urgent hazardous orders without destabilizing the whole queue.
- Lower probability that the hazardous cap blocks completion of regional shipping batches.

---

### Strategy 4: Controlled Priority Policy with Aging and Limited Preemption

#### Primary constraints addressed

- Delays to standard orders caused by express handling.
- Resource disruption from express preemption.
- Cold-station and QC contention.

#### Proposed changes

Replace absolute “express always first” behavior with a controlled priority policy.

Recommended rules:

- Use express priority primarily at queue entry, not mid-task, unless interruption is operationally safe.
- Make Packing non-preemptive after a defined commitment point, such as sealing, labeling, temperature-control setup, or hazardous handling initiation.
- Use SLA-risk-based priority rather than order-type-only priority.
- Add an aging rule: the longer a standard order has waited, the more its effective priority increases.
- Set maximum overtaking limits, such as no standard order can be overtaken by more than a defined number of express orders without escalation.
- Reserve capacity for express demand based on forecasted arrival patterns rather than interrupting standard work reactively.
- Route express orders through shorter batch-release pathways.

#### Use of data and process mining

Analyze:

- How often express orders arrive during active standard work.
- Whether preemption creates longer total service times, rework, or quality issues.
- The service benefit of preemption compared with simple queue priority.
- Standard-order delay during high express-volume periods.
- Actual rate of express SLA failure under different priority policies.

#### Expected outcomes

- Preserved express performance.
- Lower disruption to standard orders.
- Fewer interrupted Packing tasks.
- Reduced operational instability and rework.
- Improved fairness and reduced long-tail waiting times for standard orders.
- Better overall throughput if interruptions currently create setup and restart losses.

---

### Strategy 5: Targeted Capacity and Process-Decoupling Investments

#### Primary constraints addressed

- Chronic cold-packing capacity shortages.
- QC bottlenecks, especially for hazardous work.
- Batch-induced blocking of label generation.
- Peak-season demand imbalance.

#### Proposed changes

After confirming bottlenecks through process mining and simulation, consider targeted investments:

- Add one or more cold-packing stations if utilization, queue length, and SLA loss demonstrate persistent capacity shortage.
- Add flexible temporary cold capacity for peak periods.
- Cross-train labor so staffing can shift between standard Packing, cold Packing, and QC.
- Add QC capacity during hazardous demand peaks.
- Separate “label creation” from “shipping batch dispatch authorization,” allowing labels to be created earlier.
- Introduce staging lanes for completed QC orders so that batch waiting does not occupy constrained workstations.
- Adjust shift calendars to align staffing with peak cold, express, and hazardous demand.

#### Use of data and process mining

Investment should be justified with evidence such as:

- Sustained cold-station utilization above an operational threshold.
- Recurrent high P95 cold queue times.
- Repeated hazardous-cap saturation.
- Consistent QC backlog following Packing release.
- Quantified lost throughput and SLA penalties.
- Simulation of “one additional station” or “one additional QC worker” scenarios.

#### Expected outcomes

- Higher throughput during peak periods.
- Reduced resource-related queues.
- Fewer late orders.
- Better resilience to demand spikes.
- More stable performance even when several constraints occur simultaneously.

## 4. Simulation and Validation

Before changing live operations, the company should build a discrete-event simulation model calibrated using the event log. The simulation should not be a generic linear process model; it must explicitly represent shared resources, queue policies, batch dependencies, priority rules, and regulatory constraints.

### 4.1 Simulation model design

The model should include the following entities and attributes:

#### Order entities

Each simulated order should include:

- Standard or Express type.
- Destination region.
- Cold-packing requirement.
- Hazardous-material flag.
- Arrival time.
- SLA/deadline.
- Expected process path.
- Service-time distributions by activity.

#### Resources

Model:

- Pickers and their schedules.
- Standard packing stations.
- Five cold-packing stations.
- Quality-control staff.
- Label-generation system capacity, if constrained.
- Shift schedules, breaks, absenteeism assumptions, and peak staffing.

#### Shared constraints and rules

The simulation must enforce:

- Maximum five simultaneous cold-packing assignments.
- Batch grouping by destination region.
- Batch release rules and batch size/time thresholds.
- Express priority policy, including whether priority is preemptive or non-preemptive.
- Interruption behavior: pause/resume, restart, setup loss, or rework.
- Maximum ten hazardous orders simultaneously in Packing and QC.
- Any additional physical limitations, such as staging capacity or hazardous-zone capacity.

### 4.2 Calibration from the event log

Estimate from the historical data:

- Arrival-rate distributions by hour, day, season, region, and order type.
- Activity-time distributions by product characteristics.
- Resource availability and station calendars.
- Frequency and duration of interruptions.
- Batch sizes and release frequencies.
- Probability of rework, QC failures, missing-item exceptions, or routing variants.
- Correlation between attributes, such as whether cold orders are more often express or hazardous.

Using only average values is risky. The model should represent variation, especially peak-season arrival surges and long-tail processing times.

### 4.3 Validation of the baseline model

Before testing improvements, validate the baseline simulation against historical performance.

The model should reproduce reasonably similar values for:

- Total daily/shift throughput.
- End-to-end lead time distribution.
- P50/P90/P95 waiting time for Packing and QC.
- Cold-packing queue length and utilization.
- Express and Standard SLA compliance.
- Batch waiting time by region.
- Hazardous WIP distribution and time spent at the limit.
- Number and duration of priority interruptions.

If the model cannot reproduce the observed system behavior, it should not be trusted for policy decisions.

### 4.4 Experimental scenarios

Test the baseline against alternative policies, such as:

1. Current first-in-first-out policy.
2. Strict express-first priority.
3. Non-preemptive SLA-risk priority.
4. Priority with aging and overtaking limits.
5. Dynamic cold-station reservation for express demand.
6. Adaptive batch release by time and SLA risk.
7. Increased cold-packing capacity.
8. Increased QC staffing during peaks.
9. Hazardous WIP target of 8 or 9 instead of operating at 10.
10. Combined strategies, since the best result may require coordinated changes.

Each scenario should run multiple replications using different random seeds and demand realizations.

### 4.5 KPIs to evaluate

Evaluate not just average lead time, but distributional and service-level outcomes:

- End-to-end order lead time: average, median, P90, P95.
- Total throughput per shift/day.
- Express SLA compliance.
- Standard SLA compliance.
- Cold-packing queue time and queue length.
- Batch waiting time.
- Hazardous-order lead time.
- Time spent at hazardous capacity limit.
- Number of hazardous-cap violations; target must be zero.
- Number and duration of standard-order interruptions.
- Resource utilization by station type.
- Idle time caused by upstream/downstream blocking.
- Transportation/batch efficiency, if route cost data is available.
- Equity/fairness metrics for standard orders, such as longest waiting time.

The selected policy should improve the relevant KPIs without creating unacceptable degradation elsewhere. For example, an approach that improves express SLA from 96% to 99% but doubles standard P95 delay may not be acceptable.

## 5. Monitoring Post-Implementation

After implementation, the company should establish process-mining dashboards that monitor both standard process performance and the instance-spanning constraints in near real time.

### 5.1 Executive fulfillment-performance dashboard

This dashboard should provide:

- Total order throughput by hour, shift, day, and region.
- End-to-end lead time: median, P90, P95.
- On-time dispatch and delivery performance.
- SLA compliance split by Express versus Standard.
- SLA compliance split by cold, hazardous, and non-constrained orders.
- Backlog and work-in-progress across Picking, Packing, QC, and Label Generation.
- Peak-period versus normal-period performance.

### 5.2 Cold-Packing Resource Dashboard

Monitor:

- Current and historical cold-station occupancy.
- Percentage of time all five cold stations are busy.
- Cold queue length and age.
- Waiting time before cold packing, including P90/P95.
- Queue composition by Express/Standard and hazardous/non-hazardous.
- Cold-packing utilization by individual station.
- Number of express cold orders waiting beyond SLA-risk thresholds.
- Number of standard cold orders delayed by priority policies.
- Forecasted cold demand for the next shift or next several hours.

A successful intervention should show lower queue lengths, lower tail waiting times, and fewer periods in which all cold stations remain saturated while the queue grows.

### 5.3 Shipping Batch Dashboard

Monitor:

- Batch size by destination region.
- Batch formation time.
- Time from QC completion to label generation.
- Oldest order waiting in each regional batch.
- Number of orders released due to maximum-wait or SLA-risk triggers.
- Express orders held by batches.
- Batch release frequency.
- Transportation utilization or route-efficiency metrics, where available.
- Regions with recurring underfilled or excessively delayed batches.

A successful adaptive batching policy should reduce waiting time and SLA breaches without materially harming shipping efficiency.

### 5.4 Priority and Fairness Dashboard

Monitor:

- Express SLA compliance.
- Standard SLA compliance.
- Number of standard orders overtaken by express orders.
- Number and duration of preemptions.
- Interrupted work by resource and activity.
- Longest waiting Standard order.
- Queue age by order type.
- Difference in queue time between Express and Standard orders.
- Rework or quality issues associated with interruption.

This dashboard ensures that express service improvements do not become hidden standard-order degradation.

### 5.5 Hazardous Compliance and Flow Dashboard

Monitor in real time:

- Current hazardous WIP in Packing plus QC.
- Maximum hazardous WIP during each shift.
- Time spent at hazardous WIP levels 8, 9, and 10.
- Hazardous-order queue length and waiting time.
- Number of attempted admissions blocked by the hazardous limit.
- Regulatory violations, which should be zero.
- Hazardous throughput.
- Hazardous order SLA compliance.
- Forecasted hazardous arrivals and expected capacity risk.
- Whether hazardous orders are clustering by destination, shift, or batch.

The objective is not merely to remain below 10. It is to maintain compliance while avoiding prolonged operation at the cap, which creates unstable queues and delayed flow.

### 5.6 Process Mining Conformance and Root-Cause Monitoring

Maintain automated conformance checks for:

- Hazardous WIP never exceeding 10.
- Cold-required orders assigned only to certified cold-packing resources.
- Express handling rules being followed.
- Batch release rules being correctly applied.
- No unauthorized resource assignments.
- Expected order sequence, unless exceptions are authorized.

When SLA breaches occur, automatically classify the likely delay source:

- Cold-packing contention.
- Hazardous-cap admission delay.
- Batch waiting.
- Express-priority displacement.
- Long service duration.
- Rework or quality exception.
- Staffing/resource unavailability.
- Data-quality or logging issue.

This produces an operational feedback loop:

1. Detect delay patterns from the event log.
2. Attribute them to within-instance or cross-instance causes.
3. Compare current KPIs against baseline and simulation predictions.
4. Adjust thresholds, staffing, batch rules, or priority settings.
5. Revalidate changes using process mining and controlled experiments.

The result is a fulfillment process managed as a coordinated system of orders, resources, batches, priorities, and compliance limits rather than as isolated order journeys.
