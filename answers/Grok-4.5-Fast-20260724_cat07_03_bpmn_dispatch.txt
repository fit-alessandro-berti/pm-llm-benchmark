**This is a BPMN 2.0 process diagram** titled **“Dispatch of goods”** for a **Computer Hardware Shop**. It models the end-to-end workflow of preparing and shipping an order, using three swimlanes (roles/participants):

- **Logistics** (top lane)
- **Secretary** (middle lane)
- **Warehouse** (bottom lane)

### Overall Flow

1. **Start**  
   The process begins with the event **“Ship goods”** (white circle) in the Secretary lane.

2. **Parallel Split**  
   A parallel gateway (**+**) immediately splits the flow into two concurrent paths:
   - Secretary path (clarifying shipment and handling logistics/insurance)
   - Warehouse path (packaging the goods)

3. **Secretary Path**
   - **Clarify shipment method**  
     Uses the data object **“Order details”**.  
     Decision gateway (**X**): **“Special handling?”**
     - **No** → proceeds to **“Check if insurance is required”** (uses data store **“Customer information”**).  
       - Decision: **“If insurance necessary”**  
         - Yes → **“Insure parcel”** (Logistics lane) then joins back.  
         - Always → **“Write package label”**.
     - **Yes** → **“Get 3 offers from logistic companies”** → **“Select logistic company and place order”**.
   - Both branches converge at an exclusive gateway (**X**), then continue downward to join the warehouse path.

4. **Warehouse Path**
   - **Package goods**  
     Has a timer boundary event (**48 hours**).  
     If the timer expires → **“Notify customer about delay”** → joins back via an inclusive gateway (**O**).
   - The main packaging flow also reaches the same inclusive gateway.

5. **Synchronization & Final Steps**
   - An inclusive gateway (**O**) and then a parallel join (**+**) synchronize the Secretary and Warehouse paths.
   - **Fill out shipment paperwork**
   - **Move package to pickup area**
   - End event: **“Shipment prepared”** (thick-bordered circle)

### Key BPMN Elements Used
- **Pools/Lanes**: Role separation (Secretary, Warehouse, Logistics)
- **Start/End events**
- **Tasks** (rounded rectangles)
- **Exclusive gateways (X)** for decisions
- **Parallel gateways (+)** for concurrent work and joining
- **Inclusive gateway (O)** for optional/conditional joining
- **Timer boundary event** (48-hour timeout on packaging)
- **Data object** (“Order details”) and **data store** (“Customer information”)

### Business Meaning
The process ensures goods are packaged in the warehouse while the secretary simultaneously determines the shipping method, optionally obtains quotes or arranges insurance, and prepares the label. After both streams finish, paperwork is completed and the package is moved to the pickup area. A 48-hour timer triggers a customer notification if packaging takes too long.

This is a classic example of a collaborative order-fulfillment / dispatch process with parallel work, conditional logistics decisions, and a timeout escalation.
