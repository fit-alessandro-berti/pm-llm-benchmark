# POWL Model Construction

## Analysis of the Event Log

Examining the five traces, I can identify the following consistent behavioral patterns:

1. **Fixed prefix**: `OR  MS  QS` always occurs in this exact order at the start of every case.
2. **Assembly/Quality-Check loop**: `AS` is sometimes followed by `IQC`, after which `AS` is repeated (cases 1, 3, 5). In other cases (2, 4), `AS` occurs just once. This is a classic POWL **loop** structure: do `AS`, then either exit or do `IQC` and repeat `AS`.
3. **Testing/Re-testing loop**: `TST` is sometimes followed by `RT`, after which `TST` is repeated (cases 1, 3, 5, and 5 even twice). In case 2 and 4, no `RT` occurs. This is again a **loop**: do `TST`, then either exit or do `RT` and repeat `TST`.
4. **Packaging**: `PK` always follows the testing loop.
5. **Labeling**: `LB` occurs in most cases but is skipped in case 2  modeled as an exclusive **choice** between `LB` and a silent transition.
6. **Fixed suffix**: `DP  D` always concludes the case.
7. No concurrency is observed anywhere — every case follows one linear backbone (interspersed with loops/choice) — so a single `StrictPartialOrder` with a total order over the (possibly compound) nodes suffices.

## POWL Model (Python Code)

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# Activities
OR  = Transition(label="OR")
MS  = Transition(label="MS")
QS  = Transition(label="QS")
AS  = Transition(label="AS")
IQC = Transition(label="IQC")
TST = Transition(label="TST")
RT  = Transition(label="RT")
PK  = Transition(label="PK")
LB  = Transition(label="LB")
DP  = Transition(label="DP")
D   = Transition(label="D")

skip_label = SilentTransition()

# Loop: AS, then optionally IQC -> AS again (repeated in-line quality checks)
loop_iqc = OperatorPOWL(operator=Operator.LOOP, children=[AS, IQC])

# Loop: TST, then optionally RT -> TST again (re-testing)
loop_rt = OperatorPOWL(operator=Operator.LOOP, children=[TST, RT])

# Choice: Labeling may be skipped
xor_lb = OperatorPOWL(operator=Operator.XOR, children=[LB, skip_label])

# Root: overall strict partial order (fully sequential in this case)
root = StrictPartialOrder(
    nodes=[OR, MS, QS, loop_iqc, loop_rt, PK, xor_lb, DP, D]
)

root.order.add_edge(OR, MS)
root.order.add_edge(MS, QS)
root.order.add_edge(QS, loop_iqc)
root.order.add_edge(loop_iqc, loop_rt)
root.order.add_edge(loop_rt, PK)
root.order.add_edge(PK, xor_lb)
root.order.add_edge(xor_lb, DP)
root.order.add_edge(DP, D)
```

## Textual Representation

```
PO = (
  nodes = {
    OR,
    MS,
    QS,
    *( AS, IQC ),
    *( TST, RT ),
    PK,
    X( LB, tau ),
    DP,
    D
  },
  order = {
    OR --> MS,
    MS --> QS,
    QS --> *( AS, IQC ),
    *( AS, IQC ) --> *( TST, RT ),
    *( TST, RT ) --> PK,
    PK --> X( LB, tau ),
    X( LB, tau ) --> DP,
    DP --> D
  }
)
```

## Explanation

- **`*(AS, IQC)`**: Represents "Assembly with optional in-line quality checks" — execute `AS`; then either exit the loop or perform `IQC` and go back to `AS` again. This matches cases where `AS` appears multiple times interleaved with `IQC` (cases 1, 3, 5) as well as cases with a single `AS` and no `IQC` (cases 2, 4).
- **`*(TST, RT)`**: Represents "Testing with optional re-testing" — execute `TST`; then either exit or perform `RT` and test again. This captures single-test cases (2, 4), one-retest cases (1, 3), and even the double-retest case (5).
- **`X(LB, tau)`**: Represents optional labeling — either `LB` is performed, or it is silently skipped (as observed in case 2).
- The rest of the process (`OR  MS  QS  ...  PK  ...  DP  D`) is strictly sequential across all observed cases, hence modeled via a single `StrictPartialOrder` with a linear chain of order relations.
