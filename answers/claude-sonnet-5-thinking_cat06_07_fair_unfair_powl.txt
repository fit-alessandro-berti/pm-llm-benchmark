# POWL Models for GlobalTeq Solutions Hiring Process

Below are two POWL models constructed using pm4py's objects. Both share the same initial structure (application receipt, data completeness loop, skill assessment) but diverge at the cultural fit evaluation stage.

---

## Model 1: POWL Model **With Potential Unfairness**

This model introduces an XOR choice between a standard `CulturalFitCheck` and a `CommunityAffiliationCheck`. The latter path is where local-community or "Global Business Leaders Club" affiliations can introduce a subjective, unfair scoring boost, which may propagate into the `ManagerialReview`.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_application = Transition(label="ReceiveApplication")
data_completeness_check = Transition(label="DataCompletenessCheck")
request_more_info = Transition(label="RequestMoreInfo")
skill_assessment = Transition(label="SkillAssessment")

cultural_fit_check = Transition(label="CulturalFitCheck")
community_affiliation_check = Transition(label="CommunityAffiliationCheck")

managerial_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop for Data Completeness ---
# Execute DataCompletenessCheck, then either exit or RequestMoreInfo and loop back
completeness_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_completeness_check, request_more_info]
)

# --- XOR: Potential Bias Point ---
# Either standard cultural fit check OR community affiliation check (biased path)
cultural_fit_xor = OperatorPOWL(
    operator=Operator.XOR,
    children=[cultural_fit_check, community_affiliation_check]
)

# --- Build the Partial Order ---
root_unfair = StrictPartialOrder(
    nodes=[
        receive_application,
        completeness_loop,
        skill_assessment,
        cultural_fit_xor,
        managerial_review,
        final_decision
    ]
)

# Sequential ordering
root_unfair.order.add_edge(receive_application, completeness_loop)
root_unfair.order.add_edge(completeness_loop, skill_assessment)
root_unfair.order.add_edge(skill_assessment, cultural_fit_xor)
root_unfair.order.add_edge(cultural_fit_xor, managerial_review)
root_unfair.order.add_edge(managerial_review, final_decision)

# Optional: visualize
# pm4py.view_powl(root_unfair, format="png")
```

### Explanation of Model 1
- **Loop**: `DataCompletenessCheck`  `RequestMoreInfo` — models the iterative resume-completion cycle.
- **Sequence**: `ReceiveApplication  Loop  SkillAssessment  XOR(...)  ManagerialReview  FinalDecision`.
- **XOR (Bias Point)**: `CulturalFitCheck` vs. `CommunityAffiliationCheck`. Since the affiliation check can grant an implicit uplift, and this feeds into `ManagerialReview`, unfairness can propagate to the `FinalDecision`.

---

## Model 2: POWL Model **Without Unfairness**

This model removes the biased branch entirely. All applicants undergo the **same** `CulturalFitCheck`, with no alternate path based on community or club affiliation.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_application = Transition(label="ReceiveApplication")
data_completeness_check = Transition(label="DataCompletenessCheck")
request_more_info = Transition(label="RequestMoreInfo")
skill_assessment = Transition(label="SkillAssessment")

cultural_fit_check = Transition(label="CulturalFitCheck")  # single unbiased path

managerial_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop for Data Completeness (same as before) ---
completeness_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_completeness_check, request_more_info]
)

# --- No XOR here: everyone goes through the same CulturalFitCheck ---

# --- Build the Partial Order ---
root_fair = StrictPartialOrder(
    nodes=[
        receive_application,
        completeness_loop,
        skill_assessment,
        cultural_fit_check,
        managerial_review,
        final_decision
    ]
)

# Sequential ordering
root_fair.order.add_edge(receive_application, completeness_loop)
root_fair.order.add_edge(completeness_loop, skill_assessment)
root_fair.order.add_edge(skill_assessment, cultural_fit_check)
root_fair.order.add_edge(cultural_fit_check, managerial_review)
root_fair.order.add_edge(managerial_review, final_decision)

# Optional: visualize
# pm4py.view_powl(root_fair, format="png")
```

### Explanation of Model 2
- **Loop**: Identical `DataCompletenessCheck`  `RequestMoreInfo` structure — this loop is a legitimate fairness-neutral mechanism (ensuring complete data), so it's preserved.
- **Sequence**: `ReceiveApplication  Loop  SkillAssessment  CulturalFitCheck  ManagerialReview  FinalDecision`.
- **No XOR / No Bias Point**: There is only **one** path for cultural fit evaluation — `CulturalFitCheck` — applied uniformly to all candidates regardless of club membership or residency status. This removes the structural opportunity for implicit favoritism to enter the workflow.

---

## Summary of Key Difference

| Aspect | Model 1 (Unfair) | Model 2 (Fair) |
|---|---|---|
| Cultural Fit Stage | XOR(`CulturalFitCheck`, `CommunityAffiliationCheck`) | Single `CulturalFitCheck` |
| Bias Injection Point | Present (via affiliation-based branch) | Removed |
| Data Completeness Loop | Present | Present (unchanged, since it's not a bias source) |
| Overall Sequence Structure | Same skeleton | Same skeleton |

The **only structural difference** between the two models is the presence or absence of the XOR branch at the cultural fit stage — isolating exactly where subtle unfairness can enter the hiring process, and demonstrating how removing that branch (enforcing a uniform evaluation activity) eliminates the potential bias pathway.
