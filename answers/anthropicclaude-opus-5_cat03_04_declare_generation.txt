## DECLARE Model for the Product Design & Launch Process

**Intended "happy path":**
`IG  DD  TFC  CE  PC  LT  UT  AG  MP  FL`

Below is the pm4pycompatible DECLARE dictionary. Unary keys map an **activity**  `(support, confidence)`; binary keys map an **(activation, target) tuple**  `(support, confidence)`.

```python
declare_model = {

    # ---------------- UNARY TEMPLATES ----------------

    # Every product case must contain these core activities
    'existence': {
        'IG':  (1.0, 1.0),   # every case starts from an idea
        'DD':  (1.0, 1.0),   # a design draft is always produced
        'TFC': (1.0, 1.0),   # feasibility is always checked
        'CE':  (1.0, 1.0),   # costs are always evaluated
        'AG':  (1.0, 1.0),   # management approval always occurs
        'FL':  (1.0, 0.95),  # nearly all approved products are launched
    },

    # No activity is forbidden in this process
    'absence': {},

    # These activities may occur only once per case
    'exactly_one': {
        'IG':  (1.0, 1.0),
        'AG':  (1.0, 0.9),   # normally one approval gate
        'MP':  (1.0, 0.9),
        'FL':  (1.0, 0.95),
    },

    # Each case must begin with Idea Generation
    'init': {
        'IG': (1.0, 1.0),
    },

    # ---------------- BINARY TEMPLATES ----------------

    # If the first occurs, the second must occur somewhere (before or after)
    'responded_existence': {
        ('DD',  'TFC'): (1.0, 1.0),
        ('DD',  'CE'):  (1.0, 1.0),
        ('PC',  'LT'):  (1.0, 1.0),
        ('PC',  'UT'):  (1.0, 0.9),
        ('MP',  'FL'):  (1.0, 0.95),
        ('FL',  'AG'):  (1.0, 1.0),
    },

    # Both or none: lab & user testing always go together, launch needs marketing
    'coexistence': {
        ('LT', 'UT'): (1.0, 0.9),
        ('UT', 'LT'): (1.0, 0.9),
        ('FL', 'MP'): (1.0, 0.95),
        ('MP', 'FL'): (1.0, 0.95),
    },

    # A  eventually B afterwards
    'response': {
        ('IG',  'DD'):  (1.0, 1.0),
        ('DD',  'TFC'): (1.0, 1.0),
        ('TFC', 'CE'):  (1.0, 0.95),
        ('CE',  'PC'):  (1.0, 0.9),
        ('PC',  'LT'):  (1.0, 1.0),
        ('LT',  'UT'):  (1.0, 0.9),
        ('UT',  'AG'):  (1.0, 0.95),
        ('AG',  'MP'):  (1.0, 0.9),
        ('MP',  'FL'):  (1.0, 0.95),
    },

    # B  A must have occurred earlier
    'precedence': {
        ('DD',  'IG'):  (1.0, 1.0),
        ('TFC', 'DD'):  (1.0, 1.0),
        ('CE',  'DD'):  (1.0, 1.0),
        ('PC',  'TFC'): (1.0, 1.0),
        ('PC',  'CE'):  (1.0, 0.95),
        ('LT',  'PC'):  (1.0, 1.0),
        ('UT',  'PC'):  (1.0, 1.0),
        ('AG',  'LT'):  (1.0, 0.95),
        ('MP',  'AG'):  (1.0, 1.0),
        ('FL',  'AG'):  (1.0, 1.0),
        ('FL',  'MP'):  (1.0, 0.95),
    },

    # Response + Precedence (strict mutual ordering)
    'succession': {
        ('IG',  'DD'):  (1.0, 1.0),
        ('DD',  'TFC'): (1.0, 1.0),
        ('PC',  'LT'):  (1.0, 1.0),
        ('AG',  'MP'):  (1.0, 0.9),
        ('AG',  'FL'):  (1.0, 0.95),
        ('MP',  'FL'):  (1.0, 0.95),
    },

    # A  B before any new A (no repeated activation without response)
    'altresponse': {
        ('IG',  'DD'):  (1.0, 1.0),
        ('PC',  'LT'):  (1.0, 0.95),
        ('AG',  'FL'):  (1.0, 0.95),
    },

    # B  A before, with no other B in between
    'altprecedence': {
        ('DD', 'IG'):  (1.0, 1.0),
        ('LT', 'PC'):  (1.0, 0.95),
        ('FL', 'AG'):  (1.0, 0.95),
    },

    'altsuccession': {
        ('IG', 'DD'): (1.0, 1.0),
        ('AG', 'FL'): (1.0, 0.95),
    },

    # A  B occurs IMMEDIATELY after A
    'chainresponse': {
        ('IG',  'DD'):  (1.0, 1.0),
        ('TFC', 'CE'):  (1.0, 0.9),
        ('MP',  'FL'):  (1.0, 0.9),
    },

    # B  A occurs IMMEDIATELY before B
    'chainprecedence': {
        ('DD', 'IG'):  (1.0, 1.0),
        ('CE', 'TFC'): (1.0, 0.9),
        ('FL', 'MP'):  (1.0, 0.9),
    },

    'chainsuccession': {
        ('IG',  'DD'): (1.0, 1.0),
        ('TFC', 'CE'): (1.0, 0.9),
        ('MP',  'FL'): (1.0, 0.9),
    },

    # Mutually exclusive activities (none in this process)
    'noncoexistence': {},

    # A is never eventually followed by B
    'nonsuccession': {
        ('FL', 'IG'):  (1.0, 1.0),   # nothing restarts after launch
        ('FL', 'DD'):  (1.0, 1.0),
        ('FL', 'PC'):  (1.0, 1.0),
        ('FL', 'AG'):  (1.0, 1.0),
        ('MP', 'DD'):  (1.0, 0.95),  # no redesign after marketing plan
        ('AG', 'TFC'): (1.0, 0.9),   # no feasibility re-check after approval
    },

    # A is never IMMEDIATELY followed by B
    'nonchainsuccession': {
        ('PC', 'FL'):  (1.0, 1.0),   # a prototype is never launched directly
        ('DD', 'FL'):  (1.0, 1.0),
        ('IG', 'PC'):  (1.0, 1.0),   # prototyping never follows the idea directly
        ('LT', 'FL'):  (1.0, 0.95),
        ('AG', 'FL'):  (1.0, 0.9),   # a marketing plan is inserted in between
    },
}
```

### How to use it in pm4py

```python
import pm4py
from pm4py.algo.conformance.declare import algorithm as declare_conformance

log = pm4py.read_xes("product_launch.xes")

# Conformance checking against the hand-made model
diagnostics = declare_conformance.apply(log, declare_model)
print(diagnostics)

# (Optional) compare with an automatically discovered model
discovered = pm4py.discover_declare(log)
```

### Reading of the key constraints
| Template | Example | Business meaning |
|---|---|---|
| `init` | IG | Every case starts with an idea |
| `exactly_one` | FL | A product is launched at most/exactly once |
| `chainsuccession` | (MP, FL) | Launch happens directly after the marketing plan is ready |
| `precedence` | (FL, AG) | No launch without management approval |
| `coexistence` | (LT, UT) | Lab testing and user testing always come as a pair |
| `nonsuccession` | (FL, DD) | Design work never resumes after launch |
| `nonchainsuccession` | (PC, FL) | A prototype can never be launched without testing/approval |
