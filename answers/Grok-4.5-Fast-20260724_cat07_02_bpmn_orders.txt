**This is a BPMN (Business Process Model and Notation) diagram** that models an end-to-end customer order fulfillment process involving four organizational units (pools/lanes): **Sales**, **Production**, **Procurement**, and **Warehouse**.

It shows how an order is validated, planned, manufactured (with material handling), and delivered, including compensations, checks, and message exchanges between the units.

### Sales lane
- Triggered by a **timer event** (“Monday morning”).
- Flow:
  1. Start event → **Check order for completeness**.
  2. **Check if customer is already in the database**.
  3. Exclusive gateway:
     - If the customer is **not** in the database → **Add customer to the database** (with a data store association to a database).
     - Then converges at another exclusive gateway once the customer is confirmed in the database.
  4. **Send order details** (sends a message to other pools).
  5. Intermediate message event **“Product sent”**.
  6. **Draft invoice**.
  7. End event.

A grouping labeled **“Check customer’s order”** encompasses the early validation and customer-database steps.

### Production lane
- Receives the **“Order details arrive”** message.
- Parallel gateway structure:
  - **Plan production**.
  - Then **Manufacture product**.
- Sends a **“Product complete”** message.
- Includes a path for **“Material not faulty”** (loop/feedback involving material status).

### Procurement lane
- Also receives the **“Order details arrive”** message.
- Contains a **Material Compensation Subprocess**:
  - Start → **Order materials** → end.
  - Alternative path: **Return material**.
- After the subprocess: **Check materials** (with intermediate events).
- Ends with an **“Order cancellation”** path (and related intermediate events).

### Warehouse lane
- Receives the **“Product complete”** message.
- **Send product**.
- Sends the **“Product sent”** message (which is received by Sales).

### Cross-lane interactions (message flows)
Dashed message flows carry:
- **Order details** (from Sales to Production and Procurement).
- **Product complete** (from Production to Warehouse).
- **Product sent** (from Warehouse back to Sales).

### Overall process summary
1. Sales validates the order and customer data (adding the customer if needed), then broadcasts order details.
2. Production plans and manufactures the product (coordinating material status).
3. Procurement handles material ordering, checking, possible returns, and potential order cancellation (with a compensation subprocess).
4. Warehouse ships the finished product.
5. Sales is notified when the product is sent and drafts the invoice.

The diagram uses standard BPMN elements: pools/lanes, start/end events, timer and message events, tasks, exclusive and parallel gateways, a subprocess with compensation, data stores, and message flows. It models both the happy path and exception/compensation handling (faulty materials, returns, cancellation).
