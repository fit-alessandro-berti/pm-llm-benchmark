Here is the DuckDB SQL query to achieve this. 

There are two highly efficient and standard ways to write this in DuckDB: using a **Window Function** or using a **CTE with `HAVING`**. The window function approach is often the most optimized as DuckDB can compute it in a single pass over the data.

### Method 1: Using a Window Function (Recommended)
```sql
SELECT *
FROM (
    SELECT 
        *, 
        COUNT(*) OVER (PARTITION BY case_id) AS event_count
    FROM event_log
) subquery
WHERE event_count <= 6;
```

### Method 2: Using a CTE and `HAVING` Group By
This method is incredibly readable and works by first identifying the valid cases, and then joining back to get the full event details.

```sql
WITH valid_cases AS (
    SELECT case_id
    FROM event_log
    GROUP BY case_id
    HAVING COUNT(*) <= 6
)
SELECT e.* 
FROM event_log e
JOIN valid_cases v ON e.case_id = v.case_id;
```

### How it works:
1. **Method 1** calculates the count of events for each `case_id` and assigns it as a new column (`event_count`) to every row using the `OVER (PARTITION BY ...)` syntax. The outer query then simply filters out any rows where that count exceeds 6.
2. **Method 2** groups the data by `case_id`, uses `HAVING COUNT(*) <= 6` to filter out the undesired cases entirely, and then inner joins that result back to the original `event_log` table to retrieve all the columns for the kept cases.

*Both queries will dynamically check your table at runtime and return exactly the events from cases with 6 or fewer events.*
