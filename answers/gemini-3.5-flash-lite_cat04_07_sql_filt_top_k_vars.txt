To solve this task in DuckDB, we can break the logic down into four steps using Common Table Expressions (CTEs):
1. **`case_variants`**: Order the activities per `case_id` by `timestamp` and aggregate them into an ordered list (array or string) to represent the process variant.
2. **`ranked_variants`**: Count the frequency of each variant and rank them using window functions (e.g., `DENSE_RANK()` or `ROW_NUMBER()`) to identify the top $K$ variants.
3. **`target_cases`**: Filter the cases that belong to these top $K$ variants.
4. **Final Selection**: Join the original `event_log` with the filtered cases to return all events belonging exclusively to those top $K$ variants.

Here is the DuckDB SQL query. You can adjust the `@K` parameter or variable to your desired top $K$ value (set to `3` in this example).

```sql
WITH 
-- Step 1: Determine the sequence of activities for each case
case_sequences AS (
    SELECT 
        case_id,
        -- Using list aggregation ordered by timestamp to capture the exact sequence
        listagg(activity, ' -> ') WITHIN GROUP (ORDER BY timestamp, activity) AS variant_string,
        -- Alternatively, you can use DuckDB's list function for array-based variants:
        -- list(activity ORDER BY timestamp, activity) AS variant_array
    FROM event_log
    GROUP BY case_id
),

-- Step 2: Aggregate by variant, count frequencies, and assign ranks to find the top K
variant_counts AS (
    SELECT 
        variant_string,
        COUNT(case_id) AS case_count,
        DENSE_RANK() OVER (ORDER BY COUNT(case_id) DESC, variant_string ASC) as variant_rank
    FROM case_sequences
    GROUP BY variant_string
),

-- Step 3: Filter variants up to the top K (e.g., K = 3)
top_k_variants AS (
    SELECT variant_string
    FROM variant_counts
    WHERE variant_rank <= 3 -- Replace 3 with your desired K value
),

-- Step 4: Identify all case_ids that belong to the top K variants
filtered_cases AS (
    SELECT cs.case_id
    FROM case_sequences cs
    JOIN top_k_variants tkv ON cs.variant_string = tkv.variant_string
)

-- Final Output: Return all events from the original event log belonging only to the top K cases
SELECT 
    e.case_id,
    e.activity,
    e.timestamp
FROM event_log e
JOIN filtered_cases f ON e.case_id = f.case_id
ORDER BY e.case_id, e.timestamp;
```

### Explanation of Key DuckDB Features Used:
- **`listagg(..., ' -> ') WITHIN GROUP (ORDER BY ...)`**: Constructs a readable string representing the process variant sequence. If you prefer working with arrays instead of strings, you can replace this with DuckDB's native `list(activity ORDER BY timestamp)`.
- **`DENSE_RANK() OVER (ORDER BY COUNT(case_id) DESC ...)`**: Assigns a rank to each variant based on its frequency, ensuring ties in frequency are handled deterministically.
- **Multi-level CTEs**: Keeps the logic modular, making it easy to debug and maintain as the process mining pipeline scales.
