**Overall Process Purpose**

This is an order-fulfillment / quotation-to-invoice process for handling customer requests. It routes requests into two main tracks (Standard vs. Custom), performs the appropriate checks or analysis, optionally obtains managerial approval, generates an invoice when everything is in order, and finally confirms the outcome to the customer. Early termination is possible for infeasible custom requests. A rework loop exists when approval is denied.

### 1. Start and Initial Branching
- **Start Event → Task A: “Receive Customer Request”**  
  The process begins when a customer request arrives. This task captures the request details (items, quantities, special requirements, customer data, etc.).

- **XOR Gateway: “Check Request Type”**  
  Exclusive (XOR) decision based on whether the request is classified as **Standard** or **Custom**. Only one path is taken.

### 2. Standard Path
- **Task B1: “Perform Standard Validation”**  
  Basic checks that the request is complete, correctly formatted, and meets standard business rules (e.g., product codes valid, quantities within normal ranges).

- **AND Gateway: “Run Parallel Checks”**  
  Parallel (AND) split. Both of the following tasks execute concurrently:
  - **Task C1: “Credit Check”** – Verifies the customer’s credit status / payment risk.
  - **Task C2: “Inventory Check”** – Confirms stock availability (or procurement lead time).

- **AND Join** (“All Parallel Checks Completed”)  
  Synchronization point. The process waits until both C1 and C2 finish before continuing.

- **Task D: “Calculate Delivery Date”**  
  Uses the results of the credit and inventory checks (plus standard lead times) to determine a promised delivery date.

### 3. Custom Path
- **Task B2: “Perform Custom Feasibility Analysis”**  
  Deeper technical/commercial analysis to determine whether the requested customization can be produced (engineering effort, materials, capacity, cost, risk, etc.).

- **XOR Gateway: “Is Customization Feasible?”**
  - **Yes → Task E1: “Prepare Custom Quotation”**  
    Builds a tailored quotation (pricing, lead time, terms, any special conditions).
  - **No → Task E2: “Send Rejection Notice” → End Event**  
    Customer is informed that the request cannot be fulfilled; the process terminates.

### 4. Convergence After Standard or Successful Custom Path
After Task D (standard) or Task E1 (custom), the two paths merge and reach a common decision point.

- **XOR Gateway: “Is Approval Needed?”**
  - **No → Task G: “Generate Final Invoice”** (direct path).
  - **Yes → Task F: “Obtain Manager Approval”**  
    Manager reviews the quotation / delivery commitment / risk profile.

- **XOR Gateway: “Is Approval Granted?”** (only if Task F was executed)
  - **Yes → Task G: “Generate Final Invoice”**  
    Invoice (or final commercial document) is produced.
  - **No → Task H: “Re-evaluate Conditions”**  
    Conditions, pricing, scope, or delivery date are adjusted.  
    **Loop-back**:
    - Custom path → returns to Task E1 (“Prepare Custom Quotation”).
    - Standard path → returns to Task D (“Calculate Delivery Date”).  
    After the loop, the process again reaches the “Is Approval Needed?” gateway (or continues through the same decision logic).

### 5. Final Common Steps
- **Task G: “Generate Final Invoice”**  
  Creates the definitive commercial document once all validations, checks, and (if required) approvals are complete.

- **Task I: “Send Confirmation to Customer”**  
  Delivers the invoice / order confirmation / acceptance notice (and any accompanying documents) to the customer.

- **End Event**  
  Process completes successfully.

### Summary of Key Differences and Control Points

| Aspect                  | Standard Request                          | Custom Request                                      |
|-------------------------|-------------------------------------------|-----------------------------------------------------|
| Validation / Analysis   | Standard Validation + parallel Credit & Inventory checks | Custom Feasibility Analysis                        |
| Early Exit              | None                                      | Rejection notice if not feasible                    |
| Pricing / Quotation     | Implicit (standard pricing)               | Explicit “Prepare Custom Quotation”                 |
| Delivery Date           | Explicit calculation after checks         | Usually embedded in the custom quotation            |
| Approval Trigger        | Same rule for both paths                  | Same rule for both paths                            |
| Rework Loop Destination | Back to “Calculate Delivery Date”         | Back to “Prepare Custom Quotation”                  |

**Approval is triggered** when the process reaches the “Is Approval Needed?” gateway and the answer is Yes (business rules may depend on value, risk, customization complexity, customer tier, etc.).  

**Rework is triggered** only when manager approval is sought **and** denied; the process then revisits the quotation or delivery-date calculation before potentially seeking approval again.

The design ensures that standard orders flow efficiently through parallel checks, custom orders receive specialized scrutiny (with an early-exit option), and managerial oversight plus a controlled rework loop protect against unapproved or suboptimal commitments.
