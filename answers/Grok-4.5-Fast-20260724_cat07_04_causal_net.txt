**This visualization is a Causal Net (C-net)** — a process model used in process mining (common in the work of Wil van der Aalst and related literature). It depicts the control-flow of a request-handling process (a classic insurance-claim / compensation example).

### Activities (nodes)
| Label | Activity              |
|-------|-----------------------|
| a     | register request      |
| b     | examine thoroughly    |
| c     | examine casually      |
| d     | check ticket          |
| e     | decide                |
| f     | reinitiate request    |
| g     | pay compensation      |
| h     | reject request        |
| z     | end                   |

### Legend (bottom-right)
The black dots on the arcs indicate the type of split or join:

- **XOR-split / XOR-join** — exclusive choice / exclusive merge (exactly one path)
- **AND-split / AND-join** — parallel split / synchronization (all paths)
- **OR-split / OR-join** — inclusive choice / inclusive merge (one or more paths)

### Process flow
1. The process starts at **a (register request)**.
2. From **a** the model uses an **OR-split** (or equivalent binding) that can activate one or more of:
   - **b** – examine thoroughly
   - **c** – examine casually
   - **d** – check ticket
3. These examination/check activities feed into **e (decide)** via an **OR-join** (or multi-input binding). Multiple examinations may therefore contribute to the decision.
4. After **e** there is an **XOR-split**:
   - **g** – pay compensation → **z (end)**
   - **h** – reject request → **z (end)**
5. There is also a loop: from **e** a path can go back through **f (reinitiate request)**.  
   **f** reconnects (mainly) to **d (check ticket)** and can also interact with the examination activities, allowing the request to be re-examined after a decision to reinitiate.

### Key behavioural characteristics
- Parallel or alternative examinations (thorough vs. casual) can occur together with ticket checking.
- The decision at **e** is exclusive (pay **or** reject).
- The model supports iteration via the **reinitiate** loop.
- All paths eventually converge at the single end activity **z**.

This style of diagram (activities + explicit input/output bindings shown as black dots) is typical of Causal Nets, which are more flexible than classical Petri nets or BPMN for representing the flexible, often non-free-choice behaviour discovered by process-mining algorithms.
