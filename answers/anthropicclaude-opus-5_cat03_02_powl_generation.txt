## POWL Model Construction

**Reasoning about the structure:**

- `SR  CS` are strictly sequential at the start.
- `DA` and `ACI` both depend on `CS`, but not on each other  concurrent branch in the partial order.
- The configuration phase is a **loop**: `*( BNC, D&R )` — execute `BNC`, then either exit, or execute `D&R` and run `BNC` again. This matches "BNC, then optional debug & re-configure, repeat until stable".
- The deployment is an **exclusive choice**: `X( CD, MD )`.
- `QA` and `SA` both depend on the deployment choice, but are unordered w.r.t. each other  concurrent.
- `GLA` depends on both `QA` and `SA`.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------
# 1) Atomic activities (leaves)
# ---------------------------------------------------------------
SR   = Transition(label="SR")    # Service Request verification
CS   = Transition(label="CS")    # Contract Setup
DA   = Transition(label="DA")    # Datacenter Allocation
ACI  = Transition(label="ACI")   # Access Control Initialization
BNC  = Transition(label="BNC")   # Base Network Configuration
DR   = Transition(label="D&R")   # Debug & Reconfigure
CD   = Transition(label="CD")    # Containerized Deployment
MD   = Transition(label="MD")    # Monolithic Deployment
QA   = Transition(label="QA")    # Quality Assurance
SA   = Transition(label="SA")    # Security Audit
GLA  = Transition(label="GLA")   # Go-Live Approval

# ---------------------------------------------------------------
# 2) Looped configuration phase:  * ( BNC , D&R )
#    -> BNC is always executed; afterwards either exit the loop
#       (configuration stable) or perform D&R and redo BNC.
# ---------------------------------------------------------------
config_loop = OperatorPOWL(operator=Operator.LOOP, children=[BNC, DR])

# ---------------------------------------------------------------
# 3) Exclusive choice of deployment method:  X ( CD , MD )
# ---------------------------------------------------------------
deployment_choice = OperatorPOWL(operator=Operator.XOR, children=[CD, MD])

# ---------------------------------------------------------------
# 4) Root strict partial order over all sub-models
# ---------------------------------------------------------------
root = StrictPartialOrder(nodes=[
    SR,
    CS,
    DA,
    ACI,
    config_loop,
    deployment_choice,
    QA,
    SA,
    GLA
])

# --- Step 1: request verification precedes contract setup
root.order.add_edge(SR, CS)

# --- Step 2: after the contract, DA and ACI run concurrently
root.order.add_edge(CS, DA)
root.order.add_edge(CS, ACI)
# (no edge between DA and ACI  ->  they are concurrent)

# --- Step 3: the configuration loop starts only when DA and ACI are both done
root.order.add_edge(DA, config_loop)
root.order.add_edge(ACI, config_loop)

# --- Step 4: deployment choice after a stable network configuration
root.order.add_edge(config_loop, deployment_choice)

# --- Step 5: QA and SA follow the deployment, mutually unordered (concurrent)
root.order.add_edge(deployment_choice, QA)
root.order.add_edge(deployment_choice, SA)
# (no edge between QA and SA  ->  any order / concurrent)

# --- Step 6: final Go-Live Approval waits for both QA and SA
root.order.add_edge(QA, GLA)
root.order.add_edge(SA, GLA)

# ---------------------------------------------------------------
# 5) Inspection / export
# ---------------------------------------------------------------
print(root)

# Optional: visualize or convert to a Petri net for further analysis
# pm4py.view_powl(root, format="svg")
# net, im, fm = pm4py.convert_to_petri_net(root)
```

### Resulting model (textual form)

```
PO=(
  nodes={ SR, CS, DA, ACI, *( BNC, D&R ), X( CD, MD ), QA, SA, GLA },
  order={ SR-->CS,
          CS-->DA, CS-->ACI,
          DA-->*( BNC, D&R ), ACI-->*( BNC, D&R ),
          *( BNC, D&R )-->X( CD, MD ),
          X( CD, MD )-->QA, X( CD, MD )-->SA,
          QA-->GLA, SA-->GLA }
)
```

**Notes**

- No `SilentTransition` is required here: the "optional" nature of `D&R` is already captured by the loop semantics (after `BNC` you may exit immediately, so `D&R` need not occur at all). If you wanted to model the *deployment* as skippable, you would add `SilentTransition()` as an extra child of the XOR, e.g. `OperatorPOWL(operator=Operator.XOR, children=[CD, MD, SilentTransition()])`.
- Transitivity of the partial order is implied (e.g., `SR` necessarily precedes `GLA`), so only the direct (covering) edges are added.
