Here is a DuckDB SQL query that uses window functions to detect the direct three-step sequence, checks the 5-day gap, excludes the matching cases, and returns everything else ordered properly:

```sql
WITH marked_events AS (
  SELECT
    case_id,
    activity,
    timestamp,
    LEAD(activity, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS next_act,
    LEAD(activity, 2) OVER (PARTITION BY case_id ORDER BY timestamp) AS next_next_act,
    LEAD(timestamp, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS ts_create,
    LEAD(timestamp, 2) OVER (PARTITION BY case_id ORDER BY timestamp) AS ts_confirm
  FROM event_log
),
bad_cases AS (
  SELECT DISTINCT case_id
  FROM marked_events
  WHERE activity = 'Approve Purchase Requisition'
    AND next_act = 'Create Order'
    AND next_next_act = 'Confirm Order'
    AND (ts_confirm - ts_create) > INTERVAL '5 days'
)
SELECT e.*
FROM event_log e
WHERE e.case_id NOT IN (SELECT case_id FROM bad_cases)
ORDER BY e.case_id, e.timestamp;
```

### How it works
1. **`marked_events`** uses `LEAD` within each `case_id` (ordered by `timestamp`) to look at the immediate next two activities and their timestamps. This guarantees **direct succession**—no other case event can sit between them.
2. **`bad_cases`** filters for rows where the triplet is exactly  
   `Approve Purchase Requisition`  `Create Order`  `Confirm Order`, and the interval between the `Create Order` and `Confirm Order` timestamps exceeds 5 days.
3. The final `SELECT` returns **all events** from `event_log` except those belonging to any `case_id` in `bad_cases`, ordered by case and time.
