## 3. Explanation of the Transformation Logic

**Case identification – one case per work object (document / message / artifact).**
The raw log is a single, continuous UI stream with heavy multitasking. The most analystfriendly notion of a "process instance" here is *a unit of knowledge work performed on one artifact*, identified by the window title: `Quarterly_Report.docx`, `Document1.docx`, the "Annual Meeting" email thread in `Email – Inbox`, `Report_Draft.pdf`, and `Budget_2024.xlsx`. All events whose `Window`/`ToWindow` equals that artifact are assigned to the same case, even when the user leaves and comes back later. This makes the interleaving visible as *suspend  resume* patterns inside a case instead of scattering it across unrelated events.

**Handling of SWITCH / FOCUS events (case boundaries).**
A `SWITCH` line contains information about two cases, so it was split into two events: a `Suspend Work (Context Switch)` / `Close…`/`Finish…` event for the *source* artifact and an `Open…` / `Resume…` event for the *target* artifact. A `FOCUS` on a new window while another artifact was still active (09:00:00 and 09:05:00) implies the same interruption, so a *derived* suspend event was added for the previously active case (flagged in the `Source` column, so it can be filtered out if only raw evidence is wanted).

**Activity naming – abstracted from keystroke level to process steps.**
Lowlevel actions were mapped to standardized, artifacttypeaware activity names:

| Raw action(s) | Standardized activity |
|---|---|
| FOCUS / SWITCH(in) on a new artifact | Open Document / Open Spreadsheet / Open PDF Document / Open Mailbox |
| FOCUS / SWITCH(in) on a previously suspended artifact | Resume Document Editing |
| TYPING in Word | Edit Document Content |
| TYPING in Excel | Update Spreadsheet Data |
| TYPING in mail composer | Compose Email Reply |
| SAVE | Save Document / Save Spreadsheet |
| SCROLL in PDF | Review PDF Content |
| SCROLL in mailbox | Read Email Content |
| HIGHLIGHT | Annotate PDF (Highlight) |
| CLICK = Open Email / Reply / Send | Open Email Message / Initiate Email Reply / Send Email Reply |
| SWITCH(out) / FOCUS elsewhere | Suspend Work (Context Switch) |
| CLOSE, or terminal SWITCH(out) after completion | Close Document / Close Email Handling |

Repeated `TYPING` events keep the same activity name so that frequency and rework analyses aggregate correctly; the actual keystroke payload is preserved in the `Detail` attribute.

**Resulting narrative.**
The user opens the quarterly report, immediately parks it and starts drafting a new document; that draft is interrupted by an incoming "Annual Meeting" email which is read and answered endtoend; the user then briefly reviews and highlights the report PDF, jumps to Excel to update the 2024 budget, returns to the draft to insert the budget reference, saves and closes it, and finally returns to the quarterly report to write the executive summary before closing it. The log therefore exhibits a classic multitasking pattern with two full suspensions, one abandoned case (the PDF review, C4 — a useful conformance/incompleteness signal), and a clear recurring "Open  Edit  Save  Close" documenthandling pattern.
