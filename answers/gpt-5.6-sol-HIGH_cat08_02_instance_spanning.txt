## 1. Identifying Instance-Spanning Constraints and Their Impact

### 1.1 Build an analysis-ready, object-centric event model

A normal case-centric analysis—one trace per order—will show where an order waited, but not reliably explain which other order or shared condition caused the wait. I would therefore create an object-centric event model with at least these objects:

- **Order**
- **Packing station/resource**
- **Quality-check resource**
- **Shipping batch**
- **Destination region/route**
- **Hazardous-material capacity pool**

A batch-closing or label-generation event should be linked to all orders in that batch rather than copied independently into each case trace.

The log should be enriched with:

- Activity `START`, `COMPLETE`, `SUSPEND`, and `RESUME` timestamps
- The time an activity became ready or an order entered a queue
- Batch ID, batch-open time, batch-close time, and batch reason: size, timeout, cutoff
- Resource calendars, breakdowns, and station eligibility
- Explicit resource-request and resource-assignment events
- Preemption reason and interrupted order
- Hazardous-capacity denial or admission events

If these fields are not available, readiness and queueing can be inferred from predecessor completion, resource occupation, and process rules, but causal conclusions will be less certain.

For an activity occurrence \(a\) of order \(i\), define:

- \(r_{i,a}\): time the activity became individually ready
- \(s_{i,a}\): start time
- \(c_{i,a}\): completion time
- \(q_{i,a}=s_{i,a}-r_{i,a}\): pre-start waiting time
- \(p_{i,a}\): active processing time, excluding suspension
- \(u_{i,a}\): suspended/interrupted time

This allows total order time to be decomposed into touch time, ordinary process waiting, cross-order blocking, batching delay, interruption, and other unclassified delay.

### 1.2 Constraint-specific identification and metrics

| Constraint | How to identify it formally | Principal impact metrics |
|---|---|---|
| **Shared Cold-Packing stations** | Reconstruct all cold-packing intervals and effective station availability. At each timestamp, calculate the number of occupied compatible stations. An order is resource-blocked when it is ready for cold packing and all available cold stations are busy or unavailable. | Cold-packing queue time; p50/p90/p95 queue time; maximum and average queue length; station utilization; percentage of time all five stations are occupied; blocked order-minutes; throughput per station-hour; SLA misses attributable to cold-packing waits. |
| **Shipping batches** | Link orders to batch objects. For each order, compare individual readiness—normally QC completion—with batch close and label-generation start. Validate that batch members satisfy region and shipping-compatibility rules. | Individual batch wait; average and p95 batch formation time; batch size and fill ratio; percentage of batches closed by timeout versus target size; orders missing cutoffs while waiting; label-generation burst size; regional differences in batch waiting. |
| **Express priority handling** | Construct the queue visible to each resource at every dispatch point. Detect when an express order overtakes a standard order and when a standard order is suspended and later resumed. If no suspend/resume events exist, detect candidate preemptions from resource handoffs and unusually long activity gaps, then validate operationally. | Express queue-time reduction; standard-order delay caused by displacement; interruption duration; number of preemptions; context-switch/setup loss; standard-order p95 and SLA impact during express-arrival bursts; express/standard fairness and starvation indicators. |
| **Hazardous-material limit** | Use a sweep-line calculation over all hazardous Packing and QC start/complete intervals. Let \(H(t)\) be the number of distinct hazardous orders active in these activities. Conformance requires \(H(t)\leq10\) at all times. | Maximum \(H(t)\); minutes at the limit; number and duration of violations; hazardous orders blocked while \(H(t)=10\); hazardous-capacity utilization; hazardous throughput per hour; queue length before Packing/QC; estimated throughput reduction caused by the limit. |

#### Shared Cold-Packing stations

In addition to process discovery, I would perform resource-constrained token replay or interval-based queue mining. Important distinctions include:

- **Physical saturation:** all five stations are occupied.
- **Staffing saturation:** a physical station exists but is not staffed.
- **Scheduling loss:** a compatible station is idle while eligible orders wait.
- **Setup/cleaning loss:** the station is temporarily unavailable but not processing an order.

The last three require calendars and downtime/setup events; otherwise they may incorrectly appear as unexplained waiting.

The impact of adding capacity cannot be determined from utilization alone. I would use simulation or a queueing counterfactual to estimate the change in waiting time and throughput from four, five, six, or flexibly converted stations.

#### Shipping batches

For each order \(i\):

\[
\text{Batch wait}_i = \text{label start}_i-\text{QC complete}_i
\]

If only label completion is logged, estimated label-processing time must be subtracted. Ideally label generation should also have start and complete events.

Useful analyses include:

- Batch wait by region, hour, weekday, and order type
- Relationship between batch size and time-to-close
- Frequency with which orders arrive shortly after a batch closes
- Difference between predicted and actual next-order arrival
- Percentage of orders that would have met SLA under a smaller or earlier batch

#### Priority handling

Priority has two effects:

1. **Direct interruption:** a standard order is suspended so an express order can use the resource.
2. **Queue displacement:** a standard order has not started but is moved behind a later-arriving express order.

Direct interruption cost is measurable from suspend/resume events. Queue displacement is estimated by reconstructing the dispatch queue and comparing actual start time with a reference policy such as FCFS or weighted-priority scheduling.

Metrics should report both sides of the trade-off:

- Minutes and SLA risk saved for express orders
- Minutes and SLA risk added to standard orders
- Lost productive time from stop/restart or station sanitation/setup
- Whether repeated express arrivals cause starvation of standard orders

Matched-shift analysis can strengthen the causal estimate: compare operational periods with similar volume, mix, and staffing but different express-order bursts.

#### Hazardous-material limit

The compliance rule can be tested as a temporal conformance condition:

\[
H(t)=\sum_i \mathbf{1}\{\text{hazardous order }i\text{ active in Packing or QC at }t\}\leq10
\]

The log can show when the limit was binding, but not by itself establish how much throughput would exist without it. That requires a counterfactual simulation in which the limit is varied for analytical purposes. The operational recommendation must, of course, retain the legal maximum of ten.

### 1.3 Separating within-instance and between-instance delay

The core distinction is between an order's own work and delay caused by the facility state.

#### Within-instance components

- Active picking, packing, or QC processing time
- Rework or repeated activities
- Product-specific complexity
- Order-specific documentation
- Suspensions caused by an issue with that same order

#### Between-instance components

- Waiting because all eligible cold stations are occupied
- Waiting because hazardous capacity is at ten
- Waiting for enough region-compatible orders to form a batch
- Waiting because an express order was selected first
- Suspension caused by an express order taking the resource

A practical attribution method is to evaluate facility state during every waiting interval:

1. Was the activity individually enabled?
2. Was a compatible resource available?
3. For a hazardous order, was \(H(t)<10\)?
4. Was the order held for a shipping batch?
5. Was a higher-priority order dispatched first?
6. Was the facility open and staffed?

Some intervals can be subject to multiple constraints. For example, a hazardous cold order may be blocked both by cold-station capacity and the hazardous limit. These periods should be classified as **dual-constrained** or allocated using counterfactual replay rather than double-counted. Explicit reason codes are the preferred long-term solution.

Time-to-start models with time-varying predictors—cold occupancy, hazardous occupancy, express queue length, batch backlog—can quantify associations. Simulation or matched comparisons should be used before claiming that those associations are causal.

## 2. Analyzing Constraint Interactions

The constraints should not be optimized independently because relieving one bottleneck can create or intensify another.

### 2.1 Express orders and cold-packing capacity

An express cold order has fewer compatible resources than an ordinary express order. It can:

- Move ahead of several standard cold orders
- Interrupt a standard cold order
- Increase setup or restart time
- Cause long-tail waiting for standard perishable orders
- Consume reserved express capacity even during periods of high cold demand

A policy that always gives immediate express priority may improve average express time but significantly worsen standard p95 time and total throughput.

### 2.2 Express orders and hazardous limits

An express hazardous order cannot be admitted to Packing or QC if ten hazardous orders are already active. Priority must not override compliance. To expedite such an order, the scheduler must accelerate completion of an existing hazardous activity or reserve predicted hazardous capacity in advance.

### 2.3 Cold-packing and hazardous-material constraints

Some orders may require both cold packing and hazardous handling. They compete simultaneously for:

- A cold-compatible station
- Hazardous facility capacity
- Potentially specially qualified personnel

Starting such an order when one downstream constraint is unavailable may create blocking or excessive WIP. The schedule should therefore consider its complete near-term resource path, not just the next available station.

### 2.4 Batching and hazardous orders

Waiting for a batch after QC completion does not count against the hazardous limit if the order is no longer undergoing Packing or QC. However, the constraints can still interact:

- Staggering hazardous orders to respect the limit may cause early orders to wait longer for their regional batch.
- Synchronizing hazardous orders to make a batch can create a wave at Packing or QC and drive \(H(t)\) to ten.
- A hazardous order delayed by the limit may miss a regional batch, adding an entire batch cycle to its lead time.

### 2.5 Batching and priority

Express orders should generally not wait for a large standard batch. However, unrestricted bypassing can create many small shipments and reduce route efficiency. A differentiated policy—express micro-batches, maximum waits, or late joining to an open batch—is needed.

### 2.6 Why interaction analysis matters

Local improvements can have adverse system effects:

- Adding a cold station may simply move the bottleneck to QC or the hazardous limit.
- Reducing batch size can overload label generation and shipping docks.
- Aggressive express preemption can lower packing productivity.
- Increasing hazardous admissions up to ten may create a QC queue and lengthen the time each order occupies regulated capacity.

I would quantify these interactions through cohort analysis—such as express-and-cold versus cold-only—and multivariate models with interaction terms. Simulation experiments should also vary policies jointly rather than one at a time.

## 3. Constraint-Aware Optimization Strategies

### Strategy 1: Rolling-horizon, constraint-aware scheduling

**Primary constraints:** Cold-packing contention, express priority, hazardous limit.

**Proposed changes**

Implement a scheduler that recalculates assignments every few minutes using:

- Current queues and station states
- Order deadlines and remaining SLA slack
- Cold-packing eligibility
- Express status
- Hazardous occupancy and predicted release times
- Estimated processing and setup times
- Downstream QC capacity

The scheduler should use the hazardous limit as a hard constraint and minimize a weighted combination of:

- Predicted lateness
- Queue time
- Number and cost of preemptions
- Standard-order starvation
- Station idle time

Express priority should be deadline- and cost-aware rather than unconditional. Suggested rules include:

- Reserve cold capacity for express orders only when forecast demand justifies it.
- Allow preemption only at safe checkpoints.
- Do not preempt a standard order that is almost complete if the time saved is smaller than the interruption cost.
- Add an aging factor so long-waiting standard orders gradually gain priority.

**Use of data**

Historical data provides arrival forecasts, service-time distributions, interruption costs, and deadline-risk models by order type, station, product mix, and shift.

**Expected outcome**

- Lower p95 cold-packing queue time
- Fewer unnecessary preemptions
- Better express SLA performance without starving standard orders
- Zero hazardous-limit violations
- Higher resource productivity due to reduced stop/restart loss

### Strategy 2: Dynamic regional batching with maximum-wait guarantees

**Primary constraints:** Shipping batch delay and its interaction with priority and upstream constraints.

**Proposed changes**

Replace fixed-size batching with region-specific dynamic triggers. Close a batch when the first applicable condition occurs:

- Target size is reached
- Maximum wait is reached
- Carrier or route cutoff is approaching
- Predicted arrivals indicate that waiting will not produce a sufficiently larger batch
- An included order is at risk of missing SLA

Further refinements:

- Allow express orders to bypass ordinary batches or form small express micro-batches.
- Permit late joining until the shipping manifest is locked.
- Use different thresholds for high-volume and low-volume regions.
- Separate label generation from final route consolidation where technically possible: generate labels earlier, then assign the order to the final manifest later.
- Apply compatibility rules for hazardous or temperature-controlled shipments.

**Use of data**

Use historical inter-arrival times by region, time of day, day of week, and season to predict time to the next compatible order. Optimize thresholds against both delivery time and transport cost.

**Expected outcome**

- Reduced batch-formation waiting, especially for low-volume regions
- Fewer missed carrier cutoffs
- Less unnecessary waiting by completed orders
- Controlled reduction in batch efficiency rather than indiscriminate small batches
- Better handling of express and hazard-delayed orders

### Strategy 3: Flexible Cold-Packing capacity and a single virtual queue

**Primary constraint:** Limited Cold-Packing capacity.

**Proposed changes**

- Create one virtual queue for all cold-packing orders rather than separate informal station queues.
- Route the next order to the first compatible available station.
- Cross-train staff to operate cold-packing stations.
- Convert selected standard stations into cold-capable stations during predicted peaks, if facility design permits.
- Use temporary peak-season capacity or extended shifts when the modeled benefit exceeds cost.
- Schedule cleaning, maintenance, and replenishment during low-demand windows.
- Display real-time cold-station availability and queue risk to supervisors.

Capacity should be elastic rather than permanently dedicated. A station reserved continuously for express work may remain idle while standard cold orders wait.

**Use of data**

Forecast cold-order arrivals at 15- or 30-minute intervals using historical demand, promotions, seasonality, and order composition. Simulation should determine activation thresholds for an additional flexible station.

**Expected outcome**

- Reduced saturation periods and queue lengths
- Better utilization across cold stations
- Lower standard-order tail delays during express bursts
- Improved peak-season throughput without necessarily requiring permanent capital expansion

### Strategy 4: Hazardous-material admission control and flow acceleration

**Primary constraint:** Facility-wide limit of ten hazardous orders in Packing or QC.

**Proposed changes**

Implement an electronic hazardous-work permit or token system:

- A hazardous activity can start only if a permit is available.
- Permit allocation is controlled centrally across Packing and QC.
- The system gives visibility into expected permit release times.
- Hazardous orders are staged before the regulated activity rather than started and then blocked.

To increase throughput without violating the limit:

- Schedule hazardous work into rolling time slots based on predicted durations.
- Ensure hazardous QC capacity is available before releasing large waves into Packing.
- Cross-train qualified hazardous-material staff.
- Prioritize rapid handoff between Packing and QC.
- Reduce avoidable QC and documentation delay through pre-validation.
- Coordinate hazardous admission with regional batch cutoffs so orders are not released too early or too late.

**Use of data**

Estimate permit occupation times by product type, resource, and shift. Identify whether Packing or QC is responsible for most regulated occupancy and target the longer component.

**Expected outcome**

- Compliance maintained at all times
- Lower hazardous queue time despite the unchanged legal limit
- More hazardous orders completed per regulated-capacity hour
- Reduced periods where ten orders are active but some are waiting rather than progressing
- Fewer hazardous orders missing regional batches

## 4. Simulation and Validation

A discrete-event simulation or object-centric digital twin should be built before implementation. A conventional process model without shared state is insufficient because it would miss the instance-spanning behavior.

### 4.1 Model components

The simulation should represent:

#### Order arrivals

- Time-varying arrival rates
- Peak-season surges
- Joint distributions of express, cold, hazardous, region, and order complexity
- Actual correlations—for example, whether certain regions have more cold orders

#### Activities and resources

- Processing-time distributions by activity and order type
- Staff and station calendars
- Cold-station compatibility
- Standard and cold station capacity
- QC resources
- Breakdowns, cleaning, setup, and shift changes

#### Queueing and preemption

- FCFS, priority, deadline-slack, and aging rules
- Preempt-resume behavior
- Restart/setup penalties
- Non-preemptable checkpoints
- Dedicated versus dynamically reserved capacity

#### Batching

- Region-specific batch objects
- Minimum/target sizes
- Maximum waits
- Carrier cutoffs
- Predicted-arrival triggers
- Express bypass or micro-batches
- Label-generation and downstream capacity

#### Hazardous-material rule

A global semaphore or token pool of size ten must govern hazardous Packing and QC. The model must never allow an eleventh active hazardous order. It should also model separate admission to Packing and QC if the regulation applies only while the order is actively undergoing those activities.

### 4.2 Calibration and baseline validation

Parameters should be fitted from the event log, conditional on relevant attributes rather than using a single average service time. Baseline simulation output should reproduce:

- End-to-end cycle-time distribution
- Activity and queue-time distributions
- Cold-station utilization and saturation
- Batch sizes and formation times
- Express preemption frequency
- Hazardous occupancy profile
- Throughput by shift and order type

If the baseline cannot reproduce these measures, proposed scenario results should not be trusted.

### 4.3 Experiment design

Test individual and combined scenarios, for example:

- Current policy
- Dynamic scheduling only
- Dynamic batching only
- One additional flexible cold station
- Checkpoint-based express preemption
- Hazard admission control and faster QC
- Combined policy package

Use:

- Multiple replications and confidence intervals
- Peak-demand stress tests
- Station-failure and staff-absence scenarios
- Sensitivity analysis for processing-time and arrival uncertainty
- Factorial experiments to reveal constraint interactions

### 4.4 KPIs and decision criteria

Evaluate:

- Average and p95 end-to-end fulfillment time
- SLA attainment by express, standard, cold, and hazardous segments
- Throughput per hour/shift
- Queue lengths and blocked order-minutes
- Resource utilization and overtime
- Batch efficiency and transport-cost proxy
- Preemption and context-switch cost
- Quality/rework rates
- Maximum hazardous occupancy and violation count

A strategy should only be accepted if hazardous violations remain zero and improvements are not achieved by creating unacceptable quality, cost, or standard-order fairness problems.

## 5. Monitoring Post-Implementation

### 5.1 Executive flow and SLA dashboard

Track:

- End-to-end time and p50/p90/p95 values
- SLA attainment by order type, region, cold requirement, and hazardous flag
- Throughput per hour and shift
- Work in process by process stage
- Touch-time versus waiting-time decomposition
- Missed carrier cutoffs
- Volume- and mix-adjusted comparison with the pre-implementation baseline

If delivery is the ultimate objective, carrier handoff and delivery events should be added; otherwise label generation is only an intermediate proxy.

### 5.2 Cold-Packing dashboard

Track:

- Current and historical queue length
- Queue time distribution
- Station utilization
- Percentage of time all stations are busy
- Blocked order-minutes
- Idle-with-queue occurrences
- Downtime, cleaning, and staffing losses
- Express versus standard queue times
- Activation and benefit of flexible stations

Alerts should identify sustained saturation, growing p95 queue time, or an idle compatible station while orders are waiting.

### 5.3 Shipping-batch dashboard

Track:

- Batch size and fill ratio by region
- Batch-open-to-close time
- Individual order batch wait
- Percentage closed by size, timeout, SLA trigger, or cutoff
- Orders missing a batch by a short interval
- Express bypass and micro-batch rate
- Label-generation bursts and downstream congestion
- Delivery-time improvement versus transport-cost impact

### 5.4 Priority and fairness dashboard

Track:

- Express and standard queue-time distributions
- Number and duration of preemptions
- Productive time lost to interruption
- Express minutes saved versus standard minutes added
- Standard-order aging and starvation indicators
- Priority-rule conformance
- Express and standard SLA rates during demand bursts

This prevents improvement in express performance from masking unacceptable degradation of standard orders.

### 5.5 Hazardous-compliance dashboard

Track in real time:

- Current hazardous occupancy \(H(t)\)
- Maximum occupancy
- Minutes at ten
- Attempted starts blocked by the limit
- Queue time before hazardous Packing and QC
- Permit occupation time
- Hazardous throughput per permit-hour
- Time spent in Packing versus QC
- Violations, which should remain zero

The dashboard should distinguish efficient use of the legal capacity from simple saturation. Being at ten for long periods is only beneficial if those orders are actively progressing.

### 5.6 Interaction and conformance dashboard

Create cohort views for:

- Express + cold
- Hazardous + cold
- Express + hazardous
- Hazardous orders by destination batch
- Peak versus non-peak periods

Also run continuous conformance checks for:

- No more than ten hazardous orders active
- No overlapping assignments on the same station
- Cold orders using eligible stations
- Valid batch region and compatibility
- Maximum batch-wait rules
- Allowed preemption points
- Required priority and aging policies

Finally, use statistical process control and weekly or monthly counterfactual comparisons normalized for volume, season, order mix, and staffing. This will show whether reduced queues and faster batches come from the new policies rather than from temporarily lower demand.
