Cases 1 and 4 are the only cases conforming to the normative description.

The normative model defines two mutually exclusive trace variants:

* **Sufficient inventory:** `Receive order > Check inventory > Authorize payment > Package items > Ship order > Close order`
* **Insufficient inventory:** `Receive order > Check inventory > Cancel order > Close order`

With derived constraints:

1. `Receive order` first, `Close order` last.
2. `Check inventory` before any decision about payment or fulfillment - i.e. before `Authorize payment`, `Package items`, `Ship order`, `Cancel order`.
3. `Authorize payment` only after `Check inventory` and before `Package items`.
4. `Package items` only after `Authorize payment` and before `Ship order`.
5. `Ship order` only after `Package items` and never after `Cancel order`.
6. `Authorize payment / Package items / Ship order` and `Cancel order` are exclusive. It is `illogical to continue with activities intended for fulfillment after a cancellation`.

#### Case 1 - Compliant
```
Receive > Check > Authorize > Package > Ship > Close
```
Exactly the sufficient-inventory variant.

#### Case 4 - Compliant
```
Receive > Check > Cancel > Close
```
Exactly the insufficient-inventory variant.

#### Cases violating:

**Case 2 - Violates ordering Authorize vs Package**
```
Receive 09:00 > Check 09:30 > Package 10:00 > Authorize 10:30 > Ship 11:00 > Close 11:30
```
* Violation of "Package items should only occur after authorization and before shipping" and "Any deviation such as ... packaging items before authorization—would be considered a violation" and "Authorize payment should only occur ... before packaging".
* The trace shows `Package items` before `Authorize payment`. Payment must be validated before preparing goods.

**Case 3 - Violates exclusivity of branches + shipping after cancellation**
```
Receive > Check > Authorize > Cancel > Ship > Close
```
* Violation of branch logic: After `Check inventory` you must go EITHER to the fulfillment branch OR to the cancellation branch. This case does both `Authorize payment` - indicating sufficient inventory - and then `Cancel order` - indicating insufficient inventory.
* Violation of "Ship order should only occur after packaging and never after a cancellation" and "Once an order is canceled, it would be illogical to continue with activities intended for fulfillment - such as packaging or shipping". `Ship order` at 10:30 occurs after `Cancel order` at 10:00.
* Violation of `Package items` missing although `Ship order` occurred - `Ship` should only occur after packaging.

This is a double deviation.

**Case 5 - Violates mandatory packaging before shipping**
```
Receive > Check > Authorize > Ship > Close
```
* Missing `Package items`. Violation of "Once the payment is authorized, the items should be prepared for shipment... Only after items have been properly packaged is it appropriate to proceed with Ship order" and "Package items should only occur after authorization and before shipping" / "Ship order should only occur after packaging".
* While it follows the `Authorize > Ship > Close` order, it skips the mandatory preparation step. In the sufficient-inventory narrative, the entire sequence `Receive, Check, Authorize, Package, Ship, Close` is defined as the expected flow.

In summary, **2, 3, 5 are non-conformant**, with 3 being the most severe: mixing both exclusive choices and shipping a canceled order.
