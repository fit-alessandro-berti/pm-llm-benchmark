In DuckDB you can solve this with `STRING_AGG / LIST ... ORDER BY` + CTEs:

```sql
-- Set K = Top K variants to keep
-- e.g. 5
WITH case_variants AS (
    -- 1. Ordered sequence per case_id = process variant
    SELECT
        case_id,
        STRING_AGG(activity, '->' ORDER BY timestamp) AS variant,
        LIST(activity ORDER BY timestamp) AS variant_list -- type-safe alternative
    FROM event_log
    GROUP BY case_id
),
variant_stats AS (
    -- 2. Group by complete variant and count cases
    SELECT
        variant,
        COUNT(*) AS case_count
    FROM case_variants
    GROUP BY variant
),
top_k_variants AS (
    -- 3. Top K variants by frequency
    SELECT variant
    FROM variant_stats
    ORDER BY case_count DESC, variant ASC
    LIMIT 5 -- Replace 5 with K  -- In DuckDB >= 1.1 you can use LIMIT $K
)
-- 4. Return all original events belonging to top K variants
SELECT e.*
FROM event_log e
JOIN case_variants cv USING (case_id)
WHERE cv.variant IN (SELECT variant FROM top_k_variants)
ORDER BY e.case_id, e.timestamp;
```

#### What it does

1.  `case_variants`: For each `case_id`, `STRING_AGG(activity, '->' ORDER BY timestamp)` / `LIST(activity ORDER BY timestamp)` builds the ordered activity sequence.
2.  `variant_stats`: `GROUP BY variant` to identify unique variants and `COUNT(*)` = number of cases per variant.
3.  `top_k_variants`: `ORDER BY case_count DESC LIMIT K` gets the most frequent variants.
4.  Final `SELECT`: Joins back to `event_log` and filters out cases whose variant is not in `top_k_variants`.
