# 1. Identifying Instance-Spanning Constraints and Their Impact

The process should be analyzed as a multi-object, resource-constrained system, not simply as a collection of independent order traces. Traditional case-centric process mining will identify long paths such as `Quality Check  Shipping Label Generation`, but it will not explain whether the delay was caused by another order, a batch, a priority rule, or an unavailable resource.

## 1.1 Prepare an object-centric, lifecycle-aware event log

The existing log should be transformed or enriched so that events can be related to several object types:

- **Order**
- **Packing station**
- **Employee/resource**
- **Shipping batch**
- **Destination region**
- **Hazardous-material capacity token**, conceptually
- **Carrier departure**, if relevant

A batch-closing or label-generation event should be linked to all member orders rather than duplicated as an unrelated event in each order trace. This makes object-centric process mining, or OCEL-style analysis, particularly appropriate.

The following additional events or attributes are important:

- Activity enabled/ready time
- Queue entry and exit
- Resource assignment
- `PAUSE` and `RESUME`, particularly for preemption
- Batch opened, order added, batch closed, batch dispatched
- Hazardous-capacity token acquired and released
- Reason an eligible order was not dispatched, such as:
  - `COLD_STATIONS_FULL`
  - `HAZARDOUS_CAP_REACHED`
  - `WAITING_FOR_BATCH`
  - `PREEMPTED_BY_EXPRESS`
  - `NO_QUALIFIED_STAFF`

Without such events, likely causes can be inferred from system state, but they cannot always be proven from `START` and `COMPLETE` timestamps alone.

The analysis would then use:

1. **Process discovery** to establish the normal intra-order flow and variants.
2. **Conformance checking** to detect deviations and violations.
3. **Object-centric process mining** to reveal relationships among orders, batches, stations, and resources.
4. **Queue and resource-state reconstruction** by replaying start, pause, resume, and completion events over time.
5. **Timed or colored Petri-net models** to represent capacities:
   - Five tokens for cold-packing stations
   - Ten tokens for hazardous orders
   - Batch synchronization conditions
   - Priority dispatch and preemption rules

## 1.2 Separating processing time from waiting time

For order \(i\) and activity \(a\), define:

- \(r_{ia}\): time the activity became enabled or ready
- \(s_{ia}\): actual start time
- \(c_{ia}\): completion time
- \(p_{ia}\): active processing time
- \(u_{ia}\): paused or interrupted time

Then:

\[
c_{ia} - r_{ia}
=
(s_{ia}-r_{ia}) + p_{ia} + u_{ia}
\]

Where:

- \(s-r\) is pre-start queueing time.
- \(p\) is actual work time.
- \(u\) is interruption time after the activity has started.

A long active duration caused by order complexity is primarily a **within-instance** factor for that order. However, it can become an **instance-spanning** factor for other orders because the long-running order occupies a shared resource.

For each waiting interval, the facility state should be replayed:

- Were all eligible cold stations occupied?
- Was the hazardous count at ten?
- Was an express order using or taking over the resource?
- Was the order assigned to an open batch?
- Was a station available but no qualified employee available?
- Was the order simply not selected despite available capacity?

Where two causes overlap, the analysis should avoid double-counting. The scheduler should ideally record the primary blocking reason. For historical data, a counterfactual simulation or attribution method can estimate the marginal effect of each cause.

## 1.3 Constraint-specific identification and metrics

| Constraint | Formal identification | Primary impact metrics |
|---|---|---|
| **Shared cold-packing stations** | Reconstruct occupancy \(N_C(t)\) from cold-station activity intervals. A cold order is resource-blocked when ready but not started while all five eligible stations are occupied. Include staff availability if both a station and certified worker are required. | Cold queue length; average and P90/P95 cold wait; percentage of time all five stations are busy; station utilization; cold-order SLA miss rate; resource-blocked order-hours; throughput per cold station; standard versus express wait. |
| **Shipping batches** | Create a batch object with member orders and open/close times. For order \(i\) in batch \(B\), compare its QC completion time with batch closure and label-generation time. | QC-to-batch-close wait; QC-to-label time; oldest-order age at batch closure; batch size/fill rate; percentage closed by size, timeout, or carrier cutoff; missed departures; total waiting externality imposed by a late batch member. |
| **Express priority and preemption** | Detect overtaking when an express order becomes ready later but starts before a standard order waiting for the same eligible resource. Detect direct preemption through `PAUSE/RESUME` or validated resource-overlap evidence. | Express time-to-start and SLA; preemption count; interruption duration; setup/restart loss; standard-order delay; standard queue-age distribution; starvation rate; express gain versus standard penalty. |
| **Hazardous-material limit** | Reconstruct \(H(t)\), the number of distinct hazardous orders considered to be undergoing Packing or QC. Perform interval conformance checking against \(H(t)\leq10\). | Maximum \(H(t)\); time at 8, 9, and 10; violation count and duration; hazardous queue length; wait while cap is binding; token turnover; hazardous throughput; hazardous SLA; facility throughput impact. |

### Cold-packing impact

For a cold order, use Picking completion or another confirmed readiness event as the packing-ready timestamp. Its observed cold contention exposure can be approximated by:

\[
\int_{r_i}^{s_i} \mathbf{1}[N_C(t)=5]\,dt
\]

This distinguishes cold-station saturation from other delays. Average utilization alone is insufficient because short periods of full saturation can produce long queues despite moderate daily utilization.

To estimate the causal impact, compare:

- Matched time windows with similar arrivals, shift, staffing, and order mix but different cold occupancy
- A simulated capacity-five baseline against capacity-six or temporarily flexible capacity
- Observed waits against expected waits from a queueing model

### Shipping-batch impact

For batch \(B\), let:

- \(q_i\): QC completion for order \(i\)
- \(t_B\): batch closure
- \(l_B\): label-generation completion

Then:

\[
\text{Batch formation wait}_i = t_B-q_i
\]

\[
\text{Post-closure label delay}_i = l_B-t_B
\]

This prevents label-system processing delays from being incorrectly attributed to batching. If only a label `COMPLETE` event is available, a label start or batch-close event should be added.

The effect of a late member can also be quantified as:

\[
\sum_{i \in B}(t_B-q_i)
\]

This represents the aggregate order-minutes consumed while the batch forms.

### Priority-handling impact

Two effects should be measured separately:

1. **Direct interruption:** a standard activity is paused while an express order uses the required resource.
2. **Queue overtaking:** the standard order has not started but loses its next resource opportunity.

Not every standard-order delay occurring near an express order should be attributed to priority. A credible estimate should compare the actual schedule with a counterfactual schedule using the same arrivals and service times but without express preemption. Matched-cohort or regression analysis can be used as an interim method.

Key outcomes are:

- Minutes of express lead-time saved
- Minutes of standard delay introduced
- Restart/setup waste
- Standard-order starvation or excessive aging
- Net SLA benefit across both classes

### Hazardous-material limit impact

The hazardous count should be calculated as:

\[
H(t)=
\left|
\left\{
i:
i\text{ is hazardous and is undergoing Packing or QC at }t
\right\}
\right|
\]

Distinct orders should be counted once. Whether a paused hazardous activity continues to count must follow the exact regulatory interpretation.

A hazardous order ready to start while \(H(t)=10\) is potentially blocked by the global limit. The analysis should calculate:

- Percentage of operating time at the limit
- Waiting time while the cap is binding
- The number of orders blocked
- Hazardous throughput per occupied token-hour
- Maximum and average hazardous WIP

The throughput reduction can be estimated through a counterfactual model:

\[
\Delta TH_H =
TH_{\text{diagnostic uncapped}} - TH_{\text{cap 10}}
\]

The uncapped case is only for measuring impact, not as an operational proposal. More useful legal comparisons are cap-ten scheduling under the current policy versus cap-ten scheduling under improved release and sequencing policies.

# 2. Analyzing Constraint Interactions

The constraints should not be optimized independently because an intervention at one point can move or amplify the bottleneck elsewhere.

## 2.1 Express orders and cold-packing

An express cold order competes for one of only five stations. Aggressive preemption may:

- Shorten the express order’s queue time
- Increase standard-order interruption and restart time
- Cause standard-order starvation
- Increase setup, cleaning, or temperature-control loss
- Extend the period during which all stations remain occupied

If packing is not safely resumable, preemption may create more overall delay than it saves. A next-available-slot rule may outperform mid-activity interruption.

## 2.2 Cold-packing and hazardous-material capacity

An order can be both cold and hazardous. It then consumes two constrained capacities:

- A cold-packing station
- One unit of the global hazardous allowance

Adding another cold station may produce little benefit if hazardous capacity or downstream QC is already the binding constraint. Conversely, poor QC availability can cause hazardous packing work to remain open longer, reducing hazardous-token turnover.

## 2.3 Hazardous orders and shipping batches

If several hazardous orders belong to the same regional batch, the global cap can delay the last required member. Earlier completed orders then wait for that one order, amplifying its delay across the batch.

Because batching occurs after QC, batch waiting should ordinarily not consume hazardous Packing/QC capacity. If the process keeps QC activities technically open while waiting for a batch, that is both a process-design and logging issue. QC should be completed and the order moved to compliant staging unless regulations require otherwise.

## 2.4 Express orders and batching

An express order may:

- Wait for a regional batch, undermining its priority
- Cause a batch to close early, reducing vehicle or route utilization
- Bypass the batch, improving SLA but increasing shipping cost
- Shift the remaining orders into a later departure

Therefore, the correct policy requires a joint SLA-versus-consolidation decision rather than a universal “express always bypasses” rule.

## 2.5 Release waves and downstream congestion

Regional batching, picking waves, or synchronized shift practices can produce bursts that saturate Packing, QC, or Label Generation. Increasing one resource can therefore move the bottleneck to the next stage.

These interactions should be quantified by creating system-state features at each order’s readiness time:

- Cold occupancy
- Hazardous occupancy
- Express arrivals in the previous and next time window
- Queue lengths
- Batch age and expected missing members
- Staffing level
- Order’s combination of cold, hazardous, express, and region attributes

Regression, survival analysis, performance cubes, and simulation experiments with interaction terms can then identify combinations such as `Cold × Express` or `Hazardous × Batch position` that create disproportionate delay.

Understanding these interactions is essential because local optimization can improve one KPI while worsening total flow time, fairness, compliance, or shipping cost.

# 3. Constraint-Aware Optimization Strategies

## Strategy 1: Predictive flexing of cold-packing capacity

### Constraints addressed

- Shared cold-packing stations
- Express-order competition
- Indirect interaction with hazardous orders and QC

### Proposed changes

- Forecast cold-packing demand over rolling 15–60 minute horizons using current arrivals, order attributes, historical seasonal patterns, and picking completion predictions.
- Create one or more pre-certified flexible stations that can switch between standard and cold packing when projected cold wait exceeds a threshold.
- Cross-train staff so that physical cold stations are not idle due to lack of qualified employees.
- Use conditional express capacity reservation. A station should be kept available for express work only when an express arrival is likely or an express order is near SLA breach; otherwise, the capacity is released to standard work.
- If demand is persistently above sustainable capacity, use simulation and cost analysis to justify a sixth permanent cold station.

### Use of data

The trigger policy should be based on:

- Time-of-day and day-of-week arrival rates
- P90/P95 cold-packing service times
- Expected picking completions
- Historical cold utilization and queue growth
- Express and hazardous proportions
- Shift and employee qualification calendars

### Expected outcome

- Lower cold-station saturation exposure
- Reduced P90/P95 cold queue time
- Fewer express preemptions
- Better utilization than a permanently reserved express station
- Capacity investment only where it provides end-to-end benefit rather than moving the bottleneck to QC

---

## Strategy 2: Rolling-horizon, constraint-aware dispatching

### Constraints addressed

- Express priority
- Cold-station contention
- Hazardous-material limit
- Standard-order starvation

### Proposed changes

Implement a central dispatcher for Packing and QC using a rolling-horizon optimization model or a transparent priority heuristic.

Each candidate order would receive a score based on:

- Remaining SLA slack or earliest due date
- Express status
- Queue age
- Expected processing time
- Cold-station eligibility
- Hazardous status and available hazardous capacity
- Downstream QC availability
- Batch or carrier cutoff risk

Hard constraints would include:

- No more than five cold stations in use
- No more than ten hazardous orders in the regulated state
- Employee qualifications and shift calendars
- Safe resource eligibility

Priority should not mean unconditional preemption. Recommended rules are:

- Prefer non-preemptive processing for short packing tasks.
- Permit preemption only at safe, resumable boundaries.
- Preempt only when the predicted express SLA benefit exceeds setup and standard-delay costs.
- Apply an aging term or maximum-wait rule so standard orders cannot be starved.
- Reserve downstream QC capacity before starting a hazardous order where otherwise it would remain open and consume limited capacity unnecessarily.

### Use of data

Historical data supplies:

- Conditional activity-time distributions
- Preemption and restart costs
- SLA-risk predictions
- Queue-aging effects
- Resource qualification and performance profiles
- Probability that downstream capacity will be available

### Expected outcome

- Improved express SLA with lower disruption to standard orders
- Reduced unnecessary preemption
- Better fairness and more predictable standard-order lead times
- Higher throughput from coordinating Packing and QC rather than scheduling each independently
- Compliance enforced as a hard scheduling condition

---

## Strategy 3: Dynamic batching with maximum-wait and cutoff rules

### Constraints addressed

- Shipping-batch delays
- Express-order SLA
- Hazardous orders delaying batch closure

### Proposed changes

Replace fixed or informal batching with dynamic regional batching. Close a batch when the first applicable condition occurs:

- Target batch size reached
- Oldest member reaches a maximum wait
- Carrier departure cutoff approaches
- Predicted near-term arrivals are too low to justify further waiting
- The expected delay cost exceeds the expected consolidation benefit

Additional rules should include:

- Express orders bypass or use a small express batch if waiting would jeopardize SLA.
- Do not hold a regional batch open for a hazardous order that remains blocked upstream unless it is predicted to arrive within the allowed wait.
- Carry the delayed order into the next batch instead.
- Where technically feasible, generate address and compliance portions of a label immediately after QC and apply route-specific information when the shipment is assigned. This decouples administrative label work from final route consolidation.
- Record explicit `BATCH_OPEN`, `ORDER_ADDED`, `BATCH_CLOSE`, and `DISPATCH` events.

### Use of data

The batch-closing decision can use:

- Region-specific arrival forecasts
- Historical batch fill times
- Carrier schedules and costs
- SLA penalties
- Distribution of upstream hazardous and cold delays
- Probability that expected orders will arrive before cutoff

### Expected outcome

- Lower QC-to-label waiting time
- Fewer missed carrier departures
- Predictable maximum batch wait
- Better balance between route utilization and customer lead time
- Reduced amplification of one late order’s delay across an entire batch

---

## Strategy 4: Hazardous-WIP gating and fast token turnover

### Constraints addressed

- Global hazardous-material limit
- Interaction with Packing, QC, cold orders, and batching

### Proposed changes

Implement a facility-wide electronic hazardous-capacity controller:

- A hazardous order may enter the regulated stage only when a token is available.
- Token acquisition and release must correspond exactly to the regulatory definition of “undergoing Packing or QC.”
- Use a warning level of eight or nine if needed to protect against delayed events or operational uncertainty; ten remains the legal maximum.
- Stage paperwork, materials, and approved preparatory work before acquiring a token, where regulations allow.
- Coordinate Packing and QC so hazardous orders can move through both stages without unnecessary open or paused time.
- Provide certified floating QC capacity during predicted hazardous peaks.
- Complete QC before batch waiting and move the order to compliant staging so batch delays do not retain regulated capacity.
- Sequence hazardous work by due-date slack and expected duration, while still giving express orders appropriate weight.

### Use of data

The policy should use:

- Hazardous arrivals by time and order type
- Packing and QC duration distributions
- Time spent at the cap
- Downstream QC congestion
- Token turnover rate
- The number of orders that are simultaneously cold, hazardous, and express

### Expected outcome

- Zero regulatory violations
- Lower hazardous queue time
- More hazardous orders completed per permitted concurrent slot
- Reduced time at the legal limit
- Higher throughput without attempting to increase legally restricted concurrency

# 4. Simulation and Validation

A process-mining-informed **object-centric discrete-event simulation** is the most appropriate validation method. A timed colored Petri net or agent-based component can also be used where complex dispatch behavior is required.

## 4.1 Calibrate the baseline model

The simulation should be mined and calibrated from the historical event log, including:

- Time-varying arrival rates by shift, weekday, and season
- Joint distributions of order type, cold requirement, hazardous status, region, and order size
- Activity-time distributions conditioned on order attributes
- Resource calendars, qualifications, breaks, and downtime
- Rework and exceptional process variants
- Current dispatch and preemption rules
- Batch membership, fill behavior, and carrier cutoffs

Correlations should be preserved. For example, cold, hazardous, and express attributes should not be sampled independently if historical data shows they are related.

The baseline model should reproduce held-out historical values for:

- Cycle-time distributions
- Queue lengths
- Station utilization
- Batch sizes and formation times
- Number of preemptions
- Hazardous occupancy profile
- Throughput and SLA rates

## 4.2 Explicitly model instance-spanning behavior

The simulation must include:

### Resource contention

- Exactly five cold-station capacity units
- Standard-station and cold-station eligibility
- Required employee qualifications
- Shift calendars and downtime
- Queue discipline and resource assignment

### Batching

- Batch objects by region
- Batch-open and batch-close logic
- Size, timeout, and cutoff triggers
- Express exceptions
- Label-generation capacity
- Carrier departure schedules

### Priority interruption

- Queue overtaking
- Preemptive-resume or preemptive-restart behavior
- Setup and restart penalties
- Safe preemption points
- Aging and anti-starvation rules

### Hazardous-material limit

- A global semaphore of ten hazardous orders
- Exact acquisition and release semantics
- Correct treatment of paused orders
- A hard simulation assertion that the cap is never exceeded
- Interaction with both Packing and QC

## 4.3 Experimental design

Test the strategies individually and in combinations:

1. Current baseline
2. Dynamic cold capacity only
3. New dispatching only
4. Dynamic batching only
5. Hazardous-WIP gating only
6. Combined strategy
7. Capacity-five versus capacity-six cold packing
8. Current priority versus threshold-based or non-preemptive priority
9. Peak-season and demand-spike scenarios

A factorial design is valuable because it quantifies interaction effects—for example, whether an additional cold station is only beneficial when QC scheduling is also improved.

Each scenario should use multiple replications, common random-number streams, and confidence intervals. Key evaluation measures should include:

- Mean and P90/P95 end-to-end time
- SLA attainment by standard and express class
- Total and hazardous throughput
- Cold queue and utilization
- Standard-order fairness and maximum wait
- Preemption and restart cost
- Batch fill rate and shipping cost
- Hazardous-cap compliance
- Labor and equipment cost

The selected policy should be Pareto-efficient: improving lead time and throughput without unacceptable losses in compliance, fairness, or consolidation efficiency.

A limited pilot on one shift or one region should follow simulation before facility-wide deployment.

# 5. Monitoring Post-Implementation

Post-implementation monitoring should continue to use object-centric process mining and explicit constraint-state metrics. Averages should always be supplemented with percentiles and peak-period views.

## 5.1 Overall flow dashboard

Track:

- Orders completed per hour and shift
- End-to-end time: mean, median, P90, and P95
- SLA attainment by express/standard, region, cold, and hazardous status
- WIP by activity
- Queue time versus active processing time
- Rework and process-variant rates
- Bottleneck location over time
- Attributed delay waterfall:
  - Cold contention
  - Hazardous cap
  - Batch formation
  - Priority interruption
  - Staff or system unavailability
  - Within-order processing

## 5.2 Cold-packing dashboard

Track:

- Number of occupied cold stations over time
- Percentage of time all stations are occupied
- Current and P95 queue length
- Ready-to-start waiting time
- Wait by standard and express class
- Number and duration of preemptions
- Forecast demand versus available capacity
- Flexible-station activation and resulting benefit
- Cold throughput per station-hour

An alert should fire when the predicted queue or oldest waiting order exceeds the operating threshold, not merely when utilization is high.

## 5.3 Batch-performance dashboard

Track by region:

- Open batch count
- Age of the oldest order in each batch
- Average and P95 batch-formation time
- Average batch size and fill rate
- Percentage closed by size, timeout, or carrier cutoff
- Orders removed or deferred to the next batch
- Express bypass rate
- Missed departures
- Label-generation delay after batch closure
- Shipping consolidation cost versus SLA performance

This dashboard should distinguish formation delay from post-closure label-system delay.

## 5.4 Priority and fairness dashboard

Track:

- Express time to resource assignment
- Express SLA attainment
- Standard-order delay attributable to express handling
- Overtaking count
- Preemption count and interruption minutes
- Restart/setup loss
- Oldest standard order in each queue
- Percentage of standard orders exceeding maximum queue age
- Express lead-time gain versus aggregate standard penalty

This prevents an apparent express improvement from hiding excessive disruption to standard flow.

## 5.5 Hazardous-compliance dashboard

Track:

- Live \(H(t)\) across Packing and QC
- Time at eight, nine, and ten
- Number and duration of cap violations—target must remain zero
- Hazardous queue length and P95 wait
- Number blocked by the cap
- Token holding time and turnover
- Hazardous throughput per token-hour
- Time between hazardous Packing and QC
- Hazardous orders waiting for a batch after QC
- Hazardous SLA performance

A critical real-time alert is required for any \(H(t)>10\), with warning alerts as the facility approaches the cap.

## 5.6 Interaction and conformance dashboard

Use an object-centric performance view to show orders affected by multiple constraints:

- Cold and express
- Cold and hazardous
- Hazardous and batch-delayed
- Cold, hazardous, and express
- Batch wait after an upstream priority or hazardous delay

Conformance rules should continuously verify:

- Cold orders use eligible stations
- No station is double-booked unless a valid pause exists
- Hazardous occupancy never exceeds ten
- Batch members meet region rules
- Batch maximum-wait rules are respected
- Preemption occurs only under approved conditions
- Standard-order aging rules are respected

Control charts and drift detection should compare current performance with the post-pilot baseline. This is particularly important during peak season, when arrival mix and interactions may change even if average demand appears stable.

The overall implementation sequence should therefore be: improve event instrumentation, build the object-centric baseline, quantify and simulate constraints jointly, pilot the selected policies, and then monitor both flow KPIs and constraint-specific state metrics continuously.
