**High-Level Process Steps (Aggregated Activities)**

The low-level events follow a highly consistent sequential pattern across cases (A1, B2, and by extension the full log). They form four coherent manufacturing stages based on:
- Temporal clustering (events within each stage occur in rapid succession, with larger gaps between stages).
- Shared purpose / logical dependency (preparation → joining → finishing → verification).
- Resource affinity (same operator/machine type or hand-off points mark stage boundaries).
- Domain semantics of metal fabrication (sheet prep → welding → protective coating → final QA).

### 1. Material Preparation
**Low-level events included:**
- Retrieve raw metal sheet  
- Scan barcode  
- Place metal sheet on table  
- Align metal sheet  
- Preheat metal sheet  

**Rationale:**  
These form the initial setup phase. All actions prepare a single raw sheet for downstream processing. They are performed primarily by Operator A + Robot Arm #2 + Heating Unit #1 in a tight time window (~20–25 s), establish material identity and positioning, and end with the thermal precondition required before welding. No value-adding joining or finishing occurs yet.

**Suggested high-level name:** `Material Preparation`

### 2. Welding (Assembly)
**Low-level events included:**
- Pick up welding tool  
- Weld corner A  
- Weld corner B  

**Rationale:**  
These constitute the core joining/assembly operation. Operator B uses a single tool (W-12) to perform sequential spot welds. The events are temporally contiguous and resource-homogeneous. The subsequent integrity measurement is deliberately excluded so that pure execution remains distinct from verification.

**Suggested high-level name:** `Welding`

### 3. Weld Integrity Check
**Low-level events included:**
- Measure weld integrity  

**Rationale:**  
This is a dedicated in-process quality gate performed by Quality Sensor #1 immediately after welding and before any coating is applied. It evaluates the just-completed joints (IntegrityScore) and acts as a decision point. Keeping it separate highlights the quality-control boundary rather than burying it inside the welding stage.

**Suggested high-level name:** `Weld Integrity Check`

### 4. Protective Coating
**Low-level events included:**
- Apply protective coating  
- Dry coating  

**Rationale:**  
These two steps form a self-contained surface-finishing sub-process. Coating Unit #3 applies the polyurethane layer, after which Heating Unit #2 cures it. They are consecutive, share a finishing purpose, and are independent of both the prior welding and the final visual inspection.

**Suggested high-level name:** `Protective Coating`

### 5. Final Visual Inspection
**Low-level events included:**
- Visual check  

**Rationale:**  
This is the terminal quality-assurance activity performed by Operator C after all physical processing is complete. It confirms overall acceptability (“Check: Passed”) and closes the case. Isolating it makes the end-of-line verification explicit.

**Suggested high-level name:** `Final Visual Inspection`

---

**Resulting high-level process model (per case):**  
`Material Preparation` → `Welding` → `Weld Integrity Check` → `Protective Coating` → `Final Visual Inspection`

This aggregation reduces 12 low-level events to 5 meaningful stages while preserving the original sequence, resource hand-offs, and process logic. The same grouping rules apply uniformly to every case in the log.
