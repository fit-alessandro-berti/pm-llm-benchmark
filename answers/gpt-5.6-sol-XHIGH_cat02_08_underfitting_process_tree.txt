### Invalid-but-accepted trace

```text
Receive_Order
Check_Inventory
Ship_Order
Package_Items
Authorize_Payment
Close_Order
```

### Why the model accepts it

The successful branch is defined using `Operator.PARALLEL`:

```python
successful_subtree = ProcessTree(
    operator=Operator.PARALLEL,
    children=[authorize_payment, package_items, ship_order]
)
```

A parallel operator allows its child activities to occur in any interleaving. Since each child is a single activity, any permutation of these three activities is valid—including shipping first.

### Why it is problematic

The trace ships the order before:

- the items have been packaged, and
- payment has been authorized.

This violates the required successful flow:

```text
Authorize_Payment  Package_Items  Ship_Order
```

The successful subtree should therefore use `Operator.SEQUENCE`, not `Operator.PARALLEL`.

There is also a separate modeling issue in the cancellation branch: because `Close_Order` appears inside `cancel_subtree` and again after the XOR, the model can accept:

```text
Receive_Order, Check_Inventory, Cancel_Order, Close_Order, Close_Order
```

which closes the same order twice.
