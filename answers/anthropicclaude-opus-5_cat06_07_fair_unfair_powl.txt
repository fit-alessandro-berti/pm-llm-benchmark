# POWL Models for the GlobalTeq Solutions Hiring Process

## Shared Structural Skeleton

Both models share the same backbone derived from the textual description:

| Description element | POWL construct |
|---|---|
| "Applicants submit resumes and questionnaire" | `ReceiveApplication` (Transition) |
| "Any missing information triggers a loop … until complete" | `*( DataCompletenessCheck, RequestMoreInfo )` (LOOP operator) |
| "Applicants take an online skill test … scored automatically" | `SkillAssessment` (Transition) |
| Cultural evaluation stage | **This is where the two models diverge** |
| "A human reviewer examines borderline candidates" | `ManagerialReview` (Transition) |
| "The final decision is then made" | `FinalDecision` (Transition) |
| Strict stage ordering | `StrictPartialOrder` with a total (linear) order |

The loop semantics match the description exactly: `DataCompletenessCheck` is executed, then either the process leaves the loop (data complete) or `RequestMoreInfo` is executed and the check is repeated.

---

## 1. POWL Model **With** Potential Unfairness

Here the evaluation stage is an **XOR** (exclusive choice) between a neutral, merit-based `CulturalFitCheck` and a `CommunityAffiliationCheck` that applies the "slight subjective uplift" described in step 3.

```python
import pm4py
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
)
from pm4py.objects.process_tree.obj import Operator

# ---------------------------------------------------------------
# MODEL 1: hiring process WITH a potential source of unfairness
# ---------------------------------------------------------------

# --- Atomic activities -----------------------------------------
receive_application     = Transition(label="ReceiveApplication")
data_completeness_check = Transition(label="DataCompletenessCheck")
request_more_info       = Transition(label="RequestMoreInfo")
skill_assessment        = Transition(label="SkillAssessment")
cultural_fit_check      = Transition(label="CulturalFitCheck")
community_affiliation   = Transition(label="CommunityAffiliationCheck")
managerial_review       = Transition(label="ManagerialReview")
final_decision          = Transition(label="FinalDecision")

# --- Loop for data completeness ---------------------------------
# Execute DataCompletenessCheck; if data is missing -> RequestMoreInfo,
# then re-check. Repeat until the resume/questionnaire is complete.
completeness_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_completeness_check, request_more_info]
)

# --- BIAS POINT: XOR between neutral and affiliation-based path --
# Branch 1: standard, purely merit-based cultural fit assessment
# Branch 2: affiliation-driven path that grants an implicit uplift
biased_evaluation_xor = OperatorPOWL(
    operator=Operator.XOR,
    children=[cultural_fit_check, community_affiliation]
)

# --- Partial order (a strict sequence of the stages) ------------
unfair_model = StrictPartialOrder(nodes=[
    receive_application,
    completeness_loop,
    skill_assessment,
    biased_evaluation_xor,
    managerial_review,
    final_decision
])

unfair_model.order.add_edge(receive_application, completeness_loop)
unfair_model.order.add_edge(completeness_loop, skill_assessment)
unfair_model.order.add_edge(skill_assessment, biased_evaluation_xor)
unfair_model.order.add_edge(biased_evaluation_xor, managerial_review)
unfair_model.order.add_edge(managerial_review, final_decision)

print("=== MODEL 1 (potentially unfair) ===")
print(unfair_model)
# pm4py.view_powl(unfair_model, format="svg")
```

**Compact textual notation**

```
PO = ( nodes = { ReceiveApplication,
                 *( DataCompletenessCheck, RequestMoreInfo ),
                 SkillAssessment,
                 X( CulturalFitCheck, CommunityAffiliationCheck ),
                 ManagerialReview,
                 FinalDecision },
       order = { ReceiveApplication --> *( DataCompletenessCheck, RequestMoreInfo ),
                 *( DataCompletenessCheck, RequestMoreInfo ) --> SkillAssessment,
                 SkillAssessment --> X( CulturalFitCheck, CommunityAffiliationCheck ),
                 X( CulturalFitCheck, CommunityAffiliationCheck ) --> ManagerialReview,
                 ManagerialReview --> FinalDecision } )
```

**Where the unfairness lives.** The XOR node `X( CulturalFitCheck, CommunityAffiliationCheck )` means two applicants with *identical* résumés and *identical* skill-test scores can be routed through two structurally different evaluation procedures. Routing is not driven by the job requirements but by a sensitive/protected-adjacent attribute (local residency, membership of the "Global Business Leaders Club"). Because the `CommunityAffiliationCheck` branch produces an inflated cultural-alignment score, and because `ManagerialReview` consumes that score for borderline candidates, the bias is *propagated and amplified* downstream into `FinalDecision`. In process-mining terms, the branch is a discriminatory decision point: the branching condition correlates with group membership rather than with competence.

## 2. POWL Model **Without** Unfairness

The XOR is removed entirely. Every applicant traverses exactly one, identical, standardized cultural fit evaluation. No activity in the model can read or act upon affiliation or residency data.

```python
# ---------------------------------------------------------------
# MODEL 2: hiring process WITHOUT the source of unfairness
# ---------------------------------------------------------------

# --- Atomic activities (fresh objects for a separate model) -----
receive_application_f     = Transition(label="ReceiveApplication")
data_completeness_check_f = Transition(label="DataCompletenessCheck")
request_more_info_f       = Transition(label="RequestMoreInfo")
skill_assessment_f        = Transition(label="SkillAssessment")
cultural_fit_check_f      = Transition(label="CulturalFitCheck")   # single, uniform path
managerial_review_f       = Transition(label="ManagerialReview")
final_decision_f          = Transition(label="FinalDecision")

# --- The data-completeness loop is legitimate and is kept -------
completeness_loop_f = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_completeness_check_f, request_more_info_f]
)

# --- NO XOR here: CulturalFitCheck is mandatory and identical ---
fair_model = StrictPartialOrder(nodes=[
    receive_application_f,
    completeness_loop_f,
    skill_assessment_f,
    cultural_fit_check_f,
    managerial_review_f,
    final_decision_f
])

fair_model.order.add_edge(receive_application_f, completeness_loop_f)
fair_model.order.add_edge(completeness_loop_f, skill_assessment_f)
fair_model.order.add_edge(skill_assessment_f, cultural_fit_check_f)
fair_model.order.add_edge(cultural_fit_check_f, managerial_review_f)
fair_model.order.add_edge(managerial_review_f, final_decision_f)

print("=== MODEL 2 (fair) ===")
print(fair_model)
# pm4py.view_powl(fair_model, format="svg")
```

**Compact textual notation**

```
PO = ( nodes = { ReceiveApplication,
                 *( DataCompletenessCheck, RequestMoreInfo ),
                 SkillAssessment,
                 CulturalFitCheck,
                 ManagerialReview,
                 FinalDecision },
       order = { ReceiveApplication --> *( DataCompletenessCheck, RequestMoreInfo ),
                 *( DataCompletenessCheck, RequestMoreInfo ) --> SkillAssessment,
                 SkillAssessment --> CulturalFitCheck,
                 CulturalFitCheck --> ManagerialReview,
                 ManagerialReview --> FinalDecision } )
```

### Optional fairness-hardened variant

If GlobalTeq still wants a *structural* choice at the review stage, it must be one that is orthogonal to group membership — e.g. a deterministic, score-triggered escalation for borderline candidates only. This keeps the model expressive without reintroducing bias:

```python
# Optional: an escalation that depends ONLY on the objective score band,
# not on affiliation. Both branches are affiliation-blind.
second_reviewer   = Transition(label="BlindSecondReview")   # anonymized dossier
skip_escalation   = SilentTransition()

escalation_xor = OperatorPOWL(
    operator=Operator.XOR,
    children=[second_reviewer, skip_escalation]
)

fair_model_v2 = StrictPartialOrder(nodes=[
    receive_application_f2 := Transition(label="ReceiveApplication"),
    loop_f2 := OperatorPOWL(operator=Operator.LOOP,
                            children=[Transition(label="DataCompletenessCheck"),
                                      Transition(label="RequestMoreInfo")]),
    skill_f2 := Transition(label="SkillAssessment"),
    cfc_f2   := Transition(label="CulturalFitCheck"),
    escalation_xor,
    mgr_f2   := Transition(label="ManagerialReview"),
    fin_f2   := Transition(label="FinalDecision")
])
fair_model_v2.order.add_edge(receive_application_f2, loop_f2)
fair_model_v2.order.add_edge(loop_f2, skill_f2)
fair_model_v2.order.add_edge(skill_f2, cfc_f2)
fair_model_v2.order.add_edge(cfc_f2, escalation_xor)
fair_model_v2.order.add_edge(escalation_xor, mgr_f2)
fair_model_v2.order.add_edge(mgr_f2, fin_f2)
```

## Side-by-Side Comparison

| Aspect | Model 1 (unfair) | Model 2 (fair) |
|---|---|---|
| Data-completeness loop | `*( DataCompletenessCheck, RequestMoreInfo )` | identical (legitimate, applicant-agnostic) |
| Skill assessment | same objective test for all | same objective test for all |
| Cultural evaluation | `X( CulturalFitCheck, CommunityAffiliationCheck )` — **two different procedures** | `CulturalFitCheck` — **one procedure for everyone** |
| Attribute used for routing | local residency / club membership (sensitive) | none |
| Number of distinct control-flow paths after `SkillAssessment` | 2 | 1 |
| Score uplift possible | yes, via the affiliation branch | no |
| Effect on `ManagerialReview` | inherits an inflated cultural score, priming the reviewer | receives comparable, uniformly produced scores |
| Fairness property | violates procedural fairness / equal treatment | satisfies equal treatment by construction |

**Key takeaway:** the loop and the sequential ordering are *neutral* control-flow structures — they exist to guarantee data quality and stage discipline. The unfairness is localized entirely in the **XOR operator whose branching condition is a sensitive attribute**. Eliminating that single operator (rather than the loop or the sequence) is what converts Model 1 into Model 2, since every applicant is then forced through the same evaluation activity and the affiliation data can no longer influence the trace at all.
