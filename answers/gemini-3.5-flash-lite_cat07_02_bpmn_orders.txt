Based on the image provided, here is a description of the Business Process Model and Notation (BPMN) diagram.

### Overview
The diagram represents a multi-pool, event-driven business process involving four departments or roles: **Sales**, **Production**, **Procurement**, and **Warehouse**. The processes are interconnected using message flows (represented by dashed lines) and sequence flows (solid lines).

---

### Detailed Breakdown by Pool

#### 1. Sales Pool
*   **Start Event:** Initiated by a timer event ("Monday morning").
*   **Sub-process ("Check customer's order"):**
    *   **Check order for completeness:** The process verifies if all order details are present.
    *   **Check if customer is already in the database:** Determines if the customer is existing.
    *   **Exclusive Gateway:** Splits based on customer status:
        *   *Customer not in the database:* Flows to "Add customer to the database" (which interacts with a data store) and then rejoins.
        *   *Customer in the database:* Bypasses the addition step.
    *   **End of Sub-process:** An intermediate end event.
*   **Post-Subprocess Tasks:**
    *   **Send order details:** A task that sends information out.
    *   **Throw Event:** Triggers a message ("Product sent").
    *   **Draft invoice:** Final task in the Sales pool.
*   **End Event:** A standard end event terminates the Sales process.

#### 2. Production Pool
*   **Start Event:** Receives message flow "Order details arrive" from Sales.
*   **Parallel Gateway (Split):** Splits the process to simultaneously plan production and handle materials.
*   **Plan production:** A standard task.
*   **Material Check (Parallel join/split logic):** 
    *   Waits for a message "Material not faulty" from the Procurement pool.
*   **Manufacture product:** A task that executes once production is planned and materials are verified.
*   **End Event:** Triggers a message "Product complete" sent to the Warehouse.

#### 3. Procurement Pool
*   **Start Event:** Receives "Order details arrive" message from Sales.
*   **Material Compensation Subprocess:**
    *   Starts internally, goes to "Order materials".
    *   Includes a compensation boundary/intermediate event connected to "Return material".
*   **Check materials:** A task verifying material status.
*   **Outcomes:**
    *   If successful, sends a message back to Production ("Material not faulty").
    *   If faulty/cancelled, triggers an error/compensation event leading to "Order cancellation" and an end event.

#### 4. Warehouse Pool
*   **Start Event:** Receives "Product complete" message from Production.
*   **Send product:** A task where the physical item is dispatched.
*   **Throw Event:** Sends a message "Product sent" back to the Sales pool.
*   **End Event:** Finalizes the warehouse process.

### Key BPMN Elements Used
*   **Pools & Lanes:** Represent organizational boundaries (Sales, Production, Procurement, Warehouse).
*   **Sequence Flows:** Solid lines with arrows showing the order of execution within a pool.
*   **Message Flows:** Dashed lines with envelopes/circles showing communication between different pools.
*   **Gateways:** Exclusive (XOR, with 'X') and Parallel (AND, with '+') gateways to control branching and merging.
*   **Events:** Start events (thin circles), Intermediate events (double circles, timers, messages), and End events (thick circles).
*   **Data Store:** Represented by a cylinder icon in the Sales pool.
