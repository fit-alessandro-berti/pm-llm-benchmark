# DuckDB SQL Query: Filter Cases by Activity Sequence and Timing

## Approach

To solve this problem, we need to:
1. **Detect the 3-activity sequence** using window functions (`LEAD`) to look ahead at the next two events in each case, ordered by timestamp.
2. **Check the timing condition** — specifically the gap between `Create Order` and `Confirm Order` exceeding 5 days.
3. **Collect the case_ids** that match both conditions.
4. **Exclude** those case_ids from the final result set.

## Query

```sql
WITH ordered_events AS (
    SELECT
        case_id,
        activity,
        timestamp,
        LEAD(activity, 1)   OVER (PARTITION BY case_id ORDER BY timestamp) AS next_activity,
        LEAD(timestamp, 1)  OVER (PARTITION BY case_id ORDER BY timestamp) AS next_timestamp,
        LEAD(activity, 2)   OVER (PARTITION BY case_id ORDER BY timestamp) AS next_activity_2,
        LEAD(timestamp, 2)  OVER (PARTITION BY case_id ORDER BY timestamp) AS next_timestamp_2
    FROM event_log
),

flagged_cases AS (
    SELECT DISTINCT case_id
    FROM ordered_events
    WHERE activity          = 'Approve Purchase Requisition'
      AND next_activity     = 'Create Order'
      AND next_activity_2   = 'Confirm Order'
      AND (next_timestamp_2 - next_timestamp) > INTERVAL '5 days'
)

SELECT e.*
FROM event_log e
WHERE e.case_id NOT IN (SELECT case_id FROM flagged_cases)
ORDER BY e.case_id, e.timestamp;
```

## Explanation

### Step 1 — `ordered_events` CTE
- For every event, we use `LEAD()` window functions partitioned by `case_id` and ordered by `timestamp` to fetch:
  - The **next activity** and its timestamp (`next_activity`, `next_timestamp`)
  - The activity **two steps ahead** and its timestamp (`next_activity_2`, `next_timestamp_2`)

This lets us inspect any 3 consecutive events within a case as a single row.

### Step 2 — `flagged_cases` CTE
- We filter for rows where:
  - Current activity = `'Approve Purchase Requisition'`
  - Next activity = `'Create Order'`
  - Activity two steps ahead = `'Confirm Order'`
- Additionally, we check that the time difference between the `Confirm Order` timestamp (`next_timestamp_2`) and the `Create Order` timestamp (`next_timestamp`) exceeds **5 days**.
- We use `DISTINCT` to get a unique list of `case_id`s meeting these criteria — these are the cases we want to **exclude**.

### Step 3 — Final `SELECT`
- We return all events from `event_log`, **excluding** any event belonging to a case_id found in `flagged_cases`.
- Results are ordered by `case_id` and `timestamp` for readability, preserving the natural event order within each case.

## Notes
- This query assumes `timestamp` is a proper `TIMESTAMP` type so that subtraction yields an `INTERVAL`, and comparison to `INTERVAL '5 days'` works natively in DuckDB.
- The sequence check enforces **strict immediate succession** — i.e., there must be no other event of that case between these three, because `LEAD(..., 1)` and `LEAD(..., 2)` pick the *very next* rows in the timestamp-ordered partition, not just any later occurrence.
- If multiple valid `'Approve Purchase Requisition'  'Create Order'  'Confirm Order'` sequences exist within a single case, and **any one** of them satisfies the >5-day gap, that case_id is excluded entirely (since the requirement is to exclude the *case*, not just the specific occurrence).
