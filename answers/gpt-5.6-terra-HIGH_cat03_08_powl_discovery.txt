Let `` denote a `SilentTransition()`. The repeated inspection/reassembly behavior and repeated test/re-test behavior can be represented with loops.

### Submodels

\[
Q = *(\text{IQC}, \tau)
\]

`Q` represents one or more IQC executions:

\[
\text{IQC}\;(\text{IQC})^*
\]

This is needed because Case 3 contains two consecutive IQC activities before assembly resumes.

\[
A_{\text{rework}} = *(\text{AS}, Q)
\]

This represents:

\[
\text{AS}\;(\text{IQC}^{+}\;\text{AS})^*
\]

Thus, assembly always occurs first; it may be accepted immediately, or one-or-more IQC steps may be performed followed by another assembly. This captures, for example:

- `AS`
- `AS, IQC, AS`
- `AS, IQC, IQC, AS, IQC, AS`

The test/re-test behavior is:

\[
T_{\text{retest}} = *(\text{TST}, \text{RT})
\]

which represents:

\[
\text{TST}\;(\text{RT}\;\text{TST})^*
\]

Labeling is optional:

\[
L_{\text{optional}} = X(\text{LB}, \tau)
\]

---

## Final POWL model

\[
\begin{aligned}
\text{PO} = \text{PO}(&\text{nodes}=\{\\
&\text{OR},\;
\text{MS},\;
\text{QS},\;
A_{\text{rework}},\;
T_{\text{retest}},\;
\text{PK},\;
L_{\text{optional}},\;
\text{DP},\;
\text{D}
\},\\
&\text{order}=
\{\text{OR}\rightarrow\text{MS},\;
\text{MS}\rightarrow\text{QS},\;
\text{QS}\rightarrow A_{\text{rework}},\\
&\qquad A_{\text{rework}}\rightarrow T_{\text{retest}},\;
T_{\text{retest}}\rightarrow\text{PK},\\
&\qquad \text{PK}\rightarrow L_{\text{optional}},\;
L_{\text{optional}}\rightarrow\text{DP},\;
\text{DP}\rightarrow\text{D}\}^{+}
)
\end{aligned}
\]

where \(^{+}\) means the transitive closure of the listed ordering relations.

In compact POWL notation:

```text
PO(
  nodes = {
    OR,
    MS,
    QS,
    *( AS, *( IQC,  ) ),
    *( TST, RT ),
    PK,
    X( LB,  ),
    DP,
    D
  },
  order = {
    OR --> MS,
    MS --> QS,
    QS --> *( AS, *( IQC,  ) ),
    *( AS, *( IQC,  ) ) --> *( TST, RT ),
    *( TST, RT ) --> PK,
    PK --> X( LB,  ),
    X( LB,  ) --> DP,
    DP --> D
  }+
)
```

Equivalent Python-style construction:

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
)
from pm4py.objects.process_tree.obj import Operator

OR = Transition(label="OR")
MS = Transition(label="MS")
QS = Transition(label="QS")
AS = Transition(label="AS")
IQC = Transition(label="IQC")
TST = Transition(label="TST")
RT = Transition(label="RT")
PK = Transition(label="PK")
LB = Transition(label="LB")
DP = Transition(label="DP")
D = Transition(label="D")
skip = SilentTransition()

# One or more IQC checks
iqc_repeat = OperatorPOWL(
    operator=Operator.LOOP,
    children=[IQC, skip]
)

# AS followed optionally by one-or-more IQC checks and another AS,
# repeated as needed
assembly_rework = OperatorPOWL(
    operator=Operator.LOOP,
    children=[AS, iqc_repeat]
)

# TST, optionally followed by RT and another TST, repeated as needed
testing_rework = OperatorPOWL(
    operator=Operator.LOOP,
    children=[TST, RT]
)

# Labeling is optional
optional_labeling = OperatorPOWL(
    operator=Operator.XOR,
    children=[LB, skip]
)

root = StrictPartialOrder(
    nodes=[
        OR, MS, QS,
        assembly_rework,
        testing_rework,
        PK,
        optional_labeling,
        DP, D
    ]
)

root.order.add_edge(OR, MS)
root.order.add_edge(MS, QS)
root.order.add_edge(QS, assembly_rework)
root.order.add_edge(assembly_rework, testing_rework)
root.order.add_edge(testing_rework, PK)
root.order.add_edge(PK, optional_labeling)
root.order.add_edge(optional_labeling, DP)
root.order.add_edge(DP, D)
```

This model contains no concurrent branches because the supplied traces consistently establish the sequential dependencies between the major stages.
