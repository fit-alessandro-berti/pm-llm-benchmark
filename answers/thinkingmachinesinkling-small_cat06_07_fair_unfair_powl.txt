Below are the two POWL constructions.  
Both start with **ReceiveApplication**, contain the **DataCompletenessCheck / RequestMoreInfo** loop, and proceed through **SkillAssessment**, **ManagerialReview**, and **FinalDecision**.  

* **Model1 (with potential unfairness)** inserts an **XOR** after the skill test: one branch is the standard **CulturalFitCheck**, the other is **CommunityAffiliationCheck**, which can implicitly give affiliated applicants a subtle boost.  
* **Model2 (fair)** removes that branch; every applicant goes through the same **CulturalFitCheck**.

```python
# ------------------------------------------------------------
# Shared imports
# ------------------------------------------------------------
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# ------------------------------------------------------------
# 1. POWL MODEL WITH POTENTIAL UNFAIRNESS
# ------------------------------------------------------------
# Activities
recv_1       = Transition(label="ReceiveApplication")
check_1      = Transition(label="DataCompletenessCheck")
req_1        = Transition(label="RequestMoreInfo")
skill_1      = Transition(label="SkillAssessment")
cult_1       = Transition(label="CulturalFitCheck")
comm_1       = Transition(label="CommunityAffiliationCheck")
mgr_1        = Transition(label="ManagerialReview")
final_1      = Transition(label="FinalDecision")

# Loop: check completeness; if missing -> request info and loop back
loop_data_1  = OperatorPOWL(operator=Operator.LOOP, children=[check_1, req_1])

# XOR: standard cultural fit  vs.  community-affiliation path (bias point)
xor_bias     = OperatorPOWL(operator=Operator.XOR, children=[cult_1, comm_1])

# Root partial order enforcing sequence: receive -> loop -> skill -> xor -> review -> decision
model_unfair = StrictPartialOrder(nodes=[recv_1, loop_data_1, skill_1, xor_bias, mgr_1, final_1])
model_unfair.order.add_edge(recv_1, loop_data_1)
model_unfair.order.add_edge(loop_data_1, skill_1)
model_unfair.order.add_edge(skill_1, xor_bias)
model_unfair.order.add_edge(xor_bias, mgr_1)
model_unfair.order.add_edge(mgr_1, final_1)


# ------------------------------------------------------------
# 2. POWL MODEL WITHOUT UNFAIRNESS
# ------------------------------------------------------------
# Activities (re-defined for a clean second model)
recv_2       = Transition(label="ReceiveApplication")
check_2      = Transition(label="DataCompletenessCheck")
req_2        = Transition(label="RequestMoreInfo")
skill_2      = Transition(label="SkillAssessment")
cult_2       = Transition(label="CulturalFitCheck")
mgr_2        = Transition(label="ManagerialReview")
final_2      = Transition(label="FinalDecision")

# Same data-completeness loop
loop_data_2  = OperatorPOWL(operator=Operator.LOOP, children=[check_2, req_2])

# Root: no XOR branch; everyone gets the same cultural-fit evaluation
model_fair   = StrictPartialOrder(nodes=[recv_2, loop_data_2, skill_2, cult_2, mgr_2, final_2])
model_fair.order.add_edge(recv_2, loop_data_2)
model_fair.order.add_edge(loop_data_2, skill_2)
model_fair.order.add_edge(skill_2, cult_2)
model_fair.order.add_edge(cult_2, mgr_2)
model_fair.order.add_edge(mgr_2, final_2)
```

### What the structures represent

| Component | Meaning in both models |
|---|---|
| `ReceiveApplication`  `loop_data` | Application is received; then the completeness loop starts. |
| `loop_data` (`LOOP` on `DataCompletenessCheck`, `RequestMoreInfo`) | If data is incomplete, `RequestMoreInfo` fires and the loop repeats; once complete, the loop exits. |
| `SkillAssessment` | Online domain test; scored automatically. |
| **Model1 only:** `xor_bias` (`XOR` of `CulturalFitCheck` / `CommunityAffiliationCheck`) | The bias point. Applicants may be routed through either the standard evaluation or an alternative path where local-group / club membership can implicitly adjust scores. |
| **Model2 only:** direct `CulturalFitCheck` | All applicants are evaluated by the same standard cultural-fit step; no selective branch exists. |
| `ManagerialReview`  `FinalDecision` | Human review of borderline cases followed by hire/reject. |

In **Model1**, the `XOR` after `SkillAssessment` is exactly where subtle unfairness can enter: the `CommunityAffiliationCheck` branch can give preferential treatment to applicants flagged by local-community cues. In **Model2**, that branch is removed, so every applicant flows through the identical sequence (`CulturalFitCheck`  `ManagerialReview`  `FinalDecision`).
