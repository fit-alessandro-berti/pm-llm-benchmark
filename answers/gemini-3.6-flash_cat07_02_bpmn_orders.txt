This visualization is a **Business Process Model and Notation (BPMN 2.0)** process diagram that models an end-to-end order processing, procurement, manufacturing, and shipping workflow. 

The diagram is organized horizontally into four swimlanes: **Sales**, **Production**, **Procurement**, and **Warehouse**.

---

### 1. **Sales Lane**
* **Start Event:** The process begins on a schedule triggered by a timer event labeled **"Monday morning"**.
* **Subprocess ("Check customer's order"):**
  1. **Check order for completeness:** Validates incoming order data.
  2. **Check if customer is already in the database:** Evaluated via an Exclusive Gateway (XOR):
     * *Customer not in database:* Triggers **"Add customer to the database"**, which updates an external **database** data store.
     * *Customer in database:* Bypasses the database addition.
* **Send order details:** After verifying/adding the customer, order details are prepared and broadcast concurrently (via dashed message flow lines) to both **Production** and **Procurement**.
* **Product sent (Catch Event):** The Sales lane waits until it receives confirmation that the product has been shipped from the Warehouse.
* **Draft invoice:** Sales creates the final invoice draft, ending the Sales process.

---

### 2. **Procurement Lane**
* **Start Event:** Triggered when the **"Order details arrive"** message from Sales is received.
* **Material Compensation Subprocess:**
  * Runs an **"Order materials"** task. 
  * Includes a compensation handler task (**"Return material"**) linked to return materials if canceled.
* **Check materials:** Inspects incoming materials for quality.
  * **Success:** Sends a **"Material not faulty"** message to the Production lane.
  * **Failure (Error Boundary Event):** Triggers an **"Order cancelation"** compensation event, terminating this path.

---

### 3. **Production Lane**
* **Start Event:** Triggered when the **"Order details arrive"** message from Sales is received.
* **Parallel Gateway (AND Fork):** Splits into two concurrent paths:
  1. Task: **"Plan production"**.
  2. Event: Waits for the **"Material not faulty"** message flow from Procurement.
* **Parallel Gateway (AND Join):** Synchronizes both paths once production planning is done and valid materials are confirmed.
* **Manufacture product:** Manufactures the ordered goods.
* **Product complete (Throw Event):** Sends a **"Product complete"** message flow to the Warehouse lane.

---

### 4. **Warehouse Lane**
* **Start Event:** Activated upon receiving the **"Product complete"** message flow from Production.
* **Send product:** The warehouse packages and dispatches the final product.
* **Product sent (Throw Event):** Sends a message flow back to the **Sales** lane confirming shipment, allowing Sales to proceed to draft the invoice.

---

### Key Cross-Lane Message Interactions (Dashed Lines)
1. **Sales $\rightarrow$ Production & Procurement:** Message flow sending order details to both departments.
2. **Procurement $\rightarrow$ Production:** Message flow confirming materials are not faulty.
3. **Production $\rightarrow$ Warehouse:** Message flow signaling completion of product manufacturing.
4. **Warehouse $\rightarrow$ Sales:** Message flow confirming the product has been dispatched.
