## Proposed high-level process model

| Step | High-level activity | Included low-level events | Grouping rationale |
|---|---|---|---|
| 1 | **Material Preparation and Setup** | Retrieve raw metal sheet; Scan barcode; Place metal sheet on table; Align metal sheet; Preheat metal sheet | These events identify, position, align, and thermally prepare the same raw component for fabrication. Although several resources are involved, all events serve the common objective of making the material ready for welding. |
| 2 | **Spot Welding** | Pick up welding tool; Weld corner A; Weld corner B | Tool acquisition is an immediate setup action for the welding operations. The corner welds are repeated operations within the same fabrication stage and use the same operator, tool, and weld type. |
| 3 | **Weld Quality Inspection** | Measure weld integrity | This is an in-process quality-control gate that evaluates the result of welding before downstream finishing begins. It should remain separate from welding because it measures rather than transforms the product. |
| 4 | **Protective Coating and Curing** | Apply protective coating; Dry coating | Applying the coating and drying it are two phases of one surface-finishing operation. Drying cures or stabilizes the coating and is necessary to complete the treatment. |
| 5 | **Final Visual Inspection** | Visual check | This is the final product-level quality check after fabrication and finishing. It is separated from weld inspection because it occurs later and assesses the finished item rather than only weld integrity. |

## Low-level-to-high-level mapping rules

```text
Retrieve raw metal sheet
  + Scan barcode
  + Place metal sheet on table
  + Align metal sheet
  + Preheat metal sheet
    => Material Preparation and Setup

Pick up welding tool
  + one or more "Weld ..." events
    => Spot Welding

Measure weld integrity
    => Weld Quality Inspection

Apply protective coating
  + Dry coating
    => Protective Coating and Curing

Visual check
    => Final Visual Inspection
```

Events should first be partitioned by `CaseID` and ordered by `Timestamp`; events from different cases must never be combined. Semantic relationships should take precedence over resource identity: for example, material preparation uses an operator, robot arm, and heating unit but still represents one coherent process phase.

## Suggested aggregation fields

Each generated high-level event can retain the following information:

```json
{
  "CaseID": "A1",
  "HighLevelActivity": "Spot Welding",
  "StartTimestamp": "2024-03-01 08:01:00",
  "EndTimestamp": "2024-03-01 08:01:10",
  "Resources": ["Operator B"],
  "SourceEventCount": 3,
  "SourceActivities": [
    "Pick up welding tool",
    "Weld corner A",
    "Weld corner B"
  ],
  "SummaryAttributes": {
    "ToolID": "W-12",
    "WeldType": "Spot",
    "WeldLocations": ["Corner A", "Corner B"]
  }
}
```

The start and end timestamps are the earliest and latest timestamps in the group. Important measurements, identifiers, outcomes, and participating resources should be retained as aggregated attributes so that abstraction does not remove operational or quality information.
