## Hypotheses for these anomalies

1. **Manual expediting / override**  
   Resources may be pushing high-priority orders through faster by confirming or shipping before checks are complete. The flags `attempted_early=Y`, `late_confirmation=Y`, and `shipment_scheduled=N` support this.

2. **Weak process controls**  
   The system may not enforce mandatory prerequisites. For example, it allows `Ship Goods` even when `Validate Stock` has not been recorded.

3. **Logging or system integration issues**  
   Some activities may have been performed but not logged in the correct order, or manual checks may be done offline and never recorded in `order_event_log`.

4. **Payment policy variation**  
   Case 1004 may be a prepayment or advance-payment order, but the given normal process says payment should occur after invoicing. That needs business-rule verification.

5. **Resource training or role confusion**  
   Some resources may not understand the required sequence, or they may be operating under different department-specific procedures.

## SQL queries to investigate

### 1. Find all out-of-order activity pairs

This query uses the expected process step numbers and identifies cases where an activity that should happen later actually happened earlier.

```sql
WITH activity_order(activity, step) AS (
    VALUES
      ('Register Order', 1),
      ('Perform Credit Check', 2),
      ('Validate Stock', 3),
      ('Confirm Shipment', 4),
      ('Ship Goods', 5),
      ('Issue Invoice', 6),
      ('Receive Payment', 7)
)
SELECT
    e1.case_id,
    o.order_type,
    e1.timestamp AS first_time_ts,
    e1.activity AS first_time_activity,
    e2.timestamp AS second_time_ts,
    e2.activity AS second_time_activity
FROM order_event_log e1
JOIN order_event_log e2
  ON e1.case_id = e2.case_id
 AND e1.timestamp < e2.timestamp
JOIN activity_order a1
  ON e1.activity = a1.activity
JOIN activity_order a2
  ON e2.activity = a2.activity
JOIN orders o
  ON o.case_id = e1.case_id
WHERE a1.step > a2.step
ORDER BY e1.case_id, e1.timestamp;
```

### 3. Find cases where `Ship Goods` happened before required checks

This specifically targets risky shipping behavior.

```sql
WITH ship AS (
    SELECT case_id, MIN(timestamp) AS ship_time
    FROM order_event_log
    WHERE activity = 'Ship Goods'
    GROUP BY case_id
),
credit AS (
    SELECT case_id, MIN(timestamp) AS credit_time
    FROM order_event_log
    WHERE activity = 'Perform Credit Check'
    GROUP BY case_id
),
stock AS (
    SELECT case_id, MIN(timestamp) AS stock_time
    FROM order_event_log
    WHERE activity = 'Validate Stock'
    GROUP BY case_id
),
confirm AS (
    SELECT case_id, MIN(timestamp) AS confirm_time
    FROM order_event_log
    WHERE activity = 'Confirm Shipment'
    GROUP BY case_id
)
SELECT
    s.case_id,
    s.ship_time,
    c.credit_time,
    st.stock_time,
    co.confirm_time,
    (c.credit_time IS NULL OR s.ship_time < c.credit_time) AS ship_before_credit_check,
    (st.stock_time IS NULL OR s.ship_time < st.stock_time) AS ship_before_stock_validation,
    (co.confirm_time IS NULL OR s.ship_time < co.confirm_time) AS ship_before_confirm_shipment
FROM ship s
LEFT JOIN credit c ON s.case_id = c.case_id
LEFT JOIN stock st ON s.case_id = st.case_id
LEFT JOIN confirm co ON s.case_id = co.case_id
WHERE (c.credit_time IS NULL OR s.ship_time < c.credit_time)
   OR (st.stock_time IS NULL OR s.ship_time < st.stock_time)
   OR (co.confirm_time IS NULL OR s.ship_time < co.confirm_time)
ORDER BY s.case_id;
```

### 5. Find problematic `Confirm Shipment` events

This identifies confirmations that were too early, too late, missing prerequisites, or marked with suspicious flags.

```sql
WITH confirms AS (
    SELECT
        case_id,
        timestamp AS confirm_time,
        resource,
        additional_info
    FROM order_event_log
    WHERE activity = 'Confirm Shipment'
),
credit AS (
    SELECT case_id, MIN(timestamp) AS credit_time
    FROM order_event_log
    WHERE activity = 'Perform Credit Check'
    GROUP BY case_id
),
stock AS (
    SELECT case_id, MIN(timestamp) AS stock_time
    FROM order_event_log
    WHERE activity = 'Validate Stock'
    GROUP BY case_id
),
ship AS (
    SELECT case_id, MIN(timestamp) AS ship_time
    FROM order_event_log
    WHERE activity = 'Ship Goods'
    GROUP BY case_id
)
SELECT
    c.case_id,
    c.confirm_time,
    c.resource,
    c.additional_info,
    cr.credit_time,
    st.stock_time,
    sh.ship_time,
    (cr.credit_time IS NULL OR c.confirm_time < cr.credit_time) AS confirmed_without_credit_check,
    (st.stock_time IS NULL OR c.confirm_time < st.stock_time) AS confirmed_without_stock_validation,
    (sh.ship_time IS NOT NULL AND c.confirm_time > sh.ship_time) AS confirmed_after_shipment
FROM confirms c
LEFT JOIN credit cr ON c.case_id = cr.case_id
LEFT JOIN stock st ON c.case_id = st.case_id
LEFT JOIN ship sh ON c.case_id = sh.case_id
WHERE c.additional_info LIKE '%attempted_early%'
   OR c.additional_info LIKE '%late_confirmation%'
   OR c.additional_info LIKE '%shipment_scheduled=N%'
   OR (cr.credit_time IS NULL OR c.confirm_time < cr.credit_time)
   OR (st.stock_time IS NULL OR c.confirm_time < st.stock_time)
   OR (sh.ship_time IS NOT NULL AND c.confirm_time > sh.ship_time)
ORDER BY c.case_id;
```
