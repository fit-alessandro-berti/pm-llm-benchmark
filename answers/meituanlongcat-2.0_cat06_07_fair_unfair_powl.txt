# POWL Models for GlobalTeq Solutions Hiring Process

Below are two POWL models representing the hiring process. The first model includes a potential bias point through an XOR branch after the skill assessment, while the second model eliminates that unfairness by subjecting all applicants to a uniform cultural fit evaluation.

## POWL Model 1: With Potential Unfairness

This model captures the process where an applicant, after the skill assessment, may take either a standard cultural fit evaluation or a community-affiliation-based check that provides a subtle, unearned advantage. The XOR between `CulturalFitCheck` and `CommunityAffiliationCheck` is the source of unfairness.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# ----------------------------------------------------------------------
# Atomic activities
# ----------------------------------------------------------------------
ReceiveApplication = Transition(label="ReceiveApplication")
DataCompletenessCheck = Transition(label="DataCompletenessCheck")
RequestMoreInfo = Transition(label="RequestMoreInfo")
SkillAssessment = Transition(label="SkillAssessment")
CulturalFitCheck = Transition(label="CulturalFitCheck")
CommunityAffiliationCheck = Transition(label="CommunityAffiliationCheck")
ManagerialReview = Transition(label="ManagerialReview")
FinalDecision = Transition(label="FinalDecision")

# ----------------------------------------------------------------------
# Loop: DataCompletenessCheck  RequestMoreInfo
# The LOOP operator works as: execute A, then either exit or execute B and repeat A.
# Here, A = DataCompletenessCheck, B = RequestMoreInfo
# ----------------------------------------------------------------------
data_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[DataCompletenessCheck, RequestMoreInfo]
)

# ----------------------------------------------------------------------
# XOR choice: CulturalFitCheck  OR  CommunityAffiliationCheck
# The CommunityAffiliationCheck path gives an illicit uplift to certain candidates.
# ----------------------------------------------------------------------
cultural_choice = OperatorPOWL(
    operator=Operator.XOR,
    children=[CulturalFitCheck, CommunityAffiliationCheck]
)

# ----------------------------------------------------------------------
# Top-level partial order enforcing the sequential flow:
#   ReceiveApplication  data_loop  SkillAssessment  cultural_choice  ManagerialReview  FinalDecision
# ----------------------------------------------------------------------
nodes_model1 = [
    ReceiveApplication,
    data_loop,
    SkillAssessment,
    cultural_choice,
    ManagerialReview,
    FinalDecision
]

root1 = StrictPartialOrder(nodes=nodes_model1)
root1.order.add_edge(ReceiveApplication, data_loop)
root1.order.add_edge(data_loop, SkillAssessment)
root1.order.add_edge(SkillAssessment, cultural_choice)
root1.order.add_edge(cultural_choice, ManagerialReview)
root1.order.add_edge(ManagerialReview, FinalDecision)

print("Model 1 (With Unfairness):")
print(root1)
```

## POWL Model 2: Without Unfairness

This model removes the XOR branch entirely. Every applicant — regardless of community affiliation — goes through the exact same `CulturalFitCheck` activity. The process remains sequential after the skill assessment, eliminating the possibility of preferential treatment.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# ----------------------------------------------------------------------
# Atomic activities
# ----------------------------------------------------------------------
ReceiveApplication = Transition(label="ReceiveApplication")
DataCompletenessCheck = Transition(label="DataCompletenessCheck")
RequestMoreInfo = Transition(label="RequestMoreInfo")
SkillAssessment = Transition(label="SkillAssessment")
CulturalFitCheck = Transition(label="CulturalFitCheck")
ManagerialReview = Transition(label="ManagerialReview")
FinalDecision = Transition(label="FinalDecision")

# ----------------------------------------------------------------------
# Loop: DataCompletenessCheck  RequestMoreInfo (same as Model 1)
# ----------------------------------------------------------------------
data_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[DataCompletenessCheck, RequestMoreInfo]
)

# ----------------------------------------------------------------------
# Top-level partial order enforcing strictly sequential flow:
#   ReceiveApplication  data_loop  SkillAssessment  CulturalFitCheck  ManagerialReview  FinalDecision
# No XOR branch — every applicant undergoes the identical CulturalFitCheck.
# ----------------------------------------------------------------------
nodes_model2 = [
    ReceiveApplication,
    data_loop,
    SkillAssessment,
    CulturalFitCheck,
    ManagerialReview,
    FinalDecision
]

root2 = StrictPartialOrder(nodes=nodes_model2)
root2.order.add_edge(ReceiveApplication, data_loop)
root2.order.add_edge(data_loop, SkillAssessment)
root2.order.add_edge(SkillAssessment, CulturalFitCheck)
root2.order.add_edge(CulturalFitCheck, ManagerialReview)
root2.order.add_edge(ManagerialReview, FinalDecision)

print("Model 2 (Without Unfairness):")
print(root2)
```

- **No XOR node exists** after `SkillAssessment`. Every applicant proceeds to a single, uniform `CulturalFitCheck`. The evaluation criteria are applied consistently, and no applicant can gain an unearned advantage through community affiliation or club membership. The `ManagerialReview` still examines borderline candidates, but it does so without the implicit score adjustments that the `CommunityAffiliationCheck` introduced in Model 1.

## Summary of Differences

| Aspect | Model 1 (Unfair) | Model 2 (Fair) |
|--------|------------------|----------------|
| After Skill Assessment | XOR branch: `CulturalFitCheck` **or** `CommunityAffiliationCheck` | Single path: `CulturalFitCheck` only |
| Community Affiliation Advantage | Yes — `CommunityAffiliationCheck` gives an illicit uplift | No — all applicants undergo identical evaluation |
| Data Completeness Loop | Identical in both models | Identical in both models |
| Managerial Review & Final Decision | Identical in both models | Identical in both models |
| Source of Bias | The XOR node with `CommunityAffiliationCheck` | Eliminated — no alternative path exists |
