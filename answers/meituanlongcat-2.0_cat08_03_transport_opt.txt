### 1.3 Conformance Checking Against Planned Routes

I would implement **alignment-based conformance checking** to systematically compare actual traces against planned routes imported from the dispatch system. The model would be translated into a Petri net with:
- Planned stops as transitions with expected sequences
- Time constraints on transitions (planned travel windows)
- Invisible transitions for GPS-derived travel segments

**Deviation Types and Metrics:**

1. **Sequence Deviations (Fitness):**
   - *Skip*: Planned stop not visited (missing delivery attempt)
   - *Insert*: Unplanned stop (e.g., maintenance, driver break)
   - *Reorder*: Stop sequence different from planned (metric: Levenshtein distance between planned vs. actual stop sequence)

2. **Timing Deviations:**
   - *Early/Late arrival*: Actual "Arrive Customer" timestamp vs. planned time window (calculated per stop)
   - *Duration deviation*: Actual service time vs. planned service time (e.g., planned 3 min, actual 8 min)

3. **Capacity Deviations:**
   - *Overload*: Packages delivered > vehicle capacity (from dispatch data)
   - *Underutilization*: Vehicle returning with >20% capacity unused

**Conformance Metrics:**
- **Fitness**: % of events perfectly aligned (target >85%)
- **Precision**: % of actual behavior allowed by model (target >70%)

## 2. Performance Analysis and Bottleneck Identification

### 2.1 Key Performance Indicators (KPIs) from Event Log

I would calculate the following KPIs directly from the integrated event log:

**Delivery Punctuality KPIs:**
- **On-Time Delivery Rate (OTDR)**: % of "Delivery Success" events occurring within customer-requested time window (from dispatch data). Formula: `COUNT(Delivery Success WHERE timestamp BETWEEN window_start AND window_end) / COUNT(Delivery Success)`
- **Average Lateness**: Mean deviation (in minutes) from time window end for late deliveries
- **Early Delivery Rate**: % of deliveries >30 minutes before window start (indicating inefficient routing)

**Operational Efficiency KPIs:**
- **Travel Time vs. Service Time Ratio**: `SUM(Duration of "Moving" activities) / SUM(Duration of "Arrive Customer" to "Depart Customer")`. Target: <2.0 for urban delivery
- **Average Time per Delivery Stop**: `SUM(Duration from "Arrive Customer" to "Depart Customer") / COUNT(Delivery Success)`
- **Vehicle Utilization Rate**: `SUM(Duration of "Moving" + "Service" activities) / (End Shift - Start Shift)`. Target: >75%
- **Stops per Hour**: `COUNT(Delivery Success) / (SUM(Duration of "Moving" + "Service" activities) / 3600)`

**Cost-Related KPIs:**
- **Fuel Consumption per Package**: Estimated using GPS speed profiles and vehicle fuel curves: `SUM(Fuel consumption model(speed, idle_time)) / COUNT(Delivery Success)`
- **Idle Time Percentage**: `SUM(Duration where speed=0 AND ignition=on) / Total shift duration`. Target: <15%
- **Failed Delivery Rate**: `COUNT(Delivery Failed) / (COUNT(Delivery Success) + COUNT(Delivery Failed))`. Target: <5%

**Maintenance KPIs:**
- **Unscheduled Stop Frequency**: `COUNT(Unscheduled Stop) / COUNT(Vehicle-Day)`
- **Mean Time Between Failures (MTBF)**: Average operating hours between "Engine Warning" events
