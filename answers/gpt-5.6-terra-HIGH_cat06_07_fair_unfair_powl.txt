Below are two valid POWL constructions. The first contains the affiliation-based XOR branch; the second removes it and uses one uniform cultural-fit path.

```python
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition
from pm4py.objects.process_tree.obj import Operator


def sequence(nodes):
    """
    Builds a sequential StrictPartialOrder over the supplied POWL nodes.
    """
    po = StrictPartialOrder(nodes=nodes)
    for source, target in zip(nodes, nodes[1:]):
        po.order.add_edge(source, target)
    return po
```

## 1. POWL model with potential unfairness

The cultural-fit stage contains an XOR. Applicants with a local/community affiliation can be routed to `CommunityAffiliationCheck`, where an uplift may be applied instead of undergoing the ordinary `CulturalFitCheck`.

```python
# Activities
receive_application_u = Transition(label="ReceiveApplication")
data_check_u = Transition(label="DataCompletenessCheck")
request_more_info_u = Transition(label="RequestMoreInfo")
skill_assessment_u = Transition(label="SkillAssessment")

reject_after_skill_u = Transition(label="RejectAfterSkillAssessment")

cultural_fit_u = Transition(label="CulturalFitCheck")
community_affiliation_u = Transition(label="CommunityAffiliationCheck")
managerial_review_u = Transition(label="ManagerialReview")
final_decision_u = Transition(label="FinalDecision")

# Data-completeness loop:
# DataCompletenessCheck -> either exit, or RequestMoreInfo -> DataCompletenessCheck again
data_completeness_loop_u = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_check_u, request_more_info_u]
)

# Potentially unfair cultural-fit XOR:
# Standard applicants follow CulturalFitCheck;
# affiliated/local applicants may follow CommunityAffiliationCheck and receive an uplift.
cultural_branch_u = OperatorPOWL(
    operator=Operator.XOR,
    children=[cultural_fit_u, community_affiliation_u]
)

# Candidates who pass the skill screen continue through one of the cultural branches.
qualified_candidate_flow_u = sequence([
    cultural_branch_u,
    managerial_review_u,
    final_decision_u
])

# Skill-score outcome:
# low score -> reject; sufficient score -> continue.
skill_gate_u = OperatorPOWL(
    operator=Operator.XOR,
    children=[reject_after_skill_u, qualified_candidate_flow_u]
)

# Complete unfair model
unfair_hiring_model = sequence([
    receive_application_u,
    data_completeness_loop_u,
    skill_assessment_u,
    skill_gate_u
])
```

Conceptually, the relevant unfair portion is:

```text
SkillAssessment
    ->
XOR(
    CulturalFitCheck,
    CommunityAffiliationCheck
)
    ->
ManagerialReview
    ->
FinalDecision
```

The XOR should be understood as being guarded externally: affiliation/local-residency information determines whether the applicant is sent to the standard cultural check or the affiliation-sensitive path.

## 2. POWL model without unfairness

This version retains the data-completeness loop and skill-score decision, but every qualified applicant follows the same `CulturalFitCheck`. There is no `CommunityAffiliationCheck` activity and no affiliation-based routing.

```python
# Activities
receive_application_f = Transition(label="ReceiveApplication")
data_check_f = Transition(label="DataCompletenessCheck")
request_more_info_f = Transition(label="RequestMoreInfo")
skill_assessment_f = Transition(label="SkillAssessment")

reject_after_skill_f = Transition(label="RejectAfterSkillAssessment")

cultural_fit_f = Transition(label="CulturalFitCheck")
managerial_review_f = Transition(label="StructuredManagerialReview")
final_decision_f = Transition(label="FinalDecision")

# Same completeness loop as in the unfair model
data_completeness_loop_f = OperatorPOWL(
    operator=Operator.LOOP,
    children=[data_check_f, request_more_info_f]
)

# Uniform path for every candidate who passes the skill assessment.
# The review should use the same rubric and should not receive affiliation/locality cues.
qualified_candidate_flow_f = sequence([
    cultural_fit_f,
    managerial_review_f,
    final_decision_f
])

# This XOR is only a score-based pass/reject outcome, not an affiliation-based advantage.
skill_gate_f = OperatorPOWL(
    operator=Operator.XOR,
    children=[reject_after_skill_f, qualified_candidate_flow_f]
)

# Complete fairer model
fair_hiring_model = sequence([
    receive_application_f,
    data_completeness_loop_f,
    skill_assessment_f,
    skill_gate_f
])
```

Its core qualified-candidate path is therefore:

```text
SkillAssessment
    ->
CulturalFitCheck
    ->
StructuredManagerialReview
    ->
FinalDecision
```

The remaining XOR in the second model represents only the legitimate skill-assessment outcome: reject after an insufficient score or proceed after a sufficient score. No process branch is based on community affiliation, local residency, or educational/community background.
