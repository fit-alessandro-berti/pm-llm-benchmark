```sql
-- Replace 10 with the desired value of K.
WITH case_variants AS (
    SELECT
        case_id,
        list(activity ORDER BY timestamp) AS variant
    FROM event_log
    GROUP BY case_id
),

variant_counts AS (
    SELECT
        variant,
        COUNT(*) AS case_count
    FROM case_variants
    GROUP BY variant
),

top_k_variants AS (
    SELECT
        variant,
        case_count
    FROM variant_counts
    ORDER BY
        case_count DESC,
        variant::VARCHAR  -- deterministic tie-breaker
    LIMIT 10
),

selected_cases AS (
    SELECT cv.case_id
    FROM case_variants AS cv
    JOIN top_k_variants AS tk
        ON cv.variant = tk.variant
)

SELECT e.*
FROM event_log AS e
JOIN selected_cases AS sc
    ON e.case_id = sc.case_id
ORDER BY
    e.case_id,
    e.timestamp;
```

- `case_variants` creates one ordered activity list per case.
- `variant_counts` groups identical lists and counts the cases for each process variant.
- `top_k_variants` retains the `K` most frequent variants.
- `selected_cases` identifies only cases following those variants.
- The final join returns all original events for those cases.

If multiple events in the same case can have identical timestamps, an additional unique tie-breaker is needed to make their sequence deterministic, for example `ORDER BY timestamp, event_id` if such a column exists.
