```sql
WITH ordered_events AS (
    SELECT
        case_id,
        activity,
        "timestamp" AS event_timestamp,

        LEAD(activity) OVER case_window AS next_activity,
        LEAD("timestamp") OVER case_window AS next_timestamp,

        LEAD(activity, 2) OVER case_window AS second_next_activity,
        LEAD("timestamp", 2) OVER case_window AS second_next_timestamp
    FROM event_log
    WINDOW case_window AS (
        PARTITION BY case_id
        ORDER BY "timestamp"
    )
),
cases_to_exclude AS (
    SELECT DISTINCT case_id
    FROM ordered_events
    WHERE activity = 'Approve Purchase Requisition'
      AND next_activity = 'Create Order'
      AND second_next_activity = 'Confirm Order'
      -- Strictly more than five days from Create Order to Confirm Order
      AND second_next_timestamp > next_timestamp + INTERVAL '5 days'
)
SELECT e.*
FROM event_log AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM cases_to_exclude AS excluded
    WHERE excluded.case_id = e.case_id
)
ORDER BY
    e.case_id,
    e."timestamp";
```

`LEAD` examines the next two events within each case, ensuring that the three activities are directly consecutive. `DISTINCT` ensures that a case containing at least one qualifying sequence is excluded only once, while `NOT EXISTS` removes all events belonging to those cases. If events can share identical timestamps and an event identifier is available, include it after `"timestamp"` in the window ordering to make event succession deterministic.
