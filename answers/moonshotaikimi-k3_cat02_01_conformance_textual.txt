# Analysis of Event Log Against Normative Process

## Reference: The Two Valid Sequences

From the normative description, only two flows are acceptable:

- **Sufficient inventory:** Receive  Check  Authorize payment  Package  Ship  Close
- **Insufficient inventory:** Receive  Check  Cancel  Close

Key explicit constraints: Check inventory precedes everything else; Authorize payment precedes Package; Package precedes Ship; Ship never follows Cancel; no fulfillment activities after Cancel; Close is always last.

###  Case 2 — Violation

- **Packaging before payment authorization.** The description states that *"Package items" should only occur after authorization*, and that authorization must occur *"after Check inventory and before packaging."* Here the two activities are swapped, directly violating the stated ordering. Authorizing payment for goods already packaged defeats the control purpose of the authorization step (confirming the payment method before committing to fulfillment).

###  Case 3 — Violation (multiple, severe)

- **Shipping after cancellation.** This is explicitly prohibited: *"Ship order … never after a cancellation,"* and *"once an order is canceled, it would be illogical to continue with activities intended for fulfillment (such as packaging or shipping)."* This is the clearest violation in the log.
- **Shipping without packaging.** No "Package items" event occurs, violating *"Ship order should only occur after packaging."*
- **Payment authorized on a cancellation path.** The cancellation branch is defined as *Check  directly proceed to Cancel order  Close*. Interleaving an authorization mixes the two mutually exclusive branches; authorizing payment for an order that is then canceled contradicts the logic that payment is authorized only once fulfillment is confirmed.

###  Case 5 — Violation

- **Skipped packaging step.** "Ship order" occurs without any preceding "Package items," violating the constraint that shipping should *only occur after packaging* — items "must be prepared before they can be shipped."

- **Case 5** could charitably be read as a recording gap rather than a true process violation, but under a strict reading of the normative text ("Ship order should only occur **after packaging**"), the absence of a packaging event before shipping constitutes non-conformance.
