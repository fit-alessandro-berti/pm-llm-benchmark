# Accepting Petri Net for Insurance Claim Management Process

Below is the Python code constructing the accepting Petri net for the described insurance claim process. The net includes:

- A **linear backbone** of activities (C  CR  DV  FC  CA  AP  P  N  CL).
- A **loop** between `DV` and `RDS` (Re-Document Submission), allowing document re-submission before continuing.
- A **loop** between `FC` and `II` (In-depth Investigation), allowing multiple rounds of investigation before proceeding to Claim Assessment.
- An initial marking with a token in the `start` place (representing a new claim arriving).
- A final marking with a token in the `end` place (representing the claim being closed).

```python
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

# Create the Petri net
net = PetriNet(name="insurance_claim_management")

# ---------------------------------------------------------
# Places
# ---------------------------------------------------------
start       = PetriNet.Place(name="start")          # claim arrives
p_c         = PetriNet.Place(name="p_c")            # after Insurance Claim (C)
p_cr        = PetriNet.Place(name="p_cr")           # after Claim Registration (CR) / ready for DV
p_dv        = PetriNet.Place(name="p_dv")           # after Document Verification (DV) - decision point
p_fc        = PetriNet.Place(name="p_fc")           # after Fraud Check (FC) - decision point
p_ca        = PetriNet.Place(name="p_ca")           # after Claim Assessment (CA)
p_ap        = PetriNet.Place(name="p_ap")           # after Approval (AP)
p_pay       = PetriNet.Place(name="p_pay")          # after Payment (P)
p_notify    = PetriNet.Place(name="p_notify")       # after Notification (N)
end         = PetriNet.Place(name="end")            # claim closed

for place in [start, p_c, p_cr, p_dv, p_fc, p_ca, p_ap, p_pay, p_notify, end]:
    net.places.add(place)

# ---------------------------------------------------------
# Transitions
# ---------------------------------------------------------
t_c   = PetriNet.Transition(name="C",   label="Insurance Claim")
t_cr  = PetriNet.Transition(name="CR",  label="Claim Registration")
t_dv  = PetriNet.Transition(name="DV",  label="Document Verification")
t_rds = PetriNet.Transition(name="RDS", label="Re-Document Submission")
t_fc  = PetriNet.Transition(name="FC",  label="Fraud Check")
t_ii  = PetriNet.Transition(name="II",  label="In-depth Investigation")
t_ca  = PetriNet.Transition(name="CA",  label="Claim Assessment")
t_ap  = PetriNet.Transition(name="AP",  label="Approval")
t_p   = PetriNet.Transition(name="P",   label="Payment")
t_n   = PetriNet.Transition(name="N",   label="Notification")
t_cl  = PetriNet.Transition(name="CL",  label="Closure")

for t in [t_c, t_cr, t_dv, t_rds, t_fc, t_ii, t_ca, t_ap, t_p, t_n, t_cl]:
    net.transitions.add(t)

# ---------------------------------------------------------
# Arcs - main sequence
# ---------------------------------------------------------
petri_utils.add_arc_from_to(start, t_c, net)
petri_utils.add_arc_from_to(t_c, p_c, net)

petri_utils.add_arc_from_to(p_c, t_cr, net)
petri_utils.add_arc_from_to(t_cr, p_cr, net)

petri_utils.add_arc_from_to(p_cr, t_dv, net)
petri_utils.add_arc_from_to(t_dv, p_dv, net)

# Loop: DV <-> RDS (re-submission of documents before continuing)
petri_utils.add_arc_from_to(p_dv, t_rds, net)
petri_utils.add_arc_from_to(t_rds, p_cr, net)

# Continue from DV decision point to Fraud Check
petri_utils.add_arc_from_to(p_dv, t_fc, net)
petri_utils.add_arc_from_to(t_fc, p_fc, net)

# Loop: FC <-> II (in-depth investigation, can repeat multiple times)
petri_utils.add_arc_from_to(p_fc, t_ii, net)
petri_utils.add_arc_from_to(t_ii, p_dv, net)

# Continue from FC decision point to Claim Assessment
petri_utils.add_arc_from_to(p_fc, t_ca, net)
petri_utils.add_arc_from_to(t_ca, p_ca, net)

petri_utils.add_arc_from_to(p_ca, t_ap, net)
petri_utils.add_arc_from_to(t_ap, p_ap, net)

petri_utils.add_arc_from_to(p_ap, t_p, net)
petri_utils.add_arc_from_to(t_p, p_pay, net)

petri_utils.add_arc_from_to(p_pay, t_n, net)
petri_utils.add_arc_from_to(t_n, p_notify, net)

petri_utils.add_arc_from_to(p_notify, t_cl, net)
petri_utils.add_arc_from_to(t_cl, end, net)

# ---------------------------------------------------------
# Initial and Final Markings
# ---------------------------------------------------------
im = Marking()
im[start] = 1

fm = Marking()
fm[end] = 1
```

### Explanation of Structure

| Step | Meaning |
|------|---------|
| `start  C  p_c` | A new claim arrives and is filed. |
| `p_c  CR  p_cr` | The claim is registered. |
| `p_cr  DV  p_dv` | Documents are verified. |
| `p_dv  RDS  p_cr` | **Loop:** If documents are incomplete, re-submission occurs and DV is repeated. |
| `p_dv  FC  p_fc` | If documents are fine, fraud check proceeds. |
| `p_fc  II  p_dv` | **Loop:** If fraud check raises doubts, an in-depth investigation is performed; this can lead back into another FC (possibly multiple times). |
| `p_fc  CA  p_ca` | Once fraud check is cleared, the claim is assessed. |
| `p_ca  AP  p_ap` | The claim is approved by a senior manager. |
| `p_ap  P  p_pay` | Payment is made. |
| `p_pay  N  p_notify` | Customer is notified. |
| `p_notify  CL  end` | The claim is closed, reaching the **final marking**. |

This model captures the sequential process flow with two feedback loops — **DV/RDS** and **FC/II** — which can occur zero or multiple times before the process advances toward closure.
