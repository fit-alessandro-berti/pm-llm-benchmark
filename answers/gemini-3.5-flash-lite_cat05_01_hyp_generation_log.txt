### 2. Hypotheses for Underlying Causes

*   **Hypothesis 1: System Guardrail Deficiencies (Process Enforcement)**  
    The order management system lacks hard blocking constraints. Users (such as warehouse clerks or logistics managers) can override standard workflow stages and execute downstream activities (like shipping) without prerequisite checks (like credit approval or stock validation) passing first.
*   **Hypothesis 2: Manual Workarounds / "Shadow Processes"**  
    Operational staff may bypass the system queue during high-volume periods or for priority orders, performing fulfillment offline and logging events into the system retroactively or out of order.
*   **Hypothesis 3: Role Confusion or Excessive Permissions**  
    Certain resources (e.g., specific warehouse clerks or finance teams) might hold overly broad permissions, allowing them to initiate invoices or payments prematurely.

### 3. Investigative SQL Queries

To validate these hypotheses across a larger dataset, the following PostgreSQL queries can be executed.

#### Query 1: Detect Cases that Violate the Prerequisite Order (e.g., Shipped Before Stock Validation)
*Purpose: Identifies instances where physical goods were shipped (`Ship Goods`) before stock was validated (`Validate Stock`).*

```sql
SELECT 
    ship.case_id,
    ship.timestamp AS ship_time,
    val.timestamp AS validation_time
FROM order_event_log ship
JOIN order_event_log val ON ship.case_id = val.case_id
WHERE ship.activity = 'Ship Goods'
  AND val.activity = 'Validate Stock'
  AND ship.timestamp < val.timestamp;
```

#### Query 2: Quantify Process Deviations by Order Type
*Purpose: Checks if priority orders are more prone to bypassing standard steps compared to standard orders.*

```sql
SELECT 
    o.order_type,
    COUNT(DISTINCT e.case_id) AS total_cases,
    COUNT(DISTINCT CASE WHEN e.activity = 'Receive Payment' AND e.timestamp < (
        SELECT MIN(timestamp) FROM order_event_log 
        WHERE case_id = e.case_id AND activity = 'Ship Goods'
    ) THEN e.case_id END) AS paid_before_shipment_count
FROM orders o
JOIN order_event_log e ON o.case_id = e.case_id
GROUP BY o.order_type;
```

#### Query 3: Resource Involvement in Out-of-Sequence Events
*Purpose: Determines if specific resources (clerks, managers, or finance personnel) are habitual drivers of process bypasses.*

```sql
SELECT 
    e.resource,
    r.role,
    r.department,
    COUNT(e.event_id) AS anomalous_events_logged
FROM order_event_log e
JOIN resources r ON e.resource = r.resource_id
WHERE e.activity IN ('Ship Goods', 'Receive Invoice')
  AND e.timestamp < (
      SELECT MIN(timestamp) 
      FROM order_event_log 
      WHERE case_id = e.case_id AND activity = 'Register Order'
  )
GROUP BY e.resource, r.role, r.department
ORDER BY anomalous_events_logged DESC;
```
