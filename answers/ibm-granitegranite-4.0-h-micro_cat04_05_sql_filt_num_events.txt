To achieve the task described, you would need to follow these steps in a DuckDB SQL query:

1. **Group Events by `case_id`**: First, you need to group the events in the `event_log` table by `case_id` to calculate the number of events per case.
2. **Filter Out Cases with More Than Six Events**: Next, you will filter out any `case_id` that has more than six events.
3. **Return Events for Remaining Cases**: Finally, you will return the events for the cases that meet the criteria (i.e., six or fewer events).

Here is how you can write the query:

```sql
-- Step 1: Create a subquery to count the events per case_id
WITH event_counts AS (
    SELECT
        case_id,
        COUNT(*) AS event_count
    FROM event_log
    GROUP BY case_id
),

-- Step 2: Filter out cases with more than six events
filtered_cases AS (
    SELECT
        case_id
    FROM event_counts
    WHERE event_count <= 6
)

-- Step 3: Return events for the remaining cases
SELECT
    e.*
FROM event_log e
JOIN filtered_cases fc
    ON e.case_id = fc.case_id;
```

### Explanation:

- **`WITH event_counts AS (...)`**: This Common Table Expression (CTE) calculates the number of events for each `case_id` by grouping the `event_log` table on `case_id` and using `COUNT(*)` to count the rows for each group.
- **`filtered_cases AS (...)`**: This second CTE filters out any `case_id` where the event count exceeds six. It selects only those `case_id`s that have six or fewer events.
- **Final `SELECT`**: The main query selects all columns (`e.*`) from `event_log` where the `case_id` is found in the `filtered_cases` CTE. This ensures that only events from cases with six or fewer events are returned.

This approach efficiently handles the grouping, filtering, and selection processes required to answer the task.
