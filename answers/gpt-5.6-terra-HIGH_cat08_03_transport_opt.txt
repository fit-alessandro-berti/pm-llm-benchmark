## 1. Process Discovery and Conformance Checking

### 1.1 Build a cohesive event log

The source data represent different views of the same physical operation. A useful process-mining dataset must reconcile these views into timestamped, consistently defined operational events.

#### Recommended case structure

A single case definition is unlikely to answer every question. Speedy Parcels should create at least two linked process perspectives:

1. **Vehicle-day case**  
   - Case ID: `Vehicle_ID + Operational_Date`, e.g., `V12-20241205`
   - Best for analysing route execution, total shift duration, traffic delays, depot time, breakdowns, capacity use, fuel-related proxy measures, and driver/vehicle performance.

2. **Package-delivery case**  
   - Case ID: `Package_ID`, potentially linked to a delivery attempt ID.
   - Best for analysing punctuality, requested delivery windows, failed attempts, customer service time, re-delivery loops, and package lifecycle.

Where possible, an **object-centric event log** is preferable because events can relate simultaneously to several entities:

- Vehicle
- Driver
- Route / route plan
- Package
- Customer stop
- Depot
- Maintenance work order

For example, a “Delivery Success” event belongs both to the vehicle-day route and to the package journey. A maintenance event belongs to the vehicle and may affect multiple package cases.

#### Canonical event-log schema

A normalized event record should contain fields such as:

| Field | Purpose |
|---|---|
| Event ID | Unique event identifier |
| Timestamp | UTC-normalized event time |
| Case ID | Vehicle-day or package-delivery case |
| Activity | Standardized process activity |
| Vehicle ID | Vehicle used |
| Driver ID | Driver assigned |
| Route ID / Planned Stop ID | Link to dispatch plan |
| Package ID | Package-level linkage |
| Customer / Stop ID | Delivery-location linkage |
| Latitude / Longitude | Spatial analysis |
| Event source | GPS, scanner, dispatch, maintenance |
| Planned timestamp / time window | For conformance and punctuality |
| Actual timestamp | For execution analysis |
| Speed / ignition / fuel / odometer, if available | Operational performance attributes |
| Failure or delay reason | For root-cause analysis |
| Capacity loaded / packages remaining | Utilization analysis |

#### Standardize event activities

Raw system events should be mapped to a controlled activity taxonomy. For example:

**Shift and depot activities**
- Start Shift
- Vehicle Inspection
- Route Assigned
- Load Vehicle Complete
- Depart Depot
- Arrive Depot
- Unload / Return Undelivered Packages
- End Shift

**Travel and stop activities**
- Travel to Stop
- Traffic Delay
- Low-Speed Travel
- Unplanned Stop
- Parking/Search for Parking
- Arrive Customer
- Service Customer
- Depart Customer

**Delivery activities**
- Delivery Success
- Delivery Failed – Customer Absent
- Delivery Failed – Access Issue
- Delivery Failed – Address Issue
- Delivery Failed – Damaged/Other
- Re-delivery Scheduled

**Vehicle events**
- Engine Warning
- Breakdown
- Maintenance Stop
- Scheduled Maintenance
- Repair Complete

A GPS tracker may generate thousands of records per shift. These should generally not all be treated as separate process events. Instead, GPS data should be transformed into meaningful higher-level events, such as:

- A travel leg from one planned stop to the next
- A low-speed segment lasting more than a threshold, such as 5–10 minutes
- Idling exceeding a threshold, such as 3 minutes
- An unplanned dwell event outside a customer geofence
- Arrival at and departure from a depot or customer geofence
- Route deviation from the planned route corridor
- Excessive detour event
- Extended stop linked to a potential breakdown

#### Data integration steps

1. **Extract source data**
   - GPS telemetry and ignition status.
   - Handheld scanner milestones.
   - Dispatch plans, route sequences, package assignments, time windows, capacities.
   - Maintenance records, work orders, repair codes, downtime.

2. **Clean and normalize**
   - Convert all timestamps to the same time zone and format.
   - Remove duplicate or corrupted GPS pings.
   - Standardize vehicle IDs, driver IDs, route IDs, package IDs, and location identifiers.
   - Reconcile scanner timestamps that may be captured offline and uploaded later.
   - Correct impossible event ordering where feasible, such as “Depart Customer” preceding “Arrive Customer.”

3. **Geocode and geofence locations**
   - Map customer addresses and depot locations to coordinates.
   - Define geofences around customer addresses, depots, fuel stations, workshops, and known traffic hotspots.
   - Infer arrival/departure events where scanner events are missing but GPS evidence exists.

4. **Link actual events to planned route stops**
   - Match actual customer visits to planned stops using package ID, customer ID, location proximity, and time proximity.
   - Determine whether the stop was served in its planned sequence.
   - Identify unscheduled customers, skipped stops, repeated visits, and off-route movements.

5. **Create derived events and durations**
   - Travel duration: departure from prior stop to arrival at next stop.
   - Service duration: arrival at customer to departure from customer.
   - Dwell duration: stationary time not explained by delivery or planned break.
   - Delay duration: actual travel time minus expected travel time.
   - Route deviation distance/time: actual path compared with planned path.
   - Maintenance interruption duration: breakdown/repair start to recovery.

6. **Validate data quality**
   - Measure missing scanner events by driver, vehicle, and route.
   - Flag GPS gaps.
   - Check whether all loaded packages have a final status.
   - Reconcile end-of-day package counts with dispatch manifests.

### 1.2 Data integration challenges

Likely issues include:

- **Different timestamp accuracy:** GPS may be near-real-time, while scanners may upload delayed records.
- **Different granularities:** GPS produces frequent pings; scanner events are sparse but operationally meaningful.
- **Missing or inconsistent IDs:** A maintenance log may identify a vehicle but not a route or driver.
- **Ambiguous location matching:** Dense urban areas can create GPS errors, particularly around multi-unit buildings.
- **Multiple packages per stop:** Several packages may be delivered during one physical visit.
- **Multiple delivery attempts:** A package can re-enter the process after a failed delivery.
- **Event order anomalies:** Device clock differences can make events appear out of sequence.
- **Privacy and governance:** Driver-level analysis requires appropriate access controls, transparent purpose, and safeguards against unfair performance assessment.
- **Planned-versus-actual definition differences:** A dispatch “stop” may represent a building, while scanner data may represent an individual parcel.

These issues should be explicitly documented in a data-quality scorecard. Process mining results should distinguish operational findings from possible data artifacts.

### 1.3 Discover the actual delivery process

After preparing the event log, Speedy Parcels can use process discovery to reconstruct the real operational process rather than assuming routes were executed as planned.

#### Useful process-discovery techniques

1. **Directly-Follows Graphs (DFGs)**
   - Quickly show the most common sequences of events.
   - Useful for identifying common paths such as:
     - Depart Depot  Travel  Arrive Customer  Delivery Success  Depart Customer.
   - Also reveal deviations:
     - Depart Depot  Unplanned Stop  Traffic Delay  Arrive Customer.
     - Arrive Customer  Delivery Failed  Re-delivery Scheduled.
     - Travel  Engine Warning  Maintenance Stop  Resume Route.

2. **Inductive Miner**
   - Produces structured process models and handles loops reasonably well.
   - Appropriate for identifying recurring delivery patterns, re-delivery cycles, and alternative paths.

3. **Fuzzy Miner or similar simplification techniques**
   - Helpful for highly variable route processes where showing every stop would create an unreadable “spaghetti model.”
   - Can focus attention on frequent activities and major deviations.

4. **Performance-annotated process maps**
   - Add median, mean, percentile, and variance of elapsed times to transitions.
   - Example: show that “Depart Depot  Arrive First Customer” has a median of 32 minutes but a 90th percentile of 65 minutes during morning peak traffic.

5. **Spatial process mining**
   - Overlay discovered paths, dwell events, and deviations on a map.
   - Particularly important in logistics because the geographic location of a delay is often as important as the process activity.

#### Example actual process variants

A high-performing route might look like:

`Load Complete  Depart Depot  Travel  Arrive Customer  Delivery Success  Depart Customer  …  Arrive Depot  End Shift`

A problematic route might look like:

`Depart Depot  Traffic Delay  Arrive Customer  Delivery Failed  Unplanned Stop  Maintenance Warning  Repair Stop  Overtime  Arrive Depot`

Process discovery should not only reveal the dominant “happy path”; it should quantify the frequency and cost of exceptional variants.

### 1.4 Conformance checking against planned routes

The dispatch system represents the intended process: assigned vehicle, planned route, customer sequence, expected arrival time, delivery windows, package load, and planned return time. Conformance checking compares that plan with the actual event log.

#### Planned model

The planned route can be represented as:

`Load  Depart Depot  Stop 1  Stop 2  Stop 3  …  Return Depot`

Each planned stop should have:

- Planned sequence number
- Planned arrival and service time
- Customer time window
- Expected travel distance/time from prior stop
- Package count and weight/volume
- Planned route corridor or road path where available

#### Conformance techniques

1. **Alignment-based conformance checking**
   - Align actual activity sequences with planned route sequences.
   - Identify insertions, deletions, skipped activities, and reordering.

2. **Token-based replay**
   - Evaluate whether actual execution can be replayed through the planned model.
   - Useful for high-level route adherence.

3. **Temporal conformance checking**
   - Compare actual versus planned departure, arrival, service, and return times.
   - Flag late starts, late arrivals, excessive service duration, and late route completion.

4. **Spatial conformance checking**
   - Compare GPS trajectories to planned route corridors or expected travel paths.
   - Measure off-route distance, detours, unauthorized stop locations, and route backtracking.

5. **Capacity and assignment conformance**
   - Check whether assigned vehicle capacity was exceeded or underused.
   - Check whether assigned packages were delivered by the planned vehicle and driver.
   - Identify vehicle swaps or route handovers.

#### Key deviations to investigate

| Deviation type | Example | Possible meaning |
|---|---|---|
| Sequence deviation | Stop 12 served before Stop 5 | Dynamic route adjustment, poor planning, driver preference, missed time window |
| Skipped planned stop | Planned stop never visited | Delivery failure, package missing, route truncation |
| Extra stop | Visit to unplanned location | Fuel stop, personal stop, vehicle issue, ad hoc collection |
| Excessive detour | Actual distance materially exceeds planned distance | Navigation issues, traffic avoidance, poor route plan |
| Timing deviation | Arrival 35 minutes after delivery window | Traffic, late depot departure, poor estimates, high service time |
| Excessive dwell | Vehicle stationary 20 minutes outside customer/depot | Parking issue, break, breakdown, administrative delay |
| Maintenance deviation | Repair stop during route | Preventive-maintenance gap or unreliable vehicle |
| Re-delivery loop | Failed attempt followed by later route attempt | Customer availability or address/access problems |
| Shift overrun | Return after planned end time | Route overload, poor sequencing, delays, driver behavior |

A conformance dashboard should rank deviations both by frequency and operational impact, since a rare breakdown may be more expensive than many minor sequence deviations.

## 2. Performance Analysis and Bottleneck Identification

### 2.1 Key performance indicators

The KPIs should be available at multiple levels:

- Company-wide
- Depot
- Route / territory
- Vehicle
- Driver
- Customer segment
- Stop type
- Time of day / day of week
- Vehicle type
- Planned-versus-actual route

### Core punctuality and service KPIs

| KPI | Calculation from event log | Why it matters |
|---|---|---|
| On-Time Delivery Rate | Deliveries completed within customer window / total delivery attempts or successful deliveries | Primary customer-service measure |
| Late Delivery Rate | Deliveries after promised window / deliveries due | Identifies service failures |
| Average lateness | Average of `actual delivery time - promised latest time`, for late deliveries | Shows severity, not only count |
| First-attempt delivery success rate | Successful first attempts / all first delivery attempts | Measures avoidable re-delivery |
| Failed delivery rate | Failed delivery attempts / total attempts | Indicates customer availability, address/access, or scheduling issues |
| Re-delivery rate | Packages requiring another attempt / packages assigned | Direct driver of cost and service degradation |
| Stop completion rate | Completed planned stops / planned stops | Identifies route execution reliability |
| Route completion within shift | Routes ending before scheduled shift end / total routes | Measures overtime and route feasibility |

### Time and process-efficiency KPIs

| KPI | Calculation | Interpretation |
|---|---|---|
| End-to-end route cycle time | Arrive Depot or End Shift minus Depart Depot or Start Shift | Total route productivity |
| Travel time per stop | Sum of travel-leg durations / number of stops | Measures route and traffic efficiency |
| Service time per stop | Depart Customer minus Arrive Customer | Captures customer interaction, parking, handoff, scanning |
| Average time per successful delivery | Total route operating time / successful deliveries | Productivity measure |
| Travel-to-service ratio | Total travel time / total customer service time | High ratio may indicate territory or sequence inefficiency |
| Idle time percentage | Idle duration with ignition on / total route duration | Fuel and productivity issue |
| Unplanned dwell time | Time stationary outside recognized service, break, depot, or maintenance locations | Detects operational waste |
| Depot turnaround time | Depart Depot minus route assignment/load completion | Identifies loading and dispatch delays |
| Overtime hours per route | End Shift minus planned shift end, where positive | Cost and planning-feasibility measure |

### Cost and asset KPIs

| KPI | Calculation | Interpretation |
|---|---|---|
| Fuel consumption per km | Fuel used / distance traveled, if fuel data available | Identifies inefficient driving, congestion, vehicle condition |
| Fuel consumption per package | Fuel used / successful deliveries | Connects cost to output |
| Fuel proxy from idling | Idle engine-on time × estimated fuel-burn rate | Useful when direct fuel records are unavailable |
| Distance per delivery | Total route distance / successful deliveries | Assesses route density and territory design |
| Vehicle utilization rate | Productive route time or loaded capacity / available vehicle time or capacity | Identifies underuse/overloading |
| Capacity utilization | Loaded weight/volume/packages divided by vehicle capacity | Supports fleet and dispatch decisions |
| Maintenance interruption rate | Routes with repair/breakdown interruption / total routes | Measures reliability risk |
| Vehicle downtime | Maintenance/repair hours / total available vehicle hours | Asset availability indicator |
| Cost of failed delivery | Extra travel + service + administrative cost per failed package | Quantifies re-delivery impact |

### Traffic and route-deviation KPIs

| KPI | Calculation | Interpretation |
|---|---|---|
| Traffic-delay frequency | Number of low-speed or abnormal travel segments per route | Identifies recurring congestion exposure |
| Traffic-delay duration | Time below speed threshold adjusted for road type / route duration | Quantifies congestion impact |
| Excess travel time | Actual travel duration minus predicted normal travel duration | Separates traffic from ordinary travel |
| Route adherence rate | Planned stops served in intended order or within allowed sequence tolerance / planned stops | Measures execution conformity |
| Detour ratio | Actual driven distance / planned route distance | Indicates route inefficiency |
| Off-route time | Time outside planned route corridor | Identifies deviations and possible navigation issues |

To avoid misleading conclusions, compare KPIs using median values and percentiles as well as averages. Urban delivery data are usually skewed by a small number of extreme disruptions.

### 2.2 Bottleneck-identification techniques

#### Performance overlays on process maps

Annotate every activity and transition with:

- Median duration
- Average duration
- 90th or 95th percentile duration
- Frequency
- Variability
- Contribution to total route delay
- Contribution to cost

For example, an activity may be infrequent but costly:

- “Maintenance Stop” occurs on only 2% of routes but adds a median of 95 minutes.
- “Parking/Search for Parking” occurs on 30% of dense-city stops and adds a median of 8 minutes per stop.

#### Queue and waiting-time analysis

Process mining can identify where time is spent waiting rather than moving or servicing.

Examples:

- Delay between route assignment and depot departure.
- Time waiting at the customer location before access is gained.
- Time parked near customer location before scanning “Arrive Customer.”
- Time between failed delivery and re-dispatch.
- Time from warning light to repair start.

#### Segmentation analysis

Bottlenecks should be sliced by:

- Route / territory
- Postal code or customer zone
- Day of week
- Hour of day
- Weather, if available
- Driver
- Vehicle model, age, mileage, and maintenance history
- Customer type: residential, commercial, apartment, business park
- Stop density
- Package volume / load factor
- Planned sequence position: first stop, mid-route, last stop
- Delivery-window type: narrow, broad, fixed appointment

#### Spatial hotspot analysis

Use GPS data to map:

- Repeated low-speed segments.
- Locations with unusually long dwell times.
- Areas with frequent route deviations.
- Buildings with high failed-delivery rates.
- Zones where service time is consistently above expectation.
- Locations near which vehicle faults or breakdowns often occur.

#### Quantifying bottleneck impact

For each bottleneck, calculate:

1. **Frequency:** How often does it occur?
2. **Average delay:** How much additional time does it cause per occurrence?
3. **Total lost time:** Frequency × average delay.
4. **Downstream impact:** How many subsequent deliveries become late?
5. **Cost impact:** Additional fuel, labor, overtime, re-delivery, and maintenance cost.
6. **Customer impact:** Late-delivery count, failed-attempt count, complaint rate if available.

Example:

- A downtown parking bottleneck affects 1,200 stops per month.
- It adds an average of 6 minutes per stop.
- Total lost time: 7,200 minutes, or 120 driver-hours per month.
- It causes 300 late deliveries and 40 overtime shifts.
- This provides a stronger business case than merely observing that parking is “slow.”

## 3. Root Cause Analysis for Inefficiencies

Process mining identifies patterns and deviations; root-cause analysis determines whether those patterns are caused by route design, congestion, vehicle reliability, customer behavior, operational policy, or some combination.

### 3.1 Suboptimal route planning

#### Potential symptoms
- Frequent sequence deviations.
- High detour ratio.
- Repeated backtracking.
- Drivers consistently reorder the same planned stops.
- Low capacity utilization on some routes and overloaded routes on others.
- Long travel times between geographically close stops because of poor sequence logic.
- Overtime concentrated on particular territories.

#### Process-mining validation
- Compare planned stop sequence with actual sequence.
- Identify whether certain planned transitions are routinely bypassed.
- Analyze route variants by territory and route planner version.
- Compare actual distance and duration with simulated alternatives.
- Identify recurring “workarounds” used by drivers, such as visiting a particular cluster of stops first.

If many drivers independently deviate from the same planned sequence and achieve better on-time outcomes, the issue is likely route design rather than individual behavior.

---

### 3.2 Inaccurate travel-time estimation

#### Potential symptoms
- Routes are planned to fit the shift, but actual routes frequently overrun.
- Late deliveries increase later in the day.
- Actual travel times are consistently above planned times for specific legs.
- The same road segment is underestimated during predictable periods.

#### Process-mining validation
- Calculate planned versus actual travel duration for every route leg.
- Segment by time of day, weekday, season, weather, and zone.
- Examine forecast error distributions, not just averages.
- Determine whether lateness begins after a small number of early underestimated legs and cascades through the remainder of the route.

A useful result may be: “Travel time between the depot and the northern zone is underestimated by 18 minutes on weekday mornings, causing 42% of the day’s late deliveries.”

---

### 3.3 Traffic congestion patterns

#### Potential symptoms
- Repeated low-speed GPS segments.
- Long travel durations for the same road links at particular times.
- Traffic delays concentrated in morning, lunchtime, or afternoon peak periods.
- Drivers deviating from planned routes around the same locations.

#### Process-mining validation
- Correlate GPS-derived low-speed events with route-leg delays.
- Compare delay patterns by road segment, time band, and day of week.
- Integrate external traffic, roadworks, accident, weather, and event-calendar data where possible.
- Determine whether rerouting reduces or increases delay relative to the planned path.

It is important to distinguish congestion from legitimate low-speed driving in dense delivery zones. Road class, location, and vehicle status should be used to avoid treating every low-speed event as traffic.

---

### 3.4 High variability in customer service time

#### Potential symptoms
- Large differences between “Arrive Customer” and “Depart Customer.”
- High dwell times at certain building types or customer locations.
- Late deliveries caused by cumulative service delays rather than travel delays.
- Drivers with apparently poor productivity only in selected customer segments.

#### Potential root causes
- Difficult parking or loading access.
- High-rise buildings with elevator waits.
- Gated communities or access-control delays.
- Customers requiring signatures or identity checks.
- Large or multi-package deliveries.
- Building reception processes.
- Incomplete addresses.
- Time-consuming scanning or proof-of-delivery procedures.

#### Process-mining validation
- Analyze service duration by customer location, building type, package count, package size, driver, and time of day.
- Compare the same customer served by different drivers.
- Identify recurrent long-duration stops and their activity sub-patterns.
- Separate parking/search time from actual customer interaction using GPS dwell and scanner timestamps.

If a stop is slow for every driver, the cause is likely site-specific. If only certain drivers have long service times at comparable stops, training, work practices, or familiarity may be factors.

---

### 3.5 Breakdowns and maintenance disruption

#### Potential symptoms
- Unplanned stops preceded by engine-warning events.
- Routes interrupted by repair or recovery events.
- Certain vehicles with high idling, poor fuel performance, or repeated maintenance events.
- High overtime and delivery failures on routes served by specific vehicles.
- Repeated rescheduling or vehicle swaps.

#### Process-mining validation
- Link maintenance records to vehicle-day cases.
- Compare routes with and without maintenance interruptions.
- Analyze the time from warning signal to breakdown or repair.
- Group performance by vehicle age, model, mileage, repair type, and maintenance history.
- Measure delay, re-delivery, overtime, and fuel impact caused by each maintenance event.

This analysis can identify vehicles that should be prioritized for replacement, inspection, or revised maintenance intervals.

---

### 3.6 Driver behavior or skill differences

Driver-level analysis should be used carefully and adjusted for route difficulty before making conclusions.

#### Possible indicators
- Excessive idling.
- Higher-than-expected detours.
- Frequent route resequencing.
- Longer service times at comparable stops.
- Higher failed-delivery rate.
- Repeated late starts.
- Increased harsh braking/acceleration, if telematics are available.
- Better performance than peers in certain territories, suggesting transferable practices.

#### Process-mining validation
- Compare drivers only within similar route types, zones, package loads, vehicle types, and time windows.
- Use matched-route or statistically controlled comparisons.
- Compare high-performing and low-performing process variants.
- Identify whether high-performing drivers use a repeatable sequence, park at different locations, or leave the depot earlier.

The objective should be operational learning and targeted support, not simply ranking drivers.

---

### 3.7 Failed delivery attempts and re-deliveries

#### Potential symptoms
- High “customer not home” event frequency.
- Multiple attempts for the same package.
- Failed deliveries concentrated in particular time windows, neighborhoods, customer types, or senders.
- Re-delivery loops creating next-day workload and route instability.

#### Process-mining validation
- Build package-level process variants:
  - First attempt success.
  - First attempt failed  second attempt success.
  - Failed  depot return  locker/pickup point.
- Analyze failure reasons by customer segment, time window, notification status, and driver.
- Measure the cost and delay caused by re-delivery loops.
- Determine whether failures are predictable from historical patterns.

For example, residential deliveries between 09:00 and 15:00 may have a consistently high absence rate, suggesting that time windows or alternative delivery options should be changed.

## 4. Data-Driven Optimization Strategies

The following strategies should be prioritized based on estimated impact, implementation effort, operational risk, and data quality.

### Strategy 1: Dynamic routing and traffic-aware route execution

#### Inefficiency targeted
- Excess travel time.
- Traffic delays.
- Late arrivals caused by static route plans.
- Driver ad hoc detours.
- Cascading lateness after early-route congestion.

#### Root cause addressed
- Static planning does not reflect current congestion, road closures, incidents, or actual route progress.
- Historical travel-time estimates may not account for time-of-day effects.

#### Process-mining evidence
- Conformance analysis reveals systematic timing deviations on certain route legs.
- GPS data show recurring low-speed hotspots.
- Actual route variants reveal that drivers regularly bypass certain planned road segments.
- Temporal analysis identifies predictable congestion by hour and day.

#### Recommended action
- Integrate real-time traffic feeds and road closure information into dispatch or navigation tools.
- Re-optimize remaining stops during the day when significant delays occur.
- Use time-dependent travel-time models based on historical GPS execution data.
- Define thresholds for automated replanning, such as when projected lateness exceeds a defined number of minutes or affects a customer time window.
- Protect high-priority and narrow-window deliveries during rerouting.

#### Expected KPI impact
- Higher On-Time Delivery Rate.
- Lower average lateness.
- Reduced travel time per stop.
- Lower detour ratio.
- Reduced idling and fuel consumption per package.
- Lower overtime rate.

---

### Strategy 2: Redesign delivery territories and stop sequencing using actual performance

#### Inefficiency targeted
- Excessive travel distance.
- Backtracking.
- Uneven route workloads.
- Underused or overloaded vehicles.
- Routes that regularly exceed driver shift limits.

#### Root cause addressed
- Planned territories may not match real geographic demand density, customer service times, road restrictions, or traffic patterns.
- Route sequencing may optimize distance but not time-window feasibility, parking difficulty, or building access.

#### Process-mining evidence
- Frequent planned-versus-actual sequence deviations.
- Routes with repeated overtime or low route completion rates.
- High detour ratio in certain territories.
- Actual high-performing variants differ consistently from planned routes.
- Certain zones have systematically higher customer service times or parking delays.

#### Recommended action
- Re-cluster delivery territories using historical stop density, service time, delivery-window patterns, traffic exposure, and parcel volume.
- Rebalance workload using expected route duration, not package count alone.
- Use historical service-time distributions per customer/area in planning.
- Sequence stops to account for time windows, congestion, parking restrictions, building access, and priority customers.
- Create separate route templates for morning commercial deliveries, daytime residential deliveries, dense urban zones, and suburban zones.
- Test redesigned territories through controlled pilots before full rollout.

#### Expected KPI impact
- Reduced distance per delivery.
- Improved route completion within shift.
- Lower overtime hours.
- Improved vehicle capacity utilization.
- Reduced travel-to-service time ratio.
- Better On-Time Delivery Rate.
- Lower fuel consumption per package.

---

### Strategy 3: Improve customer time-window management and failed-delivery prevention

#### Inefficiency targeted
- Failed delivery attempts.
- Re-delivery loops.
- Unproductive service time.
- Customer complaints due to late or missed deliveries.

#### Root cause addressed
- Broad or poorly selected delivery windows.
- Customer absence.
- Inaccurate address or access information.
- Insufficient customer notification.
- No attractive alternative delivery channel.

#### Process-mining evidence
- Package-level process mining reveals repeated failed-delivery variants.
- Failure rates vary by time of day, customer segment, neighborhood, building type, and sender.
- “Customer not home” events may cluster in particular windows.
- Re-delivery cases consume disproportionate route capacity and generate lateness.

#### Recommended action
- Send estimated-time-of-arrival notifications and delivery reminders.
- Offer customer confirmation, rescheduling, safe-place instructions, neighbor delivery consent, parcel locker, or pickup-point alternatives.
- Use historical success probability to assign more suitable time windows.
- Require improved address/access instructions for locations with repeated failures.
- Prioritize high-risk deliveries for earlier customer contact or alternative delivery methods.
- Flag repeat-failure addresses in driver handheld applications.

#### Expected KPI impact
- Higher first-attempt delivery success rate.
- Reduced failed-delivery and re-delivery rates.
- Lower cost per delivered package.
- Higher stop completion rate.
- Improved customer satisfaction.
- Reduced route disruption and overtime.

---

### Strategy 4: Predictive and risk-based vehicle maintenance

#### Inefficiency targeted
- In-route breakdowns.
- Unplanned maintenance stops.
- Vehicle-related delays and missed deliveries.
- Fuel inefficiency from deteriorating vehicles.
- Vehicle downtime.

#### Root cause addressed
- Maintenance may be calendar-based rather than based on actual operating stress, mileage, idling, warning events, and recurring fault patterns.
- Vehicles with early warning indicators may remain in service until a failure occurs.

#### Process-mining evidence
- Process variants with engine warnings, unscheduled stops, and repairs are linked to overtime and missed deliveries.
- Certain vehicles show repeated maintenance patterns and higher fuel or idle proxies.
- Maintenance interruptions may occur after particular operating patterns, such as high mileage, prolonged idling, or repeated urban stop-start driving.

#### Recommended action
- Build a vehicle-risk score using mileage, age, warning events, repair history, idle time, route type, and recent fuel-efficiency changes.
- Schedule preventive inspections during off-peak periods before likely failures.
- Avoid assigning high-risk vehicles to routes with narrow customer time windows or high delivery density.
- Maintain contingency vehicles and rapid route-transfer procedures.
- Use maintenance findings to inform vehicle replacement and fleet procurement decisions.

#### Expected KPI impact
- Reduced maintenance interruption rate.
- Reduced vehicle downtime.
- Lower overtime and route abandonment.
- Improved On-Time Delivery Rate.
- Lower repair cost volatility.
- Improved fuel consumption per km where maintenance improves engine performance.

---

### Strategy 5: Targeted driver support, training, and operational standardization

#### Inefficiency targeted
- Excessive idling.
- Inefficient route execution.
- Long service times at comparable stops.
- Inconsistent scanning behavior.
- Repeated avoidable detours.
- Unsafe or fuel-intensive driving behavior.

#### Root cause addressed
- Differences in familiarity with dense urban areas, parking strategies, handheld-device use, customer-interaction procedures, or eco-driving practices.
- Lack of standard operating procedures for common disruptions.

#### Process-mining evidence
- Variant analysis identifies repeatable high-performance paths.
- Controlled driver comparisons reveal performance gaps after accounting for territory, load, vehicle, and customer mix.
- High-performing drivers may consistently use better stop ordering or lower-idling patterns.
- Certain drivers may show high data-quality issues, such as missing scanner milestones, requiring system or training intervention.

#### Recommended action
- Develop route-specific training for difficult territories.
- Share high-performing practices identified from process variants.
- Train drivers on eco-driving, parking procedures, handling access issues, and customer-contact escalation.
- Provide in-app guidance for high-risk stops, common access instructions, and expected parking locations.
- Use coaching dashboards rather than punitive rankings.
- Standardize rules for reporting vehicle warnings, exceptions, and failed deliveries.

#### Expected KPI impact
- Reduced idling time.
- Reduced fuel consumption per km.
- Reduced service-time variability.
- Improved route adherence and completion rate.
- Higher first-attempt success where customer-contact practices improve.
- Improved data quality for ongoing process mining.

## 5. Operational Constraints and Continuous Monitoring

### 5.1 Incorporating operational constraints

Optimization should not simply minimize distance or maximize deliveries. It must produce executable routes that comply with operational and legal constraints.

#### Driver working hours

Routing and re-optimization must respect:

- Maximum shift duration.
- Required breaks and rest periods.
- Overtime policies.
- Driver start and end locations.
- Skills, certifications, and vehicle permissions where relevant.
- Fair workload distribution across drivers.

The route optimizer should use realistic historical travel and service-time estimates, including uncertainty. Planning based on average durations alone will create frequent shift overruns.

#### Vehicle capacity and suitability

Plans must account for:

- Package count.
- Weight and volume capacity.
- Refrigerated or specialized-package requirements if applicable.
- Vehicle size restrictions in dense areas.
- Low-emission zone rules.
- Vehicle reliability risk.
- Battery range if electric vehicles are introduced.
- Availability lost to maintenance.

A route that is physically feasible by package count may still be infeasible by volume, time windows, or urban access restrictions.

#### Customer time windows

The route plan must respect:

- Hard versus soft time windows.
- Priority customers.
- Customer-requested dates.
- Commercial receiving hours.
- Building access restrictions.
- Probability of first-attempt success by time window.

Dynamic routing should only reorder stops within rules that preserve customer commitments. A rerouting decision should consider both traffic savings and the risk of making later time-window deliveries late.

#### Practical constraints in urban last-mile operations

Other relevant constraints include:

- Parking restrictions and loading-zone availability.
- Pedestrian-only or restricted-access streets.
- Depot loading capacity and dispatch cut-off times.
- Driver familiarity with delivery zones.
- Availability of parcel lockers and pickup points.
- Contingency arrangements for vehicle failure.
- Data latency: real-time routing is only useful if GPS and traffic data are timely and reliable.

---

### 5.2 Continuous monitoring plan

Process mining should become an ongoing operational-management capability rather than a one-time diagnostic project.

#### Monitoring cadence

| Cadence | Focus |
|---|---|
| Intraday / near real-time | Routes at risk of late completion, traffic incidents, breakdown warnings, missed time windows |
| Daily | Route completion, delivery failures, overtime, route adherence, major deviations |
| Weekly | Territory performance, driver/vehicle-adjusted trends, failure hotspots, maintenance risk |
| Monthly | Strategic capacity, territory redesign, fleet reliability, customer-service improvement, cost savings |
| Quarterly | Revalidate process models, route-planning assumptions, KPI targets, and operational policies |

#### Dashboard views

##### 1. Executive operations dashboard
Track:

- On-Time Delivery Rate.
- First-attempt delivery success.
- Average route duration.
- Overtime rate.
- Cost/fuel per package.
- Vehicle availability.
- Total re-delivery cost.
- Trend versus baseline and target.

##### 2. Route conformance dashboard
Track:

- Planned versus actual stop sequence.
- Route adherence rate.
- Planned versus actual distance.
- Planned versus actual travel and service time.
- Late departures and late returns.
- Detours, skipped stops, extra stops, and unplanned dwell.
- Route completion status.

##### 3. Delivery performance dashboard
Track:

- On-time performance by territory, route, customer segment, and time window.
- Failed-delivery reasons.
- Re-delivery process variants.
- Repeated problem addresses or building types.
- Service-time hotspots.

##### 4. Traffic and spatial bottleneck dashboard
Track:

- Low-speed hotspots.
- Delay duration by road segment and time of day.
- Parking and access-delay hotspots.
- Geographic distribution of lateness.
- Route corridors with recurring detours.

##### 5. Fleet and maintenance dashboard
Track:

- Breakdown and warning-event frequency.
- Maintenance interruption duration.
- Vehicle downtime.
- Fuel or idling proxy by vehicle.
- Reliability risk score.
- Impact of maintenance events on delivery performance.

##### 6. Process-variant dashboard
Track:

- Most common successful route variants.
- Most expensive or delay-heavy variants.
- Growth in exception paths.
- New process variants after changes are implemented.
- Frequency of re-delivery loops and maintenance interruptions.

### 5.3 Measure whether improvements are working

Each optimization should be implemented with a clear baseline and evaluation period.

For example:

1. Establish a pre-change baseline for:
   - On-Time Delivery Rate.
   - Average route duration.
   - Fuel per package.
   - Failed-delivery rate.
   - Overtime.
   - Detour ratio.

2. Pilot the change in selected routes or territories.

3. Compare pilot routes with similar control routes, adjusting for:
   - Delivery volume.
   - Customer mix.
   - Seasonality.
   - Weather.
   - Driver and vehicle mix.
   - Day-of-week patterns.

4. Monitor unintended consequences:
   - A route change may reduce distance but increase failed deliveries.
   - Dynamic routing may improve punctuality but create driver workload instability.
   - Tighter time windows may improve customer satisfaction but decrease route flexibility.
   - Reduced idling may be offset by increased unsafe driving if incentives are poorly designed.

5. Update the process model and planning assumptions as behavior changes.

## Recommended overall implementation sequence

A practical rollout could follow this order:

1. **Create the integrated event log and validate data quality.**
2. **Establish baseline KPIs and process models.**
3. **Perform conformance checking against dispatch plans.**
4. **Identify top bottlenecks by total time, cost, and customer impact.**
5. **Pilot high-value actions**, particularly:
   - Traffic-aware routing,
   - Territory and sequence redesign,
   - Failed-delivery prevention,
   - Predictive vehicle maintenance.
6. **Deploy continuous process-mining dashboards.**
7. **Use recurring findings to improve route planning, driver support, customer communication, and fleet decisions.**

The central advantage of process mining for Speedy Parcels is that it connects operational plans, actual vehicle movement, delivery outcomes, driver activity, and maintenance events in one evidence-based view. This makes it possible to distinguish between isolated incidents and recurring systemic causes of lateness, fuel waste, overtime, and vehicle downtime.
