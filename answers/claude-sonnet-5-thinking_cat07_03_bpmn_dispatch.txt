# BPMN Process Diagram: Dispatch of Goods (Computer Hardware Shop)

This is a **Business Process Model and Notation (BPMN)** diagram illustrating the workflow for shipping goods from a computer hardware shop. The process is organized into a pool called "Dispatch of goods - Computer Hardware Shop" with three swim lanes representing different roles/departments:

## Swim Lanes (Participants)
1. **Logistics** (top)
2. **Secretary** (middle)
3. **Warehouse** (bottom)

## Process Flow

**Start:** The process begins with a "Ship goods" start event, which triggers a parallel split (parallel gateway) into two simultaneous paths:

### Path 1 - Secretary Track:
1. **Clarify shipment method**
2. Decision: **"Special handling?"**
   - **No**  Check if insurance is required (referencing "Customer information" database and "Order details" document)
     - If insurance necessary  passed to Logistics to **Insure parcel**
     - Otherwise  proceeds directly
   - **Yes**  **Get 3 offers from logistic companies**  **Select logistic company and place order**
3. Both branches converge, then paths merge again before reaching **Write package label**

### Path 2 - Warehouse Track (parallel):
1. **Package goods**
   - Includes a **timer boundary event** (48 hours) that triggers **Notify customer about delay** if packaging takes too long
2. Both the normal and delayed paths converge

### Convergence:
- All paths merge at a parallel gateway (join)
- **Fill out Shipment paperwork**
- **Move package to pickup area**

**End:** The process concludes with the **"Shipment prepared"** end event.

## Key BPMN Elements Used:
- **Gateways:** Parallel (+), Exclusive (X), and Event-based (circle with X) gateways for branching/merging logic
- **Data objects:** Order details (document), Customer information (database)
- **Boundary event:** Timer event on "Package goods" task
- **Cross-lane collaboration:** Shows handoffs between Secretary, Logistics, and Warehouse roles

This diagram effectively models a real-world order fulfillment process with conditional logic, cross-departmental collaboration, and time-based escalation handling.
