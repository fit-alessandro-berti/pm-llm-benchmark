# POWL Models for GlobalTeq Solutions Hiring Process

Below are two POWL models representing the hiring process described. Both share the same initial structure (application receipt, data completeness loop, and skill assessment), but they diverge at the cultural fit evaluation stage.

---

## Model 1: POWL Model **With Potential Unfairness**

This model includes an XOR choice between a standard `CulturalFitCheck` and a `CommunityAffiliationCheck`. The latter path represents the subtle bias mechanism described in the text, where local community affiliation or club membership can lead to an implicit scoring advantage that feeds into the `ManagerialReview`.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_app = Transition(label="ReceiveApplication")
data_check = Transition(label="DataCompletenessCheck")
request_info = Transition(label="RequestMoreInfo")
skill_assessment = Transition(label="SkillAssessment")

cultural_fit = Transition(label="CulturalFitCheck")
community_check = Transition(label="CommunityAffiliationCheck")  # Bias-prone activity

managerial_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop for data completeness check ---
# Execute DataCompletenessCheck; if incomplete, RequestMoreInfo, then repeat DataCompletenessCheck
completeness_loop = OperatorPOWL(operator=Operator.LOOP, children=[data_check, request_info])

# --- XOR choice: standard cultural fit vs. biased community affiliation path ---
cultural_or_affiliation = OperatorPOWL(operator=Operator.XOR, children=[cultural_fit, community_check])

# --- Partial order: overall sequential process ---
root_unfair = StrictPartialOrder(
    nodes=[
        receive_app,
        completeness_loop,
        skill_assessment,
        cultural_or_affiliation,
        managerial_review,
        final_decision
    ]
)

root_unfair.order.add_edge(receive_app, completeness_loop)
root_unfair.order.add_edge(completeness_loop, skill_assessment)
root_unfair.order.add_edge(skill_assessment, cultural_or_affiliation)
root_unfair.order.add_edge(cultural_or_affiliation, managerial_review)
root_unfair.order.add_edge(managerial_review, final_decision)

# Optional: visualize
pm4py.view_powl(root_unfair, format="png")
```

### Structure Explanation (Model 1)
- **Loop**: `DataCompletenessCheck`  (exit) or  `RequestMoreInfo`  back to `DataCompletenessCheck`.
- **Sequence**: `ReceiveApplication`  Loop  `SkillAssessment`  XOR(`CulturalFitCheck`, `CommunityAffiliationCheck`)  `ManagerialReview`  `FinalDecision`.
- **Bias Point**: The XOR branch allows some applicants to bypass the standard cultural fit evaluation and instead go through `CommunityAffiliationCheck`, which — per the textual description — provides an implicit, non-merit-based score uplift. This branch structurally encodes the potential unfairness: applicants "selected" (explicitly or implicitly) for this path have a systematically different (and easier) route to a favorable `ManagerialReview`.

---

## Model 2: POWL Model **Without Unfairness**

This model removes the XOR branch entirely. All applicants — regardless of community affiliation or club membership — go through the **same** `CulturalFitCheck` activity. There is no alternate path that could introduce a systematic advantage.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_app = Transition(label="ReceiveApplication")
data_check = Transition(label="DataCompletenessCheck")
request_info = Transition(label="RequestMoreInfo")
skill_assessment = Transition(label="SkillAssessment")

cultural_fit = Transition(label="CulturalFitCheck")  # Single unified path, no bias branch

managerial_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop for data completeness check (same as before) ---
completeness_loop = OperatorPOWL(operator=Operator.LOOP, children=[data_check, request_info])

# --- Partial order: overall sequential process, no XOR branch for cultural fit ---
root_fair = StrictPartialOrder(
    nodes=[
        receive_app,
        completeness_loop,
        skill_assessment,
        cultural_fit,
        managerial_review,
        final_decision
    ]
)

root_fair.order.add_edge(receive_app, completeness_loop)
root_fair.order.add_edge(completeness_loop, skill_assessment)
root_fair.order.add_edge(skill_assessment, cultural_fit)
root_fair.order.add_edge(cultural_fit, managerial_review)
root_fair.order.add_edge(managerial_review, final_decision)

# Optional: visualize
pm4py.view_powl(root_fair, format="png")
```

### Structure Explanation (Model 2)
- **Loop**: Same as Model 1 — `DataCompletenessCheck` with optional `RequestMoreInfo` retries.
- **Sequence**: `ReceiveApplication`  Loop  `SkillAssessment`  `CulturalFitCheck`  `ManagerialReview`  `FinalDecision`.
- **No Bias Branch**: There is no XOR choice at the cultural fit stage. Every applicant undergoes the exact same `CulturalFitCheck` activity, with no alternate "affiliation-based" pathway. This structurally guarantees that community membership or local-residency status cannot alter the evaluative path taken, removing the source of potential unfairness identified in the original process description.

---

## Summary of Key Difference

| Aspect | Model 1 (Unfair) | Model 2 (Fair) |
|---|---|---|
| Cultural fit stage | `XOR(CulturalFitCheck, CommunityAffiliationCheck)` | Single `CulturalFitCheck` only |
| Bias mechanism | Present — affiliation path yields implicit score uplift | Absent — uniform evaluation for all |
| Structural difference | Extra XOR operator node | XOR node removed; direct edge to `ManagerialReview` |

This contrast illustrates how a single structural element in a POWL model — here, the XOR branch introducing `CommunityAffiliationCheck` as an alternative to the standard `CulturalFitCheck` — can encode a concrete, auditable point of process unfairness that can be surgically removed (Model 2) while preserving all other legitimate process logic (loops for data completeness, sequential skill assessment, managerial review, and final decision).
