**Explanation of Logic**

**Case Identification**  
Cases were defined around coherent logical work units (the primary document, email thread, or file being actively worked on), following the guidance that a case can represent editing a specific document, handling a particular email, or reviewing a PDF.  

- **Edit_Document1**: All interactions with `Document1.docx` (initial drafting + later return to insert a budget reference and close). This captures the multi-stage editing of one document, including the cross-application dependency.  
- **Handle_Annual_Meeting_Email**: The complete email handling sequence (open → review → reply → send) treated as one self-contained communication process instance.  
- **Review_Report_Draft_PDF**: The short focused review + highlight session on the PDF.  
- **Update_Budget_2024**: The complete Excel update cycle (open → edit figures → save).  
- **Edit_Quarterly_Report**: Interactions with `Quarterly_Report.docx` (initial focus + later focused drafting of the executive summary and close). The early isolated FOCUS is retained in this case as the start of work on that document.  

This produces multiple short, analyst-friendly process instances rather than one long interleaved session. Events remain in global timestamp order so tools can still reconstruct the real timeline and detect multi-tasking.

**Activity Naming**  
Low-level system actions (FOCUS, TYPING, CLICK, SCROLL, SWITCH, SAVE, CLOSE, HIGHLIGHT) were mapped to standardized, higher-level process steps that describe the user’s intent:  
- FOCUS / SWITCH-into → “Open …”, “Resume …”, or “Switch to …”  
- TYPING sequences → “Draft Content”, “Compose Reply”, “Update Budget Figures”, “Insert Cross Reference”, “Draft Executive Summary”  
- CLICK (contextual) → “Open Email”, “Start Reply”, “Send Email”  
- SCROLL / HIGHLIGHT → “Review … Content”, “Highlight Key Findings”  
- SAVE / CLOSE → “Save …”, “Close …”  

Activity names are consistent within and across cases, human-readable, and suitable for directly discovery, conformance checking, or performance analysis in standard process mining tools (ProM, Disco, Celonis, pm4py, etc.). Additional attributes (Application, Window/Object, Original Action, Details) are preserved so analysts can drill down or filter if needed.
