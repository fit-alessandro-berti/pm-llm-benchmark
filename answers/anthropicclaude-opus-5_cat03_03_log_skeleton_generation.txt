## Log Skeleton for the Order Fulfillment Process

The process is essentially a strict, oncepercase sequence:

**RO  CA  RI  PI  QC  PO  GSL  D  IC  RP**

Since every order flows through each step exactly once, all activities are mutually *equivalent* (same number of occurrences), each step *always after* its successor chain, each step *always before* its predecessor, and the whole chain is captured by *directlyfollows* constraints. No two activities are mutually exclusive, so `never_together` is empty.

```python
log_skeleton = {

    # ---------------------------------------------------------------
    # EQUIVALENCE: every activity happens exactly as often as the others
    # (one order -> one execution of each step)
    # ---------------------------------------------------------------
    'equivalence': {
        ('RO',  'CA'),
        ('CA',  'RI'),
        ('RI',  'PI'),
        ('PI',  'QC'),
        ('QC',  'PO'),
        ('PO',  'GSL'),
        ('GSL', 'D'),
        ('D',   'IC'),
        ('IC',  'RP'),
    },

    # ---------------------------------------------------------------
    # ALWAYS BEFORE: if X occurs, Y must have occurred earlier
    # (each activity requires all upstream activities)
    # ---------------------------------------------------------------
    'always_before': {
        ('CA',  'RO'),
        ('RI',  'CA'),  ('RI',  'RO'),
        ('PI',  'RI'),  ('PI',  'CA'),  ('PI',  'RO'),
        ('QC',  'PI'),  ('QC',  'RI'),  ('QC',  'CA'),  ('QC',  'RO'),
        ('PO',  'QC'),  ('PO',  'PI'),  ('PO',  'RI'),  ('PO',  'CA'),  ('PO',  'RO'),
        ('GSL', 'PO'),  ('GSL', 'QC'),  ('GSL', 'PI'),  ('GSL', 'RI'),
        ('GSL', 'CA'),  ('GSL', 'RO'),
        ('D',   'GSL'), ('D',   'PO'),  ('D',   'QC'),  ('D',   'PI'),
        ('D',   'RI'),  ('D',   'CA'),  ('D',   'RO'),
        ('IC',  'D'),   ('IC',  'GSL'), ('IC',  'PO'),  ('IC',  'QC'),
        ('IC',  'PI'),  ('IC',  'RI'),  ('IC',  'CA'),  ('IC',  'RO'),
        ('RP',  'IC'),  ('RP',  'D'),   ('RP',  'GSL'), ('RP',  'PO'),
        ('RP',  'QC'),  ('RP',  'PI'),  ('RP',  'RI'),  ('RP',  'CA'),
        ('RP',  'RO'),
    },

    # ---------------------------------------------------------------
    # ALWAYS AFTER: if X occurs, Y must occur later
    # (each activity forces all downstream activities)
    # ---------------------------------------------------------------
    'always_after': {
        ('RO',  'CA'),  ('RO',  'RI'),  ('RO',  'PI'),  ('RO',  'QC'),
        ('RO',  'PO'),  ('RO',  'GSL'), ('RO',  'D'),   ('RO',  'IC'),
        ('RO',  'RP'),
        ('CA',  'RI'),  ('CA',  'PI'),  ('CA',  'QC'),  ('CA',  'PO'),
        ('CA',  'GSL'), ('CA',  'D'),   ('CA',  'IC'),  ('CA',  'RP'),
        ('RI',  'PI'),  ('RI',  'QC'),  ('RI',  'PO'),  ('RI',  'GSL'),
        ('RI',  'D'),   ('RI',  'IC'),  ('RI',  'RP'),
        ('PI',  'QC'),  ('PI',  'PO'),  ('PI',  'GSL'), ('PI',  'D'),
        ('PI',  'IC'),  ('PI',  'RP'),
        ('QC',  'PO'),  ('QC',  'GSL'), ('QC',  'D'),   ('QC',  'IC'),
        ('QC',  'RP'),
        ('PO',  'GSL'), ('PO',  'D'),   ('PO',  'IC'),  ('PO',  'RP'),
        ('GSL', 'D'),   ('GSL', 'IC'),  ('GSL', 'RP'),
        ('D',   'IC'),  ('D',   'RP'),
        ('IC',  'RP'),
    },

    # ---------------------------------------------------------------
    # NEVER TOGETHER: no mutually exclusive activities in this model
    # ---------------------------------------------------------------
    'never_together': set(),

    # ---------------------------------------------------------------
    # ACTIVITY OCCURRENCES: every activity occurs exactly once per case
    # ---------------------------------------------------------------
    'activ_freq': {
        'RO':  {1},
        'CA':  {1},
        'RI':  {1},
        'PI':  {1},
        'QC':  {1},
        'PO':  {1},
        'GSL': {1},
        'D':   {1},
        'IC':  {1},
        'RP':  {1},
    },

    # ---------------------------------------------------------------
    # DIRECTLY-FOLLOWS: the strict end-to-end control flow
    # ---------------------------------------------------------------
    'directly_follows': {
        ('RO',  'CA'),
        ('CA',  'RI'),
        ('RI',  'PI'),
        ('PI',  'QC'),
        ('QC',  'PO'),
        ('PO',  'GSL'),
        ('GSL', 'D'),
        ('D',   'IC'),
        ('IC',  'RP'),
    },
}
```

**Reading of the model**

| Constraint type | Meaning in this scenario |
|---|---|
| `equivalence` | An order that is received is also checked, reserved, picked, inspected, packed, labelled, dispatched, invoiced and paid — exactly the same number of times. |
| `always_before` | E.g. `('D','GSL')`: a package cannot be dispatched unless a shipping label was generated earlier. |
| `always_after` | E.g. `('RO','RP')`: once an order is received, a payment record must eventually be created. |
| `never_together` | Empty — every activity is compatible with every other. |
| `activ_freq` | Each activity is mandatory and nonrepeating (`{1}`). |
| `directly_follows` | Encodes the rigid chain RO  CA  RI  PI  QC  PO  GSL  D  IC  RP with no interleaving. |
