### Explanation of Case and Activity Logic

#### **Case Identification**
Cases are determined by the **application and window** the user is interacting with. Each time the user switches to a new application or window, a new case begins. This approach ensures that each case represents a coherent work session focused on a specific task or document. For example:
- **Case_1** starts when the user opens *Quarterly_Report.docx* (though no further activity occurs in this document until later).
- **Case_2** begins when the user switches to *Document1.docx* and continues through editing, saving, and switching to email.
- **Case_3** starts when the user opens the email inbox in Chrome and includes composing/ sending an email.
- **Case_4** begins when the user reviews *Report_Draft.pdf* in Adobe Acrobat.
- **Case_5** starts when the user updates *Budget_2024.xlsx* in Excel.
- **Case_6** begins when the user returns to *Document1.docx* to add a budget reference.
- **Case_7** starts when the user revisits *Quarterly_Report.docx* to draft an executive summary.

#### **Activity Naming**
Activities are translated into meaningful, high-level actions to support process analysis:
- **FOCUS**: Mapped to **"Open Document"** when starting a work session on a document.
- **TYPING**: Mapped to **"Edit Content"** to represent text input or modifications.
- **SAVE**: Mapped to **"Save Document"** to indicate saving progress.
- **SWITCH**: Mapped to **"Switch Application"** to denote context changes between apps.
- **CLICK**: Contextualized based on the action (e.g., "Open Email," "Reply to Email," "Send Email").
- **SCROLL**: Mapped to **"Scroll Document"** or **"Scroll Email"** depending on the app/window.
- **HIGHLIGHT**: Mapped to **"Highlight Key Points"** to capture annotation actions.
- **CLOSE**: Mapped to **"Close Document"** to indicate document closure.

#### **Coherent Narrative**
The event log reflects a user workflow involving iterative document editing, email management, and budget updates. The structure ensures that each case represents a distinct task (e.g., editing a document, responding to an email, reviewing a PDF), enabling analysts to study patterns like document editing sequences, email response times, and cross-application workflows. The final case (Case_7) completes the narrative by resolving the initial *Quarterly_Report.docx* session.
