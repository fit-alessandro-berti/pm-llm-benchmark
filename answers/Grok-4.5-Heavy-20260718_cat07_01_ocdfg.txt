**This visualization is an Object-Centric Directly-Follows Graph (OC-DFG / OCDFG)** from **Object-Centric Process Mining (OCPM)**.

It shows the interacting lifecycles of five related business document item types (typical of an ERP system such as SAP) in a combined procure-to-pay / order-to-cash / returns process. Unlike traditional process maps that force everything into a single case notion, this diagram keeps the different object types separate while showing where they interact.

### How to read the diagram
- **Top boxes** = Object types with their total volumes (number of objects).
- **Colored Start nodes and arrows** = Beginning of each object’s lifecycle (color-coded by object type).
- **Activity boxes** = Process steps.  
  – “Overall: X.XM” = total throughput (how many times the activity was executed across all objects).  
  – Colored dots inside the box = which object types participate in that activity.
- **Arrows / edges** = Directly-follows relations.  
  – Color matches the object type(s) flowing along that path.  
  – Number in ms = average transition time (waiting + processing time) between the two activities.
- **End nodes** = Completion of different process paths.

### Object types (by color and volume)
| Color  | Object Type              | Volume   | Primary role                          |
|--------|--------------------------|----------|---------------------------------------|
| Purple | PurchaseRequisitionItem  | 2.0 M    | Requisitioning                        |
| Blue   | PurchaseOrderItem        | 5.0 M    | Purchasing / procurement              |
| Orange | SalesOrderItem           | 3.5 M    | Sales order fulfillment               |
| Green  | VendorInvoiceItem        | 1.2 M    | Vendor invoicing                      |
| Red    | ReturnOrderItem          | 0.8 M    | Returns handling                      |

### Main process paths

**Purple – Purchase Requisition path**  
Start → Create Requisition (Overall 3.0 M) → Approve Requisition →  
then primarily to Send Order (5.2 M) and Check Stock (1.0 M), with paths continuing toward payment/invoice activities or ending.

**Blue – Purchase Order path**  
Start → Create Order (Overall 8.5 M) →  
branches both left into Approve Requisition and right toward packing, then heavily involves Send Order → Approve Payment (1.5 M) → Create Invoice (2.0 M) → End.

**Orange – Sales Order fulfillment path** (most linear)  
Start → Create Order (8.5 M) → Pack Goods (2.0 M) → Ship Goods (1.8 M) → Confirm Delivery (1.7 M) → Close Order (1.7 M) → End.

**Green – Vendor Invoice path**  
Start → Approve Requisition → Process Return and/or Create Invoice → End.

**Red – Return Order path**  
Start → Approve Requisition → Process Return (0.8 M) → Close Order (and sometimes payment/invoice paths) → End.

### Key shared / multi-object activities (interaction points)
- **Create Order (8.5 M)** – Highest-volume activity. Combines SalesOrderItem + PurchaseOrderItem.
- **Approve Requisition (5.7 M)** – Major convergence hub for purple, blue, green, and red objects.
- **Send Order (5.2 M)** – Shared by requisitions and purchase orders.
- **Process Return (0.8 M)** – Handles both returns and some vendor-invoice-related flows.
- **Create Invoice (2.0 M)** – Shared by purchase-order and vendor-invoice objects.
- **Close Order (1.7 M)** – End of both sales fulfillment and some return paths.

### Performance observations
Longer average transition times (potential delays or bottlenecks) include:
- ~800 ms (Process Return → Approve Payment area)
- ~650 ms (Approve Requisition → Process Return)
- ~600 ms (VendorInvoiceItem → Approve Requisition)
- 400–500 ms transitions around Create Order / Approve Requisition and returns

Shorter transitions (100–250 ms) dominate the sales fulfillment path and many Send Order connections. A few near-0 ms / 10 ms edges appear, which may indicate near-instantaneous steps or measurement artifacts.

### Overall interpretation
The diagram shows a highly integrated ERP process in which requisitioning, purchasing, sales order processing, delivery, vendor invoicing, and returns all interact at key control points (especially **Approve Requisition**, **Create Order**, **Create Invoice**, and **Close Order**).  

The right-hand side is a relatively clean, linear sales-order fulfillment chain, while the center and left side show more complex, multi-object interactions involving approvals, stock checks, order sending, payments, invoicing, and returns handling.
