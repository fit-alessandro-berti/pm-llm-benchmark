### **Overview**
This visualization is an **Object-Centric Process Mining Diagram** (commonly used in enterprise process analytics tools like Celonis). It maps complex, interconnected business workflows—specifically combining **Order Fulfillment, Purchase Requisitioning, Return Processing, and Invoicing/Payment Approval**. 

The process includes multiple entity/object types tracking execution volumes (in millions of objects) and transition latencies (measured in milliseconds, `ms`).

---

### **1. Entry Points / Object Types (Top)**
At the top, five primary input objects initiate different process flows:
1. **`VendorInvoiceItem`** (1.2M objects) – Green flow path.
2. **`ReturnOrderItem`** (0.8M objects) – Red/brown flow path.
3. **`PurchaseRequisitionItem`** (2.0M objects) – Purple flow path.
4. **`SalesOrderItem`** (3.5M objects) – Orange flow path.
5. **`PurchaseOrderItem`** (5.0M objects) – Blue flow path.

Each object begins at an oval **`Start`** node.

---

### **2. Main Process Flow & Sub-Processes**

#### **A. Order Fulfillment Flow (Right Side - Orange/Blue Path)**
* **Create Order** (Overall: 8.5M): Merges flows from `SalesOrderItem` and `PurchaseOrderItem` (350ms).
* **Pack Goods** (Overall: 2.0M): Sequential step after *Create Order* (300ms delay).
* **Ship Goods** (Overall: 1.8M): Sequential step after *Pack Goods* (200ms delay).
* **Confirm Delivery** (Overall: 1.7M): Follows *Ship Goods* (220ms delay).
* **Close Order** (Overall: 1.7M): Follows *Confirm Delivery* (180ms delay), leading directly to **`End`** nodes.

#### **B. Requisition & Purchase Approval Flow (Left/Center)**
* **Create Requisition** (Overall: 3.0M): Originates from `PurchaseRequisitionItem` (300ms delay).
* **Approve Requisition** (Overall: 5.7M): A central hub node receiving inputs from:
  * *Create Requisition* (250ms)
  * *Create Order* (400ms)
  * *VendorInvoiceItem* start path (600ms)
  * *ReturnOrderItem* start path (450ms)

#### **C. Downstream Purchasing, Returns, & Payment Processing**
From **`Approve Requisition`**, several parallel paths emerge:
* **Send Order** (Overall: 5.2M): Connected to *Approve Requisition* (200ms) and loops with payment/stock checks. Ends at an oval **`End`** node.
* **Check Stock** (Overall: 1.0M): Receives paths from *Approve Requisition* (320ms / 500ms).
* **Process Return** (Overall: 0.8M): Connected to return order flows (500ms / 650ms).
* **Approve Payment** (Overall: 1.5M): Receives inputs from stock/requisition approvals (800ms / 250ms).
* **Create Invoice** (Overall: 2.0M): Combines outputs from payment approval and return processing, terminating in two separate **`End`** nodes.

---

### **3. Key Visual Elements**
* **Activity Cards:** Rounded rectangle nodes containing:
  * **Activity Name** (e.g., *Ship Goods*)
  * **Overall Object Volume** (e.g., *Overall: 1.8M*)
  * **Colored Indicator Dots:** Represent which object types participate in that specific step.
* **Flow Lines & Arrows:** Directional connectors color-coded by object type, annotated with throughput time latencies (e.g., `180ms`, `400ms`, `600ms`).
* **Terminal Nodes:** Oval nodes indicating **`Start`** and **`End`** points of specific pathways.
