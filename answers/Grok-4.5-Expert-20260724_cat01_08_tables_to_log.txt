**Event Log for Process Mining**

**Assumptions made:**
- Case ID = `order_id` throughout.
- Activity names derived logically from table semantics (e.g., one “Item Picked” event per order line; separate “Order Dispatched” / “Order Arrived” per delivery record; payments linked to orders via `invoice_id`).
- Resource = human-readable name from the Resources table (or carrier name); role shown where available. Payments have no explicit actor → Resource left blank.
- “Other Attributes” aggregates the most relevant extra fields for each event type so the log remains usable for process mining while staying compact.
- All provided records are included (order 1004 is incomplete in downstream tables and ends after picking).
- Events are listed sorted by Case ID, then Timestamp (guaranteeing chronological order within each case).
