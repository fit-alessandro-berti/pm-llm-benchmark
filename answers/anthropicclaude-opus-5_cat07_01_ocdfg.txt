## Overview

This is an **objectcentric process model / processmining graph** (the kind of "process explorer" diagram produced by tools like Celonis or ProM). It shows how several different business object types flow through a shared set of activities, with average transition times annotated on each edge.

## Object types (top row, hatched/dashed boxes)

| Object type | Volume |
|---|---|
| PurchaseRequisitionItem | 2.0M objects |
| SalesOrderItem | 3.5M objects |
| PurchaseOrderItem | 5.0M objects |
| VendorInvoiceItem | 1.2M objects |
| ReturnOrderItem | 0.8M objects |

Each object type has its own **Start** oval (the ellipses), and each object type's path through the graph is drawn in its own colour — purple for requisitions, orange for sales orders, blue for purchase orders, green for vendor invoices, and a red/brick tone for return orders.

## Activities (rounded rectangles, with "Overall" object counts)

- **Create Requisition** – 3.0M
- **Create Order** – 8.5M (highest volume, bold/highlighted border)
- **Approve Requisition** – 5.7M (four coloured dots  four object types converge here)
- **Send Order** – 5.2M
- **Check Stock** – 1.0M
- **Process Return** – 0.8M
- **Pack Goods** – 2.0M  **Ship Goods** – 1.8M  **Confirm Delivery** – 1.7M  **Close Order** – 1.7M (the bold-bordered fulfilment chain on the right)
- **Approve Payment** – 1.5M
- **Create Invoice** – 2.0M

The small coloured bullets in the top-left of each box indicate which object types touch that activity (e.g., *Approve Requisition* has purple, blue, green and red dots; *Create Invoice* has blue and green).

## Flow structure

- **Requisition branch (purple):** Start  Create Requisition (300ms)  Approve Requisition (250ms)  fans out to Send Order (200ms), Check Stock (600ms) and Process Return.
- **Purchase order branch (blue):** Start  Create Order (350ms)  Approve Requisition (400ms)  Send Order / Check Stock / Approve Payment (100–500ms)  Create Invoice  End.
- **Sales order branch (orange):** Start  Create Order (400ms)  a strictly sequential logistics chain: Pack Goods (300ms)  Ship Goods (200ms)  Confirm Delivery (220ms)  Close Order (180ms)  End (100ms).
- **Vendor invoice branch (green):** Start  Approve Requisition (600ms)  Process Return / Create Invoice  End.
- **Return order branch (red):** Start  Approve Requisition (450ms)  Process Return (650ms)  Close Order (300ms)  End.
- Several **End** ovals appear along the bottom (and one under Send Order), representing case completion per object type.

## Visual/design notes

- Edge labels are all durations in milliseconds (100ms–800ms), giving a sense of bottlenecks — e.g. the 800ms edge into Approve Payment and the 600–650ms edges out of Approve Requisition are the slowest handoffs.
- Line thickness roughly encodes flow volume; the orange salesorder chain and the Create Order node are emphasised with darker/bolder strokes.
- Because many long horizontal connectors cross the middle of the diagram, some edge labels overlap and are partially clipped (e.g. "…00ms", "…50ms"), which makes a few timings hard to read.
- Overall shape: two convergence points dominate — **Approve Requisition** (where four object types merge) and **Create Order** (highest overall count) — after which the process splits into a procurement/invoicing side (left/bottom) and an orderfulfilment side (right).
