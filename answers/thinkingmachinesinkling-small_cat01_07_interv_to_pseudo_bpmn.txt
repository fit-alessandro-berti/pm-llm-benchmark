**BPMN-Style Textual Process Model: Invoice Approval & Payment Scheduling**

*Derived from interviews with AP Clerk (Mary), Purchasing Officer (Dan), Department Manager (Carlos), AP Supervisor (Rita), Supplier Relationship Manager (Karen), and external Supplier.*

---

### 1. Process Overview & Roles (Lanes / Pools)

| Lane / Participant | Key Role in Process |
|---|---|
| **Accounts Payable (AP)** | **Mary (Clerk)** – intake, logging, matching, scheduling; **Rita (Supervisor)** – exception escalation, retrospective PO, supplier coordination for unresolved issues |
| **Purchasing** | **Dan (Officer)** – receipt verification, PO comparison, supplier contact on discrepancies |
| **Department Management** | **Carlos (Manager)** – final approval / rejection; budget / suspicious-item review |
| **Supplier Relations** | **Karen (Mgr)** – contract/pricing verification; supplier outreach for missing info or pricing errors |
| **Accounting System** | Automated notifications (manager approval request) and data recording |
| **External Supplier** | Source of invoice, revised invoice, corrected details, PO references |

---

### 2. Artifacts / Data Objects

- **Invoice Document** (received by email; may include/miss PO reference)
- **Purchase Order (PO) Record** (system / document)
- **Accounting System Entry / Logged Invoice**
- **Confirmation Email** (Purchasing  AP)
- **System Approval Request Email / Notification** (to Carlos)
- **Approved Invoice / Payment Schedule** (for payment run)

---

### 3. Process Flow (Textual Sequence & Gates)

**Start Event** (Message): *Invoice arrives (email) to AP Clerk (Mary).*

---

**Task T1: Receive & Check for Valid PO** *(Mary / AP)*
- Inspect invoice for valid Purchase Order number/reference.

**Gateway G1: Valid PO Present?** *(Exclusive)*
- **YES**  Proceed to **T2**.
- **NO**  **Exception Path A (No / Missing PO):**
  - **Task T1a:** Request missing details / revised invoice from Supplier. *(Mary / Karen may assist)*
  - **Task T1b:** If invoice relates to informal/service contract  **Rita** coordinates with Department Head to create *retrospective PO* or decide **Rejection**.
  - **Loop:** Once resolved / PO obtained  return to **G1** (or hold until resolved).

---

**Task T2: Log Invoice into Accounting System** *(Mary)*
- Add invoice record; link to PO.

---

**Task T3: Forward to Purchasing for Receipt & Verification** *(Mary)*
- Send invoice / reference to **Dan (Purchasing)** to confirm goods/services received.

---

**Task T4: Verify Details Against PO & Confirm Receipt** *(Dan)*
- Open PO; compare quantities, prices, delivery charges; confirm receipt.
- Check for discrepancies.

**Gateway G2: Details / Receipt Verified?** *(Exclusive)*
- **YES / No Discrepancy**  **Task T5:** Send confirmation email back to AP  proceed to **T6**.
- **NO / Discrepancy or Missing Info**  **Exception Path B (Verification Failure):**
  - **Task T4a:** Contact Supplier directly (Dan) OR ask Mary to **Hold Invoice** pending corrected version.
  - **Task T4b:** If pricing / contract issue  loop in **Karen** to verify contract terms / correct pricing.
  - **Task T4c:** If discrepancy unresolved / complex  **Escalate to Rita (Supervisor)** for coordination.
  - **Loop:** Hold until supplier sends corrected invoice / clarification; return to **T4** (or to **G2** upon re-check).

---

**Task T6: Receive Confirmation; Match Line Items to PO in System** *(Mary)*
- Upon receiving Dan’s confirmation, perform formal line-item matching in the accounting system.

**Gateway G3: Line Items Match / No Discrepancy?** *(Exclusive)*
- **YES**  Proceed to **T7** (Manager Approval Trigger).
- **NO / Discrepancy Found**  **Exception Path C (Matching Issue):**
  - **Task T6a:** Email Purchasing (Dan) to clarify / resolve.
  - **Task T6b:** If still unresolved  **Escalate to Rita** for investigation / supplier coordination.
  - **Loop:** Resolve issue; return to **T6** / **G3**.

---

**Task T7: System Notifies Department Manager** *(Automatic / System)*
- System sends approval request with invoice details, PO, and confirmation.

**Task T8: Review Invoice, PO & Confirmation** *(Carlos / Manager)*

**Gateway G4: Manager Approval Decision?** *(Exclusive)*
- **APPROVE**  **Task T9: Approve in System** *(Carlos)*  proceed to **T10**.
- **REJECT / SUSPICIOUS**  **Exception Path D (Manager Rejection / Hold):**
  - **Task T8a:** Reject invoice OR ask Mary to **Hold** and investigate further (e.g., budget variance, unexpected items, large amount differences).
  - **Task T8b:** Investigation / resolution via **Rita / Karen / Supplier**; loop back to **T8** after clarification / correction.
  - *Note: Per Carlos, this occurs infrequently (~once every couple of months).*

---

**Task T9: Approve Invoice in System** *(Carlos)*

**Task T10: Schedule for Payment / Add to Next Payment Cycle** *(Mary / AP)*

**End Event:** *Invoice approved and scheduled for payment run.*

---

### 4. Sequence Flow Summary (Simplified Linear Path)

```
[Start: Invoice Received]
   T1 (Check PO) 
     G1 [Valid?]  NO  Exception A (Supplier / Rita / Retrospective PO)  back to G1
     YES  T2 (Log)  T3 (To Purchasing)  T4 (Verify / Confirm Receipt)
       G2 [Verified?]  NO  Exception B (Hold / Contact Supplier / Karen / Rita)  back to T4
       YES  T6 (Match Line Items)
         G3 [Match?]  NO  Exception C (Clarify / Escalate Rita)  back to T6
         YES  T7 (Auto-Notify Manager)  T8 (Review)
           G4 [Approve?]  NO  Exception D (Hold / Investigate / Loop back to T8 after fix)
           YES  T9 (Approve)  T10 (Schedule Payment)  [End]
```

### 5. Exceptions, Variations & Ambiguities Noted

| Exception / Variation | Source Evidence | How Modeled |
|---|---|---|
| **Missing / Invalid PO** | Mary sends back to supplier; Dan says never approve without confirmed PO; Rita creates retrospective PO for informal contracts; Karen asks for revised invoice / PO info. | **G1  Exception Path A** with Supplier / Karen / Rita loops. |
| **Pricing / Quantity Discrepancy** | Dan contacts supplier or asks AP to hold; Karen checks contract; Mary emails Purchasing; Rita escalates if unresolved. | **G2 / G3  Exception Paths B & C** with supplier contact, holding, and supervisor escalation. |
| **Unresolvable Issues / Complex Escalation** | Rita takes over when Mary can’t match or Purchasing has unresolved issues; coordinates between dept heads / suppliers. | **T6b / T4c / T8b:** Explicit escalation tasks to Rita with loop-backs. |
| **Manager Suspicion / Budget Mismatch** | Carlos rejects or holds if suspicious (e.g., big total difference, unexpected items); asks Mary to investigate. | **G4  Exception Path D** with hold/investigate loop. |
| **Timing / Trigger of Matching vs. Verification** | Mary describes confirming receipt first, then matching line items; Dan describes comparing details which overlaps with matching. | Model treats **T4 (Verification / Receipt)** and **T6 (Formal Line Matching)** as sequential, acknowledging that in practice these may overlap or be performed by either party depending on case. |
| **Payment Scheduling** | Mary schedules after approval; Carlos believes it goes back to AP for payment cycle; Dan assumes AP handles scheduling. | **T10 (Schedule Payment)** placed after approval, performed by AP. |

---

### 6. Key Decisions / Gateways (Quick-Reference)

| Gate ID | Condition / Rule | Outcome Paths |
|---|---|---|
| **G1** | Invoice has valid, confirmed PO? | Yes  Log / Verify; No  Request / Retrospective PO / Reject |
| **G2** | Purchasing verifies details / receipt correct? | Yes  Confirm / Match; No  Hold / Correct / Escalate |
| **G3** | Line-item match complete / no discrepancy? | Yes  Manager; No  Clarify / Escalate |
| **G4** | Manager approves (quantities/pricing/notes okay)? | Yes  Schedule; No  Hold / Investigate / Loop |

### 7. How to Convert to BPMN

- **Start Event:** Message Start (Invoice Email).
- **Tasks:** Rounded rectangles (T1–T10, Exception sub-tasks).
- **Gateways:** Diamonds (G1–G4); use **X** inside for Exclusive.
- **Sequence Flows:** Solid arrows; label exception loops clearly.
- **Pools / Lanes:** Top-level pools for AP, Purchasing, Management, Supplier Relations; external Supplier pool for message flows.
- **Message Flows:** Dashed lines for emails (Invoice receipt, Confirmation to AP, System Notification to Carlos, Supplier correspondence via Karen/Dan).
- **Data Objects:** Document icons for Invoice, PO, System Entry.
- **Boundary / Intermediate Events:** Not required unless modeling timers for “hold until corrected”; can be omitted for simplicity, but a **Timer Intermediates** on “Hold” paths can indicate waiting for supplier response.

This model captures the **standard “happy path”** (Receive  Check PO  Log  Verify  Match  Manager Approve  Schedule) while clearly mapping the **three main exception loops** (missing PO / discrepancy at verification / discrepancy at matching / manager rejection) and the **escalation roles** (Rita, Karen) mentioned across all five interviews.
