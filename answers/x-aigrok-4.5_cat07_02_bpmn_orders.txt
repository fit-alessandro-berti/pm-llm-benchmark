The image is a **BPMN (Business Process Model and Notation)** diagram depicting an end-to-end **customer order fulfillment process**. It is organized into four horizontal swimlanes (departments/roles):

- **Sales**
- **Production**
- **Procurement**
- **Warehouse**

Message flows (dashed lines) and data objects show inter-department communication. Below is a step-by-step description of the process.

### 1. Sales Lane
- The process is triggered every **Monday morning** by a timer start event.
- **Check order for completeness**.
- **Check if customer is already in the database**.
  - Decision (gateway):
    - If the customer is **not** in the database  **Add customer to the database** (data store writing).
    - If the customer is already in the database  continue.
- The two paths merge, and the Sales department **sends order details** (message event/message flow) to Production and Procurement.
- Sales then waits for a **“Product sent”** message.
- Finally, Sales performs **Draft invoice** and the process ends.

### 2. Production Lane
- Receives the **“Order details arrive”** message.
- A parallel gateway (+) splits the flow:
  - One path goes to **Plan production**.
  - Both paths re-converge via another parallel gateway and proceed to **Manufacture product**.
- An intermediate compensation/throw event (“Material not faulty”) allows a loop back if material issues arise.
- When manufacturing finishes, a **“Product complete”** message is thrown (sent to the Warehouse).

### 3. Procurement Lane
- Also receives the **“Order details arrive”** message.
- A collapsed **Material Compensation Subprocess** is triggered:
  - **Order materials**.
  - Contains a compensation handler that can execute **Return material** if needed.
- After the subprocess, **Check materials** is performed.
- Possible exception path: an error event **“Order cancelation”** leads to an end event.
- Timer boundary events and intermediate catching events monitor the material check.

### 4. Warehouse Lane
- Receives the **“Product complete”** message from Production.
- Executes **Send product**.
- Throws a **“Product sent”** message, which is received by Sales (triggering invoice drafting).

### Key Process Characteristics
- **Parallelism**: Production planning and manufacturing use AND-gateways.
- **Compensation**: Material ordering has explicit compensation (“Return material”) handling.
- **Exception handling**: Order cancellation path in Procurement.
- **Inter-process communication**: Asynchronous message flows (“Order details”, “Product complete”, “Product sent”).
- **Data**: Interaction with a customer database and order-detail messages.

In summary, the diagram models a typical **order-to-cash** process that begins with sales order validation and customer master-data maintenance, proceeds through material procurement and production, ends with warehouse shipping, and finally returns control to Sales for invoicing.
