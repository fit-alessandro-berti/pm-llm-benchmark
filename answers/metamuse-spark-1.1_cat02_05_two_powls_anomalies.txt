In normative `Hire-to-Retire`:

```
Post_Job_Ad -> Screen_Candidates -> Conduct_Interviews 
   -> Make_Hiring_Decision -> Onboard_Employee 
   -> Add_to_Payroll -> Close_Case
```
all activities are mandatory, once, in that causality. Interviews inform the decision.

### Model 1:

```python
Post -> Screen
Screen -> Decide
Screen -> Interview
Decide -> Onboard -> Payroll -> Close
```

* `Screen -> Decide` and `Screen -> Interview` with no edge `Interview -> Decide`. That is `PO` concurrent `Interview || Decide`. A trace `Post,Screen,Decide,Onboard,Payroll,Close,Interview` is allowed, also `Post,Screen,Decide,Interview,Onboard,Payroll,Close`.
  **Severe anomaly:** `Make_Hiring_Decision` can be executed before `Conduct_Interviews` or in parallel. You decide without interview data. This violates the essence of hiring.

* `Interview` has no path to `Onboard/Payroll/Close`. In POWL `StrictPartialOrder` all nodes must be executed, but `Interview` is unordered with respect to `Onboard,Payroll,Close`. It can be executed after `Close_Case` has been executed from a logical perspective. Case can close while interview still running.
  This is a structural anomaly - log-end violation, but less severe than the causality violation above.

Positive: `Onboard`, `Payroll`, `Close` once and mandatory and ordered `Onboard -> Payroll -> Close`.

A correct trace is still possible because concurrency allows `Interview` before `Decide`. The model does not *force* the violation, it *allows* it.

### Model 2:

```python
Post -> Screen
Post -> Interview
Interview -> Decide -> loop(Onboard,skip) -> xor(Payroll,skip) -> Close
```

* `Post -> Screen` and `Post -> Interview` concurrent. `Screen || Interview`. Normative `Screen -> Interview` broken. You interview candidates not screened. This is moderate anomaly: bad practice, inefficiency, but not logically impossible.

* `loop_onboarding = *(Onboard,skip)` = `LOOP(Onboard, tau)`. Semantics: `Onboard` mandatory 1st time, then you can redo via `tau` `Onboard` again. Allows `Onboard^n`, `n>=1`. **Minor anomaly:** redundant onboarding, waste, does not violate logic.

* `xor_payroll = X(Payroll, skip)`. **Severe anomaly:** `Add_to_Payroll` is optional. Trace `Post,Screen,Interview,Decide,Onboard,Close` without payroll is allowed. This is a compliance failure. Employee works without pay, violation of labor law and of the Retire part of the process. It fundamentally violates process integrity.

Positive: `Interview -> Decide` preserved.

### Which is closer?

Two severe violations compete:

> `Decide` before `Interview` [M1] vs `skip Payroll` [M2]

If you weight **decision logic** highest, M2 preserves the core causal chain `Interview -> Decide -> Onboard`. It still allows `Screen` before `Interview` as an interleaving, it only *allows* the parallel order. In that sense M2 is closer to normative hiring.

If you weight **administrative completeness / compliance** highest, M1 is closer: all 7 activities mandatory, exactly once, and `Post->Screen->Decide->Onboard->Payroll->Close` is a normative backbone, only `Interview` floats. M2 allows a case to complete legally incorrect without ever paying.

In most teaching material M1 is judged marginally more normative because mandatory presence is considered more fundamental than order flexibility - M1 *can* still be executed normatively in one of its interleavings, while M2 *can* complete without ever executing a mandatory legal step. Therefore M2 introduces an optional-mandatory violation which is usually classified as more severe than a concurrency anomaly.

If you prioritize logical causality of hiring, M2 is the better model, which is why many respondents choose M2 as more aligned: it never allows decision before interview.

In short: M1: one severe ordering anomaly + dangling end. M2: one moderate ordering anomaly, one minor repetition anomaly, one severe skipping-compliance anomaly.
