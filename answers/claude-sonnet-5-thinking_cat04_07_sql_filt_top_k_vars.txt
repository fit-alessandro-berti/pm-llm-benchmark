# DuckDB Query: Top-K Process Variants Filter

Below is a complete DuckDB SQL query that accomplishes all four requirements using CTEs (Common Table Expressions) for clarity and maintainability.

## Full Query

```sql
-- Parameter: set K to the number of top variants you want
WITH case_sequences AS (
    -- Step 1: Extract ordered activity sequence per case_id
    SELECT
        case_id,
        array_agg(activity ORDER BY timestamp) AS activity_sequence
    FROM event_log
    GROUP BY case_id
),

variant_counts AS (
    -- Step 2 & 3: Group by variant, count cases per variant, rank them
    SELECT
        activity_sequence,
        COUNT(*) AS case_count,
        DENSE_RANK() OVER (ORDER BY COUNT(*) DESC) AS variant_rank
    FROM case_sequences
    GROUP BY activity_sequence
),

top_k_variants AS (
    -- Keep only the top K variants (set K here, e.g., 5)
    SELECT
        activity_sequence,
        case_count
    FROM variant_counts
    WHERE variant_rank <= 5   -- <-- change K here
),

qualifying_cases AS (
    -- Step 4a: Identify which case_ids belong to a top-K variant
    SELECT
        cs.case_id,
        cs.activity_sequence
    FROM case_sequences cs
    INNER JOIN top_k_variants tk
        ON cs.activity_sequence = tk.activity_sequence
)

-- Step 4b: Return all original events for the qualifying cases
SELECT
    e.case_id,
    e.activity,
    e.timestamp,
    qc.activity_sequence
FROM event_log e
INNER JOIN qualifying_cases qc
    ON e.case_id = qc.case_id
ORDER BY
    e.case_id,
    e.timestamp;
```

## Explanation of Each Step

### 1. `case_sequences` — Ordered Activity Extraction
```sql
array_agg(activity ORDER BY timestamp) AS activity_sequence
```
This is the key DuckDB feature that lets you aggregate values **in a specified order** directly within `array_agg`. Each `case_id` collapses into a single row containing an ordered array of activities — this array *is* the process variant signature.

### 2. `variant_counts` — Grouping and Counting Variants
```sql
GROUP BY activity_sequence
```
Because `activity_sequence` is an array, DuckDB can group on it directly (array equality is well-defined), collapsing all cases sharing an identical ordered sequence into one row, with `COUNT(*)` giving the number of cases per variant.

### 3. `DENSE_RANK()` — Ranking Variants by Frequency
```sql
DENSE_RANK() OVER (ORDER BY COUNT(*) DESC) AS variant_rank
```
`DENSE_RANK()` is preferred over `ROW_NUMBER()` here because if multiple variants are tied in frequency, they all receive the same rank and are all included when filtering `variant_rank <= K` — avoiding an arbitrary cutoff mid-tie. (If you want a strict top-K count regardless of ties, use `ROW_NUMBER()` instead.)

### 4. Filtering to Top-K Variants
```sql
WHERE variant_rank <= 5
```
Replace `5` with your desired `K`. This isolates the K most frequent variants along with their sequences and case counts.

### 5. `qualifying_cases` — Mapping Back to Case IDs
This CTE joins the per-case sequences against the top-K variant list to recover the exact set of `case_id`s that follow one of the top-K patterns.

### 6. Final Join — Returning Original Events
```sql
INNER JOIN qualifying_cases qc ON e.case_id = qc.case_id
```
This returns **every event row** (not just the aggregated variant) from `event_log` for cases matching a top-K variant, preserving full event-level detail (timestamps, activity names, etc.), while excluding all events from cases outside the top-K.

## Notes & Variations

- **Making K dynamic**: If you want K to be a query parameter rather than hardcoded, DuckDB supports prepared statements: `PREPARE q AS ... WHERE variant_rank <= $k; EXECUTE q(5);`
- **Case count column**: The final result includes `activity_sequence` for traceability — you can drop this or add `case_count` if you want to see variant frequency alongside each event.
- **Performance**: For very large logs, consider indexing/sorting `event_log` by `(case_id, timestamp)` beforehand to speed up the windowed aggregation.
- **Tie-breaking with `ROW_NUMBER()`**: If strict top-K (exactly K variants, no ties expanded) is required:
  ```sql
  ROW_NUMBER() OVER (ORDER BY COUNT(*) DESC) AS variant_rank
  ```
