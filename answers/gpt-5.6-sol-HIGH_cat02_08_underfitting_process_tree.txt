### Invalid-but-accepted trace

```text
Receive_Order 
Check_Inventory 
Ship_Order 
Package_Items 
Authorize_Payment 
Close_Order
```

### Why the model accepts it

The successful branch is modeled using `Operator.PARALLEL`:

```python
PARALLEL(Authorize_Payment, Package_Items, Ship_Order)
```

A parallel operator permits these three activities to occur in any interleaving. Therefore, the model allows `Ship_Order` to happen before both `Package_Items` and `Authorize_Payment`.

### Why it is problematic

In the intended Order-to-Cash process:

1. Payment must be authorized before fulfillment.
2. Items must be packaged before they can be shipped.
3. Shipping must therefore occur only after authorization and packaging.

The example trace ships the order before it is packaged or paid for, which is logically invalid. The successful subtree should instead use a sequence operator:

```python
SEQUENCE(Authorize_Payment, Package_Items, Ship_Order)
```

There is also a separate modeling issue on the cancellation path: `Close_Order` appears inside `cancel_subtree` and again at the root, allowing:

```text
Receive_Order  Check_Inventory  Cancel_Order  Close_Order  Close_Order
```

This closes the same order twice.
