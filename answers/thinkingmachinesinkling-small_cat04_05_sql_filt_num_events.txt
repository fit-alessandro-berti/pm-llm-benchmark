Here is a concise, correct DuckDB query. It first identifies which `case_id`s have 6 or fewer events (`GROUP BY` + `HAVING`), then returns every row for only those cases.

```sql
SELECT *
FROM event_log
WHERE case_id IN (
    SELECT case_id
    FROM event_log
    GROUP BY case_id
    HAVING COUNT(*) <= 6
);
```

**How it works:**
1. The subquery groups by `case_id` and uses `HAVING COUNT(*) <= 6` to keep only cases with six or fewer events (excluding any case with >6).
2. The outer query selects all original columns (`*`) for rows whose `case_id` appears in that filtered list.

**Alternative (using a window function and DuckDB’s `QUALIFY`):**
If you prefer to avoid a self-join/subquery and compute counts in one pass:

```sql
SELECT *
FROM event_log
QUALIFY COUNT(*) OVER (PARTITION BY case_id) <= 6;
```

Both achieve the same result: cases with >6 events are entirely removed, and all remaining events are returned.
