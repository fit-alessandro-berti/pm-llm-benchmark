Here are the two POWL models constructed with `pm4py`. Both include the initial loop for data completeness and the sequential skill-check flow, but differ exactly at the cultural-fit stage: **Model 1** introduces an XOR split that allows a privileged “CommunityAffiliationCheck” path, while **Model 2** removes that split so every applicant follows the same “CulturalFitCheck”.

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# =====================================================================
# MODEL 1: WITH POTENTIAL UNFAIRNESS
# =====================================================================

# 1. Initial application
receive_app = Transition(label="ReceiveApplication")

# 2. Loop: check data completeness; if missing, request more info and re-check
data_check   = Transition(label="DataCompletenessCheck")
request_more = Transition(label="RequestMoreInfo")
loop_data    = OperatorPOWL(operator=Operator.LOOP, children=[data_check, request_more])

# 3. Skill assessment
skill_assess = Transition(label="SkillAssessment")

# 4. XOR branch: standard cultural fit OR community-affiliation-biased path
cultural_fit     = Transition(label="CulturalFitCheck")
community_affil   = Transition(label="CommunityAffiliationCheck")
xor_fit_unfair    = OperatorPOWL(operator=Operator.XOR, children=[cultural_fit, community_affil])

# 5. Managerial review and final decision
review = Transition(label="ManagerialReview")
decision = Transition(label="FinalDecision")

# Root partial order: linear sequence with the XOR embedded after skills
root_unfair = StrictPartialOrder(
    nodes=[receive_app, loop_data, skill_assess, xor_fit_unfair, review, decision]
)
root_unfair.order.add_edge(receive_app, loop_data)
root_unfair.order.add_edge(loop_data, skill_assess)
root_unfair.order.add_edge(skill_assess, xor_fit_unfair)
root_unfair.order.add_edge(xor_fit_unfair, review)
root_unfair.order.add_edge(review, decision)


# =====================================================================
# MODEL 2: WITHOUT UNFAIRNESS (BIAS REMOVED)
# =====================================================================

# 1. Initial application
receive_app_f = Transition(label="ReceiveApplication")

# 2. Same completeness loop
data_check_f    = Transition(label="DataCompletenessCheck")
request_more_f  = Transition(label="RequestMoreInfo")
loop_data_f     = OperatorPOWL(operator=Operator.LOOP, children=[data_check_f, request_more_f])

# 3. Skill assessment
skill_assess_f = Transition(label="SkillAssessment")

# 4. Single, uniform cultural-fit evaluation (no XOR, no special branch)
cultural_fit_f = Transition(label="CulturalFitCheck")

# 5. Managerial review and final decision
review_f  = Transition(label="ManagerialReview")
decision_f = Transition(label="FinalDecision")

# Root partial order: purely sequential, with the loop and then one shared fit check
root_fair = StrictPartialOrder(
    nodes=[receive_app_f, loop_data_f, skill_assess_f, cultural_fit_f, review_f, decision_f]
)
root_fair.order.add_edge(receive_app_f, loop_data_f)
root_fair.order.add_edge(loop_data_f, skill_assess_f)
root_fair.order.add_edge(skill_assess_f, cultural_fit_f)
root_fair.order.add_edge(cultural_fit_f, review_f)
root_fair.order.add_edge(review_f, decision_f)
```

### Key Differences

| Feature | Model 1 (Unfair) | Model 2 (Fair) |
|---|---|---|
| **Loop for completeness** | `* (DataCompletenessCheck, RequestMoreInfo)` | Same loop preserved |
| **Skill check** | `SkillAssessment` (sequential) | `SkillAssessment` (sequential) |
| **Fit / Affiliation stage** | `XOR` between `CulturalFitCheck` and `CommunityAffiliationCheck` — the second branch can implicitly uplift candidates with local-group ties | Only `CulturalFitCheck`; **no XOR**, so every applicant is evaluated identically |
| **Final stages** | `ManagerialReview`  `FinalDecision` | `ManagerialReview`  `FinalDecision` |

In Model 1, the XOR node (`xor_fit_unfair`) is the explicit point where bias enters: depending on how the applicant is routed, they may either face the standard evaluation or receive the “subtle uplift” via the community-affiliation path. Model 2 eliminates that routing option entirely, ensuring a single, uniform evaluation path for all candidates.
