## Modeling Approach

**Sequential backbone:**
`CR  DV  FC  CA  (AP or skip)  P  N  CL`

**Loops (both realized as "back-jumps" to an earlier place, so they can fire arbitrarily many times):**

* **RDS loop:** after `DV` the token sits in `p_docs_checked`. From there, either the process continues with `FC`, or `RDS` fires and sends the token back to `p_registered`, forcing `DV` to be executed again.
* **II loop:** after `FC` the token sits in `p_fraud_checked`. From there either `CA` continues the process, or `II` fires and returns the token to `p_docs_checked`, so `FC` is repeated — this may happen multiple times.

**Optional approval:** since `AP` is only mandatory above a threshold, a silent (invisible, `label=None`) transition allows skipping it.

```python
from pm4py.objects.petri_net.obj import PetriNet, Marking
from pm4py.objects.petri_net.utils import petri_utils

net = PetriNet(name="insurance_claim_management")

# ----------------------------------------------------------------------
# PLACES (states between the activities)
# ----------------------------------------------------------------------
start          = PetriNet.Place(name="start")            # new claim arrived
p_registered   = PetriNet.Place(name="p_registered")     # claim logged, docs to be verified
p_docs_checked = PetriNet.Place(name="p_docs_checked")   # after DV (or after II) -> FC / RDS
p_fraud_checked= PetriNet.Place(name="p_fraud_checked")  # after FC -> CA / II
p_assessed     = PetriNet.Place(name="p_assessed")       # after CA -> AP / skip
p_approved     = PetriNet.Place(name="p_approved")       # ready for payment
p_paid         = PetriNet.Place(name="p_paid")           # payment done
p_notified     = PetriNet.Place(name="p_notified")       # customer notified
end            = PetriNet.Place(name="end")              # claim closed & archived

for p in [start, p_registered, p_docs_checked, p_fraud_checked,
          p_assessed, p_approved, p_paid, p_notified, end]:
    net.places.add(p)

# ----------------------------------------------------------------------
# TRANSITIONS (activities)
# ----------------------------------------------------------------------
t_cr   = PetriNet.Transition(name="CR",   label="Claim Registration")
t_dv   = PetriNet.Transition(name="DV",   label="Document Verification")
t_rds  = PetriNet.Transition(name="RDS",  label="Re-Document Submission")
t_fc   = PetriNet.Transition(name="FC",   label="Fraud Check")
t_ii   = PetriNet.Transition(name="II",   label="In-depth Investigation")
t_ca   = PetriNet.Transition(name="CA",   label="Claim Assessment")
t_ap   = PetriNet.Transition(name="AP",   label="Approval")
t_skip = PetriNet.Transition(name="skip_AP", label=None)   # silent: amount below threshold
t_p    = PetriNet.Transition(name="P",    label="Payment")
t_n    = PetriNet.Transition(name="N",    label="Notification")
t_cl   = PetriNet.Transition(name="CL",   label="Closure")

for t in [t_cr, t_dv, t_rds, t_fc, t_ii, t_ca, t_ap, t_skip, t_p, t_n, t_cl]:
    net.transitions.add(t)

# ----------------------------------------------------------------------
# ARCS
# ----------------------------------------------------------------------
# start -> CR -> registered
petri_utils.add_arc_from_to(start, t_cr, net)
petri_utils.add_arc_from_to(t_cr, p_registered, net)

# registered -> DV -> docs checked
petri_utils.add_arc_from_to(p_registered, t_dv, net)
petri_utils.add_arc_from_to(t_dv, p_docs_checked, net)

# LOOP 1: incomplete documents -> RDS -> verify again (arbitrarily often)
petri_utils.add_arc_from_to(p_docs_checked, t_rds, net)
petri_utils.add_arc_from_to(t_rds, p_registered, net)

# docs checked -> FC -> fraud checked
petri_utils.add_arc_from_to(p_docs_checked, t_fc, net)
petri_utils.add_arc_from_to(t_fc, p_fraud_checked, net)

# LOOP 2: doubts -> II -> fraud check again (may repeat multiple times)
petri_utils.add_arc_from_to(p_fraud_checked, t_ii, net)
petri_utils.add_arc_from_to(t_ii, p_docs_checked, net)

# fraud checked -> CA -> assessed
petri_utils.add_arc_from_to(p_fraud_checked, t_ca, net)
petri_utils.add_arc_from_to(t_ca, p_assessed, net)

# assessed -> AP (or silent skip) -> approved
petri_utils.add_arc_from_to(p_assessed, t_ap, net)
petri_utils.add_arc_from_to(t_ap, p_approved, net)
petri_utils.add_arc_from_to(p_assessed, t_skip, net)
petri_utils.add_arc_from_to(t_skip, p_approved, net)

# approved -> P -> N -> CL -> end
petri_utils.add_arc_from_to(p_approved, t_p, net)
petri_utils.add_arc_from_to(t_p, p_paid, net)
petri_utils.add_arc_from_to(p_paid, t_n, net)
petri_utils.add_arc_from_to(t_n, p_notified, net)
petri_utils.add_arc_from_to(p_notified, t_cl, net)
petri_utils.add_arc_from_to(t_cl, end, net)

# ----------------------------------------------------------------------
# INITIAL AND FINAL MARKING
# ----------------------------------------------------------------------
im = Marking()
im[start] = 1          # a new insurance claim (C) arrives

fm = Marking()
fm[end] = 1            # claim paid, customer notified, claim closed/archived

# ----------------------------------------------------------------------
# (optional) inspection / visualization
# ----------------------------------------------------------------------
if __name__ == "__main__":
    import pm4py
    print(net)
    print("Initial marking:", im)
    print("Final marking:", fm)
    # pm4py.view_petri_net(net, im, fm)
    # pm4py.write_pnml(net, im, fm, "insurance_claim.pnml")
```

**Accepted language (examples):**

* `CR, DV, FC, CA, AP, P, N, CL`
* `CR, DV, RDS, DV, FC, CA, P, N, CL` (document re-submission, approval skipped)
* `CR, DV, FC, II, FC, II, FC, CA, AP, P, N, CL` (repeated in-depth investigations)

The net is a **sound workflow net**: one source (`start`), one sink (`end`), a single token flows through it, both loops always return to a reachable state, and every firing sequence can be extended to reach exactly `fm = [end:1]`.
