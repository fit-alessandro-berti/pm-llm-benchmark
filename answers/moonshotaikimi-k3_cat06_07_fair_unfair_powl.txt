# POWL Models for the GlobalTeq Hiring Process

Both models share the same backbone:

- **Loop:** `*( DataCompletenessCheck, RequestMoreInfo )` — the check runs; if data is missing, `RequestMoreInfo` executes and the check repeats until the data is complete.
- **Sequence:** `ReceiveApplication  loop  SkillAssessment  [cultural stage]  ManagerialReview  FinalDecision`.

The only difference is the **cultural stage**: Model 1 uses an XOR with a privileged affiliation branch (bias point), Model 2 uses a single uniform path.

---

## Model 1 — With Potential Unfairness

POWL structure:

```
PO = ( nodes = { ReceiveApplication,
                 *( DataCompletenessCheck, RequestMoreInfo ),
                 SkillAssessment,
                 X( CulturalFitCheck, CommunityAffiliationCheck ),
                 ManagerialReview,
                 FinalDecision },
       order = { ReceiveApplication --> *(...),
                 *(...) --> SkillAssessment,
                 SkillAssessment --> X(...),
                 X(...) --> ManagerialReview,
                 ManagerialReview --> FinalDecision } )
```

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_app   = Transition(label="ReceiveApplication")
data_check    = Transition(label="DataCompletenessCheck")
request_info  = Transition(label="RequestMoreInfo")
skill_assess  = Transition(label="SkillAssessment")
cultural_fit  = Transition(label="CulturalFitCheck")
community     = Transition(label="CommunityAffiliationCheck")  # grants implicit uplift -> BIAS SOURCE
manager_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop: *( DataCompletenessCheck, RequestMoreInfo ) ---
# Execute DataCompletenessCheck; either exit, or run RequestMoreInfo and check again.
data_loop = OperatorPOWL(operator=Operator.LOOP, children=[data_check, request_info])

# --- XOR branch (unfairness point) ---
# Either the standard merit-based evaluation OR the affiliation-based path
# that subtly boosts candidates with local/community ties.
cultural_xor = OperatorPOWL(operator=Operator.XOR, children=[cultural_fit, community])

# --- Partial order (fully sequential backbone) ---
root_unfair = StrictPartialOrder(
    nodes=[receive_app, data_loop, skill_assess, cultural_xor, manager_review, final_decision]
)
root_unfair.order.add_edge(receive_app, data_loop)
root_unfair.order.add_edge(data_loop, skill_assess)
root_unfair.order.add_edge(skill_assess, cultural_xor)
root_unfair.order.add_edge(cultural_xor, manager_review)
root_unfair.order.add_edge(manager_review, final_decision)

# Optional: visualize
# pm4py.view_powl(root_unfair)
```

**Where the bias lives:** in `X( CulturalFitCheck, CommunityAffiliationCheck )`. Because the process *allows* a privileged alternative path, two equally skilled candidates can be treated differently depending on club membership or local residency — and `ManagerialReview` downstream inherits that tilt.

## Model 2 — Without Unfairness

POWL structure:

```
PO = ( nodes = { ReceiveApplication,
                 *( DataCompletenessCheck, RequestMoreInfo ),
                 SkillAssessment,
                 CulturalFitCheck,
                 ManagerialReview,
                 FinalDecision },
       order = { ReceiveApplication --> *(...),
                 *(...) --> SkillAssessment,
                 SkillAssessment --> CulturalFitCheck,
                 CulturalFitCheck --> ManagerialReview,
                 ManagerialReview --> FinalDecision } )
```

```python
import pm4py
from pm4py.objects.powl.obj import StrictPartialOrder, OperatorPOWL, Transition, SilentTransition
from pm4py.objects.process_tree.obj import Operator

# --- Activities ---
receive_app    = Transition(label="ReceiveApplication")
data_check     = Transition(label="DataCompletenessCheck")
request_info   = Transition(label="RequestMoreInfo")
skill_assess   = Transition(label="SkillAssessment")
cultural_fit   = Transition(label="CulturalFitCheck")   # single, uniform evaluation for everyone
manager_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# --- Loop: *( DataCompletenessCheck, RequestMoreInfo ) ---
data_loop = OperatorPOWL(operator=Operator.LOOP, children=[data_check, request_info])

# --- No XOR at the cultural stage: one identical path for all applicants ---
root_fair = StrictPartialOrder(
    nodes=[receive_app, data_loop, skill_assess, cultural_fit, manager_review, final_decision]
)
root_fair.order.add_edge(receive_app, data_loop)
root_fair.order.add_edge(data_loop, skill_assess)
root_fair.order.add_edge(skill_assess, cultural_fit)
root_fair.order.add_edge(cultural_fit, manager_review)
root_fair.order.add_edge(manager_review, final_decision)

```

## Key Differences at a Glance

| Aspect | Model 1 (Unfair) | Model 2 (Fair) |
|---|---|---|
| Data completeness loop | `*(DataCompletenessCheck, RequestMoreInfo)` | identical |
| Skill assessment | sequential step | identical |
| Cultural stage | `X(CulturalFitCheck, CommunityAffiliationCheck)` — selective uplift possible | single `CulturalFitCheck` for all |
| Review & decision | sequential, inherits upstream bias | sequential, bias source removed |

**Note:** the unfairness isn't caused by choice constructs in general — it's caused by *what the XOR offers*: a privileged path tied to affiliation rather than merit. Removing that branch (Model 2) guarantees every applicant flows through the identical evaluative structure, while the legitimate loop (data completeness) and the sequential control flow remain intact. If desired, `FinalDecision` in either model could be further refined as `X(Hire, Reject)` — an outcome-based choice that carries no bias.
