Assuming the idealized process follows the fixed order

`IG  DD  TFC  CE  PC  LT  UT  AG  MP  FL`

and every activity occurs exactly once in every trace, the following dictionary represents the DECLARE model. Each rule has support `1.0` and confidence `1.0`.

Binary constraint keys are represented as `(activity_a, activity_b)` tuples.

```python
from itertools import combinations

activities = [
    "Idea Generation",
    "Design Draft",
    "Technical Feasibility Check",
    "Cost Evaluation",
    "Prototype Creation",
    "Laboratory Testing",
    "User Testing",
    "Approval Gate",
    "Marketing Plan",
    "Final Launch",
]

def score():
    # [support, confidence]
    return [1.0, 1.0]

def make_rules(keys):
    return {key: score() for key in keys}

# Ordered pairs following the process order
forward_pairs = [
    (activities[i], activities[j])
    for i in range(len(activities))
    for j in range(i + 1, len(activities))
]

# Ordered pairs opposite to the process order
reverse_pairs = [
    (activities[i], activities[j])
    for i in range(len(activities))
    for j in range(i - 1, -1, -1)
]

# Pairs of activities that are immediately adjacent in the process
adjacent_pairs = [
    (activities[i], activities[i + 1])
    for i in range(len(activities) - 1)
]

# All directed pairs
all_directed_pairs = [
    (a, b)
    for a in activities
    for b in activities
    if a != b
]

# Symmetric pairs
coexistence_pairs = list(combinations(activities, 2))

# Not-chain-succession holds for every directed pair except
# the immediately consecutive forward pairs.
non_chain_succession_pairs = [
    pair for pair in all_directed_pairs
    if pair not in adjacent_pairs
]

declare_model = {
    # Unary templates
    "existence": make_rules(activities),

    # No activity is absent
    "absence": {},

    # Every activity occurs exactly once
    "exactly_one": make_rules(activities),

    # Idea Generation is the first activity
    "init": make_rules(["Idea Generation"]),

    # Binary templates
    # Since every activity occurs in every trace, every activity
    # implies the existence of every other activity.
    "responded_existence": make_rules(all_directed_pairs),

    # Co-existence is symmetric
    "coexistence": make_rules(coexistence_pairs),

    # Forward-order constraints
    "response": make_rules(forward_pairs),
    "precedence": make_rules(forward_pairs),
    "succession": make_rules(forward_pairs),

    "altresponse": make_rules(forward_pairs),
    "altprecedence": make_rules(forward_pairs),
    "altsuccession": make_rules(forward_pairs),

    # Immediate-order constraints
    "chainresponse": make_rules(adjacent_pairs),
    "chainprecedence": make_rules(adjacent_pairs),
    "chainsuccession": make_rules(adjacent_pairs),

    # No two activities are mutually exclusive
    "noncoexistence": {},

    # Reverse-order pairs cannot satisfy succession
    "nonsuccession": make_rules(reverse_pairs),

    # Any pair except an immediately consecutive forward pair
    # satisfies non-chain-succession
    "nonchainsuccession": make_rules(non_chain_succession_pairs),
}
```

For example, some entries in the resulting model are:

```python
declare_model["existence"]["Idea Generation"]
# [1.0, 1.0]

declare_model["init"]["Idea Generation"]
# [1.0, 1.0]

declare_model["succession"][
    ("Idea Generation", "Design Draft")
]
# [1.0, 1.0]

declare_model["chainsuccession"][
    ("Approval Gate", "Marketing Plan")
]
# [1.0, 1.0]
```

This model assumes no optional activities, loops, rework, or alternative paths. In a real DECLARE model discovered from an event log, the supports and confidences would be calculated from the observed traces rather than all being `1.0`.
