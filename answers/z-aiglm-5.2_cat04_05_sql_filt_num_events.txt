Here is the DuckDB SQL query to achieve this. 

You can use a subquery in the `WHERE` clause with the `IN` operator to first identify the valid `case_id`s (those with 6 or fewer events) and then return all their corresponding events:

```sql
SELECT *
FROM event_log
WHERE case_id IN (
    SELECT case_id
    FROM event_log
    GROUP BY case_id
    HAVING COUNT(*) <= 6
);
```

### How it works:
1. **Subquery**: `SELECT case_id FROM event_log GROUP BY case_id HAVING COUNT(*) <= 6` groups the events by `case_id` and counts the number of events per case. The `HAVING` clause filters this list, keeping only those `case_id`s with 6 or fewer events.
2. **Main Query**: `SELECT * FROM event_log WHERE case_id IN (...)` retrieves all columns for the events belonging exclusively to the `case_id`s returned by the subquery.

### Alternative approach using Window Functions:
If you prefer to avoid subqueries, you can also use a Common Table Expression (CTE) with a window function to count the events per case, and then filter the results:

```sql
WITH case_counts AS (
    SELECT *, COUNT(*) OVER (PARTITION BY case_id) AS event_count
    FROM event_log
)
SELECT case_id, activity, timestamp
FROM case_counts
WHERE event_count <= 6;
```
*(Note: In this alternative, we specify the columns to select in the final query rather than `SELECT *` to avoid including the temporary `event_count` column in the final output.)*
