## 1. Identifying Instance-Spanning Constraints and Their Impact

### 1.1 Prepare and enrich the event log

Standard case-based process mining alone is insufficient because the constraints involve interactions among orders, resources, stations, batches, and facility-wide capacity. I would create an **object-centric event log (OCEL)** or an equivalent relational model with these objects:

- Order
- Packing/QC activity instance
- Physical station and station type
- Staff member
- Shipping batch
- Destination region
- Hazardous-capacity pool
- Time shift/day

Each activity should have reliable start and completion timestamps. Additional useful fields include:

- Time an order became ready for its next activity
- Queue-entry timestamp
- Station assignment and release timestamps
- Batch creation, closure, and dispatch timestamps
- Preemption, suspension, and resume events
- Express-arrival timestamp
- Hazardous-capacity reservation and release events
- Cancellation, rework, and exceptional-release events

Where explicit queue events are unavailable, readiness times can be inferred from the preceding activity’s completion, while recognizing transport or release rules. Queue and interruption events should preferably be added prospectively.

Data quality checks should cover:

- Matched start/complete events
- Overlapping assignments for the same resource
- Invalid station/type combinations
- Missing batch identifiers
- Order attributes changing unexpectedly
- Clock and timezone consistency
- Activities completing before they start
- Censored cases at the beginning or end of the three-month window

I would then discover the normal order flow using a directly-follows graph, Petri net, BPMN model, or process tree, and augment this with **multi-object/resource views** to detect cross-order dependencies.

### 1.2 General time decomposition

For each transition into an activity:

\[
\text{Inter-activity time}
=
\text{Ready time to activity start}
+
\text{Activity duration}
\]

That is:

\[
T_{\text{transition}} = T_{\text{queue/wait}} + T_{\text{service}}
\]

The waiting component should then be attributed to causes such as:

- Resource unavailable
- Batch not yet released
- Express preemption
- Hazardous work-in-process cap reached
- Normal transport/release delay
- Missing input, rework, or another within-order condition

Attribution should use explicit state data where available and counterfactual or statistical inference where it is not. Waiting reasons can overlap, so a causal hierarchy or competing-risks model is needed to avoid double counting.

---

### 1.3 Shared Cold-Packing stations

#### Identification

For every cold-packing order, calculate:

- Time at which picking completed and the order became packing-ready
- Time at which a cold station became available
- Actual packing start
- Which station was assigned
- Which other order occupied each cold station during the waiting interval
- Queue composition and priority at that time

Build station occupancy intervals from Packing START/COMPLETE events and sweep them across time. With five stations, contention exists when all eligible cold stations are occupied and one or more ready cold orders are waiting.

Queueing analysis can be segmented by:

- Hour and shift
- Weekday
- Peak versus non-peak season
- Express versus standard
- Hazardous versus non-hazardous
- Product mix
- Station and operator

#### Metrics

- Mean, median, P90, and P95 cold-packing queue time
- Percentage of cold orders that wait
- Time-weighted queue length
- Maximum and P95 queue length
- Cold-station utilization and idle time
- Arrival rate, service rate, and utilization by period
- Throughput per station-hour
- Abandonment, rerouting, or SLA-breach rate
- Percentage of waiting time during which all eligible stations were occupied
- Delay contribution of cold-packing contention to total cycle time
- Fairness and delay by order type
- Blocking caused by downstream hazardous limits or QC congestion

A useful counterfactual measure is:

\[
\text{Contention delay}
=
\max(0,\ \text{actual start} - \text{earliest feasible station availability})
\]

This distinguishes cold-station contention from delays that occurred even when an eligible station was idle.

### 1.4 Shipping batches

#### Identification

Link each order to its batch through a batch ID, label resource, or destination/time clustering. Reconstruct:

- Time each order became label-ready
- Batch opening time
- Time each order joined the batch
- Batch closure/release time
- Batch size and region
- Label-generation time
- Carrier cutoff or dispatch deadline

For order \(i\):

\[
T_{\text{batch wait},i}
=
T_{\text{batch release},i} - T_{\text{label ready},i}
\]

The snippet suggests ORD-5001 was label-ready after QC at 10:35:15 and received its label at 10:45:50. Most of the resulting 10 minutes 35 seconds is a candidate batching delay, subject to any normal transfer or system-processing time.

#### Metrics

- Average and percentile batch-wait time
- Batch formation time
- Batch size distribution and fill rate
- Percentage of orders released by size, timer, cutoff, or urgent trigger
- Oldest-order age at release
- SLA breaches attributable to batch waiting
- Label-system throughput
- Dispatch consolidation or transportation-cost benefit
- Region-level volume volatility
- Percentage of express orders delayed by batching
- Marginal delay imposed on early batch members by the last arrivals

Batching should be assessed as a trade-off, not only as a delay: fulfillment performance must be compared with route utilization and shipping cost.

---

### 1.5 Express-priority handling and preemption

#### Identification

Reconstruct resource timelines and identify cases where:

1. A standard order is in service.
2. An express order becomes ready for the same resource class.
3. The standard task is suspended, slowed, reassigned, or restarted.
4. The express task starts ahead of it.

Ideally, the log should contain SUSPEND and RESUME events. Without them, likely preemptions can be inferred from unusually long standard activity durations, overlapping assignments, resource switches, and express starts during gaps.

Compare actual sequencing with alternative scheduling rules, controlling for:

- Arrival time
- Activity and station type
- Product complexity
- Hazardous/cold attributes
- Shift and resource
- Queue state

#### Metrics

- Express queue time and SLA attainment
- Standard-order delay following express arrivals
- Number of preemptions per shift
- Suspension duration
- Restart/setup or lost-work time
- Express leapfrogging count
- Standard P90/P95 cycle-time inflation
- Throughput lost to context switching
- Priority inversion rate, where an express order waits behind eligible standard work
- Starvation risk for standard orders
- Net SLA-weighted benefit of priority handling

A difference-in-differences, matched comparison, or discrete-event counterfactual can estimate how much standard delay is caused by express prioritization rather than ordinary workload.

---

### 1.6 Hazardous-material concurrency limit

#### Identification

Construct intervals for each hazardous order while it is in Packing or Quality Check. The exact regulatory rule must be clarified:

- Does the count include only actively processed orders?
- Does it include orders suspended in those activities?
- Is an order moving from Packing to QC counted continuously or only during active intervals?
- Does an order simultaneously represented in both states count once or twice?

Assuming each hazardous order counts once while actively in either activity, compute:

\[
H(t)=
\left|\{\text{hazardous orders active in Packing or QC at time }t\}\right|
\]

Perform an interval sweep over all start and completion events to reconstruct \(H(t)\).

#### Metrics

- Maximum concurrent hazardous WIP
- Percentage of time at 8, 9, and 10 concurrent orders
- Number and duration of violations where \(H(t)>10\)
- Hazardous admission queue length and wait time
- Packing/QC idle time while the hazardous cap is binding
- Throughput of hazardous orders per hour
- Cycle-time difference between hazardous and comparable non-hazardous orders
- Frequency and duration of blocked starts at \(H(t)=10\)
- Capacity-slot utilization
- Number of reserved but unused slots
- Downstream blockage caused by slow QC or rework

Throughput reduction can be estimated by comparing observed performance with a simulated unconstrained scenario and with scenarios that retain the cap but improve scheduling.

---

### 1.7 Separating within-order and between-order causes

A long activity duration is generally a **service-time issue within an order**. A gap before an activity may arise from either category:

| Delay type | Evidence |
|---|---|
| Long processing time | START-to-COMPLETE interval is high |
| Shared-resource contention | Order is ready, eligible stations are all occupied |
| Batch wait | Order is label-ready, but batch release condition is unmet |
| Priority delay | Standard order is postponed/suspended when eligible express work arrives |
| Hazardous-cap delay | Order is ready, but facility hazardous count is 10 |
| Internal order problem | Missing information, rework, exception, or predecessor not complete |
| Unexplained operational delay | Resource appears available and no known gate is active |

Methods should include:

- Token replay or alignments to identify process deviations
- Performance overlays on discovered models
- Queue reconstruction from lifecycle events
- Resource-state and batch-state reconstruction
- Root-cause classification or survival analysis
- Matched comparisons across equivalent orders
- Counterfactual simulation to estimate delay under removal of one constraint at a time

Because several constraints may be active simultaneously, delay attribution can use an ordered rule set—for example, regulatory blocking first, then resource unavailability, then batching—or a Shapley-style decomposition across counterfactual scenarios.

## 2. Analyzing Constraint Interactions

### 2.1 Express orders and cold-packing contention

An express cold order may leapfrog standard cold orders or preempt one already in service. This improves express SLA performance but can:

- Increase standard queue length and tail latency
- Cause setup/restart losses
- Reduce effective cold-station capacity
- Create starvation during bursts of express arrivals
- Occupy a hazardous slot if the express order is also hazardous
- Push standard completion times toward later shipping batches

Thus, an apparently successful local priority policy may worsen total throughput and batch delays.

### 2.2 Cold-packing and hazardous limits

A cold hazardous order needs two capacities simultaneously:

1. A cold-packing station
2. One of the ten hazardous active-work slots

Poor coordination can produce avoidable idleness:

- A cold station is reserved while no hazardous slot is available.
- A hazardous slot is held while the order waits for a cold station.
- Congested QC keeps hazardous slots occupied, preventing new packing starts.

Scheduling must therefore coordinate both resources rather than optimize each separately.

### 2.3 Batching and priority

A fast express order may complete processing quickly but then lose its advantage while waiting for a regional batch. Conversely, immediately releasing every express order can:

- Reduce consolidation
- Raise transport costs
- Fragment later batches
- Delay standard orders through reduced carrier capacity

Express orders may need a shorter batching timeout or carrier-cutoff-aware release rather than complete exemption from batching.

### 2.4 Batching and hazardous orders

A group of hazardous orders for one region may be attractive as a shipping batch, but synchronizing their completion can create a wave of hazardous work in Packing and QC. If the facility reaches ten active hazardous orders:

- New hazardous orders are blocked
- Cold hazardous orders may occupy scarce queues
- Some batch members finish early and wait for stragglers
- A batch rule may indirectly amplify regulatory bottlenecks

Batch planning should therefore consider projected production completion, not merely destination and order arrival.

### 2.5 Hazardous limits and express priority

An express hazardous order cannot legally start when ten hazardous orders are active. Preempting a standard hazardous order may or may not free a regulatory slot, depending on whether a suspended order is still considered “undergoing” the activity. If it remains counted, preemption creates disruption without creating capacity.

A policy must encode the legal interpretation rather than assume that ordinary priority logic is applicable.

### 2.6 Why interaction analysis matters

Optimizing one KPI in isolation can shift the bottleneck:

- Adding cold capacity may move congestion to QC.
- Aggressive express preemption may reduce throughput.
- Larger batches may reduce transport cost but cause SLA breaches.
- Keeping hazardous capacity at 10 continuously may reduce resilience and increase violation risk during timestamp or handoff errors.

The correct objective is a facility-level combination of:

- End-to-end cycle time
- Throughput
- SLA attainment by service class
- Regulatory compliance
- Shipping cost
- Resource cost
- Fairness and operational stability

Object-centric process mining, interaction regression, temporal correlation, and simulation can reveal these cross-case effects.

## 3. Constraint-Aware Optimization Strategies

### Strategy 1: Predictive, coordinated scheduling for Packing and QC

#### Constraints addressed

- Cold-station contention
- Express priority
- Hazardous concurrency
- Interaction between Packing and QC

#### Proposed changes

Use a real-time scheduler that assigns ready orders according to a weighted score, for example:

\[
\text{Score}_i =
w_1(\text{SLA urgency})
+w_2(\text{waiting age})
+w_3(\text{express status})
+w_4(\text{batch cutoff proximity})
-w_5(\text{setup cost})
-w_6(\text{downstream congestion risk})
\]

Assignments must satisfy hard constraints:

- Cold orders use eligible cold stations.
- Hazardous active WIP never exceeds 10.
- Resource and staff qualifications are respected.
- Preemption is permitted only at safe, low-cost points.
- Standard orders receive aging-based priority to prevent starvation.

Use a central hazardous-cap token pool. A token is acquired immediately before regulated work starts and released at the legally defined completion point. Coordinate Packing and QC admissions so that slow QC does not consume all slots.

Reserve limited cold capacity for urgent orders only when forecast demand justifies it. A practical policy might allow one flexible priority lane, with unused capacity reverting immediately to standard work.

#### Data use

- Forecast cold, express, and hazardous arrivals by 15- or 30-minute interval
- Estimate processing-time distributions by order attributes
- Predict SLA breach risk
- Estimate preemption/setup cost
- Monitor downstream QC capacity
- Train and validate using historical queue states and outcomes

#### Expected outcomes

- Lower cold-station queue time
- Better express SLA attainment
- Fewer disruptive preemptions
- Lower standard tail latency and starvation
- Higher effective station throughput
- Full hazardous-limit compliance
- Better balance between Packing and QC

---

### Strategy 2: Dynamic, deadline-aware shipping batches

#### Constraints addressed

- Batch formation delays
- Priority/batch interaction
- Regional volume variability
- Hazardous completion waves

#### Proposed changes

Replace fixed-size or indefinite waiting rules with dynamic release triggers. Release a regional batch when the first applicable condition is met:

- Target batch size is reached
- Oldest order exceeds a maximum waiting time
- An express order approaches its SLA threshold
- Carrier cutoff is approaching
- Predicted time to the next arrivals exceeds the economic value of waiting
- The marginal transportation saving is smaller than expected lateness cost

Use separate but coordinated policies for service classes:

- Express: short timeout or micro-batching
- Standard: longer but bounded timeout
- Low-volume region: scheduled time-window batching
- High-volume region: size-based batching
- Urgent mixed batches: allowed when carrier and routing rules permit

Do not require all planned batch members to finish before releasing ready orders. Maintain a rolling pool based on actual readiness and predicted near-term completions.

#### Data use

- Region-specific arrival distributions
- Historical batch-fill curves
- Carrier cutoffs and route capacity
- Predicted upstream completion times
- SLA risk and penalty cost
- Consolidation benefit by incremental order

The release decision can minimize:

\[
\text{Expected transport cost}
+\text{lateness penalty}
+\text{waiting cost}
\]

#### Expected outcomes

- Reduced label-ready-to-release time
- Fewer batch-related SLA breaches
- Faster handling of low-volume regions and express orders
- Preservation of most consolidation benefits
- Less sensitivity to upstream cold/hazardous variability

---

### Strategy 3: Reduce harmful preemption through protected capacity and safe interruption points

#### Constraints addressed

- Express-priority disruption
- Cold-packing queue inflation
- Throughput losses from restart/setup

#### Proposed changes

Adopt a hybrid priority policy:

- Keep a small amount of flexible capacity for express demand during predicted peaks.
- If no express work is waiting, use it for short standard jobs.
- Preempt only at documented safe checkpoints.
- Do not preempt when remaining standard processing time is below a threshold.
- Use aging to raise long-waiting standard orders’ priority.
- Limit the number of consecutive express jobs when standard queues exceed thresholds.
- Route express work to the station with the lowest expected disruption, not merely the first available one.

For cold packing, one of the five stations could be configured as flexible priority capacity during high-risk intervals, but only if simulation demonstrates that this does not materially reduce standard throughput.

#### Data use

- Express arrival forecasts
- Remaining-processing-time estimates
- Historical restart and setup losses
- Queue age and SLA risk
- Demand by station capability

#### Expected outcomes

- Lower express response time without uncontrolled standard-order delay
- Fewer suspensions and restarts
- More predictable station throughput
- Reduced standard P95/P99 cycle time
- Lower priority-induced queue instability

---

### Strategy 4: Hazardous-flow admission control and downstream balancing

#### Constraints addressed

- Facility-wide hazardous concurrency cap
- Packing-to-QC blocking
- Interaction with cold orders and batches

#### Proposed changes

Implement a visible, auditable hazardous-work controller:

- Ten electronic capacity tokens enforce the hard cap.
- Consider operating with a normal target of nine and using the tenth as controlled surge capacity, if economically justified.
- Admit hazardous orders based on downstream capacity, urgency, and expected duration.
- Reserve a token for an express hazardous order only for a short, defined horizon; otherwise release it.
- Prioritize completion of hazardous work already in QC when this will release a slot.
- Stagger hazardous starts to prevent waves.
- Use a dedicated staging area before regulated activities that does not count toward the legal limit, if regulations permit.
- Align staffing and QC coverage with hazardous arrival forecasts.

#### Data use

- Hazardous service-time distributions
- QC rework probability
- Projected token-release times
- Arrival forecasts
- Cold-station eligibility
- SLA deadlines and regional shipping cutoffs

#### Expected outcomes

- Zero regulatory violations
- Lower hazardous admission waiting
- Better use of the ten permitted slots
- Less blocking of cold stations
- Higher hazardous throughput without increasing the legal limit
- Faster release of slots through improved QC flow

---

### Strategy 5: Targeted capacity and process redesign

#### Constraints addressed

- Persistent cold-packing bottlenecks
- QC bottlenecks that hold hazardous slots
- Batch coupling

#### Proposed changes

After optimizing scheduling, test selective investments:

- Cross-train standard stations or create modular cold-packing conversion capability.
- Add temporary cold capacity during forecast seasonal peaks.
- Cross-train staff to operate both cold and standard stations.
- Add QC staffing during hazardous peaks.
- Move non-value-adding documentation outside regulated activity intervals where legally allowed.
- Pre-generate label data before QC, but activate/print labels only after QC approval.
- Separate batch planning from label computation so orders do not wait for avoidable system work.
- Introduce a fast lane for simple, short-duration orders when it improves throughput without disadvantaging urgent complex work.

#### Data use

- Bottleneck and utilization analysis
- Queueing models
- Seasonal forecasts
- Cost per hour of delay
- Scenario simulation and return-on-investment analysis

#### Expected outcomes

- Lower peak utilization and queue growth
- Higher throughput
- Reduced hazardous-slot holding time
- Faster label generation
- Capacity expenditure focused on the true bottleneck rather than averages

## 4. Simulation and Validation

### 4.1 Model type

Build a **discrete-event simulation** or digital twin calibrated from the mined process. An agent-based layer may be added if detailed operator decisions or preemption behavior matter.

The model should represent individual orders and shared facility state, not independent case traces. Each order should carry:

- Arrival time
- Service class
- Destination
- Cold requirement
- Hazardous flag
- Processing-time distributions
- Due time/SLA
- Routing and rework probabilities

### 4.2 Required instance-spanning mechanisms

The simulation must explicitly include:

#### Resource contention

- Five cold-packing stations
- Standard stations
- Resource calendars, breaks, failures, and qualifications
- Setup/changeover times
- Queues and assignment policies
- Shared QC resources

#### Batching

- Regional batch pools
- Size, timer, cutoff, and urgency triggers
- Actual and predicted batch membership
- Carrier departure schedules
- Consolidation benefit and release cost

#### Priority and interruptions

- Express queue discipline
- Safe preemption rules
- Suspend/resume behavior
- Restart and setup losses
- Aging/fairness rules
- Reserved versus flexible capacity

#### Hazardous limit

- Global counter/token pool
- Exact legal counting rule
- Token acquisition and release
- Packing-to-QC transitions
- Suspension handling
- Blocking and staging behavior
- A hard invariant enforcing \(H(t)\leq10\)

### 4.3 Calibration and validation

Use the first portion of the log for calibration and a later period for validation. Compare simulated and observed:

- Activity-duration distributions
- Queue-time distributions
- Resource utilization
- Queue-length trajectories
- Batch sizes and formation times
- Express preemption frequency
- Hazardous-concurrency distribution
- End-to-end throughput and SLA attainment

Validate not only means but P50/P90/P95 values, time-of-day patterns, seasonal peaks, and correlations between congestion states.

### 4.4 Scenarios and experiments

Test:

1. Current policy baseline
2. Each strategy individually
3. Combined strategies
4. Peak-season demand
5. Express-demand surge
6. High cold-order mix
7. High hazardous-order mix
8. Station downtime or staff absence
9. Low-volume regional batches
10. Extreme but plausible joint stress scenarios

Use multiple replications with confidence intervals. Warm-up periods and full seasonal horizons should prevent transient bias.

### 4.5 Evaluation criteria

Primary KPIs:

- Mean and P90/P95 end-to-end cycle time
- Orders shipped per hour/day
- SLA attainment by order type
- Cold-packing queue time
- Batch-wait time
- Standard delay attributable to priority handling
- Hazardous throughput and admission wait
- Zero hazardous-limit violations
- Labor and station utilization
- Shipping/consolidation cost
- Overtime and investment cost

Multi-objective analysis should expose trade-offs rather than declare a winner based on a single average. A strategy should be accepted only if compliance is guaranteed and service improvements are robust across peak scenarios.

A pilot can then be run on one shift, region, or station group using a controlled before/after or stepped-wedge design.

## 5. Monitoring Post-Implementation

### 5.1 Executive flow dashboard

Monitor:

- Order arrival rate and completion rate
- Work in process
- End-to-end cycle time: median, P90, and P95
- SLA attainment by express/standard, region, cold, and hazardous status
- Throughput per shift
- Backlog age
- Cost per fulfilled order
- Variant frequency and rework

Use statistical process-control limits and compare against demand-adjusted baselines, not just the prior week.

### 5.2 Cold-packing dashboard

Show in near real time:

- Number of ready cold orders
- Queue length and oldest waiting age
- Queue time percentiles
- Utilization by station
- Station downtime
- Express and hazardous composition of queue
- Estimated time to next station availability
- Percentage of delay with all eligible stations occupied
- Starvation and preemption indicators

Alerts should trigger for prolonged queue growth, high P95 waiting, or excessive priority displacement.

### 5.3 Batch-performance dashboard

Track by region and service class:

- Open batches and current size
- Age of oldest member
- Predicted next-arrival time
- Time to carrier cutoff
- Average and P95 formation time
- Label-ready-to-release delay
- Release trigger used
- Batch fill rate
- Express orders at SLA risk
- Transportation saving versus delay cost

This directly reveals whether dynamic batching is reducing waiting without destroying consolidation economics.

### 5.4 Priority dashboard

Monitor:

- Express SLA attainment
- Standard queue and cycle-time impact
- Preemption and resume counts
- Average suspension duration
- Restart/setup loss
- Number of consecutive express jobs
- Standard starvation incidents
- Priority inversions
- Utilization of reserved/flexible capacity

A policy is not successful merely because express performance improves; the dashboard must show the net facility effect.

### 5.5 Hazardous-compliance dashboard

Provide an auditable real-time view of:

- Current hazardous count in Packing and QC
- Token holder/order IDs
- Time spent at counts 8, 9, and 10
- Maximum concurrency
- Blocked hazardous queue
- Oldest blocked order
- Projected token-release times
- Hazardous Packing and QC durations
- Violations or near misses
- Token leaks caused by missing completion events
- Hazardous throughput and SLA performance

Any count above 10 must create an immediate compliance alert and incident record. Long occupancy at 10 should create an operational warning even without a violation.

### 5.6 Process-mining and conformance dashboard

Apply continuous conformance checking for:

- Cold orders packed only at eligible stations
- No overlapping use of one physical resource
- Batch release rules followed
- Express preemption only at approved points
- Hazardous count never exceeding 10
- Tokens acquired and released correctly
- Required QC sequence completed before label activation
- Unexpected loops, rework, or skipped steps

Object-centric views should allow analysts to move between:

- Order flow
- Station utilization
- Batch evolution
- Hazardous-capacity state
- Resource timeline

### 5.7 Closed-loop improvement

Review performance at several cadences:

- **Real time:** compliance, queue, and cutoff alerts
- **Daily:** flow, staffing, batch, and priority exceptions
- **Weekly:** root-cause and policy-threshold review
- **Monthly/seasonal:** model recalibration and capacity planning

Compare actual results with the simulation’s predicted ranges. If demand mix, service times, or routing patterns drift, retrain forecasts and retune scheduling and batch thresholds. This creates a continuous cycle of process discovery, conformance checking, simulation, implementation, and monitoring rather than a one-time optimization effort.
