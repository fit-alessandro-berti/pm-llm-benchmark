## 1. Issues with the current model

The main problem is this part of the model:

```python
parallel_block = ProcessTree(operator=Operator.PARALLEL, children=[
    create_po,
    receive_goods,
    receive_invoice,
    match_invoice,
    pay_invoice
])
```

`Operator.PARALLEL` means:

> All children must be executed, but they can be executed in any order.

So the current model allows unwanted behavior such as:

- `Pay_Invoice` before `Create_Purchase_Order`
- `Pay_Invoice` before `Receive_Goods`
- `Pay_Invoice` before `Match_Invoice_to_PO`
- `Receive_Invoice` before `Create_Purchase_Order`
- `Match_Invoice_to_PO` before `Receive_Invoice`
- `Receive_Goods` before `Create_Purchase_Order`

In the simplified standard Procure-to-Pay flow, these activities should **not** be parallel. They should occur in the exact intended order:

1. Create Purchase Requisition  
2. Approve Purchase Requisition  
3. Create Purchase Order  
4. Receive Goods  
5. Receive Invoice  
6. Match Invoice to PO  
7. Pay Invoice  
8. Close Case

```python
from pm4py.objects.process_tree.obj import Operator, ProcessTree

# Define activities
create_req = ProcessTree(label="Create_Purchase_Requisition")
approve_req = ProcessTree(label="Approve_Purchase_Requisition")
create_po = ProcessTree(label="Create_Purchase_Order")
```

## 3. Why this fixed model prevents unwanted behavior

The corrected model uses only a `SEQUENCE` operator at the root.

A `SEQUENCE` means:

> The first child must finish before the second child starts, and so on.

So the model now accepts only the single intended happy-path trace:

```text
Create_Purchase_Requisition
 Approve_Purchase_Requisition
 Create_Purchase_Order
 Receive_Goods
 Receive_Invoice
 Match_Invoice_to_PO
 Pay_Invoice
 Close_Case
```

It rejects:

- paying before matching,
- matching before receiving the invoice,
- receiving goods before creating a PO,
- receiving an invoice before creating a PO,
- closing the case before payment,
- any parallel / out-of-order behavior.

No `AND`, `XOR`, or loop is needed here, because the simplified standard process contains exactly one mandatory path through all eight activities.
