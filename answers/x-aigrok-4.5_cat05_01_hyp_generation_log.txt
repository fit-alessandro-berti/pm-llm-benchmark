**Anomalies and Undesirable Behaviors Identified**

Comparing against the assumed normal happy path (Register Order  Perform Credit Check  Validate Stock  Confirm Shipment  Ship Goods  Issue Invoice  Receive Payment), the event log shows multiple conformance issues. Case 1001 is fully compliant (correct sequence and complete). The others have clear deviations:

Credit Check and Validate Stock happen only after goods are already shipped. This is a critical sequence violation (shipping without credit approval or stock validation). Also has an early Confirmation (attempted_early=Y in additional_info).

- **Case 1003**:  
  Ship Goods occurs right after Credit Check, **skipping Validate Stock entirely** and performing Confirm Shipment only **after** Ship Goods *and* Issue Invoice. Confirm Shipment appears late (late_confirmation=Y). Missing stock validation + inverted Confirm/Ship order is a serious logistics and compliance breach.

- **Case 1004** (highest value 3000):  
  Receive Payment occurs almost immediately after Register Order (and **before** Issue Invoice). Confirm Shipment and Ship Goods happen later. Completely **missing** Perform Credit Check and Validate Stock. Payment-before-invoice + missing credit/stock controls is highly undesirable (inventory risk, credit risk, potential accounting/compliance issue). shipment_scheduled=N appears, yet goods were still shipped.

**Common undesirable patterns across cases**:
- Shipping without prior Credit Check (1002, 1003, 1004).
- Shipping without (or after) Validate Stock (all three deviant cases; completely absent in 1003/1004).
- Confirm Shipment out of expected position (before stock/credit or after actual ship/invoice).
- Invoice/Payment order inversion and premature payment (1004).
- Incomplete process executions relative to the normal flow.
- Additional_info flags hinting at awareness of the deviation (attempted_early, late_confirmation, shipment_scheduled=N).
- No obvious duplicate/redundant activities or loops, but clear activity skipping and reordering.

These directly risk financial loss (unapproved credit, out-of-stock shipping costs, inventory write-offs), compliance failures, audit findings, and customer/inventory issues.

**Hypotheses for Why These Occur**

1. **System / Workflow Engine Issues**: Incomplete process automation or missing mandatory gates (e.g., no hard stop preventing “Ship Goods” without previous Credit Check + Validate Stock completion). Race conditions, incomplete cases being force-closed, or a buggy orchestration layer allowing activity reordering. UI/system that does not enforce sequence (users can pick any next activity).

2. **Policy Violations / Pressure & Incentive Misalignment**: Staff deliberately skipping controls for speed (especially visible on the priority order 1002 and high-value 1004). Sales or logistics KPIs emphasizing “ship fast / receive payment” over compliance. “Ship first, check later” culture.

3. **Training / Awareness Gaps**: Resources (especially Warehouse/Logistics) not understanding mandatory order of activities or how to use the system correctly. New staff or temporary workers unaware of the full process model. Role/responsibility confusion (e.g., logistics staff initiating Confirm/Ship too early).

4. **Manual Overrides / Exceptions Process Abuse**: Legitimate-looking exceptions (priority handling, prepayment customers, “customer already paid”) being over-used without proper authorization or without still executing the skipped steps later as remediation. additional_info flags suggest people are consciously marking early/late actions.

5. **Data / Integration Problems**: Events from different source systems arriving out of order or being logged with wrong timestamps/resources. Missing events (Validate Stock never generated due to upstream failure). Partial case logging (incomplete traces).

6. **Fraud / Collusion Indicators (lower probability but worth checking)**: Shipping high-value goods without credit check + early payment receipt could mask unauthorized shipments or collusion (though data is limited).

7. **Process Design Flaws**: The “normal” model may be incomplete (e.g., no explicit exception paths for prepayment or urgent/priority orders). Resources table roles exist but the process may not be role-enforced.

**Proposed SQL Queries for Further Investigation**  
(These are self-contained explorative queries on the given schema; run them yourself to quantify, filter, and validate the hypotheses. Adjust thresholds/dates as needed. All use PostgreSQL syntax.)

```sql
-- 1. Identify cases missing critical activities (Credit Check or Validate Stock)
SELECT case_id,
       COUNT(*) FILTER (WHERE activity = 'Perform Credit Check') AS credit_checks,
       COUNT(*) FILTER (WHERE activity = 'Validate Stock') AS stock_validations,
       COUNT(*) FILTER (WHERE activity = 'Ship Goods') AS ships,
       COUNT(*) FILTER (WHERE activity = 'Receive Payment') AS payments
FROM order_event_log
GROUP BY case_id
HAVING COUNT(*) FILTER (WHERE activity = 'Perform Credit Check') = 0
    OR COUNT(*) FILTER (WHERE activity = 'Validate Stock') = 0
ORDER BY case_id;
```

```sql
-- 2. Detect sequence violations: Ship Goods occurring before Perform Credit Check
WITH ordered AS (
  SELECT case_id, activity, timestamp,
         ROW_NUMBER() OVER (PARTITION BY case_id ORDER BY timestamp, event_id) AS rn
  FROM order_event_log
)
SELECT a.case_id,
       a.timestamp AS ship_time,
       b.timestamp AS credit_time,
       a.resource AS ship_resource,
       b.resource AS credit_resource
FROM ordered a
JOIN ordered b ON a.case_id = b.case_id
WHERE a.activity = 'Ship Goods'
  AND b.activity = 'Perform Credit Check'
  AND a.timestamp < b.timestamp
ORDER BY a.case_id;
```

```sql
-- 3. Detect Confirm Shipment before Validate Stock / after Ship Goods, and Payment before Invoice
WITH ordered AS (
  SELECT case_id, activity, timestamp, resource, additional_info,
         LEAD(activity) OVER (PARTITION BY case_id ORDER BY timestamp, event_id) AS next_activity,
         LAG(activity) OVER (PARTITION BY case_id ORDER BY timestamp, event_id) AS prev_activity
  FROM order_event_log
)
SELECT case_id, activity, timestamp, resource, additional_info, prev_activity, next_activity
FROM ordered
WHERE (activity = 'Confirm Shipment' AND prev_activity IN ('Register Order', 'Ship Goods', 'Issue Invoice'))
   OR (activity = 'Ship Goods' AND prev_activity NOT IN ('Confirm Shipment', 'Validate Stock'))
   OR (activity = 'Receive Payment' AND prev_activity = 'Register Order')
   OR (activity = 'Issue Invoice' AND next_activity IS NULL)  -- incomplete invoice chains etc.
ORDER BY case_id, timestamp;
```

```sql
-- 4. Resource / role analysis: who performs the deviant activities? (join to resources)
SELECT oel.case_id, oel.activity, oel.resource, r.role, r.department, oel.timestamp, oel.additional_info
FROM order_event_log oel
LEFT JOIN resources r ON oel.resource = r.resource_id
WHERE oel.activity IN ('Ship Goods', 'Confirm Shipment', 'Receive Payment')
  AND oel.case_id IN (1002, 1003, 1004)   -- or expand to all cases later
ORDER BY oel.case_id, oel.timestamp;
```

```sql
-- 5. Join to orders and look for correlation with order_type / order_value (priority/high-value more deviant?)
SELECT o.case_id, o.order_type, o.order_value,
       COUNT(*) FILTER (WHERE e.activity = 'Perform Credit Check') AS has_credit,
       COUNT(*) FILTER (WHERE e.activity = 'Validate Stock') AS has_stock,
       MIN(e.timestamp) FILTER (WHERE e.activity = 'Ship Goods') AS first_ship,
       MIN(e.timestamp) FILTER (WHERE e.activity = 'Receive Payment') AS first_payment,
       MIN(e.timestamp) FILTER (WHERE e.activity = 'Register Order') AS reg_time
FROM orders o
JOIN order_event_log e ON o.case_id = e.case_id
GROUP BY o.case_id, o.order_type, o.order_value
HAVING COUNT(*) FILTER (WHERE e.activity = 'Perform Credit Check') = 0
    OR MIN(e.timestamp) FILTER (WHERE e.activity = 'Ship Goods') 
       < MIN(e.timestamp) FILTER (WHERE e.activity = 'Perform Credit Check')
ORDER BY o.order_value DESC;
```

```sql
-- 6. Timeline / duration overview + flag early confirmation / late confirmation via additional_info
SELECT case_id,
       activity,
       timestamp,
       resource,
       additional_info,
       timestamp - LAG(timestamp) OVER (PARTITION BY case_id ORDER BY timestamp) AS delta_from_prev
FROM order_event_log
WHERE additional_info ILIKE '%early%' 
   OR additional_info ILIKE '%late%'
   OR additional_info ILIKE '%scheduled=N%'
   OR case_id IN (SELECT case_id FROM order_event_log GROUP BY case_id HAVING COUNT(DISTINCT activity) < 6)
ORDER BY case_id, timestamp;
```

```sql
-- 7. Cases with payment before invoice (or payment with missing prior activities)
WITH events AS (
  SELECT case_id,
         MIN(timestamp) FILTER (WHERE activity = 'Receive Payment') AS pay_ts,
         MIN(timestamp) FILTER (WHERE activity = 'Issue Invoice') AS inv_ts,
         BOOL_OR(activity = 'Perform Credit Check') AS has_credit,
         BOOL_OR(activity = 'Validate Stock') AS has_stock
  FROM order_event_log
  GROUP BY case_id
)
SELECT e.*, o.order_type, o.order_value
FROM events e
JOIN orders o ON e.case_id = o.case_id
WHERE pay_ts < inv_ts OR NOT has_credit OR NOT has_stock
ORDER BY o.order_value DESC;
```
