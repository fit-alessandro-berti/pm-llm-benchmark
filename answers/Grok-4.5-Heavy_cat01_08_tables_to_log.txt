**Event Log for Process Mining**

**Assumptions and design decisions** (documented for transparency):
- **Case ID** = `order_id` for every event (process instance = order lifecycle).
- **Activity names** derived directly from data and prompt guidance: *Order Created*, *Item Picked* (one event per order line to preserve individual picker, time, and item detail), *Delivery Dispatched*, *Delivery Arrived* (separate events per delivery record to support multi-shipment cases), *Invoice Issued*, *Payment Received*.
- **Resource** column uses human-readable names from the Resources table (fallback to blank when no actor is present, e.g., payments). Original IDs are retained inside Attributes for traceability.
- **Attributes** column is a compact semicolon-separated key=value list containing all relevant source fields plus enrichments (item_description + item_category from Products table; customer details, notes, etc.).
- No synthetic events, amounts, or timestamps were invented. Incomplete cases (especially order 1004, which has only order creation + picking) are left as-is.
- Payments are linked to the correct case via `invoice_id → order_id`.
- Final ordering: Case ID ascending, then Timestamp ascending within each case (guarantees chronological process flow).
