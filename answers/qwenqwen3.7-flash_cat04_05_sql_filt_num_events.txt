Here's a clean, performant DuckDB SQL query that fulfills your requirements:

```sql
WITH valid_cases AS (
    SELECT case_id
    FROM event_log
    GROUP BY case_id
    HAVING COUNT(*) <= 6
)
SELECT e.*
FROM event_log e
INNER JOIN valid_cases vc ON e.case_id = vc.case_id
ORDER BY e.case_id, e.timestamp;
```

###  How it works:
1. **`valid_cases` CTE**: Groups the table by `case_id` and uses `HAVING COUNT(*) <= 6` to filter out any cases that exceed six events. Only the qualifying `case_id`s are kept.
2. **`INNER JOIN`**: Joins the original `event_log` back to the filtered list of valid cases, ensuring only events belonging to those cases are returned.
3. **`ORDER BY`**: Adds deterministic sorting (by case and timestamp), which is helpful for process mining/event log analysis. Remove it if order doesn't matter.
4. **`e.*`**: Returns all columns from the original table. You can replace it with specific column names (e.g., `e.case_id, e.activity, e.timestamp`) if you prefer explicit projection.

###  DuckDB-Specific Alternative (Using `QUALIFY`)
If you prefer a more concise, window-function-native approach that leverages DuckDB's optimization engine:
```sql
SELECT *
FROM event_log
QUALIFY COUNT(*) OVER(PARTITION BY case_id) <= 6
ORDER BY case_id, timestamp;
```
Both queries are fully compatible with DuckDB and will perform efficiently on typical event log sizes. Choose the one that best fits your team's style guide or query complexity preferences.
