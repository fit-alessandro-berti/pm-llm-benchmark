Below is a normative DECLARE model for a single-pass product launch. It assumes:

- Each activity occurs exactly once.
- Idea Generation starts the process.
- Technical Feasibility Check and Cost Evaluation may occur in either order.
- Laboratory Testing and User Testing may occur in either order.
- Approval Gate is followed immediately by Marketing Plan, which is followed immediately by Final Launch.
- Values are represented as `[support, confidence]`.

```python
declare_model = {
    "existence": {
        "Idea Generation": [1.0, 1.0],
        "Design Draft": [1.0, 1.0],
        "Technical Feasibility Check": [1.0, 1.0],
        "Cost Evaluation": [1.0, 1.0],
        "Prototype Creation": [1.0, 1.0],
        "Laboratory Testing": [1.0, 1.0],
        "User Testing": [1.0, 1.0],
        "Approval Gate": [1.0, 1.0],
        "Marketing Plan": [1.0, 1.0],
        "Final Launch": [1.0, 1.0],
    },

    "absence": {},

    "exactly_one": {
        "Idea Generation": [1.0, 1.0],
        "Design Draft": [1.0, 1.0],
        "Technical Feasibility Check": [1.0, 1.0],
        "Cost Evaluation": [1.0, 1.0],
        "Prototype Creation": [1.0, 1.0],
        "Laboratory Testing": [1.0, 1.0],
        "User Testing": [1.0, 1.0],
        "Approval Gate": [1.0, 1.0],
        "Marketing Plan": [1.0, 1.0],
        "Final Launch": [1.0, 1.0],
    },

    "init": {
        "Idea Generation": [1.0, 1.0],
    },

    "responded_existence": {},

    "coexistence": {},

    # These are implied by the succession constraints below.
    "response": {},

    # These are implied by the succession constraints below.
    "precedence": {},

    # succession(A, B): A must eventually be followed by B,
    # and B must be preceded by A.
    "succession": {
        # Both feasibility activities follow the design.
        ("Design Draft", "Technical Feasibility Check"): [1.0, 1.0],
        ("Design Draft", "Cost Evaluation"): [1.0, 1.0],

        # Both feasibility activities must complete before prototyping.
        ("Technical Feasibility Check", "Prototype Creation"): [1.0, 1.0],
        ("Cost Evaluation", "Prototype Creation"): [1.0, 1.0],

        # Both types of testing follow prototype creation.
        ("Prototype Creation", "Laboratory Testing"): [1.0, 1.0],
        ("Prototype Creation", "User Testing"): [1.0, 1.0],

        # Both types of testing must complete before approval.
        ("Laboratory Testing", "Approval Gate"): [1.0, 1.0],
        ("User Testing", "Approval Gate"): [1.0, 1.0],
    },

    "altresponse": {},
    "altprecedence": {},
    "altsuccession": {},

    # These are implied by the chainsuccession constraints below.
    "chainresponse": {},
    "chainprecedence": {},

    # chainsuccession(A, B): B immediately follows A.
    "chainsuccession": {
        ("Idea Generation", "Design Draft"): [1.0, 1.0],
        ("Approval Gate", "Marketing Plan"): [1.0, 1.0],
        ("Marketing Plan", "Final Launch"): [1.0, 1.0],
    },

    "noncoexistence": {},
    "nonsuccession": {},
    "nonchainsuccession": {},
}
```

This allows four main milestone orderings because the two feasibility activities and the two testing activities can each be interleaved. If rework or repeated testing should be allowed, the `exactly_one` constraints should be removed and alternating constraints such as `altresponse`, `altprecedence`, or `altsuccession` should be used where appropriate.
