### Rationale behind the design

| Constraint type | Interpretation in this process |
|---|---|
| `existence` | Every product journey must contain idea generation, design, prototype, approval, and launch. |
| `absence` | User/Lab testing may be skipped for low-risk products. |
| `exactly_one` | Core governance steps (Idea Gen, Design, Approval, Launch) happen once per case. |
| `init` | Every case starts with **Idea Generation**. |
| `response` / `precedence` / `succession` | Encode the logical designbuildtestapprovemarketlaunch pipeline. |
| `chain*` | Capture tight, immediate sequencing (e.g., Marketing Plan directly followed by Final Launch). |
| `alt*` | Allow for repeated iterations (e.g., multiple approval attempts) while preserving ordering. |
| `noncoexistence` / `nonsuccession` / `nonchainsuccession` | Prevent illogical patterns, such as Final Launch preceding Idea Generation. |

This structure mirrors what `pm4py.discovery.discover_declare()` would typically output when mining a real event log of such a process, with `support` fixed at `1.0` (all constraints apply to the full log) and varying `confidence` values reflecting how strictly each rule holds across process instances.
