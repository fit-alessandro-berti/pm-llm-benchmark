### 1. Identifying Instance-Spanning Constraints and Their Impact

Traditional process mining focuses on single-instance lifecycles (e.g., tracking Order A from start to finish). To analyze **instance-spanning constraints** (inter-case dependencies), we must construct a **state-aware event log** and leverage Object-Centric Process Mining (OCPM) or queueing/resource-centric process analysis.

```
+-----------------------------------------------------------------------------------+
|                        INTRA-CASE VS. INTER-CASE DELAYS                           |
+-----------------------------------------------------------------------------------+
| INTRA-CASE: [Item Picking] -------------> [Packing Activity]                      |
|             (Time to walk between stations or internal processing time)           |
|                                                                                   |
| INTER-CASE: [Item Picking] ---> [ QUEUE / BLOCKED ] ---> [Packing Activity]       |
|                                   |                                               |
|                                   +---> Waiting for Cold Station (5 max)          |
|                                   +---> Waiting for Batch (Region = North)        |
|                                   +---> Hazardous Cap Reached (10 max active)     |
|                                   +---> Express Order Preempted Resource          |
+-----------------------------------------------------------------------------------+
```

#### Differentiating Intra-Case vs. Inter-Case Waiting Time
To isolate delays, we analyze the transition between consecutive activities $A_1$ (e.g., *Item Picking*) and $A_2$ (e.g., *Packing*):
*   **Execution Time (Intra-Case):** $T_{\text{complete}}(A_1) - T_{\text{start}}(A_1)$
*   **Total Inter-Activity Delay:** $T_{\text{start}}(A_2) - T_{\text{complete}}(A_1)$
*   **Intra-Case Waiting Time:** Natural transit/buffer time when the required resource for $A_2$ is available, but the item is in transit.
*   **Inter-Case (Instance-Spanning) Delay:** Delay caused because the required resource for $A_2$ is locked by another case, or a global/system-level condition is blocking entry.

#### Identification Methodologies & Metrics by Constraint

| Constraint Type | Process Mining Detection Methodology | Primary Quantification Metric |
| :--- | :--- | :--- |
| **1. Shared Cold-Packing Stations** | Track concurrent executions of `Packing` where `Resource ID` belongs to Cold Stations (C1–C5). Measure queue duration after `Item Picking COMPLETE` when active Cold Pack count $= 5$. | **Cold Station Blockade Time:** $T_{\text{wait\_cold}} = T_{\text{start}}(\text{Packing}) - T_{\text{complete}}(\text{Picking})$ while Active Cold Resources $= 5$. |
| **2. Shipping Batches** | Calculate delay between `Quality Check COMPLETE` and `Shipping Label Gen. START/COMPLETE`. Group by `Destination Region` and correlate timestamp jumps across multiple cases sharing a `Batch ID`. | **Batch Holding Dwell Time:** Time an individual case sits in completed state waiting for the batch threshold/timer trigger. |
| **3. Express Priority Preemption** | Identify instances where a `Standard` order’s `Packing` activity has an abnormally long duration or an explicit `PAUSE` lifecycle event corresponding to the `START` of an `Express` order on the same station. | **Preemption Overhead:** Delta in cycle time for Standard orders interrupted by Express orders: $\Delta T = T_{\text{elapsed}}(\text{Standard}) - T_{\text{baseline}}(\text{Standard})$. |
| **4. Hazardous Material Limits** | Calculate global concurrency counter $N_{\text{haz}}(t)$ across `Packing` and `Quality Check` activities. Calculate delay for hazardous cases at $N_{\text{haz}}(t) = 10$. | **Regulatory Queue Time:** Time spent waiting in queue while system state $N_{\text{haz}}(t) = 10$. |

### 2. Analyzing Constraint Interactions

Instance-spanning constraints rarely operate in isolation. When multiple inter-case constraints collide, they create exponential queueing delays and performance degradation.

```
                      +----------------------------------+
                      |   Express Order (Cold + Haz)     |
                      +----------------------------------+
                                       |
                   +-------------------+-------------------+
                   |                                       |
                   v                                       v
     [Preempts Cold Station C1]                 [Occupies Haz Slot (1/10)]
                   |                                       |
                   v                                       v
    Standard Cold Orders Delayed             Standard Haz Orders Held Up
                   |                                       |
                   +-------------------+-------------------+
                                       |
                                       v
                       [Regional Batch Blocked]
               (Batch cannot dispatch until trailing
                standard/haz items complete QC)
```

#### Key Constraint Interactions

1.  **Priority Preemption $\times$ Shared Cold Stations:**
    When an Express order requiring cold-packing arrives, it preempts a Standard order currently occupying one of the 5 Cold Stations. 
    *   *Impact:* The preempted Standard order's packing cycle is interrupted, increasing its station hold time. This creates a cascade effect, causing secondary queues for subsequent non-express cold orders.

2.  **Hazardous Limits $\times$ Regional Batching:**
    A regional batch requires all constituent orders to reach `Quality Check COMPLETE` before `Shipping Label Generation` can trigger the batch release. If 2 out of 20 orders in a "North Region" batch contain hazardous materials, and the facility has reached its max limit of 10 active hazardous orders, those 2 orders are blocked upstream.
    *   *Impact:* The remaining 18 non-hazardous orders—even though fully processed—sit idle waiting for the 2 hazardous orders to clear the bottleneck. The regional batch delay is governed by the slowest hazardous order.

3.  **Express Preemption $\times$ Hazardous Limits $\times$ Batching Cascades:**
    An Express Hazardous order enters the system, forcing its way into the Hazardous processing pool. This pushes a Standard Hazardous order out of the current processing window. If that Standard Hazardous order is the final dependency for an outbound regional truck load, an entire batch of 50+ orders misses its shipment cutoff time.

#### Strategic Relevance of Interaction Analysis
Optimizing individual constraints in silos (e.g., simply speeding up picking for Express orders) will shift bottlenecks downstream or amplify constraints elsewhere (e.g., breaching hazardous limits faster). Optimization must be **state-aware** and evaluate system-wide ripple effects.

### 3. Constraint-Aware Optimization Strategies

```
+-----------------------------------------------------------------------------------+
|                        PROPOSED OPTIMIZATION ARCHITECTURE                         |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [Incoming Orders]                                                                |
|         |                                                                         |
|         v                                                                         |
|  +-----------------------------------------------------------------------------+  |
|  | STRATEGY 3: Hazardous Limit Engine (Predictive Token Allocation <= 10)     |  |
|  +-----------------------------------------------------------------------------+  |
|         |                                                                         |
|         v                                                                         |
|  +-----------------------------------------------------------------------------+  |
|  | STRATEGY 1: Dynamic Cold-Packing Allocation (Soft Reservation for Express) |  |
|  +-----------------------------------------------------------------------------+  |
|         |                                                                         |
|         v                                                                         |
|  +-----------------------------------------------------------------------------+  |
|  | STRATEGY 2: Adaptive Regional Batching (Dynamic Timeouts & Dynamic Cutoffs) |  |
|  +-----------------------------------------------------------------------------+  |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

#### Strategy 1: Predictive Soft-Reservation for Cold Packing
*   **Target Constraint:** Shared Cold-Packing Stations & Priority Preemption.
*   **Proposed Changes:** Implement a dynamic resource-reservation algorithm. Instead of hard-preempting a Standard order mid-pack (which wastes labor and packaging), the Warehouse Management System (WMS) uses predictive picking times to create a "soft reservation" on Station C5 10 minutes before an Express Cold order finishes picking. Standard orders are non-preemptible once packing begins, but new Standard orders are routed to standard stations or held briefly in picking until C1–C4 clear.
*   **Data/Analytics Leverage:** Uses historical transit times between `Picking START` and `Packing START` to predict Express arrivals at packing stations with $>90\%$ accuracy.
*   **Expected Outcomes:** Eliminates mid-activity packing interruptions (reducing standard packing cycle times by 15%), lowers Express cold-pack queue times by 40%, and stabilizes throughput.

#### Strategy 2: Adaptive Dynamic Regional Batching
*   **Target Constraint:** Batching for Shipping & Hazardous Limits.
*   **Proposed Changes:** Replace static batch sizes (e.g., "Wait for 30 orders per region") with adaptive dynamic triggers. The system triggers batch completion based on a composite function:
    $$\text{Trigger} = f(\text{Carrier Departure Time}, \text{Current Batch Volume}, \text{Upstream Haz Blockades})$$
    If a regional batch is at 80% capacity and its remaining orders are blocked by Hazardous processing limits, the system dynamically "splits" the batch, releasing the ready orders for label generation and rolling the trailing hazardous orders into an express shuttle or subsequent batch.
*   **Data/Analytics Leverage:** Historical order velocity patterns per region and carrier SLA deadlines extracted from event logs.
*   **Expected Outcomes:** Reduces post-QC holding time by 50% for non-hazardous items in mixed batches; reduces missed carrier cutoff deadlines to $<1\%$.

#### Strategy 3: Upstream Hazardous Token-Bucket Engine
*   **Target Constraint:** Regulatory Hazardous Material Limits (Max 10 active).
*   **Proposed Changes:** Implement a global "token bucket" (max 10 tokens) regulating entry into the combined `Packing` + `Quality Check` zone. Orders requiring hazardous handling must acquire a token *before* entering `Item Picking`. If no tokens are available, the order remains in `Order Received` state, preventing physical clutter and queueing on the warehouse floor. Express Hazardous orders bypass standard hazardous orders in the token queue.
*   **Data/Analytics Leverage:** Process mining duration logs for `Packing` + `QC` on hazardous items to dynamically compute average Token Hold Time ($\mu_{th}$) and adjust token issuance rates.
*   **Expected Outcomes:** 100% compliance with regulatory safety limits; reduces floor congestion and physical queueing times at packing/QC by 65%.

### 4. Simulation and Validation

Before live deployment, proposed changes must be validated using a **State-Aware Discrete Event Simulation (DES)** built on parameters derived directly from process mining logs.

```
+-----------------------------------------------------------------------------------+
|                           DES SIMULATION MODEL ARCHITECTURE                       |
+-----------------------------------------------------------------------------------+
|  [Event Log] ---> [Extract Distributions] ---> [DES Model with Global Variables]  |
|                                                       |                           |
|      +------------------------------------------------+                           |
|      |                                                                            |
|      v                                                                            |
|  [Global State Counters]                                                          |
|  * Haz_Active_Count <= 10                                                         |
|  * Cold_Station_Occupancy (1..5)                                                  |
|  * Region_Batch_Buffers [North, South, East, West]                                |
|                                                                                   |
|      |                                                                            |
|      v                                                                            |
|  [Scenario Testing Engine]                                                        |
|  * Baseline Log Replay                                                            |
|  * Strategy 1 + 2 + 3 Applied                                                     |
|                                                                                   |
|      |                                                                            |
|      v                                                                            |
|  [Validation Metrics]                                                             |
|  * On-Time In-Full (OTIF) % | Peak Bottleneck Shift | SLA Breach Rates            |
+-----------------------------------------------------------------------------------+
```

#### Simulation Modeling Requirements
To model instance-spanning constraints accurately, the DES architecture must move beyond standard independent-case simulation:

1.  **Global System Counters (State Variables):**
    *   `Haz_Active_Count` (Integer: 0 to 10): Dynamically incremented at `Packing START` for hazardous items; decremented at `Quality Check COMPLETE`.
    *   `Cold_Station_Pool` (Resource Array of size 5): Tracks specific station assignment and express reservation status.

2.  **Entity Aggregation & Batching Logic:**
    *   Batching nodes must group tokens (cases) by attribute (`Destination Region`). Simulation rules must enforce conditional triggers: *Release batch if Size $\ge N$ OR Time In Buffer $> T_{\text{max}}$ OR Carrier Cutoff $< T_{\text{dep}}$.*

3.  **Resource Preemption & Interruption Logic:**
    *   Define preemption rules: Express orders can interrupt Standard orders *only* during resource acquisition, or pause active Standard tokens, adding state-dependent penalty durations.

#### Validation Scenarios & KPIs
We re-play peak season arrival frequencies (e.g., Black Friday logs) through the simulation model under three configurations:

*   **Scenario A (Baseline):** Current system logic (as reflected in historical logs).
*   **Scenario B (Isolated Improvements):** Implementing Strategy 1 (Cold Pack) alone vs. Strategy 3 (Haz Bucket) alone.
*   **Scenario C (Combined Strategy Architecture):** Integrated application of Strategies 1, 2, and 3.

**Key Metrics Evaluated in Simulation:**
*   Overall End-to-End Throughput Time (P50, P95, P99).
*   On-Time In-Full (OTIF) delivery rate against customer SLAs.
*   Resource Utilization Rates (Cold Stations, QC Staff).
*   Violation Count of Hazardous Safety Cap ($N > 10$).

#### Process Mining Operational Dashboard Design

##### 1. Inter-Instance Queue & Bottleneck Heatmap
*   **Metric:** Ratio of *Inter-Case Delay* to *Total Lead Time*.
*   **Visualization:** Real-time process map where edge thickness corresponds to waiting time caused by shared resource contention or batching delays (rather than standard activity durations).

##### 2. Real-Time Regulatory Concurrency Monitor
*   **Metric:** Active Hazardous Case Count $N_{\text{haz}}(t)$.
*   **Visualization:** Live gauge chart showing current active count (0–10). Triggers an alert if $N_{\text{haz}} \ge 9$, and logs a severity-1 compliance violation if $N_{\text{haz}} > 10$.

##### 3. Batch Formation Efficiency Dashboard
*   **Metrics:** 
    *   *Average Dwell Time in Batch Buffer* per region.
    *   *Partial Batch Release Rate* (tracking how often dynamic timeouts trigger compared to size thresholds).
*   **Visualization:** Distribution histograms of time spent in `Awaiting Batch` status grouped by region and time of day.

##### 4. Preemption & Priority Impact Tracker
*   **Metrics:** 
    *   *Express On-Time Delivery %*.
    *   *Standard Order Degradation Index* ($\frac{\text{Actual Standard Cycle Time}}{\text{Uninterrupted Baseline}}$).
*   **Visualization:** Scatterplot comparing Express arrivals against Standard order queue spikes at Cold Packing.

#### Continuous Conformance Checking
Process mining engine rules continuously run in the background against live event streams to detect process anomalies:
*   **Unauthorized Routing:** Flags orders routed to non-compliant stations (e.g., attempting cold packing at standard stations during peak queues).
*   **Safety Non-Conformance:** Immediately alerts safety officers if an 11th hazardous order enters `Packing` without a valid system token.
*   **Bottleneck Drift Detection:** Automatically alerts analysts if operational improvements in Packing shift the system-wide bottleneck downstream to Quality Check or Shipping Label Generation.
