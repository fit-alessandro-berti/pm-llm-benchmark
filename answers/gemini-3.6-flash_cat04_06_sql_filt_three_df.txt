Here is the DuckDB SQL query that fulfills all your requirements:

```sql
WITH sequence_checks AS (
    SELECT
        case_id,
        activity,
        timestamp,
        -- Get the immediately preceding activity in the case
        LAG(activity, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS prev_activity,
        -- Get the immediately succeeding activity in the case
        LEAD(activity, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS next_activity,
        -- Get the timestamp of the immediately succeeding activity
        LEAD(timestamp, 1) OVER (PARTITION BY case_id ORDER BY timestamp) AS next_timestamp
    FROM event_log
),
excluded_cases AS (
    SELECT DISTINCT case_id
    FROM sequence_checks
    WHERE activity = 'Create Order'
      AND prev_activity = 'Approve Purchase Requisition'
      AND next_activity = 'Confirm Order'
      -- Elapsed time between 'Create Order' and 'Confirm Order' is more than 5 days
      AND next_timestamp - timestamp > INTERVAL '5 days'
)
SELECT *
FROM event_log
WHERE case_id NOT IN (SELECT case_id FROM excluded_cases)
ORDER BY case_id, timestamp;
```

### How It Works:
1. **`sequence_checks` CTE**: Uses window functions (`LAG` and `LEAD`) partitioned by `case_id` and ordered by `timestamp` to inspect immediately adjacent events (direct succession) without any intervening activities.
2. **`excluded_cases` CTE**: Filters for rows where the current activity is `'Create Order'`, the directly preceding activity is `'Approve Purchase Requisition'`, the directly succeeding activity is `'Confirm Order'`, and the duration between `'Create Order'` and `'Confirm Order'` strictly exceeds 5 days (`INTERVAL '5 days'`).
3. **Final Query**: Returns all events from `event_log` whose `case_id` is **not** in the excluded set, maintaining the original event log structure ordered by `case_id` and `timestamp`.
