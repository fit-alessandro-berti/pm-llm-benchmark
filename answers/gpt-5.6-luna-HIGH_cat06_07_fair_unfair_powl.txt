Below are two POWL models implemented with `pm4py`. Both include:

- Application receipt
- Questionnaire completion
- A data-completeness loop
- Skill assessment
- Managerial review
- Final decision

The models differ only in the cultural-fit stage.

```python
from pm4py.objects.powl.obj import (
    StrictPartialOrder,
    OperatorPOWL,
    Transition
)
from pm4py.objects.process_tree.obj import Operator


def ordered_process(nodes):
    """
    Construct a sequential partial order:
    nodes[0] -> nodes[1] -> ... -> nodes[n]
    """
    po = StrictPartialOrder(nodes=nodes)

    for source, target in zip(nodes, nodes[1:]):
        po.order.add_edge(source, target)

    return po
```

## 1. POWL model with potential unfairness

The XOR after `SkillAssessment` allows either:

- The normal `CulturalFitCheck`, or
- `CommunityAffiliationCheck`, where affiliation or local-resident status may produce a subjective advantage.

```python
# Activities before the skill assessment
receive_application = Transition(label="ReceiveApplication")
questionnaire = Transition(label="CompleteQuestionnaire")

# Data completeness loop:
# DataCompletenessCheck is executed first.
# If data is missing, RequestMoreInfo is executed and the check repeats.
data_completeness_check = Transition(label="DataCompletenessCheck")
request_more_info = Transition(label="RequestMoreInfo")

completeness_loop = OperatorPOWL(
    operator=Operator.LOOP,
    children=[
        data_completeness_check,
        request_more_info
    ]
)

# Main process activities
skill_assessment = Transition(label="SkillAssessment")

standard_cultural_fit = Transition(label="CulturalFitCheck")
community_affiliation_check = Transition(
    label="CommunityAffiliationCheck"
)

# XOR branch introducing the possible unfairness
cultural_fit_xor = OperatorPOWL(
    operator=Operator.XOR,
    children=[
        standard_cultural_fit,
        community_affiliation_check
    ]
)

managerial_review = Transition(label="ManagerialReview")
final_decision = Transition(label="FinalDecision")

# Root partial order
unfair_model = ordered_process([
    receive_application,
    questionnaire,
    completeness_loop,
    skill_assessment,
    cultural_fit_xor,
    managerial_review,
    final_decision
])
```

Conceptually, this model is:

```text
ReceiveApplication
    ->
CompleteQuestionnaire
    ->
*(DataCompletenessCheck, RequestMoreInfo)
    ->
SkillAssessment
    ->
X(CulturalFitCheck, CommunityAffiliationCheck)
    ->
ManagerialReview
    ->
FinalDecision
```

The potential source of unfairness is:

```text
X(CulturalFitCheck, CommunityAffiliationCheck)
```

The `CommunityAffiliationCheck` branch represents the selective path through which local affiliations or community membership may influence the evaluation.

## 2. POWL model without unfairness

In this version, every applicant undergoes the same `CulturalFitCheck`. There is no affiliation-specific XOR branch.

```python
# Activities before the skill assessment
receive_application_2 = Transition(label="ReceiveApplication")
questionnaire_2 = Transition(label="CompleteQuestionnaire")

# Data completeness loop
data_completeness_check_2 = Transition(label="DataCompletenessCheck")
request_more_info_2 = Transition(label="RequestMoreInfo")

completeness_loop_2 = OperatorPOWL(
    operator=Operator.LOOP,
    children=[
        data_completeness_check_2,
        request_more_info_2
    ]
)

# Common assessment path for all applicants
skill_assessment_2 = Transition(label="SkillAssessment")
cultural_fit_check_2 = Transition(label="CulturalFitCheck")
managerial_review_2 = Transition(label="ManagerialReview")
final_decision_2 = Transition(label="FinalDecision")

# Root partial order
fair_model = ordered_process([
    receive_application_2,
    questionnaire_2,
    completeness_loop_2,
    skill_assessment_2,
    cultural_fit_check_2,
    managerial_review_2,
    final_decision_2
])
```

Conceptually, this model is:

```text
ReceiveApplication
    ->
CompleteQuestionnaire
    ->
*(DataCompletenessCheck, RequestMoreInfo)
    ->
SkillAssessment
    ->
CulturalFitCheck
    ->
ManagerialReview
    ->
FinalDecision
```

The second model removes the potential bias by ensuring that `CommunityAffiliationCheck` is not part of the control flow and that all candidates follow the same cultural-fit evaluation path.
