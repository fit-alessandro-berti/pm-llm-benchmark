# BPMN-Like Textual Process Model: Invoice Approval

## 1. Participants and Lanes

### Internal organization
1. **Accounts Payable Clerk (AP Clerk)**
   - Receives and validates invoices
   - Logs invoices
   - Performs formal PO matching
   - Places invoices on hold
   - Coordinates exception resolution
   - Schedules approved invoices for payment

2. **Purchasing Officer / Purchasing Department**
   - Verifies the PO and ordered details
   - Confirms receipt of goods or services
   - Investigates quantity, price, and delivery-charge discrepancies
   - May contact the supplier directly

3. **Department Manager**
   - Performs final business approval
   - May approve, reject, or request investigation

4. **Accounts Payable Supervisor**
   - Handles unresolved exceptions
   - Coordinates suppliers and internal departments
   - Facilitates retrospective POs or rejection of invalid invoices
   - Does not provide final invoice approval

5. **Supplier Relationship Manager**
   - Supports exception resolution
   - Contacts key suppliers
   - Checks contractual pricing and terms
   - Does not approve invoices or update the approval system directly

6. **Department Head**
   - Assists with non-PO invoices
   - May authorize or help create a retrospective PO

7. **Accounting System**
   - Stores invoice records
   - Maintains hold and approval status
   - Sends automatic manager approval notifications
   - Stores the manager’s decision and payment schedule

### External participant
8. **Supplier**
   - Sends the original invoice
   - Provides missing PO information, clarification, or a corrected invoice

## 2. Main Process Flow

### Notation
- `(S/E)` = Start or end event
- `[T]` = Task
- `<X>` = Exclusive gateway
- `<OR>` = Inclusive gateway
- `[[SP]]` = Subprocess

```text
(S0) Message Start Event: Invoice received from supplier, usually by email
  |
  v
[T1 – AP Clerk] Check whether the invoice references a valid purchase order
  |
  v
<X1> Is a valid PO reference present?
  |
  +-- Yes -->
  |     [T2 – AP Clerk] Log the invoice in the accounting system
  |       |
  |       v
  |     [T3 – AP Clerk] Forward the invoice to Purchasing for verification
  |       |
  |       v
  |     [T4 – Purchasing] Perform purchasing verification:
  |          - Open and review the PO
  |          - Compare quantities, prices, and delivery charges
  |          - Confirm that goods or services were received
  |       |
  |       v
  |     <X2> Purchasing verification result?
  |       |
  |       +-- Confirmed -->
  |       |     [T5 – Purchasing] Send confirmation to Accounts Payable
  |       |       |
  |       |       v
  |       |     [T6 – AP Clerk] Formally match invoice line items against
  |       |          the PO and Purchasing/receipt confirmation
  |       |       |
  |       |       v
  |       |     <X3> Does the invoice match?
  |       |       |
  |       |       +-- Yes -->
  |       |       |     [T7 – Accounting System] Create manager approval
  |       |       |          work item and send automatic email notification
  |       |       |       |
  |       |       |       v
  |       |       |     [T8 – Department Manager] Review:
  |       |       |          - Invoice details
  |       |       |          - PO
  |       |       |          - Purchasing/receipt confirmation
  |       |       |          - Quantities, pricing, special notes, and
  |       |       |            relevant budget information
  |       |       |       |
  |       |       |       v
  |       |       |     <X4> Manager decision?
  |       |       |       |
  |       |       |       +-- Approve -->
  |       |       |       |     [T9 – Department Manager] Approve in system
  |       |       |       |       |
  |       |       |       |       v
  |       |       |       |     [T10 – AP Clerk] Add invoice to the next
  |       |       |       |           payment cycle
  |       |       |       |       |
  |       |       |       |       v
  |       |       |       |     (E1) End: Invoice scheduled for payment
  |       |       |       |
  |       |       |       +-- Hold / investigate -->
  |       |       |       |     [[SP1 – Resolve Invoice Exception]]
  |       |       |       |       reason = manager concern
  |       |       |       |       already logged = Yes
  |       |       |       |
  |       |       |       +-- Reject -->
  |       |       |             [T11 – System/AP] Record rejection
  |       |       |               |
  |       |       |               v
  |       |       |             (E2) End: Invoice rejected
  |       |       |
  |       |       +-- No, discrepancy -->
  |       |             [[SP1 – Resolve Invoice Exception]]
  |       |               reason = AP matching discrepancy
  |       |               already logged = Yes
  |       |
  |       +-- Missing or invalid PO -->
  |       |     [[SP1 – Resolve Invoice Exception]]
  |       |       reason = PO issue found by Purchasing
  |       |       already logged = Yes
  |       |
  |       +-- Quantity, price, receipt, or delivery discrepancy -->
  |             [[SP1 – Resolve Invoice Exception]]
  |               reason = Purchasing discrepancy
  |               already logged = Yes
  |
  +-- No -->
        [[SP1 – Resolve Invoice Exception]]
          reason = missing PO
          already logged = No
```

### Approval trigger

`T7` may occur only when both conditions are true:

1. Purchasing has confirmed receipt and the purchasing details; and  
2. Accounts Payable has completed a successful invoice-to-PO match.

## 3. Exception Resolution Subprocess

### `SP1 – Resolve Invoice Exception`

```text
(SP1-Start) Exception received
  |
  v
[R1 – AP Clerk] Place invoice on hold and record the exception reason
    - If the invoice has not yet been logged, retain it in the intake queue
      rather than creating a normal payable item.
  |
  v
<OR1> Select one or more appropriate resolution channels
  |
  +-- Missing PO or missing information -->
  |     [R2 – AP Clerk and/or Supplier Relationship Manager]
  |     Ask supplier to provide the PO number, additional details,
  |     or a revised invoice
  |
  +-- Quantity, price, delivery, receipt, or missing-item discrepancy -->
  |     [R3 – AP Clerk/Purchasing]
  |     Clarify the discrepancy; Purchasing may contact the supplier directly
  |
  +-- Contract pricing discrepancy -->
  |     [R4 – Supplier Relationship Manager]
  |     Review the supplier contract and advise AP or Purchasing of
  |     the correct terms
  |
  +-- Manager concern -->
        [R5 – AP Clerk]
        Investigate with Purchasing, the relevant department,
        and, where necessary, the supplier
  |
  v
[R6 – Relevant role] Wait for and receive clarification,
     supporting evidence, missing PO information, or a corrected invoice
  |
  v
<X5> Has the issue been resolved at the working level?
  |
  +-- Yes -->
  |     [R7 – AP Clerk] Validate the new information and update or replace
  |          the invoice record; attach supporting correspondence
  |       |
  |       v
  |     <X6> Was the invoice already logged?
  |       |
  |       +-- No --> Return to [T2] Log invoice
  |       |
  |       +-- Yes --> Return to [T3] Forward to Purchasing for
  |                   renewed confirmation
  |
  +-- No, still awaiting information -->
  |     [R8] Remain on hold and wait for supplier or departmental response
  |       |
  |       +--> Return to [R6] when information arrives
  |       +--> Escalate when AP determines the issue cannot be resolved easily
  |
  +-- No, cannot be resolved easily -->
        [R9 – AP Clerk] Escalate exception to AP Supervisor
          |
          v
        [R10 – AP Supervisor] Contact supplier and coordinate Purchasing,
              Supplier Relationship Management, and relevant departments
          |
          v
        <X7> Supervisor-level outcome?
          |
          +-- Corrected invoice, clarification, or valid PO obtained -->
          |     Return to [R7]
          |
          +-- Invoice relates to an informally contracted service
          |   with no existing PO -->
          |     [R11 – AP Supervisor + Department Head]
          |     Attempt to create a retrospective PO
          |       |
          |       v
          |     <X8> Retrospective PO created?
          |       |
          |       +-- Yes --> Return to [R7]
          |       |
          |       +-- No -->
          |             [R12] Record decision to reject invoice
          |               |
          |               v
          |             (E2) End: Invoice rejected
          |
          +-- Invoice determined to be invalid or unacceptable -->
          |     [R12] Record decision to reject invoice
          |       |
          |       v
          |     (E2) End: Invoice rejected
          |
          +-- Still pending -->
                Return to [R10] or remain on hold until information arrives
```

After any resolved exception, the canonical re-entry point is Purchasing verification at `T3/T4`, followed by AP matching and manager approval. This reflects the supervisor’s description that cleared exceptions return to the normal flow.

## 4. Data Objects and Artifacts

| ID | Data object/artifact | Created or used by |
|---|---|---|
| D1 | Original invoice | Supplier; received by AP |
| D2 | Revised/corrected invoice | Supplier; used during exception resolution |
| D3 | Purchase order, including possible retrospective PO | AP, Purchasing, Department Head, Supervisor |
| D4 | Accounting-system invoice record | Created by AP at T2; updated during exceptions |
| D5 | Goods/services receipt confirmation | Produced or confirmed by Purchasing |
| D6 | Purchasing confirmation email | Purchasing to AP at T5 |
| D7 | Discrepancy/hold record and correspondence | AP, Purchasing, Supervisor |
| D8 | Supplier contract or agreed pricing terms | Supplier Relationship Manager |
| D9 | Manager approval package | System; includes invoice, PO, and confirmation |
| D10 | Manager decision: approve, hold, or reject | Manager/System |
| D11 | Payment-cycle entry | AP after approval |
| D12 | Budget or departmental reference information | Consulted by Manager where relevant |

### Key message flows

1. **Supplier  AP:** Original invoice  
2. **AP/Purchasing/Supplier Relationship Manager  Supplier:** Request for PO, clarification, or corrected invoice  
3. **Supplier  AP/Purchasing/Supplier Relationship Manager:** PO information, explanation, or revised invoice  
4. **Purchasing  AP:** Confirmation or discrepancy notification  
5. **Accounting System  Department Manager:** Automatic approval request  
6. **Department Manager/System  AP:** Approval, rejection, or hold decision  

---

## 5. Variations and Ambiguities

1. **Overlap in matching responsibilities:**  
   Purchasing reports comparing quantities, prices, and delivery charges, while AP reports performing the formal invoice-to-PO line match. The model therefore includes both a Purchasing business verification and a subsequent AP system match.

2. **Missing-PO handling varies:**  
   AP may return the invoice directly to the supplier, Purchasing may tell AP to obtain the information, or the Supplier Relationship Manager may contact the supplier. If no legitimate PO exists, the AP Supervisor and department head may attempt to create a retrospective PO.

3. **Supplier contact is not owned by one role:**  
   Purchasing may contact the supplier directly, while AP may involve the Supplier Relationship Manager, especially for key suppliers or contractual pricing issues. These are modeled as inclusive alternatives.

4. **Post-correction re-entry is not stated consistently:**  
   The canonical model repeats Purchasing verification before AP rematching. A simple clarification that does not alter the invoice or PO might, in practice, proceed directly to AP rematching, but this shortcut is not confirmed by all interviewees.

5. **Manager rejection aftermath is unspecified:**  
   Rejection is modeled as the end of the current invoice case. A later corrected invoice may initiate a new case or re-enter the exception process, depending on local practice.

6. **Payment execution is outside the described scope:**  
   The modeled process ends when AP schedules the approved invoice for the next payment cycle, not when funds are actually transferred.
