The main flow is:

`RA > VF > AE > [RMI+ > VF]* > AD > SC > AC`

With `*` = `LOOP`

> 0 times `*`  = `Case 2`
> 1 time with 1 `RMI` = `Case 1`
> 1 time with 2 `RMI` = `Case 3`

For `>1 RMI` in one iteration `RMI` itself is a loop:

```
LOOP_INNER = * ( RMI , RMI ) = RMI+  // one or more RMI
LOOP_OUTER = * ( tau , ->( LOOP_INNER , VF ) ) = [RMI+ VF]*
```

Final tree - n-ary notation:

```text
-> (
  'Receive Application (RA)',
  'Validate Form (VF)',
  'Assess Eligibility (AE)',
  * (
    tau,
    -> (
      * ( 'Request Missing Info (RMI)', 'Request Missing Info (RMI)' ),
      'Validate Form (VF)'
    )
  ),
  'Approval Decision (AD)',
  'Send Confirmation (SC)',
  'Archive Case (AC)'
)
```

If `RMI` is not required to repeat consecutively, the core model is:

```text
->( RA, VF, AE, *( tau, ->( RMI, VF) ), AD, SC, AC )
```

Binary compliant form:

```text
->( RA, ->( VF, ->( AE, ->( *( tau, ->( *(RMI,RMI), VF) ), ->( AD, ->( SC, AC ) ) ) ) ) )
```

This gives fitness for `RA VF AE [RMI RMI.. VF]* AD SC AC` and high precision / simplicity.
