## BPMN-Like Textual Process Model: Invoice Approval and Payment Scheduling

### 1. Participants / Swimlanes

**Pool: Organization – Invoice Processing**

| Lane / Participant | Responsibilities |
|---|---|
| Supplier | Sends invoice, supplies missing PO information, issues corrected invoice where needed. |
| Accounts Payable Clerk (Mary / AP) | Receives and logs invoices, performs initial PO validation and matching, coordinates approvals, schedules payment. |
| Purchasing Department / Purchasing Officer (Dan) | Validates PO details, confirms receipt of goods/services, investigates invoice-to-PO discrepancies. |
| Department Manager (Carlos) | Reviews and approves or rejects invoices after validation. |
| AP Supervisor (Rita) | Resolves unresolved discrepancies, missing-PO exceptions, and stalled invoices. |
| Supplier Relationship Manager (Karen) | Assists with supplier communications and contractual/pricing disputes. |
| Accounting System | Stores invoice and PO records; sends manager approval notifications; supports payment scheduling. |

---

### 2. Main End-to-End Process Flow

```text
START EVENT: Invoice received
    Trigger: Supplier sends invoice, usually by email.

[AP Clerk] Task A1: Receive invoice
    Input: Supplier invoice (email attachment or equivalent).

[AP Clerk] Task A2: Check whether invoice contains a valid PO number
    Data checked: Invoice PO number; purchase order records.

XOR Gateway G1: Is a valid PO number present?
```

---

## 3. PO Validation Paths

### Path G1-Yes: Valid PO Present

```text
[AP Clerk] Task A3: Log invoice in accounting system
    Output: Invoice record in accounting system.

[AP Clerk] Task A4: Send invoice to Purchasing for validation / receipt confirmation
    Message: Invoice details and PO reference sent to Purchasing.
```

```text
[Purchasing Officer] Task P1: Review invoice against PO
    Review includes:
      - Ordered quantities
      - Invoice quantities
      - Prices
      - Delivery charges
      - Contractual or agreed terms, where applicable

[Purchasing Officer] Task P2: Confirm goods/services were received
    Note: Mary describes Purchasing as confirming receipt of goods/services.
    Ambiguity: Dan primarily describes validating the invoice against the PO; the
    specific system or evidence used for receipt confirmation is not specified.
```

```text
XOR Gateway G2: Are goods/services received and invoice details consistent with the PO?
```

#### Path G2-Yes: Receipt Confirmed and Invoice Matches PO

```text
[Purchasing Officer] Task P3: Send confirmation to Accounts Payable
    Message: Confirmation that invoice/PO/receipt validation is satisfactory.

[AP Clerk] Task A5: Match invoice line items against PO in accounting system
    Data objects: Invoice; PO; purchasing confirmation.

XOR Gateway G3: Does AP confirm that invoice line items, quantities, and pricing match?
```

##### Path G3-Yes: Match Successful

```text
[AP Clerk] Task A6: Submit invoice for department-manager approval

[Accounting System] Intermediate Message Event E1:
    Automatically send approval notification to Department Manager.
    Notification includes:
      - Invoice details
      - PO
      - Purchasing confirmation
      - Any relevant notes
```

Continue at **Manager Approval Flow** below.

##### Path G3-No: AP Identifies Discrepancy

```text
[AP Clerk] Task A7: Place invoice on hold / flag discrepancy
    Examples:
      - Incorrect pricing
      - Missing items
      - Quantity mismatch
      - Other invoice-to-PO inconsistency

[AP Clerk] Task A8: Request clarification from Purchasing
    Message: Email or other communication describing discrepancy.
```

Continue at **Discrepancy Resolution Subprocess** below.

---

#### Path G2-No: Purchasing Finds a Problem

```text
[Purchasing Officer] Task P4: Identify discrepancy or missing information
    Examples:
      - Extra units billed
      - Incorrect price
      - Incorrect delivery charges
      - Invoice details inconsistent with PO
      - No usable PO reference
      - Goods/services not confirmed as received

XOR Gateway G4: Can Purchasing resolve the issue directly with Supplier?
```

##### Path G4-Yes: Purchasing Resolves with Supplier

```text
[Purchasing Officer] Task P5: Contact Supplier and request clarification or corrected invoice

[Supplier] Task S1: Provide clarification, PO information, credit, or corrected invoice

[Purchasing Officer] Task P6: Revalidate corrected/clarified invoice against PO

Sequence Flow: Return to Gateway G2
```

##### Path G4-No: Issue Cannot Be Resolved Easily

```text
[Purchasing Officer] Task P7: Notify AP Clerk to hold invoice and/or escalate issue

[AP Clerk] Task A9: Escalate unresolved issue to AP Supervisor

Sequence Flow: Continue at Exception Handling Subprocess.
```

---

### Path G1-No: No Valid PO Number Present

```text
[AP Clerk] Task A10: Put invoice on hold

[AP Clerk] Task A11: Request missing PO information from Supplier
    Message: Request for PO number, supporting details, or revised invoice.
```

```text
[Supplier] Task S2: Provide PO number or revised invoice
```

```text
XOR Gateway G5: Has a valid PO reference been provided?
```

#### Path G5-Yes: PO Information Received

```text
[AP Clerk] Task A12: Update invoice record with PO reference

Sequence Flow: Return to Task A3: Log invoice in accounting system
    Note: If the invoice was already logged as an exception, update the existing record
    rather than creating a new record.
```

#### Path G5-No: PO Still Missing / Invoice Cannot Be Validated

```text
[AP Clerk] Task A13: Escalate missing-PO exception to AP Supervisor

Sequence Flow: Continue at Exception Handling Subprocess.
```

## 4. Discrepancy Resolution Subprocess

### Subprocess: Resolve Invoice Exception

**Trigger:** A discrepancy, missing information, missing PO, receipt problem, or unresolved supplier issue prevents the invoice from proceeding.

```text
[AP Supervisor] Task R1: Review escalated invoice exception
    Inputs may include:
      - Invoice
      - PO, if available
      - AP matching notes
      - Purchasing findings
      - Supplier correspondence
      - Contract information

[AP Supervisor] Task R2: Coordinate investigation and resolution
    Possible actions:
      - Contact Supplier directly
      - Coordinate with Purchasing
      - Contact Department Manager / department head
      - Request missing documentation
      - Request corrected invoice
      - Determine whether a retrospective PO is required
```

```text
[Optional: Supplier Relationship Manager] Task K1: Assist with supplier communication
    Used when:
      - Supplier is a key supplier;
      - Pricing or contractual terms are disputed;
      - PO information is missing;
      - A corrected invoice is required.

[Supplier Relationship Manager] Task K2: Review supplier contract / agreed terms
    Output: Guidance on correct pricing, terms, or required supplier correction.

[Supplier Relationship Manager] Task K3: Communicate with Supplier and inform AP or Purchasing of resolution
```

```text
XOR Gateway G6: Can the exception be resolved with a valid PO and acceptable invoice?
```

### Path G6-Yes: Exception Resolved

```text
[AP Supervisor] Task R3: Confirm resolution and release invoice from hold

XOR Gateway G7: Is a retrospective PO required?
```

#### Path G7-Yes: Retrospective PO Required

```text
[Department Head / Relevant Department] Task D1: Create or authorize retrospective PO
    Note: Used for invoices associated with informally contracted services or invoices
    that do not match an existing PO.

[AP Clerk] Task A14: Update invoice with retrospective PO reference

Sequence Flow: Return to Task A4: Send invoice to Purchasing for validation / receipt confirmation.
```

#### Path G7-No: Existing PO / Invoice Issue Corrected

```text
Sequence Flow: Return to Task A4: Send invoice to Purchasing for validation / receipt confirmation.

Alternative interpretation:
    If Purchasing confirmation remains valid and only an AP-level matching issue was
    corrected, the process may return directly to Task A5: Match invoice line items
    against PO. The interviews do not specify a consistent re-entry point.
```

### Path G6-No: Exception Cannot Be Resolved

```text
XOR Gateway G8: Should the invoice be rejected?
```

#### Path G8-Yes: Reject Invoice

```text
[AP Supervisor or AP Clerk] Task R4: Reject invoice / notify Supplier
    Output: Rejection notice and reason for rejection.

END EVENT: Invoice rejected / no payment scheduled
```

#### Path G8-No: Keep Invoice on Hold

```text
[AP Supervisor] Task R5: Maintain invoice on hold pending further information

Intermediate Event: Additional information received
    Possible sources:
      - Supplier
      - Purchasing
      - Department head
      - Supplier Relationship Manager

Sequence Flow: Return to Task R1: Review escalated invoice exception
```

## 5. Manager Approval Flow

```text
[Department Manager] Task M1: Review invoice approval request in system
    Inputs:
      - Invoice
      - PO
      - Purchasing confirmation
      - Matching details
      - Any special notes or supporting documentation

[Department Manager] Task M2: Assess invoice against budget and business need
    Checks may include:
      - Quantities
      - Pricing
      - Total amount
      - Budget variance
      - Unexpected items
      - Special notes
```

```text
XOR Gateway G9: Does the Manager approve the invoice?
```

### Path G9-Yes: Manager Approves

```text
[Department Manager] Task M3: Approve invoice in accounting system

[Accounting System] Task SYS1: Record approval status

[AP Clerk] Task A15: Schedule approved invoice for payment
    Output: Invoice added to next payment cycle / payment run.

END EVENT: Invoice approved and scheduled for payment
```

### Path G9-No: Manager Rejects or Requests Investigation

```text
XOR Gateway G10: Does the Manager reject the invoice outright or request investigation?
```

#### Path G10-Investigate: Hold and Investigate

```text
[Department Manager] Task M4: Request AP to hold invoice and investigate
    Message: Approval rejection/hold notification sent to AP.

[AP Clerk] Task A16: Place invoice on hold and investigate manager concern
    Examples:
      - Significant budget difference
      - Unexpected invoice item
      - Suspicious total amount

Sequence Flow: Continue at Exception Handling Subprocess.
```

#### Path G10-Reject: Reject Invoice

```text
[Department Manager] Task M5: Reject invoice in system

[AP Clerk] Task A17: Notify Supplier and/or Purchasing of rejection reason
    Note: The interviews do not specify whether every manager rejection is final.
    Some rejected invoices may instead be corrected and resubmitted.

END EVENT: Invoice rejected / no payment scheduled
```

## 6. Key Data Objects / Artifacts

| Data Object | Created / Used By | Purpose |
|---|---|---|
| Supplier Invoice | Supplier, AP, Purchasing, Manager | Request for payment; basis for validation and approval. |
| Purchase Order (PO) | Purchasing, AP, Manager | Authorizes purchase and provides expected quantity, price, and terms. |
| Goods/Services Receipt Confirmation | Purchasing | Confirms that ordered goods or services were received. |
| Accounting-System Invoice Record | AP / Accounting System | Stores invoice details, matching status, approval status, and payment scheduling information. |
| Purchasing Confirmation Email | Purchasing Officer | Confirms satisfactory PO, receipt, and invoice validation. |
| Discrepancy / Hold Record | AP, Purchasing, Supervisor | Documents unresolved pricing, quantity, receipt, or PO issues. |
| Supplier Contract / Agreed Terms | Supplier Relationship Manager, Purchasing | Used to resolve price or contractual discrepancies. |
| Corrected Invoice | Supplier | Replaces or amends an incorrect invoice. |
| Retrospective PO | Department Head / AP / Purchasing | Created for exceptional invoices where no prior PO exists, particularly informal service arrangements. |
| Manager Approval Notification | Accounting System | Automatically requests manager approval after validation. |
| Payment Schedule / Payment Run Entry | AP | Indicates approved invoice is included in a future payment cycle. |

---

## 7. Summary of Gateways

| Gateway | Decision |
|---|---|
| G1 | Does the invoice contain a valid PO number? |
| G2 | Are goods/services received and invoice details consistent with the PO? |
| G3 | Does AP’s invoice-line matching succeed? |
| G4 | Can Purchasing resolve the discrepancy directly with the Supplier? |
| G5 | Has missing PO information been received? |
| G6 | Can the escalated exception be resolved? |
| G7 | Is a retrospective PO required? |
| G8 | Should an unresolved invoice be rejected or retained on hold? |
| G9 | Does the Department Manager approve the invoice? |
| G10 | If not approved, should the invoice be investigated or rejected? |

---

## 8. Identified Variations and Ambiguities

1. **Timing of invoice matching:**  
   Mary describes Purchasing confirming receipt first and AP subsequently matching invoice line items to the PO. Dan describes Purchasing itself comparing quantities, pricing, and delivery charges. Therefore, both Purchasing and AP may perform overlapping invoice-to-PO validation.

2. **Missing PO handling:**  
   The normal rule is that invoices without a valid PO cannot be approved. However, Rita reports an exception for informally contracted services, where a retrospective PO may be created rather than rejecting the invoice.

3. **Discrepancy ownership:**  
   Purchasing may contact the Supplier directly, AP may request clarification from Purchasing, and the AP Supervisor may coordinate cross-functional resolution. The exact owner depends on the discrepancy type and complexity.

4. **Manager rejection outcome:**  
   A manager may reject an invoice outright or ask AP to hold it and investigate. The interviews do not define whether rejected invoices may later be corrected and resubmitted; this model treats that as a possible exception/rework path.

5. **Payment execution is outside the described scope:**  
   The interviews end with AP scheduling the invoice for the next payment cycle. Actual payment-run execution, bank transfer, remittance advice, and payment reconciliation are not described and are therefore outside this process model’s endpoint.
